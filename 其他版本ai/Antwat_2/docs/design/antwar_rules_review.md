# AntWar 游戏策略维度分析

## 概述

本文档基于对 AntWar 游戏规则的深入分析，梳理策略维度的重要性排序，并推导对神经网络设计的指导原则。

**目的**：为神经网络架构设计提供**游戏层面**的依据，而非具体实现建议。

---

## 一、游戏本质特性

### 1.1 信息对称性

AntWar 是**完全信息对称**的回合制游戏：

- 双方玩家获得完全相同的观察结构（`PublicRoundState`）
- 不存在战争迷雾、对手手牌等隐藏信息
- 随机性仅来自引擎内部（蚂蚁移动的 softmax 采样）

**对设计的启示**：不需要建模隐藏信息，网络只需基于当前状态做最优决策。

### 1.2 蚂蚁不可控

**核心结论**：AI **无法精细控制**蚂蚁的行军路线。

蚂蚁的目标由引擎决定（`engine.py:725-742`）：
```python
def _move_target_for_ant(self, ant: Ant) -> tuple[int, int]:
    if ant.kind != AntKind.COMBAT:
        return PLAYER_BASES[1 - ant.player]  # 目标固定为敌方基地
```

AI **只能间接**影响蚂蚁路径：
- 建造/升级防御塔 → 改变 risk field 和 control field
- 使用超级武器 → 改变信息素或直接伤害
- 升级基地科技 → 影响蚂蚁属性（血量、生成速度）

**对设计的启示**：策略重点应放在防御塔和超级武器的运营上，而非蚂蚁控制。

### 1.3 先手后手机制（重要！）

**发现时间**：2026-05-05

AntWar 是一个**标准的回合制（sequential）游戏**，存在明确的先手后手机制：

#### 1.3.1 机制详解

游戏每两个step才构成一个完整的游戏回合：

```python
# AntWarSequentialEnv 的实现逻辑
if self._current_player == 0:  # 玩家0（先手）
    self._runtime.apply_self_operations([current_player_op])
else:  # 玩家1（后手）
    self._runtime.apply_opponent_operations([current_player_op])
    if not self._runtime.state.terminal:
        self._runtime.state.advance_round()  # 只有玩家1行动后才推进回合
```

#### 1.3.2 行动顺序

| 步骤 | 玩家 | 操作 | 回合变化 |
|:---:|:---:|------|:-------:|
| step=1 | 玩家0 (先手) | apply_self_operations | 不推进 |
| step=2 | 玩家1 (后手) | apply_opponent_operations + advance_round | round 0→1 |
| step=3 | 玩家0 (先手) | apply_self_operations | 不推进 |
| step=4 | 玩家1 (后手) | apply_opponent_operations + advance_round | round 1→2 |
| step=5 | 玩家0 (先手) | apply_self_operations | 不推进 |
| step=6 | 玩家1 (后手) | apply_opponent_operations + advance_round | round 2→3 |

#### 1.3.3 关键影响

**重要结论**：

1. **每两个step构成一个完整回合**
   - step 1+2 = 游戏回合0
   - step 3+4 = 游戏回合1
   - step 5+6 = 游戏回合2
   - ...

2. **如果 max_steps=512，实际最多只有 256 个完整回合**

3. **对战评估时长的计算**
   - 假设平均每回合耗时 0.1秒
   - 256回合 × 0.1秒 = 25.6秒（理论对战时长）
   - 实际可能更短，因为游戏可能提前结束

4. **训练时的步数概念混淆**
   - `training_metrics.json` 中的 "步数" 实际是 `step` 次数
   - 不是完整的游戏回合数
   - 一个游戏回合 = 2个step

#### 1.3.4 对训练的影响

| 配置 | 实际含义 |
|------|---------|
| max_steps=512 | 最多512个step = 最多256个完整回合 |
| num_envs=2 | 并行2个环境，每个环境独立运行 |
| episodes=100 | 100个训练周期，每个周期可能有多个episode |

#### 1.3.5 训练日志中的证据

从训练日志可以看到：

```
step=1 完成, round_index=0   (玩家0行动)
step=2 完成, round_index=1   (玩家1行动，回合推进)
step=3 完成, round_index=1   (玩家0行动)
step=4 完成, round_index=2   (玩家1行动，回合推进)
step=5 完成, round_index=2   (玩家0行动)
```

## 二、策略维度重要性排序

### 2.1 排序结果

| 排序 | 策略维度 | 动作类别 | 动作空间占比 |
|:---:|----------|----------|-------------|
| 1 | **防御塔运营** | 建造/升级/拆除 | 80/96 ≈ 83% |
| 2 | **经济管理** | （贯穿全局） | — |
| 3 | **基地升级** | 科技升级 | 2/96 ≈ 2% |
| 4 | **超级武器** | 4种超级武器 | 20/96 ≈ 21% |
| 5 | **攻击节奏** | 蚂蚁生成控制 | 间接 |
| 6 | **升级路径** | 塔升级方向 | 间接 |

### 2.2 各维度详解

#### 维度 1：防御塔运营（最重要）

**为什么关键**：
- 占动作空间 **80/96 ≈ 83%**
- 防御塔是**唯一可精细控制**的战场元素
- 塔的摆放位置决定封锁效果
- 升级路径选择决定防御类型组合

**AI 能做的决策**：
- 在哪里建造新塔（10 个高地位置可选）
- 升级哪座塔、朝哪个方向升级（多种升级树分支）
- 拆除哪座塔（资源回收）

**升级树分支**：
```
基础 → 重型 / 快速 / 迫击炮 / 生产者
重型 → 重型+ / 冰冻 / 迷惑
快速 → 快速+ / 双发 / 狙击
迫击炮 → 迫击炮+ / 脉冲 / 导弹
```

#### 维度 2：经济管理（贯穿全局）

**为什么关键**：
- 资源是所有策略的**硬约束**
- 建造费用指数增长：`(n//2) 个 3^((n//2)) × 15`

**金币来源**：
- 初始金币：50
- 每回合收入：3 金币（每 2 回合）
- 击杀奖励：6-14 金币（视蚂蚁等级）
- 拆除返还：40%-80% 费用

**核心决策**：何时建造（费用高时观望）、何时拆除（回收资源）

#### 维度 3：基地升级

**为什么重要**：
- `generation_level` 决定蚂蚁生成间隔（4.5 → 4.0 → 3.5 回合）
- `ant_level` 决定蚂蚁血量（20 → 25 → 25 HP）
- 升级费用明确（200/250 金币）

#### 维度 4：超级武器（战略级技能）

**为什么重要**：
- 高成本（60-135 金币）、高收益
- 冷却时间长（25-45 回合），使用窗口关键
- 可改变战场格局

**4 种超级武器**：
| 类型 | 费用 | 冷却 | 效果 |
|------|------|------|------|
| 闪电风暴 | 90 | 35 | 范围伤害 + 攻击塔 |
| EMP | 135 | 45 | 使防御塔失效 |
| 偏射盾 | 60 | 25 | 保护己方蚂蚁 |
| 紧急回避 | 60 | 25 | 给蚂蚁闪避 |

#### 维度 5：攻击节奏

**为什么重要**：
- 通过控制蚂蚁生成来控制进攻密度
- 蚂蚁太多会堵塞路径、浪费资源
- 蚂蚁太少无法压制对方

#### 维度 6：升级路径选择

**为什么重要**：
- 不同升级组合产生不同战术效果

**关键塔类型**：
- **冰冻塔**：控场，限制蚂蚁移动
- **迷惑塔**：使敌方蚂蚁偏离目标
- **脉冲塔**：范围伤害
- **生产者塔**：加速蚂蚁生产
- **狙击塔**：超远攻击范围（6 格）

## 三、策略维度与网络输入要求的映射

### 3.1 映射关系

| 策略维度 | 对网络的输入要求 | 核心学习目标 |
|----------|----------------|-------------|
| 防御塔运营 | **精细空间编码** | 位置选择、升级路径 |
| 经济管理 | 全局状态理解 | 资源分配、建造时机 |
| 基地升级 | 科技树状态 | 升级时机决策 |
| 超级武器 | 冷却/效果状态 | 使用时机判断 |
| 攻击节奏 | 时序模式感知 | 生产节奏控制 |
| 升级路径 | 塔类型组合理解 | 战术组合优化 |

### 3.2 对网络设计的启示

**核心启示**：网络结构应**优先满足**高优先级的策略维度。

```
策略重要性排序         对网络的要求
─────────────────────────────────────
1. 防御塔运营 (83%)   精细空间编码
2. 经济管理            全局状态感知
3. 基地升级            科技状态感知
4. 超级武器            冷却状态感知
5. 攻击节奏            时序感知（可选）
6. 升级路径            塔类型识别
```

```
动作 ID    动作类型            数量    策略维度

0          NO_OP               1       —
1-10       BUILD_TOWER        10      防御塔运营

42         UPGRADE_ANT_HP    1       基地升级

```

### 4.2 关键特性

**动态映射问题**：
- Tower ID 由引擎分配，动态递增（`next_tower_id += 1`）
- 但动作空间固定 96 维
- 当塔数量 > 5 时，upgrade/downgrade 动作与 tower_id 的映射需要特殊处理

## 五、对神经网络设计的指导原则

### 5.1 空间编码原则

**核心观点**：防御塔运营是最重要的策略维度，位置决策需要精细的空间信息。

**设计要点**：
- 空间特征应保留**精细的位置信息**
- 避免过度的空间压缩（如 19×19 → 4×4）
- 空间编码应能区分不同高地位置的语义

### 5.2 状态完整性原则

**核心观点**：影响决策的关键状态必须编码。

**设计要点**：
- 超级武器冷却状态必须编码（否则无法学习使用时机）
- 金币、经济状态要完整
- 敌我对比信息要有

### 5.3 动作处理原则

**核心观点**：96 维动作空间是固定的，动作编码要与动态的 tower_id 解耦。

**设计要点**：
- Action mask 必须正确反映当前可执行动作
- 每回合要根据状态重新计算 mask
- NO_OP 始终合法

### 5.4 时序建模原则

**核心观点**：RNN 不是必须的，但可能有助于捕捉时序模式。

**分析**：
- 游戏是完全信息对称的，MDP 结构清晰
- Global features 已经编码了很多统计量
- RNN 的价值在于捕捉尚未显式编码的时序模式

### 5.5 先手后手机制对训练的影响

**重要认知**：
- 训练时的 `step` 概念 ≠ 游戏回合
- 1个游戏回合 = 2个step（先手+后手）
- max_steps=512 实际最多256个完整回合

**建议**：
- 评估训练效率时，应该关注**完整回合数**而非step数
- 训练指标中的"步数"可能需要乘以2才是实际游戏回合数
- 对战评估的时长预期应该调整（每回合约0.05-0.1秒）

## 六、总结

### 6.1 核心认知

1. **AI 无法精细控制蚂蚁**，只能通过防御塔和超级武器间接引导
2. **防御塔运营是最重要的策略维度**，占 83% 的动作空间
3. **经济管理是所有策略的硬约束**，影响决策时机
4. **超级武器是战略级技能**，高成本高收益
5. **游戏存在先手后手机制**，每两个step构成一个完整回合

### 6.2 设计原则

| 优先级 | 策略维度 | 设计原则 |
|--------|----------|----------|
| **高** | 防御塔运营 | 空间编码精度要高，避免过度压缩 |
| **高** | 超级武器 | 冷却状态必须编码 |
| **高** | 先手后手机制 | 理解step与回合的转换关系 |
| 中 | 经济管理 | 全局特征编码要完整 |
| 中 | 基地升级 | 科技等级状态要清晰 |

### 6.3 架构选择提示

| 游戏特性 | 推荐处理方式 | 理由 |
|----------|-------------|------|
| 强空间性 | CNN 处理空间特征 | 保留空间信息 |
| 多模态观察 | Board 和 Global 分别编码 | 各取所长 |
| 完全信息对称 | RNN 可选 | 不是必须 |
| 高离散动作 | Softmax Policy | 96 维动作空间 |
| 回合制 | 步数转换 | 1回合=2step |
