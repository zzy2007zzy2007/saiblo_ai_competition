# 两阶段对战评估优化方案 v2（精简版）

> 版本: v2.0
> 日期: 2026-06-12
> 状态: 待实施
> 前身: [两阶段对战评估优化方案](./两阶段对战评估优化方案.md)（v1，pass_ratio=0.5，总对局 ~2000）

## 1. 需求再审视

### 1.1 算法框架的真实需求

当前配置 `num_seeds=8, elitism_count=2`，且 `population_size=80`。每代评估真正需要的是：

- **正确选出 top-10 左右的个体**作为亲本候选（前 2 精英 + 前 8 种子）
- 第 11~80 名的内部排序**不需要准确**——它们不参与交叉变异
- 甚至 top-10 内部的精确排序也不需要——只要都在亲本池内即可

这意味着评估系统不需要回答"80 个人的完整 ELO 排序"，只需要回答"哪 10 个人最强"。

### 1.2 对方案设计的关键影响

| 维度 | v1 假设 | v2 修正 |
|------|--------|--------|
| 精排人数 | 40（pass_ratio=0.5） | **20~24**（pass_ratio=0.25~0.3） |
| 精排目标 | 对 40 人精确排序 | **对 20 人选出 top-8** |
| 粗排目标 | 筛掉 bottom 50% | **筛掉 bottom 70%** |
| 粗排参照物数 | 2 个 | **1 个**（可探讨） |
| 总对局数 | ~2000 | **~800~1100** |

## 2. 当前方案基线

### 2.1 当前评估流程与成本

```
80 个体 × 6 参照物 × 6 局/对 = 2880 局/代（含 baseline 验证则为 ~4000 局）
```

但实际上基线验证（8 种子 × 3 参照物 × 50 局 = 1200 局）本身就是 50 局的高精度评估。**当前的 baseline 验证已经给了每个种子高精度的完整信息**，selection 阶段再对全部 80 个体做全量评估，是对 baseline 验证之外那 72 个个体的冗余投入。

### 2.2 p 值实测数据回顾（server10 gen2）

| 参照物 | 均值 p | 标准差 | 评估 |
|--------|--------|--------|------|
| BasicRandomAI | 0.83 | 0.13 | 区分度差：大家都轻松赢 |
| BasicTowerAI | 0.26 | 0.34 | 区分度好：个体从全败到全胜 |
| MediumRuleAI | 0.25 | 0.33 | 区分度好 |

**TowerAI 和 MediumAI 是当前最好的区分器**。BasicRandomAI 对当前的种群已经没有区分价值。

### 2.3 bootstrap 测算回顾（8 种子 × 200 次模拟）

| n_battles | Kendall τ（精排） | recall@4（精排） |
|-----------|-------------------|-------------------|
| 1 | 0.719 | 86.0% |
| 3 | **0.805** | **91.4%** |
| 5 | 0.831 | 93.4% |
| 10 | 0.821 | 91.1% |

**n_battles=3 已达排序精度天花板**（τ=0.805），推到 5 只多 0.026 τ。

## 3. 精简方案设计

### 3.1 整体架构

```
每代 Selection
│
├─ 阶段一：粗排（Course Ranking）
│  ├─ 80 个体
│  ├─ 1 个低门槛参照物（从 CourseReferencePool 选出）
│  ├─ n_battles=2（每对 4 局，先后手各 2）
│  ├─ 对局数：80 × 1 × 4 = 320 局
│  └─ 按胜率排序，取前 24 个（30%）
│
├─ 阶段二：精排（Fine Ranking）
│  ├─ 前 24 个个体
│  ├─ 5 个参照物（3 锚定 + 2 动态）
│  ├─ n_battles=3（每对 6 局）
│  ├─ 对局数：24 × 5 × 6 = 720 局
│  └─ 输出：ELO 排序，取前 8 为种子 + 前 2 为精英
│
└─ 总对局数：320 + 720 = 1040 局
```

### 3.2 对局规模对比

| | 当前方案 | v1 方案 | **v2 方案** |
|--|---------|---------|------------|
| 粗排 | — | 320 | **320** |
| 精排 | 2400 | 1440 | **720** |
| 头对头 | — | 240 | **—**（没必要） |
| **总计** | **2400** | **~2000** | **~1040** |
| 节省 | — | 17% | **57%** |
| 弱个体评估成本 | 30 局 | 4 局 | **4 局** |
| 强个体评估成本 | 30 局 | 36 局 | **34 局** |

### 3.3 为什么只用一个参照物做粗排就够了

Bootstrap 测算显示 n_battles=3 时排序 τ=0.805，但这是**全量精确排序**的精度。粗排只需要把 bottom 70% 筛掉——这是一个**二分类问题**，比精确排序简单得多。

**单参照物粗排的统计可靠性**：

假设低门槛参照物的强度正好位于种群中游水平（p≈0.5 附近），那么：
- 强个体（p≈0.7~0.9）：4 局中 ≥3 胜的概率 = C(4,3)×0.8³×0.2 + 0.8⁴ ≈ 0.41+0.41 = **82%**
- 弱个体（p≈0.1~0.3）：4 局中 ≤1 胜的概率 = 0.7⁴ + C(4,1)×0.3×0.7³ ≈ 0.24+0.41 = **65%**

取前 24 名（30%），在 80 个体的场景下，真实的 top-10 几乎不可能全部被筛掉——因为：
1. 真正的 top-10 对中游参照物的真实 p 远高于 0.5（至少 0.7+）
2. 即使偶有一两个 top-10 发挥失常（概率 <5%），前 24 的容量也提供了足够的安全边际
3. 精排会再次对晋级的 24 人做精确评估，粗排阶段漏掉的真实强者会在精排中自然排名靠前，不影响最终种子选拔

**但为了进一步降低误筛风险**，粗排 n_battles 从 v1 的 1 增加到 **2**（4 局/对）。单参照物 4 局 / 80 个体 = 320 局，与 v1 的双参照物 2 局成本相同。

### 3.4 精排参照物精简

精排从 6 个参照物（3 锚定 + 3 动态）精简到 **5 个**（3 锚定 + 2 动态），因为：
- BasicRandomAI 区分度已退化（均值 p=0.83），保留它仅作为跨代 ELO 锚定（不作为排序依据）
- 动态参照物从上代冠军 1 个 + 对手池 2 个 → 仅对手池 2 个
- 上代冠军的作用被精排的种子候选人间天然击败关系覆盖

| 类型 | v1 | v2 | 理由 |
|------|-----|-----|------|
| 固定锚定 | 3 | 3 | 保持跨代可比性 |
| 动态参照物 | 2+1(冠军) | 2 | 减少冗余 |
| **合计** | **6** | **5** | |

### 3.5 不再需要头对头修正

v1 中的头对头修正（前 16 名互相对战 240 局）的目的是精细区分 #6~#12 的边界排名。但在 v2 中：
- 只需要从 24 人中选出 8 个种子，不需要精确排序 #9~#24
- 精排 24 人 × 5 参照物 × 6 局 = 720 局已足够选出 top-8（bootstrap τ=0.805）
- 头对头修正的 240 局收益不足以 justify 其成本

## 4. 粗排风险量化分析

### 4.1 单参照物 4 局的失误概率

设真实 top-10 个体对低门槛参照物的真实胜率为 p。4 局中该个体得分低于阈值（从而可能被误筛）的概率：

| 真实 p | P(0胜) | P(1胜) | P(≤1胜) | P(≤2胜) |
|--------|--------|--------|---------|---------|
| 0.90 | <0.01 | 0.004 | **<0.01** | 0.05 |
| 0.85 | <0.01 | 0.01 | **0.01** | 0.11 |
| 0.80 | 0.002 | 0.03 | **0.03** | 0.18 |
| 0.75 | 0.004 | 0.05 | **0.05** | 0.26 |
| 0.70 | 0.008 | 0.08 | **0.08** | 0.35 |

对于真正的 top-10（p≥0.75），5% 概率 ≤1 胜。即使出现这种情况，只要晋级人数足够多（24 人），该个体仍可能以边界排名晋级。

### 4.2 安全边际分析

晋级人数 24 意味着 cutoff 大约在 80 人的第 30 百分位。真实 top-10（p≥0.75）的 ≥2 胜概率 ≥ 95%，而 bottom 50（p≤0.4）的 ≥3 胜概率约为：

P(≥3胜 | p=0.4) = C(4,3)×0.4³×0.6 + 0.4⁴ = 0.15+0.03 = 18%

这意味着 40 个弱个体中约有 7 个侥幸拿到 3-4 胜。24 个晋级名额中，预期有 ~10 个真正强者（≥3 胜）+ ~7 个侥幸弱个体 + ~7 个边界个体。这个构成是安全的——**真正的强者几乎全部晋级**，掺杂的弱个体在精排中会被自然淘汰。

### 4.3 最坏情况：低门槛参照物选择不当

如果低门槛参照物太强（如选了对手池前 10% 的对手），大部分个体 p≈0，4 局全 0 胜，粗排失去筛选能力。

**缓解措施**：
1. CourseReferencePool 严格从 TrueSkill mu 的 30%~60% 区间选取
2. 当 pool 为空时，fallback 到 BasicTowerAI（均值 p=0.26，确保有区分度）
3. 如果粗排阶段所有个体都是 0 胜或 4 胜（无区分度），自动触发 pool 强制刷新

### 5.1 变更清单

### 5.2 v2 配置

```yaml
# 两阶段评估配置（v2 精简版）
two_phase:
  enabled: true
  pass_ratio: 0.3              # 粗排晋级比例（80→24）
  course_n_battles: 2          # 粗排每对 4 局（1 参照物）
  fine_n_battles: 3            # 精排每对 6 局
  course_n_refs: 1             # 粗排参照物数（v2 从 2 减为 1）

  # v2 不再需要头对头修正
  head_to_head_enabled: false

# 低门槛参照物池
course_pool:
  max_size: 5
  refresh_interval: 3
  stale_elo_gap: 400.0
```

### 5.3 `evaluate_population_two_phase()` v2 关键变化

相比 v1，核心变化：

```python
# v1: 粗排 2 参照物，40 人晋级
course_refs = course_pool.select(2)     # v1
n_pass = int(80 * 0.5)                  # v1: 40

# v2: 粗排 1 参照物，24 人晋级
n_course_refs = config.get("course_n_refs", 1)   # v2
course_refs = course_pool.select(n_course_refs)  # v2
n_pass = int(80 * 0.3)                           # v2: 24

# v1: 精排 6 参照物（3锚定+3动态）
fine_refs = anchor_refs + dynamic_refs           # v1: 6

# v2: 精排 5 参照物（3锚定+2动态）
# dynamic_refs 本身已从 3 减为 2（去掉上代冠军）
fine_refs = anchor_refs + dynamic_refs           # v2: 5
```

### 5.4 粗排去重检查

新增一个安全保护：如果粗排阶段所有 80 个个体对低门槛参照物的胜率完全相同（all 0 或 all 4），说明参照物失去区分度，应跳过粗排直接全量精排：

```python
def _run_battle_phase(self, ...):
    # ... 对战逻辑 ...
    
    # 去重检查：如果所有个体得分相同，说明参照物无区分度
    if phase == "course":
        scores = [ind.elo_rating for ind in individuals]
        if len(set(scores)) <= 1:
            logger.warning(
                f"Course ranking has zero discriminability "
                f"(all scores={scores[0] if scores else 'N/A'}). "
                f"Falling back to full fine ranking."
            )
            return sorted(individuals,
                         key=lambda ind: ind.elo_rating, reverse=True)
    # ...
```
