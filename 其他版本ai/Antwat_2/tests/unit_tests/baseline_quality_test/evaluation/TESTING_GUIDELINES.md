# 测试执行规范

## ⚠️ 重要警告

**🚨 严禁在本地运行计算量大的测试！**

### 必须在服务器上运行的测试类型

1. **策略对战模拟**
   - 多轮对战测试
   - 胜率统计计算
   - 策略性能对比

2. **大规模性能测试**
   - 压力测试
   - 并发测试
   - 长时间运行的测试

3. **训练相关测试**
   - 模型训练
   - 强化学习训练
   - 大规模数据集处理

### 为什么不能在本地运行？

1. **资源限制**
   - 本地环境CPU、内存资源有限
   - 可能导致系统卡顿或崩溃
   - 影响其他开发工作

2. **效率问题**
   - 计算密集型任务会严重影响本地开发效率
   - 可能需要数小时甚至数天才能完成

3. **环境差异**
   - 服务器环境更接近生产环境
   - GPU资源更适合深度学习任务

### 正确的测试流程

#### 1. 部署测试代码到服务器

```bash
cd tools/deploy
./deploy_official_battle.exp
```

#### 2. 检查测试状态

```bash
cd tools/sync
./check_official_battle_status.exp
```

#### 3. 拉取测试结果

```bash
cd tools/sync
./pull_official_battle_data.exp
```

### 可在本地运行的测试

以下测试可以在本地运行：

1. **单元测试**
   - 快速的功能验证
   - 小规模数据测试
   - 代码逻辑验证

2. **调试测试**
   - 单次对战测试（少量回合）
   - 策略逻辑验证
   - 接口兼容性测试

3. **代码质量检查**
   - 语法检查
   - 类型检查
   - 代码格式化

### 违规后果

在本地运行计算量大的测试可能导致：

1. **系统资源耗尽**
   - 电脑卡顿甚至死机
   - 其他应用程序无法正常运行

2. **开发效率下降**
   - 无法进行其他开发工作
   - 可能需要重启系统

3. **测试结果不准确**
   - 本地环境与服务器环境差异
   - 可能导致错误的结论
