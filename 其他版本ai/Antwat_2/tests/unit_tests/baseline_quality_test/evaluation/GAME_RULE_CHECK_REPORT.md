## 发现的问题

### 1. Seed 0的信息素对称性问题

**问题描述：**
- 当使用Seed 0初始化游戏时，双方的信息素矩阵完全对称
- 这会导致双方的蚂蚁移动路径完全一致，HP变化也会完全相同

**影响：**
- 使用Seed 0进行对战测试时，无法有效评估策略差异
- 对战结果缺乏多样性

**解决方案：**
- 避免使用Seed 0进行对战测试
- 使用其他Seed（如1, 2, 3等）进行测试

**状态：** ⚠️ 已知问题，无法修复（官方SDK特性）

### 2. 策略文件中的升级阈值错误

**问题描述：**
- 多个策略文件中的升级检查阈值错误
- 使用`my_coin >= 80`检查，但实际升级成本为200金币

**受影响的文件：**
- gen199.py
- gen99.py
- ann_593.py
- sample.py
- ann_v1.py

**影响：**
- 策略无法正确执行升级操作
- 导致对战结果异常（HP值完全一致）

**解决方案：**
- 将所有策略文件中的`my_coin >= 80`修改为`my_coin >= 200`

**状态：** ✅ 已修复

### 4. 策略文件中的防御塔建造位置错误

**问题描述：**
- 多个策略文件中的防御塔建造位置错误
- 选择的坐标不是高台位置，导致防御塔建造失败
- 这是导致所有对战HP值完全一致的根本原因

**受影响的文件：**
- gen199.py: 使用Coord(4, 6), Coord(4, 12), Coord(13, 6), Coord(13, 12) - 都不是高台
- gen99.py: 使用Coord(5, 5), Coord(5, 13), Coord(12, 5), Coord(12, 13) - 都不是高台
- ann_v1.py: 使用Coord(4, 6), Coord(4, 12), Coord(13, 6), Coord(13, 12) - 都不是高台
- ann_593.py: 使用Coord(3, 7), Coord(3, 11), Coord(14, 7), Coord(14, 11) - 都不是高台
- basic_tower.py: 使用Coord(6, 14), Coord(11, 14) - 不是高台

**影响：**
- 所有策略都无法成功建造防御塔
- 导致双方行为完全一致，HP变化相同
- 对战结果异常（先手必胜）

**解决方案：**
- 修改所有策略文件，使用正确的高台位置
- 玩家0的高台：Coord(5, 6), Coord(5, 7), Coord(6, 4), Coord(6, 7)等
- 玩家1的高台：Coord(12, 6), Coord(12, 7), Coord(11, 4), Coord(11, 5)等

**状态：** ✅ 已修复

### 3. 策略文件中的金币扣减逻辑错误

**问题描述：**
- 多个策略文件中的金币扣减逻辑错误
- 升级检查阈值已修复为200，但扣减金币仍使用80
- 导致策略逻辑与实际游戏规则不符

**受影响的文件：**
- gen199.py
- gen99.py
- ann_593.py
- sample.py
- ann_v1.py

**影响：**
- 策略在金币>=200时执行升级，但只扣减80金币
- 导致策略能够执行更多升级操作，但与实际游戏规则不符
- 可能导致策略在金币不足时仍然尝试升级

**解决方案：**
- 将所有策略文件中的`my_coin -= 80`修改为`my_coin -= 200`

**状态：** ✅ 已修复

## 重要发现：接口不兼容问题

### 问题描述

在检查过程中发现，项目中存在两套策略文件：

1. **baselines目录下的策略**：
   - 使用官方SDK的`BackendState`接口
   - 使用`BaseAgent`抽象基类
   - 使用`ActionBundle`和`ActionCatalog`
   - 需要实现`choose_bundle`方法

2. **tests/strategies目录下的策略**：
   - 使用简化版`GameState`接口
   - 使用简单类定义
   - 直接返回操作列表
   - 需要实现`select_action`方法

### 影响

- 接口不兼容导致无法直接使用baselines中的策略
- 需要维护两套策略代码，增加维护成本
- tests/strategies中的策略容易出现bug（如本次发现的4个严重bug）

### 解决方案

**推荐方案：直接使用baselines策略**

1. **使用official_battle_engine.py**：
   - 使用官方SDK的`BackendState`
   - 直接调用baselines策略的`choose_bundle`方法
   - 完全兼容官方SDK

2. **使用baseline_strategy_loader.py**：
   - 动态加载baselines中的策略
   - 自动发现所有可用的baseline策略
   - 支持ann_593, ann_v1, sample, gen199, gen99等

3. **新策略开发**：
   - 继承`BaseAgent`
   - 使用官方SDK接口
   - 避免重复造轮子

### 建议

1. **避免使用Seed 0进行对战测试**，使用其他Seed确保测试的有效性
2. **定期运行检查脚本**，确保代码与官方SDK保持一致
3. **在修改策略代码时**，注意检查成本阈值是否正确
4. **优先使用baselines策略**，避免维护两套代码
