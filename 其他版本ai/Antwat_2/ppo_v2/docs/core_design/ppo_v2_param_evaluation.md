# PPO v2 训练参数合理性评估

> 评估日期：2026-06-11
> 基于代码库 `ppo_v2/src/ppo_antwar/` 全量扫描，结合 PPO 论文（Schulman et al., 2017）及工程实践经验。

---

## 一、评估框架

| 等级 | 含义 | 标准 |
|------|------|------|
| **A级** | 最佳实践范围内 | 参数值在 PPO 论文推荐值或主流框架（SB3、CleanRL、TorchRL）默认值范围内，无需调整 |
| **B级** | 可接受，有小幅优化空间 | 参数值偏离最佳实践但仍在合理区间，可能在特定场景下有效，建议观察训练指标后决定是否微调 |
| **C级** | 偏离最佳实践，建议调整 | 参数值明显偏离公认范围，可能导致训练效率下降或收敛困难，建议优先调整 |
| **D级** | 明显不合理，需优先修复 | 参数值严重偏离最佳实践，很可能导致训练失败或性能显著劣化，必须优先修复 |

## 二、PPO 核心算法参数

### 2.1 lr（策略学习率）

| 项目 | 内容 |
|------|------|
| **当前值** | 0.0005 (5e-4) |
| **作用** | 策略网络 Adam 优化器学习率，控制策略参数更新步长 |
| **理论合理范围** | 2.5e-4 ~ 5e-4（PPO 论文推荐 3e-4，SB3 默认 3e-4，CleanRL 默认 2.5e-4） |
| **分级** | **B级** |
| **评估理由** | 5e-4 略高于 PPO 论文推荐的 3e-4，但在合理范围内。配合 cosine decay 调度，实际平均学习率会低于初始值。对于 AntWar 这种具有 119 维结构化动作空间的复杂任务，稍高的学习率有助于加速初期收敛。需关注 `approx_kl` 指标，若频繁触发 target_kl 早停，说明学习率偏高。 |
| **建议** | 可保持当前值，若训练中出现 KL 散度频繁超限，降至 3e-4 |

### 2.2 lr_vf（价值学习率）

| 项目 | 内容 |
|------|------|
| **当前值** | 0.00025 (2.5e-4) |
| **作用** | 价值网络 Adam 优化器学习率，控制价值函数参数更新步长 |
| **理论合理范围** | 1e-4 ~ 1e-3（通常与策略学习率持平或更高） |
| **分级** | **C级** |
| **评估理由** | 价值学习率仅为策略学习率的一半（0.5x），这在 PPO 实践中是反直觉的。价值函数需要比策略更快收敛以提供准确的优势估计（GAE 依赖 V(s) 的准确性）。主流实现中，价值学习率通常 ≥ 策略学习率（SB3 使用同一学习率，某些实现中价值学习率甚至更高）。当前设置会导致价值函数收敛滞后，使 GAE 优势估计偏差较大，进而影响策略更新质量。 |
| **建议** | 将 lr_vf 提升至与 lr 相同（5e-4）或更高（1e-3），确保价值函数能快速跟上策略变化 |

### 2.3 gamma（折扣因子）

| 项目 | 内容 |
|------|------|
| **当前值** | 0.99 |
| **作用** | 折扣因子，控制未来奖励的衰减速率。γ=0.99 意味着 100 步后的奖励权重为 0.99^100≈0.37 |
| **理论合理范围** | 0.99 ~ 0.999（回合制策略游戏） |
| **分级** | **A级** |
| **评估理由** | 0.99 是 PPO 最标准的折扣因子。AntWar 回合数通常在 50-200 之间，0.99^100≈0.37，远期奖励仍有合理权重，适合需要长期规划的策略游戏。 |
| **建议** | 无需调整 |

### 2.4 gae_lambda（GAE 参数）

| 项目 | 内容 |
|------|------|
| **当前值** | 0.95 |
| **作用** | GAE（Generalized Advantage Estimation）的 λ 参数，平衡优势估计的偏差与方差。λ=1 为蒙特卡洛估计（低偏差高方差），λ=0 为 TD(0)（高偏差低方差） |
| **理论合理范围** | 0.90 ~ 0.98（PPO 论文推荐 0.95） |
| **分级** | **A级** |
| **评估理由** | 0.95 是 PPO 论文的标准推荐值，也是所有主流框架的默认值。在偏差-方差之间取得了良好平衡。 |
| **建议** | 无需调整 |

### 2.5 clip_eps（策略裁剪范围）

| 项目 | 内容 |
|------|------|
| **当前值** | 0.15 |
| **作用** | PPO 策略裁剪参数 ε，限制新旧策略的概率比在 [1-ε, 1+ε] 范围内，防止策略更新过大 |
| **理论合理范围** | 0.1 ~ 0.3（PPO 论文推荐 0.2） |
| **分级** | **A级** |
| **评估理由** | 0.15 比论文标准值 0.2 更保守，对于 AntWar 这种具有结构化动作头的复杂策略空间，稍紧的裁剪有助于防止策略突变。配合 target_kl=0.05 的早停机制，形成了双重保护。可通过 `clip_fraction` 指标验证：若 clip_fraction 长期接近 0，说明裁剪过紧；若持续 >0.3，说明裁剪过松。 |
| **建议** | 无需调整，观察 clip_fraction 指标 |

### 2.6 clip_eps_vf（价值裁剪范围）

| 项目 | 内容 |
|------|------|
| **当前值** | 0.2 |
| **作用** | 价值函数裁剪参数，限制价值预测的变化幅度：V_new = V_old + clip(V_new - V_old, -ε, ε) |
| **理论合理范围** | 0.1 ~ 0.4（通常与 clip_eps 相同或更大） |
| **分级** | **A级** |
| **评估理由** | 0.2 是价值裁剪的标准值，与 PPO 论文一致。价值函数比策略函数更容忍较大的更新步长，0.2 是合理的。 |
| **建议** | 无需调整 |

### 2.7 ent_coef（熵系数）

| 项目 | 内容 |
|------|------|
| **当前值** | 0.1 |
| **作用** | 策略熵正则化系数，鼓励策略保持探索性。损失函数中添加 -ent_coef × entropy 项 |
| **理论合理范围** | 0.001 ~ 0.05（PPO 论文推荐 0.01，SB3 默认 0.0，CleanRL 默认 0.01） |
| **分级** | **C级** |
| **评估理由** | 0.1 远高于 PPO 论文推荐的 0.01 和主流框架的默认值（0.001~0.05）。虽然 AntWar 有 119 维动作空间需要较强的探索，但 0.1 的熵系数会过度鼓励随机行为，导致策略难以收敛到确定性策略。更关键的是，当前系统同时使用了三种探索机制（熵正则 + ε-greedy + logit噪声），熵系数过高会加剧探索冗余问题。可通过 `entropy` 指标监控：若训练后期熵值仍居高不下，说明探索过强。 |
| **建议** | 降至 0.01~0.03，与 logit_noise_std 和 exploration_epsilon 协同调整（详见跨参数分析） |

### 2.8 exploration_epsilon（ε-贪心探索率）

| 项目 | 内容 |
|------|------|
| **当前值** | 0.05 |
| **作用** | ε-贪心探索概率，每步有 5% 概率随机选择合法动作 |
| **理论合理范围** | 0.0 ~ 0.1（PPO 通常不使用 ε-贪心，DQN 中常用 0.1 并衰减） |
| **分级** | **B级** |
| **评估理由** | PPO 本身通过熵正则化实现探索，额外添加 ε-贪心并非标准做法。但在结构化动作空间中，ε-贪心可以确保所有动作类型都被尝试，避免某些动作类型被完全忽略。5% 的概率相对温和。然而，与 ent_coef=0.1 和 logit_noise_std=0.2 叠加，总探索量可能过高。 |
| **建议** | 保留但降至 0.02~0.03，或考虑在训练后期衰减到 0 |

### 2.9 logit_noise_std（logit 高斯噪声标准差）

| 项目 | 内容 |
|------|------|
| **当前值** | 0.2 |
| **作用** | 训练时在类型选择 logits 上添加高斯噪声 N(0, 0.2²)，增强探索多样性 |
| **理论合理范围** | 0.0 ~ 0.1（非标准 PPO 技术，类似 NoisyNet 但更简单） |
| **分级** | **C级** |
| **评估理由** | logit 噪声是第三种探索机制。0.2 的标准差对于 softmax 输入来说相当大——logits 的典型范围在 [-5, 5]，0.2 的噪声可以显著改变概率分布。更重要的是，三种探索机制（熵正则 + ε-贪心 + logit噪声）同时使用是冗余的，且缺乏理论保证。logit 噪声还会导致 on-policy 数据收集时的策略与 PPO 更新时的策略不一致（噪声在 get_action 时添加但 evaluate_actions 时不添加），可能违反 PPO 的 on-policy 假设。 |
| **建议** | 降至 0.05~0.1，或完全移除，依赖熵正则化提供足够的探索 |

### 2.10 vf_coef（价值损失系数）

| 项目 | 内容 |
|------|------|
| **当前值** | 0.05 |
| **作用** | 价值函数损失在总损失中的权重。总损失 = policy_loss + vf_coef × value_loss - ent_coef × entropy |
| **理论合理范围** | 0.25 ~ 1.0（PPO 论文隐含 0.5，SB3 默认 0.5，CleanRL 默认 0.5） |
| **分级** | **D级** |
| **评估理由** | 这是当前配置中最严重的问题。vf_coef=0.05 意味着价值损失仅贡献总损失的 5%，导致价值函数参数的梯度被严重抑制。由于代码使用 `total_loss.backward()` 统一反向传播（而非分别对策略和价值损失做反向传播），价值参数实际接收的梯度为 `0.05 × ∂value_loss/∂θ_v`，即使 max_grad_norm_vf=50.0 也无法有效补偿——梯度在反向传播时已经被缩放，裁剪阈值再高也无法放大已缩小的梯度。价值函数收敛缓慢会直接导致 GAE 优势估计不准确，进而影响策略更新质量。可通过 `value_loss` 和 `td_error_mean` 指标验证：若 value_loss 长期不降或 td_error 偏大，说明价值函数学习不足。 |
| **建议** | **优先修复**。将 vf_coef 提升至 0.5（PPO 标准值），同时将 max_grad_norm_vf 降至 5.0~10.0 |

### 2.11 max_grad_norm（策略梯度裁剪阈值）

| 项目 | 内容 |
|------|------|
| **当前值** | 2.5 |
| **作用** | 策略网络梯度范数裁剪阈值，防止梯度爆炸 |
| **理论合理范围** | 0.5 ~ 5.0（SB3 默认 0.5，CleanRL 默认 0.5，但较大网络常用 1.0~5.0） |
| **分级** | **A级** |
| **评估理由** | 2.5 对于 AntWar 的网络规模（hidden_dim=256，含 CNN+MLP 双编码器）是合理的。比 SB3 的 0.5 更宽松，但对于复杂网络是必要的，因为更深的网络通常有更大的梯度范数。可通过 `grad_norm_policy` 指标验证：若经常被裁剪到 2.5，说明阈值偏低。 |
| **建议** | 无需调整 |

### 2.12 max_grad_norm_vf（价值梯度裁剪阈值）

| 项目 | 内容 |
|------|------|
| **当前值** | 50.0 |
| **作用** | 价值网络梯度范数裁剪阈值 |
| **理论合理范围** | 0.5 ~ 10.0（通常与策略梯度裁剪阈值相近或略大） |
| **分级** | **C级** |
| **评估理由** | 50.0 是策略梯度裁剪阈值的 20 倍，这在 PPO 实践中极不寻常。这个异常高的值很可能是为了补偿 vf_coef=0.05 导致的价值梯度被过度缩放——但这是治标不治本的做法。即使裁剪阈值设为 50，由于 `total_loss.backward()` 中价值损失的梯度已经被乘以 0.05，实际到达价值参数的梯度仍然很小。正确做法是提高 vf_coef 并降低此阈值。 |
| **建议** | 配合 vf_coef 调整至 0.5 后，将此值降至 5.0~10.0 |

### 2.13 ppo_epochs（PPO 更新轮数）

| 项目 | 内容 |
|------|------|
| **当前值** | 2 |
| **作用** | 每批数据上执行 PPO 更新的轮数。更多轮数提高数据利用率但增加策略偏移风险 |
| **理论合理范围** | 3 ~ 10（PPO 论文推荐 3-4，SB3 默认 10 但配合 early stopping） |
| **分级** | **B级** |
| **评估理由** | 2 轮偏少，数据利用率较低。但配合 target_kl=0.05 的早停机制，即使设为 3-4 轮也可能在 2 轮内就触发早停。2 轮的优势是策略偏移风险最小，适合自对弈场景中保持策略稳定性。若 `approx_kl` 指标显示 KL 散度远低于 target_kl，说明可以增加轮数。 |
| **建议** | 可提升至 3-4，依赖 target_kl 早停机制控制策略偏移 |

### 2.14 batch_size（minibatch 大小）

| 项目 | 内容 |
|------|------|
| **当前值** | 1024 |
| **作用** | PPO 更新时每个 minibatch 的样本数。每次 PPO update 将总样本按此大小切分为多个 minibatch |
| **理论合理范围** | 256 ~ 4096（取决于总样本量和 GPU 显存） |
| **分级** | **A级** |
| **评估理由** | 1024 是合理的 minibatch 大小。以 n_envs=20、max_steps=512 估算，每次 PPO update 的总样本量约 20×200=4000 步（假设平均 200 步/局），1024 的 minibatch 会产生约 4 个 minibatch，梯度估计稳定。 |
| **建议** | 无需调整 |

### 2.15 target_kl（目标 KL 散度）

| 项目 | 内容 |
|------|------|
| **当前值** | 0.05 |
| **作用** | 近似 KL 散度的早停阈值。当一个 epoch 内的平均 KL 散度超过此值时，停止后续 epoch |
| **理论合理范围** | 0.01 ~ 0.1（PPO 实践中常用 0.015~0.05） |
| **分级** | **A级** |
| **评估理由** | 0.05 是合理的早停阈值，在策略更新幅度和数据利用率之间取得了良好平衡。可通过 `approx_kl` 指标监控实际 KL 散度。 |
| **建议** | 无需调整 |

### 2.16 lr_cosine_decay（学习率余弦衰减）

| 项目 | 内容 |
|------|------|
| **当前值** | true |
| **作用** | 启用余弦退火学习率调度，学习率从初始值平滑衰减到接近 0 |
| **理论合理范围** | true / false |
| **分级** | **A级** |
| **评估理由** | 余弦衰减是 PPO 训练中常用的学习率调度策略，有助于训练后期稳定收敛。实现正确（`LRScheduler` 中 `(1 + cos(π × progress)) / 2` 公式）。 |
| **建议** | 无需调整 |

## 三、辅助任务参数

### 3.1 enable_auxiliary（辅助任务开关）

| 项目 | 内容 |
|------|------|
| **当前值** | true |
| **作用** | 启用辅助任务头（塔伤害、金币收入、基地伤害预测），为编码器提供额外学习信号 |
| **理论合理范围** | true（推荐） |
| **分级** | **A级** |
| **评估理由** | 辅助任务是提升表征学习质量的有效手段（类似 AlphaGo 的价值头和 AlphaZero 的额外头）。AntWar 的辅助任务（预测未来塔伤害、金币收入、基地伤害）直接关联游戏核心机制，有助于编码器学习有意义的特征。同时为策略和价值编码器各配备独立的辅助头，设计合理。 |
| **建议** | 无需调整 |

### 3.2 辅助损失系数组

| 参数 | 当前值 | 分级 | 评估 |
|------|--------|------|------|
| aux_tower_coef | 0.005 | **B级** | 己方塔伤害预测系数。0.005 足够小不会干扰主损失，但能提供有效梯度信号。可通过 `aux_tower_loss` 指标验证损失是否在下降 |
| aux_gold_coef | 0.001 | **B级** | 己方金币收入预测系数。比塔伤害系数更小，合理——金币预测的 MSE 通常比塔伤害更小，不需要太大系数 |
| aux_enemy_tower_coef | 0.005 | **B级** | 敌方塔伤害预测系数。与己方相同，合理 |
| aux_enemy_gold_coef | 0.001 | **B级** | 敌方金币收入预测系数。与己方相同，合理 |
| aux_base_dmg_coef | 0.0003 | **B级** | 己方基地伤害预测系数。极小值，说明基地伤害预测的梯度信号较弱，可能是因为基地伤害事件稀少 |
| aux_enemy_base_dmg_coef | 0.01 | **B级** | 敌方基地伤害预测系数。是己方的 33 倍，这个不对称设计有意为之——预测敌方基地伤害（即己方进攻效果）对策略学习更有价值，更大的系数强调这一信号 |

**总体评估**：辅助损失系数整体偏小但合理。辅助任务的作用是提供额外的表征学习信号，而非主导训练。建议关注 `aux_*_loss` 指标，若损失长期不降，可适当增大系数。

## 四、数值安全参数（clip_values）

| 参数 | 当前值 | 分级 | 评估 |
|------|--------|------|------|
| logits_min/max | -20 / 20 | **A级** | 合理的 logit 裁剪范围，防止数值溢出。softmax(20) ≈ 1.0，softmax(-20) ≈ 0 |
| values_min/max | -500 / 500 | **A级** | 价值范围足够宽。AntWar 单局奖励约 [-50, 50]，γ=0.99 下 V(s) 不会超过 ±500 |
| returns_min/max | -1e6 / 1e6 | **B级** | 范围极宽，实际上等于不裁剪。GAE 计算的 returns 通常在 [-200, 200] 内，可收紧至 ±1000 |
| advantages_min/max | -1e4 / 1e4 | **B级** | 范围过宽。归一化后优势通常在 [-3, 3] 内，归一化前也极少超过 ±100。可收紧至 ±1000 |
| prob_min | 1e-10 | **A级** | 标准的最小概率值，防止 log(0) |
| ratio_min/max | 1e-5 / 10.0 | **C级** | 下界 1e-5 过松。ratio=1e-5 意味着新策略认为某动作的概率是旧策略的十万分之一，这在 clip_eps=0.15 的框架下不应出现。过松的下界可能导致 log_ratio 计算出现极端值（log(1e-5)≈-11.5）。建议收紧至 0.01 / 10.0 |
| loss_max | 1e6 | **B级** | 阈值很高，正常训练中 loss 不应超过 1000。可收紧至 1e4 |
| nan_threshold | 5 | **A级** | 连续 5 次 NaN 触发恢复机制，合理。既不会因偶发 NaN 过早停止，也不会让 NaN 持续恶化 |

## 五、训练循环参数

### 5.1 total_episodes（总训练局数）

| 项目 | 内容 |
|------|------|
| **当前值** | 2000 |
| **作用** | 训练总 episode 数，每 episode 为一局完整对战 |
| **理论合理范围** | 10000 ~ 100000（自对弈训练） |
| **分级** | **C级** |
| **评估理由** | 2000 局对于自对弈训练来说明显不足。参考 AlphaZero 和 OpenAI Five 的经验，自对弈需要大量对局才能实现策略进化。2000 局意味着：仅产生约 20 个对手快照（每 100 局一个），每个对手平均只被对战约 100 次，策略进化空间有限。对于 AntWar 这种具有 119 维动作空间的复杂策略游戏，2000 局可能仅够完成初期探索，远未达到策略收敛。 |
| **建议** | 提升至 10000~50000，配合更频繁的对手更新（如每 50 局） |

### 5.2 save_interval（检查点保存间隔）

| 项目 | 内容 |
|------|------|
| **当前值** | 20 |
| **作用** | 每 20 个 episode 保存一次模型检查点 |
| **理论合理范围** | 10 ~ 100 |
| **分级** | **A级** |
| **评估理由** | 20 局保存一次是合理的频率，既不会丢失太多进度，也不会产生过多检查点（配合 keep_last_n=5 的清理策略）。 |
| **建议** | 无需调整 |

### 5.3 opponent_update_interval（对手更新间隔）

| 项目 | 内容 |
|------|------|
| **当前值** | 100 |
| **作用** | 每 100 个 episode 将当前策略快照添加到对手池 |
| **理论合理范围** | 50 ~ 200 |
| **分级** | **B级** |
| **评估理由** | 100 局更新一次对手是合理的。但若 total_episodes 提升至 10000+，可考虑缩短至 50 局，使对手池中的策略多样性更高。当前设置下，2000 局训练会产生约 20 个对手快照，但对手池大小限制为 10，会触发淘汰。 |

## 九、跨参数交互分析

### 9.1 三重探索冗余（关键问题）

当前系统同时使用三种探索机制：

| 机制 | 参数 | 强度 |
|------|------|------|
| 熵正则化 | ent_coef=0.1 | 高（远超标准值 0.01） |
| ε-贪心 | exploration_epsilon=0.05 | 中 |
| Logit 噪声 | logit_noise_std=0.2 | 高 |

**问题**：三重探索叠加导致总探索量过高，策略难以收敛到确定性策略。此外，logit 噪声在数据收集时添加但 PPO 更新时不存在，违反了 on-policy 算法的行为策略与更新策略一致性假设。

**建议方案**：
- **方案 A（保守）**：ent_coef 降至 0.02，logit_noise_std 降至 0.05，exploration_epsilon 保持 0.05
- **方案 B（推荐）**：ent_coef 降至 0.01，移除 logit_noise_std（设为 0），exploration_epsilon 降至 0.02
- **方案 C（激进）**：ent_coef 降至 0.01，移除 logit_noise_std 和 exploration_epsilon，纯依赖熵正则

### 9.2 价值函数学习不足（关键问题）

vf_coef=0.05 与 max_grad_norm_vf=50.0 的组合存在根本性问题：

```
价值参数实际梯度 = 0.05 × ∂value_loss/∂θ_v
                  ↓
              被 clip 到 max_norm=50.0
                  ↓
              有效更新 ≈ 0.05 × 原始梯度（远小于应有的更新量）
```

**影响链**：价值函数收敛慢 → GAE 优势估计偏差大 → 策略更新方向不准确 → 训练效率下降

**建议**：vf_coef 提升至 0.5，max_grad_norm_vf 降至 5.0~10.0

### 9.3 训练量与评估开销失衡

| 项目 | 数量 |
|------|------|
| 训练对局 | 2000 局 |
| 评估对局 | 100 局/次 × (2000/20) = 10,000 局 |
| 评估/训练比 | 5:1 |

评估开销是训练的 5 倍，严重拖慢训练速度。且 2000 局训练量对自对弈来说不足。

**建议**：total_episodes 提升至 10000+，battle_interval 提升至 50~100

### 9.4 学习率与价值学习率比例

当前 lr:lr_vf = 2:1（策略学习率是价值的 2 倍），而标准做法是 lr:lr_vf = 1:1 或 1:2（价值学习率 ≥ 策略学习率）。

**建议**：lr_vf ≥ lr，例如 lr=3e-4, lr_vf=5e-4
