# PPO v1 SelfPlay 策略退化研究报告

> 基于 Episode 36-72 共 37 局 SelfPlay 对战日志的全面分析，以及源码审查。

---

## 1. 退化现象概要

| 区间 | Episodes | 胜负 | Agent 动作模式 |
|:---|:---:|:---|:---|
| **36-40** | 5 局 | 2 win / 3 loss | NO-OP 79~88%；有 BUILD + 少量 UPGRADE |
| **41-46** | 6 局 | 3 win / 3 loss | NO-OP 80~87%；BUILD 集中在少数位置 |
| **47-48** | 2 局 | 2 win | NO-OP ~79%；仍有 BUILD 行为 |
| **49-72** | 24 局 | **全部 loss** | **100% NO-OP**，金币累积至 800+ 从未消耗 |

退化过程呈现出**相变特征**：
- Ep36-46：策略正常，建塔/升级/偶尔超武
- Ep47-48：过渡期，策略开始摇摆
- Ep49-72：完全坍缩，100% NO-OP，不再有任何有效动作

## 2. 退化原因分析框架

按照三类主因 + 一个补充类别的框架分析：

| 类别 | 描述 | 严重程度 |
|:---|:---|---:|
| (1) **奖励系统** | 奖励设计 + gamma 折现导致 NO-OP 在数学上"看似不差" | 🔴 核心原因 |
| (2) **PPO 参数** | 超参组合产生协同负面效应 | 🔴 重要诱因 |
| (3) **网络/代码 Bug** | 是否存在导致表达受限的缺陷 | 🟢 无 Bug |
| (4) **训练范式** | SelfPlay 正反馈循环（补充类别） | 🔴 关键放大器 |

## 3. 类别 (1)：奖励系统分析

### 3.1 奖励系统架构（两层）

```
每步奖励 = action_reward + round_reward

action_reward:  动作即时奖励（建塔/升级/NO-OP惩罚等）
round_reward:   回合末结算（HP伤害、金币、塔存活、科技、死亡、终局）
```

所有超参定义在 `action_constants.py:REWARD_CONFIG` 和 `action_constants.py:TYPE_CONFIG` 中，具体计算在 `antwar_env.py:_resolve_turn_from_ops()` 和 `_compute_action_reward()`。

### 3.2 NO-OP 行为的奖励估算

以 250 回合满回合为例，假设纯 NO-OP：

| 奖励分量 | 计算公式 | 250 回合总值 |
|:---|---:|---:|
| NO-OP 惩罚 | 第 4 步起 -0.005/步，每 10 步递增，最大 -0.10 | **-8** |
| 己方金币收入 | 初始 50 + 每 2 回合收入 3，总计 ~425 金币 × 0.02 | **+8.5** |
| 塔存活 | 不建塔，0 座 | **0** |
| HP 伤害（对敌） | 自动蚂蚁缓慢啃咬，约 40-49 HP × 0.3 | **+12 ~ +15** |
| HP 损失（己方） | 同样被敌方蚂蚁打，约 40-49 HP × 0.3 | **-12 ~ -15** |
| 科技奖励 | 0（不升级） | **0** |
| 蚂蚁死亡惩罚 | 约 100 只蚂蚁死亡 × -0.05 | **-5** |
| 终局奖励 | SelfPlay 下胜负约各半，+100 和 -100 期望 ≈ 0 | **≈ 0** |
| **合计** | | **-4 ~ +11** |

**关键发现**：在不考虑终局奖励时，NO-OP 行为的每回合小奖励总和是一个**轻微正或接近零的数**。这意味着 NO-OP 行为本身在数学上**并不被显著惩罚**。

### 3.3 建塔行为的奖励估算

假设建 3 座塔，存活约 150 回合：

| 奖励分量 | 250 回合总值 |
|:---|---:|
| 建塔即时奖励（递减） | 0.6 + 0.5 + 0.5 = **+1.6** |
| 建塔金币机会成本 | (15+30+45) 金币 × 0.02 金币奖励 = **-1.8** |
| NO-OP 惩罚节省 | 约 **+5** |
| 塔存活奖励（3 塔 × 0.20 × 150 回合） | **+90** |
| HP 防御效果 | 约 **+3 ~ +6** |
| 终局奖励提升 | 略高 |
| **合计** | **~ +99** |

建塔在数学上的累积奖励**远高于** NO-OP。问题出在折现因子上。

### 3.4 gamma=0.95 折现效应

```
gamma^250 = 0.95^250 ≈ 2.7 × 10⁻⁶ ≈ 0
```

这意味着终局的 +100/-100 奖励信号经过 250 步折现后**完全消失**，PPO 的梯度更新几乎无法从这个信号学到任何东西。

GAE 的有效 horizon 约为：

```
有效 horizon ≈ 1 / (1 - gamma×lambda) ≈ 1 / (1 - 0.85) ≈ 6.7 步
```

Agent 实际上只能感知未来约 7 步内的奖励。远期塔存活奖励（第 10~150 回合的累积 +90）在 gamma 折现下的等效贡献约为：

```
折现后的塔存活奖励 ≈ 0.20 × Σγ^t (t=0 to horizon) ≈ 0.20 × 6.7 ≈ 1.34
```

最终对比（折现后）：

| 策略 | 折现后感知奖励 |
|:---|---:|
| NO-OP | ~+4 |
| 建塔 | ~+6 |

**在模型感知到的信号中，NO-OP 和建塔的差距极其微弱。** 在这种模糊的信号下，策略随机漂移到 NO-OP 并不令人意外。

### 3.5 建塔奖励衰减问题

`build_tower_tiers = [0.6, 0.5, 0.5, 0.3, 0.3, 0.3, 0.1]`

如果 Agent 在同一塔位反复建塔（建了被打掉、再建），第三次之后即时奖励就降到 0.3 以下。从 review 数据看，塔的"建了又丢、丢了又建"正是常态（建塔和失塔次数高度匹配）。

这意味着：**建塔的即时奖励在反复争夺的塔位上快速衰减，而 NO-OP 的惩罚是固定的低值**，进一步缩小了两者的感知差距。

### 3.6 NO-OP 惩罚分析

当前规则：
- 容忍前 3 次连续 NO-OP
- 第 4 次起：`penalty = max(-0.005 - 0.005 × ((n-3)//10), -0.10)`
- 250 步连续 NO-OP 的总惩罚：约 **-8**

相比之下，单次建塔的即时奖励就是 +0.6。**连续 120 步 NO-OP 的惩罚才等于一次建塔的奖励**。这个惩罚强度对引导策略远离 NO-OP 是不足的。

### 3.7 奖励系统小结

| 问题 | 影响 |
|:---|:---|
| gamma=0.95 远期折现近于零 | 终局 +100/-100 信号丢失；建塔远期收益无法传递到当前决策 |
| NO-OP 惩罚过弱 | 250 步连续 NO-OP 总惩罚仅 -8，不足以产生厌恶 |
| 建塔奖励衰减过快 | 反复争夺的塔位上，建塔即时奖励快速降到 0.1 |
| 技术升级/超武等动作无独立引导信号 | Agent 从未探索这些动作 |

## 4. 类别 (2)：PPO 参数分析

### 4.1 当前参数

| 参数 | 当前值 | 标准 PPO 常用值 | 问题 |
|:---|:---:|:---:|:---|
| gamma | **0.95** | 0.99~0.999 | 对长 horizon 任务太低 |
| gae_lambda | 0.90 | 0.95 | 尚可 |
| ppo_epochs | **1** | 4~10 | 数据利用效率极低 |
| clip_eps | 0.15 | 0.1~0.2 | 尚可 |
| ent_coef 起始 | 0.2 | 0.01~0.1 | 偏高 |
| ent_coef 终值 | 0.02 | 0.001~0.01 | 尚可 |
| learning_rate | 1e-4 | 1e-4~3e-4 | 正常 |
| batch_size | 512 | 可接受 | 正常 |
| max_grad_norm | 1.0 | 0.5~1.0 | 正常 |

### 4.2 关键参数的协同负面效应

```
gamma=0.95（短视）
    → 远期奖励信号弱
    → ppo_epochs=1（利用不足）
        → 策略更新幅度小
        → entropy 退火速度快
            → 策略坍缩到局部最优（NO-OP）
            → SelfPlay 中 NO-OP vs NO-OP 胜负各半
                → 无外部纠正信号（self-consistency）
                → 退化被巩固
```

### 4.3 gamma 参数问题的量化

| gamma | γ^250 | 有效 horizon (1/(1-γ)) | 意义 |
|:---:|:---:|:---:|:---|
| 0.95 | 2.7×10⁻⁶ | 20 步 | 终局信号完全丢失 |
| 0.99 | 0.081 | 100 步 | 终局信号部分保留 |
| 0.995 | 0.286 | 200 步 | 终局信号基本保留 |
| 0.999 | 0.779 | 1000 步 | 终局信号充分保留 |

### 4.4 ppo_epochs=1 的影响

标准 PPO 的核心优势之一是**重要性采样 + 多次利用**——用同一个数据 batch 多轮更新，提升数据效率。`ppo_epochs=1` 相当于放弃了这一核心优势，使得每个环境 step 产生的数据只能对策略产生一次影响。

对于 250 步的 long horizon 任务，在早期探索阶段，如果好的动作序列（如建塔）只被学习了一次就被新数据覆盖，策略很难收敛到正确的方向。

### 4.5 评估频率问题

训练配置：`battle_interval: 20, n_battles: 4`

即每隔 20 个训练 episode 才与 baseline agents（BasicTowerAI 等）进行 4 局对战来评估。退化发生在约 3-4 个 opponent_update_interval（60-80 episode）内。

**在退化窗口期间，模型评估次数太少（仅 3-4 次，每次 4 局），不足以在退化初期就捕获并纠正问题。** 一旦 selfplay 的内部对手池也全部是 NO-OP 策略，评估对战就失去了检测退化的能力。

### 4.6 PPO 参数小结

| 问题 | 影响 |
|:---|:---|
| gamma=0.95 过低 | 长期策略价值无法学习，短期 NO-OP 的"舒适"被高估 |
| ppo_epochs=1 | PPO 核心优势未发挥，数据效率低 |
| 评估频率不足 | 退化发生后才被发现，错过干预窗口 |

### 5.2 发现的设计缺陷（非 Bug）

**缺陷 1：建塔奖励衰减过快**

`build_tower_tiers = [0.6, 0.5, 0.5, 0.3, 0.3, 0.3, 0.1]`

问题在于：建塔奖励按**同一 tower_slot** 的历史计数递减，而不是按塔的存活时间或累计贡献。一个塔位如果反复被打掉重建，Agent 每次只能拿到递减后的微小奖励，即使重建后该塔可能存活很久。

**缺陷 2：拆塔惩罚 (downgrade_tower_penalty: -3.15) 前 1000 回合不可用**

在 `action_mask.py` 中，downgrade_tower 动作在前 1000 回合被禁用。这原本是保护机制，但也意味着 Agent 永远无法通过拆塔来学习"重新规划"的策略。

**缺陷 3：技术升级奖励高但从未触及**

- `upgrade_gen_speed`: 一级 +1.0，二级 +0.8（所有动作奖励中最高的）
- `upgrade_gen_ant`: 一级 +0.5，二级 +0.1

但这些动作 Agent 从未执行过。说明：**动作探索在早期就已失败**，Agent 从未走出 NO-OP 的局部区域去触及这些高奖励动作。这不是奖励设计的问题，而是探索初始化的问题。

### 5.3 Bug 检查结论

**未发现导致退化的代码 Bug。** 网络结构设计合理（HexCNN 六边形卷积、分层 ActionHead、双 clip 价值损失等），奖励计算正确，训练循环逻辑完整。退化是由奖励参数、PPO 参数、训练范式的综合效应导致的，而非代码缺陷。

## 6. 类别 (4)：SelfPlay 正反馈循环（补充分析）

这是我认为退化**从"可能"变成"必然"**的关键因素。

### 6.1 退化循环

```
[初始] 策略有探索，偶尔建塔
    ↓
[反馈] 建塔 → 塔被打掉 → 建塔递减奖励 → 净收益下降
    ↓
[漂移] 策略在"建塔"和"NO-OP"之间徘徊
    ↓
[SelfPlay] 对手也是自己 → 两种模式胜率接近 → 无选择压力
    ↓
[坍缩] NO-OP 占据主导 → value function 学会预测 NO-OP 的价值
    ↓
[锁定] policy logits 被 value 信号打压 → 完全锁定 NO-OP
    ↓
[自我巩固] 对手池内所有 Agent 都是 NO-OP → 无可比差异
```

### 6.2 "相变"机制

从数据观察到的过渡模式符合相变特征：

| 阶段 | Episodes | 特征 | 驱动因素 |
|:---|:---:|:---|:---|
| 正常 | 36-46 | 有 BUILD、UPGRADE，动作多样性 | 探索仍在起作用 |
| 过渡 | 47-48 | BUILD 比例下降，动作多样性减少 | 建塔衰减 + gamma 短视开始主导 |
| 坍缩 | 49-72 | 100% NO-OP | selfplay 自我巩固，无外部纠正 |

一旦进入坍缩阶段，selfplay 机制**无法自我纠正**——因为对手也是同一个网络的旧版本，同样输出 NO-OP。需要外部信号（如与不同对手的混合训练、higher baseline 评估频率）才能打破循环。

### 6.3 对比：为什么不是所有 SelfPlay 都会坍缩？

典型的 SelfPlay 成功案例（如 AlphaGo/AlphaZero）中，有以下几点与本实现不同：

| 因素 | 本实现 | 成功的 SelfPlay 系统 |
|:---|:---|:---|
| gamma | 0.95 | 通常 0.997+ |
| 对手多样性 | 仅自己的旧版本 | 混合历史版本 + 多样性采样 |
| 探索噪声 | logit_noise + epsilon | 更强的 Dirichlet 噪声 |
| 评估频率 | 每 20 ep 4 局 | 持续的 holdout 评估 |
| 奖励稀疏度 | 密集，但远期信号弱 | 稀疏但 gamma 充分保留远期信号 |

## 7. 综合结论

### 7.1 根因排序

| 排名 | 原因 | 类别 | 贡献度 |
|:---:|:---|:---|:---:|
| **1** | **SelfPlay 正反馈循环** — NO-OP 打 NO-OP → 50%胜率 → 无外部选择压力 → 退化自我巩固 | 训练范式 | 🔴 关键 |
| **2** | **gamma=0.95** 远期折现 — 终局 +100/-100 信号折现后接近于零，建塔远期收益无法传递 | PPO 参数 | 🔴 关键 |
| **3** | **NO-OP 惩罚过弱** — 250 步总惩罚仅 -8，远不及其它动作的机会成本 | 奖励设计 | 🟡 重要 |
| **4** | **ppo_epochs=1** — PPO 核心优势（数据多次利用）未被发挥 | PPO 参数 | 🟡 重要 |
| **5** | **建塔奖励衰减过快** — 反复争夺的塔位上即时奖励快速降到 0.1 | 奖励设计 | 🟢 次要 |
| **6** | **评估频率不足** — 退化后才被发现，错过干预窗口 | 训练范式 | 🟢 次要 |

### 7.2 修复方向建议

| 优先级 | 方向 | 预期的改善效果 |
|:---:|:---|---:|
| P0 | `gamma: 0.95 → 0.99` 或 `0.995` | 远期信号可传递到近 100-200 步，建塔和终局的收益可被学习 |
| P0 | 增加对手多样性：对手池中混合 baseline agents + 早期存档 | 打破 SelfPlay 自我巩固循环，提供不同策略的对比信号 |
| P1 | 提高 NO-OP 惩罚：`noop_base_penalty: -0.005 → -0.03`，`noop_max_penalty: -0.10 → -0.30` | 增加 NO-OP 的厌恶度 |
| P1 | `ppo_epochs: 1 → 4` | 提升数据利用率，让好的探索经验被充分学习 |
| P2 | 评估频率提升：`battle_interval: 20 → 5` | 早期发现退化 |
| P2 | 建塔奖励衰减改为基于存活时间而非同一槽位计数 | 奖励重建行为 |
| P3 | 提高 `logit_noise_std: 0.2 → 0.5` 或熵系数 | 增加探索力度 |
