本文档描述一次**理想**的 AntWar PPO + SelfPlay 训练过程应该表现出的特征。这些特征可作为训练监控的"体检清单"——在每个训练阶段，对照检查当前指标是否在健康范围内，以及是否朝着正确的方向演进。

---

## 1. 总体训练曲线特征

### 1.1 奖励曲线

```
avg_reward
  ^
  |                                          ┌──────────────────
  |                                   ┌──────┘  (3) 高位震荡
  |                            ┌──────┘
  |                     ┌──────┘
  |              ┌──────┘  (2) 加速增长
  |       ┌──────┘
  |───────┘  (1) 缓慢起步
  |
  +──────────────────────────────────────────────────────────> episodes
```

| 阶段 | 大致 episode 范围 | 奖励特征 | 说明 |
|------|:---:|------|------|
| **(1) 缓慢起步** | 0 ~ 200 | 奖励在 0 附近波动，增长缓慢 | 策略网络在随机探索，偶尔撞到正向事件（击杀蚂蚁、到达基地）|
| **(2) 加速增长** | 200 ~ 1000 | 奖励斜率明显增大 | 学会了基础建塔和升级，开始形成稳定收入流 |
| **(3) 高位震荡** | 1000+ | 奖励在高位波动，偶有回撤 | 策略趋于成熟，增长空间缩小；回撤通常由新对手引入或策略探索导致 |

**健康信号**：
- 阶段 (1) 不应过长（>500 episodes 仍无增长趋势 → 检查 reward 设计或探索策略）
- 阶段 (2) 的斜率应持续为正，不应出现平台期
- 阶段 (3) 的回撤幅度应 < 阶段 (2) 增幅的 30%，否则可能是策略崩溃

### 1.2 对局回合数曲线

**期望趋势**：对局回合数应**先升后稳**。

| 阶段 | 对局长度 | 原因 |
|------|:---:|------|
| 初期（双方随机） | 较短（~50-150 回合） | 双方都不会防守，蚂蚁很快到达基地 |
| 中期（一方学会防守） | 拉长（~150-280 回合） | 防守方建塔拦截，进攻方尚未学会有效突破 |
| 后期（双方均衡） | 稳定（~240-320 回合） | 双方攻防水平接近，拉锯至超时判负 |

**健康信号**：
- 平均回合数收敛到 **250-300** 之间（参考实测 MediumRuleAI vs MediumRuleAI 的 265-322）
- 回合数方差逐渐缩小（双方策略趋于稳定，不再出现一方快速崩盘）
- 不应出现平均回合数持续下降（说明一方在"虐菜"，对手池需要更新）

### 1.3 胜率曲线

**期望趋势**：

```
win_rate vs 初始对手
  ^
  |                          ┌──────────────── 95%+
  |                   ┌──────┘
  |            ┌──────┘
  |     ┌──────┘
  |─────┘  50%
  +──────────────────────────────────────────> episodes
```

| 对手类型 | 期望胜率趋势 |
|------|------|
| vs 初始对手（规则 AI 或随机） | 快速上升至 > 80%，最终 > 95% |
| vs 历史快照（比自己早 100-200 episodes） | 周期性波动：上升→平台→上升，最终 > 65% |
| vs 同期对手（同一 episode） | 约 50%（SelfPlay 对称训练的自然结果） |

**健康信号**：
- 对历史快照的胜率应整体呈上升趋势，不应长期低于 50%
- TrueSkill mu 值应单调递增（允许短期波动）
- 不应出现"新 agent 打不过旧 agent"的退化现象持续超过 50 episodes

## 2. PPO 算法指标期望

### 2.1 核心训练指标

| 指标 | 健康范围 | 异常信号 | 数据来源 |
|------|:---:|------|------|
| **policy_loss** | 逐渐下降并趋于小幅波动 | 持续为 0（策略不再更新）；持续上升（学习率过大或奖励尺度过大） | `training_metrics.json` |
| **value_loss** | 逐渐下降并趋于稳定 | 持续上升（价值估计失准）；震荡剧烈（环境随机性过高或网络容量不足） | 同上 |
| **entropy** | 从高（~2.0）降至中等（~0.5-1.5）并保持 | 降至 < 0.1（过早收敛，策略塌缩）；始终 > 2.0（几乎随机，没学到东西） | 同上 |
| **clip_fraction** | 0.05 ~ 0.20 | > 0.3（过多更新被裁剪，可能学习率过大）；< 0.02（更新过于保守，学习效率低） | 同上 |
| **gradient_norm** | 稳定在 0.1 ~ 10 之间 | 突然飙升 > 100（梯度爆炸）；持续 < 0.001（梯度消失） | 同上 |
| **advantages_mean** | 接近 0 | 持续偏离 0 较远（基线估计有偏） | 同上 |

### 2.2 熵的阶段性期望

熵是衡量策略"确定程度"的关键指标。在 AntWar 这种有明确最优动作区间的环境中：

| 训练阶段 | 期望 entropy | 说明 |
|------|:---:|------|
| 探索期（ep 0-200） | 1.5 ~ 2.5 | 策略高度随机，大量尝试各种动作 |
| 学习期（ep 200-1000） | 0.8 ~ 1.8 | 开始收敛到有效动作子集 |
| 收敛期（ep 1000+） | 0.3 ~ 1.2 | 核心策略确定，保留适度探索 |

**注意**：entropy 不应降得过低。AntWar 的动作空间虽然离散（96 维），但存在多种有效策略路径（激进进攻 vs 防守反击 vs 科技优先），过低的 entropy 意味着策略塌缩到单一打法，对 SelfPlay 多样性不利。

### 2.3 价值函数准确性

| 指标 | 期望 | 说明 |
|------|:---:|------|
| **explained_variance**（如有记录） | 逐步上升至 > 0.6 | 价值函数对回报的预测准确度 |
| **value_loss 与 reward 量级的关系** | value_loss < (avg_reward × 0.3)² | 粗略判断价值估计是否在合理精度内 |
| **td_error 分布** | 均值 ≈ 0，标准差随训练缩小 | TD 误差不应出现系统性偏差（如始终高估或低估） |

### 2.4 权重统计

来自 `weight_stats.jsonl`：

| 指标 | 期望 |
|------|------|
| 各层权重均值 | 稳定在 0 附近（不应持续漂移） |
| 各层权重标准差 | 逐步收敛到稳定值（不应持续增大或减小） |
| 各层梯度范数 | 稳定，不应出现某个层的梯度范数远超其他层（可能网络结构问题） |

## 3. 策略质量指标期望

### 3.1 动作分布演进

这是衡量策略是否"学会玩游戏"的最直观指标。来自 `training_metrics.json` 中的 `type_*` 字段。

#### 3.1.1 动作分布随时间的变化

| 动作 | 初期 (ep 0-200) | 中期 (ep 200-800) | 后期 (ep 800+) | 理想占比 |
|------|:---:|:---:|:---:|:---:|
| **NO_OP** | 极高（> 60%） | 下降（20-40%） | 低（10-20%） | 仅在等待攒钱时使用 |
| **BUILD_TOWER** | 中（10-20%） | 上升（20-35%） | 稳定（15-25%） | 集中在前 50 回合 |
| **UPGRADE_TOWER** | 极低（< 5%） | 上升（10-20%） | 稳定（15-25%） | 中期开始频繁使用 |
| **USE_LIGHTNING_STORM** | —（< 1%） | 上升（3-8%） | 稳定（5-10%） | 阶段 3+ 每 35 回合用一次 |
| **USE_EMP_BLASTER** | —（< 1%） | 低（1-3%） | 上升（2-5%） | 昂贵但战略价值高 |
| **USE_DEFLECTOR** | —（< 1%） | 上升（3-8%） | 稳定（5-10%） | 冷却短（25），应频繁使用 |
| **USE_EMERGENCY_EVASION** | —（< 1%） | 低（1-3%） | 低（1-5%） | 瞬时效果，场景有限 |
| **UPGRADE_GENERATION_SPEED** | —（< 1%） | 上升（1-3%） | 稳定（1-3%） | 一局仅 1-2 次，占比天生低 |
| **UPGRADE_GENERATED_ANT** | —（< 1%） | 极低（< 1%） | 极低（< 1%） | L1→L2 是陷阱，不应频繁升级 |

**关键对比**：实测 MediumRuleAI 几乎不使用 EMP/LS（平均每局 2.4 次超级武器），理想训练的 agent 应在阶段 3+ 主动使用超级武器（5-7 次/局）。

#### 3.1.2 分阶段动作分布（收敛后的一局内）

这是更细粒度的检查——不是看全局占比，而是看**同一局内动作随回合的分布**：

| 动作 | 阶段 1 (0-50r) | 阶段 2 (51-100r) | 阶段 3 (101-150r) | 阶段 4 (151-200r) | 阶段 5 (201-256r) |
|------|:---:|:---:|:---:|:---:|:---:|
| BUILD_TOWER | **高** | **中** | 低 | 极低 | 极低 |
| UPGRADE_TOWER | 极低 | **中** | **高** | **高** | **高** |
| NO_OP | 中 | 中 | 低 | 低 | 极低 |
| SUPER_WEAPON | — | 低 | **中** | **高** | **高** |
| TECH_UPGRADE | 极低 | **中** | 低 | — | — |

**验证方法**：从 `selfplay_{ep}_{opp}_{ts}.json` 的 `actions[]` 中，按 `step` 对应的 `round` 字段分组统计动作频率。

### 3.2 经济效率指标

来自 `training_metrics.json` 的 coin 相关字段和 detailed battle 日志。

#### 3.2.1 累计金币

| 指标 | 健康范围 | 说明 |
|------|:---:|------|
| 我方累计金币（256 回合） | **900 ~ 1100** | 接近经济模型理论值 1054 |
| 敌方累计金币（256 回合） | 明显 ≤ 我方 | 我方应压制敌方收入 |
| 阶段 3+ 战斗收入占比 | **> 55%** | 后期击杀+到达应占主导，参考最优模型 70% |

**对比基准**：MediumRuleAI 实测归一化总累计收入 948（低于最优模型 10%），理想训练的 agent 应接近 1054。

#### 3.2.2 金币使用效率

| 行为特征 | 健康信号 | 警告信号 |
|------|------|------|
| 每局建造塔次数（含重建） | 初期可能 ~18 次，后期降至 **6-10 次** | 持续 > 15 次（陷入重建循环） |
| 峰值并发塔数 | **4-6 座** | < 3（防线薄弱）或 > 7（浪费金币） |
| 塔升级次数/局 | **4-7 次** | < 2（不会升级）或 > 10（升级后塔很快被摧毁） |
| gen_speed L0→L1 时机 | 收敛到 **回合 60-100** | 持续 > 200 回合（参考 MediumRuleAI 的 224） |
| gen_speed L1→L2 频率 | 偶尔（优势局中） | 每局都升或从不升 |
| ant_level 升级频率 | **极少**（仅 L0→L1 偶尔） | L1→L2 的升级应几乎为 0 |

#### 3.2.3 避免"保守策略陷阱"

经济模型文档揭示了一个关键的策略退化模式：

```
塔被摧毁 → 花钱重建 → 无力升级科技 → 蚂蚁等级无法提升
    → 击杀奖励恒为 6 → 金币增量有限 → 继续无力升级 → ...
```

**健康信号**（说明 agent 打破了这个循环）：
- 塔被摧毁后，agent 更倾向于**升级剩余健康塔**而非在同位重建
- gen_speed 升级不受塔重建的挤出
- 阶段 3+ 击杀奖励单价 > 6（说明蚂蚁等级已提升）

### 3.3 防御效率指标

| 指标 | 健康范围 | 数据来源 |
|------|:---:|------|
| 敌方蚂蚁到达率 | < 15%（256 回合中 < 8 只到达） | `detailed_battles/*.json` 中统计敌方回合间 HP 变化 |
| 我方塔存活率（终局时） | > 60% 的建造过的塔仍存活 | `round_details[]` 的 `our_towers` |
| 塔平均存活回合数 | > 80 回合 | 计算每座塔从建造到被摧毁的回合跨度 |

### 3.4 进攻效率指标

| 指标 | 健康范围 | 说明 |
|------|:---:|------|
| 我方蚂蚁到达敌方基地次数/局 | **3-6 次** | 均衡局中的合理到达率 |
| 到达基地的蚂蚁中沿相同路径的比例 | **> 50%** | 说明 agent 在利用信息素"滚雪球" |
| 超级武器对敌方塔的累计禁用回合 | EMP 累计 > 15 回合 | 有效使用 EMP 的证据 |
| 敌方塔被摧毁次数/局 | **1-4 次** | 通过蚂蚁攻击或战斗蚂蚁自毁摧毁 |

## 4. SelfPlay 多智能体动态期望

### 4.1 对手池健康度

| 指标 | 期望 | 数据来源 |
|------|------|------|
| 对手池大小 | 随训练增长至 **5-10 个**多样化对手 | `opponent_pool.json` |
| 对手技能跨度 | TrueSkill mu 值跨度 > 5（有明确的强弱分层） | `payoff.json` |
| 对手添加频率 | 每 100-200 episodes 添加一个新对手（当 win_rate 过高时） | `opponent_pool.json` 的 `added_episodes` |
| 各对手被选中频率 | 分布均匀，不应对某个对手过度采样 | `selfplay_battle_stats.json` |

### 4.2 Payoff 矩阵特征

```
           vs_opp1  vs_opp2  vs_opp3  vs_opp4  vs_cur
opp1        —        0.45     0.30     0.20     0.10
opp2        0.55     —        0.35     0.25     0.15
opp3        0.70     0.65     —        0.40     0.30
opp4        0.80     0.75     0.60     —        0.45
cur         0.90     0.85     0.70     0.55     —
```

**期望特征**：
- **传递性**：如果 A > B 且 B > C，则 A > C（大致成立，允许少量非传递性）
- **时间单调性**：后添加的对手对先添加的对手胜率 > 50%
- **当前 agent 对历史最强对手胜率** > 55%（持续进步的证据）
- **不存在循环克制**（A > B > C > A）——如果出现，说明训练不收敛或策略空间存在非传递性博弈（这本身不是 bug，但需要确认）

### 4.3 TrueSkill 演进

| 指标 | 期望 |
|------|------|
| 当前 agent 的 mu | 单调递增（允许短期波动 ±0.5） |
| 当前 agent 的 sigma | 逐步缩小（不确定性降低） |
| 历史对手的 mu | 随新 agent 加入而相对下降（反映整体水平提升） |

## 5. 训练稳定性期望

### 5.1 不应出现的异常模式

| 异常模式 | 可能原因 | 检查方向 |
|------|------|------|
| reward 突然暴跌 > 50% 且不恢复 | 策略崩溃（policy collapse）；新对手过强导致负反馈 | 检查 entropy 是否骤降；检查对手池是否有异常强的对手 |
| policy_loss 持续为 0 | 梯度消失；学习率过低；reward 尺度导致优势为 0 | 检查 gradient_norm；检查 advantages 分布 |
| value_loss 持续上升 | 环境变化过快（对手更新太频繁）；网络容量不足 | 检查对手池添加频率；增大网络或降低学习率 |
| entropy 降至 < 0.05 | 策略过度确定，失去探索能力 | 增大 entropy_coef；增加对手多样性 |
| 某一类动作占比突然降至 0 | 策略塌缩到动作空间的子集 | 检查是否该类动作的 reward 信号过弱；考虑调整 reward 权重 |
| training_speed 持续下降 | 对局变长导致每 episode 耗时增加 | 正常现象（对局从 50 回合增长到 300 回合），但下降应趋于稳定 |

### 5.2 奖励分解的健康比例

来自 `training_metrics.json` 的 `rw_*` 字段：

| 奖励分量 | 健康占比（终局） | 说明 |
|------|:---:|------|
| `rw_hp_attack` | **30-45%** | 对敌方基地造成伤害是终极目标 |
| `rw_coin_gain` | **25-35%** | 经济积累是手段而非目的 |
| `rw_tower_survival` | **10-20%** | 塔存活是防守能力的体现 |
| `rw_tech_bonus` | **5-10%** | 科技升级是一次性奖励，占比不宜过高 |
| `rw_speed_bonus` | **3-8%** | 速胜奖励，优势局中出现 |
| `rw_end_reward` | **5-15%** | 终局奖惩（胜负/超时） |

**注意**：奖励分量占比是**结果**而非**原因**——如果某个分量占比异常，说明 agent 的行为模式偏离了设计意图，需要检查 reward 设计是否合理。

## 6. 分阶段检查清单

### 6.1 训练前 200 episodes（起步期）

- [ ] avg_reward 不再为 0 或负值，开始出现正向奖励
- [ ] avg_rounds 从 ~50 开始上升（双方都学会了建塔防守）
- [ ] `type_build_tower` 占比 > 10%（agent 学会了建造塔）
- [ ] entropy 从初始值开始下降
- [ ] value_loss 从初始高值开始下降
- [ ] 无 NaN 或 Inf 出现在 loss 中
- [ ] `nan_skip_count` = 0

### 6.2 训练 200-800 episodes（学习期）

- [ ] avg_reward 持续增长，斜率 > 0
- [ ] avg_rounds 收敛到 150-250
- [ ] `type_upgrade_tower` 占比 > 5%（agent 学会了升级塔）
- [ ] `type_tech_upgrade` 占比 > 0.5%（agent 开始升级科技）
- [ ] 至少有一种超级武器的使用占比 > 1%
- [ ] 对初始对手的胜率 > 60%
- [ ] clip_fraction 稳定在 0.05-0.20
- [ ] entropy 在 0.8-1.8 之间

### 6.3 训练 800-2000 episodes（收敛期）

- [ ] avg_reward 在高位震荡，偶尔刷新高
- [ ] avg_rounds 稳定在 240-320
- [ ] avg_our_cumulative_coins 接近 900-1100
- [ ] 分阶段动作分布与经济模型预测一致（参见 §3.1.2）
- [ ] gen_speed 升级时机在回合 60-120
- [ ] ant_level L1→L2 升级几乎为 0
- [ ] 每局超级武器使用次数 5-7 次
- [ ] 每局塔建造次数（含重建）降至 6-10 次
- [ ] 峰值并发塔数 4-6 座
- [ ] 对历史快照胜率 > 60%
- [ ] TrueSkill mu 持续增长
- [ ] entropy 在 0.3-1.2（保留探索）
- [ ] 权重统计中无异常漂移或梯度爆炸

## 8. 总结：理想训练的 10 条核心特征

| # | 特征 | 一句话描述 |
|:---:|------|------|
| 1 | **奖励单调增长** | avg_reward 整体趋势向上，阶段 (1)→(2)→(3) 清晰可辨 |
| 2 | **对局长度收敛** | 平均回合数稳定在 250-300，方差缩小 |
| 3 | **PPO 指标健康** | entropy 0.3~1.5、clip_fraction 0.05~0.20、无梯度爆炸 |
| 4 | **动作分布演进** | 从"只会 NO_OP"到"阶段 1 建塔 → 阶段 2 升级 → 阶段 3+ 武器"，符合经济模型 |
| 5 | **经济效率最优** | 累计金币接近 1054，后期战斗收入占比 > 55% |
| 6 | **打破保守陷阱** | 优先升级科技而非反复重建塔；gen_speed 升级在 60-100 回合 |
| 7 | **超级武器活用** | 每局 5-7 次，不限于 Deflector（实测规则 AI 的 3 倍以上） |
| 8 | **塔数量理性** | 并发 4-6 座，新建次数 6-10 次（含重建），不过度建设 |
| 9 | **避免策略塌缩** | entropy 不过低；ant_level L1→L2 几乎不被选择；多策略共存 |
| 10 | **SelfPlay 传递性** | payoff 矩阵大致传递，新 agent > 旧 agent，TrueSkill mu 递增 |
