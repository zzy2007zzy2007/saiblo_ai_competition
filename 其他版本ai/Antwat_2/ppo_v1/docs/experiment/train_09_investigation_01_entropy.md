# Train 09 调查 01：熵值异常根因分析

> 日期：2026-05-30
> 调查范围：异常清单 §2.1 熵值异常低下、§3.5 回合数过早稳定
> 数据来源：server9 / `20260530_120710` 训练日志

---

## 1. 调查结论摘要

**根因：`valid_actions_mean` 仅为 1.79-2.10，有效动作空间过于狭小。熵值 0.24-0.31 占理论最大熵（~0.69）的 35-45%，属于合理范围而非严重异常。**

评估文档 §2.1 使用的熵值期望（1.5-2.5 / 0.8-1.8 / 0.3-1.2）是**无效基准**——该基准隐含假设有效动作空间远大于实际值。在实际仅有 ~2 个有效动作的条件下，熵的理论上限仅为 `log(2) ≈ 0.69`。

---

## 2. 证据链条

### 2.1 训练起点：全新训练，非从 checkpoint 恢复

**证据**：
- `training.log` 第 1 行：`2026-05-30 12:07:12 | PPOTrainer initialized successfully`
- 第 8 行：`Creating 3 initial opponents...`
- 第 14 行：`Starting self-play training for 2000 episodes`
- `grep` 日志中无 "Resume"、"Restore"、"Checkpoint loaded" 等关键词
- `weight_stats.jsonl` 第一条记录为 episode 40（无 episode 0 记录，因为 save_interval=20，第一次保存 checkpoint 在 ep40）

**结论**：训练从零开始，初始模型权重为随机初始化（PyTorch 默认的 Kaiming uniform 初始化）。低熵并非继承自已有模型。

### 2.2 有效动作空间：均值仅 ~2.0

**证据**（从 `training_metrics_history.jsonl` 提取）：

| Episode | valid_actions_mean | valid_actions_min |
|:---:|:---:|:---:|
| 20 | **2.10** | 1.0 |
| 100 | 1.93 | 1.0 |
| 200 | 1.81 | 1.0 |
| 400 | 1.86 | 1.0 |
| 600 | 1.77 | 1.0 |
| 760 | 1.85 | 1.0 |

整个训练周期中，**平均每个 step 仅有 1.77-2.10 个合法动作**。最小值始终为 1.0，意味着在某些 step 中只有 NO_OP 一个合法动作。

**有效动作空间的构成**（各动作类型的 valid 占比）：

| 动作类型 | Ep20 可用率 | Ep760 可用率 | 说明 |
|------|:---:|:---:|------|
| NO_OP | **100%** | **100%** | 始终可用 |
| BUILD_TOWER | **72.75%** | **70.32%** | 主要可用动作 |
| UPGRADE_TOWER | **17.60%** | **8.59%** | 偶尔可用 |
| DOWNGRADE_TOWER | **0.00%** | **0.00%** | 回合 < 1000 时被硬编码禁用 |
| LIGHTNING_STORM | 非零（ep20）→ **0.00%** | **0.00%** | 冷却 + 金币限制 |
| EMP_BLASTER | 非零（ep20）→ **0.00%** | **0.00%** | 冷却 + 金币限制 |
| DEFLECTOR | 10.57% → **0.00%** | **0.00%** | 冷却 + 金币限制 |
| EMERGENCY_EVASION | 9.40% → **0.00%** | **0.00%** | 冷却 + 金币限制 |
| TECH_UPGRADE | **0.00%** | **0.00%** | 金币不足 200 |

**有效动作 = NO_OP (100%) + BUILD_TOWER (~72%) + UPGRADE_TOWER (~8-18%) ≈ 1.8-1.9 个**

超级武器和科技升级的零可用率是因为：
- **金币限制**：`avg_our_coins = 20-28`，`our_coins_lt_30 = 57%+`，agent 几乎从未持有超过 60 金币
- **冷却限制**：超级武器使用后有 25-45 回合冷却期
- **费用对比**：最便宜的 DEFLECTOR 也需要 60 金币，而 agent 57%+ 的时间金币 < 30

### 2.3 熵值 vs 理论最大熵

**理论最大熵计算**（假设策略均匀分布在所有有效动作上）：
- 若 `valid_actions_mean = 2.0`：`H_max = -log(1/2) = log(2) ≈ 0.693`
- 若 `valid_actions_mean = 1.8`：`H_max = log(1.8) ≈ 0.588`

**实际熵值**：

| Episode | entropy | valid_actions | 熵/理论最大 (%) | 动作分布 |
|:---:|:---:|:---:|:---:|------|
| 20 | 0.242 | 2.10 | **35%** | NO_OP:88.8%, BUILD:9.2%, UPGRADE:0.36% |
| 100 | 0.303 | 1.93 | **44%** | NO_OP:84.9%, BUILD:14.2%, UPGRADE:0.79% |
| 760 | 0.297 | 1.85 | **43%** | NO_OP:85.2%, BUILD:14.1%, UPGRADE:0.73% |

**实际熵占理论最大熵的 35-44%**，这意味着策略有一定程度的确定性偏向，但并非"完全塌缩"。考虑到：
- NO_OP (88.8%) 和 BUILD_TOWER (9.2%) 的分布反映的是真实策略偏好（"大部分时间等待攒钱，偶尔建塔"）
- 这不是"熵崩坏"而是"环境约束下的合理策略"

### 2.4 熵系数 warmup 机制

**Config 设置**：
- `ent_coef: 0.2` → `ent_coef_final: 0.02`（线性退火，ent_anneal_power=1.0）
- `warmup.entropy_adaptive: true`
- `warmup.entropy_target_ratio: 0.15`
- `warmup.ent_coef_max: 2.0`

**实际 entropy_coef 序列**：

| Episode | entropy_coef |
|:---:|:---:|
| 20 | 0.198 |
| 40 | **0.392**（峰值） |
| 100 | 0.380 |
| 200 | 0.360 |
| 400 | 0.320 |
| 760 | 0.248 |

entropy_coef 最高仅达到 0.392（远低于 2.0 的 max），说明 adaptive warmup 在一定程度上调整了 coef，但未能将熵拉到目标水平。hard_entropy_penalty 全程在 16-18，说明熵持续低于 min_ratio 阈值（0.25）。

**warmup 未能大幅提升熵的原因**：有效动作空间本身就很小（~2 个动作），即使策略完全均匀分布，熵也最多是 0.69。在 0.24-0.31 的基础上，entropy_coef 从 0.2 调到 0.392 已经将熵从 ~0.24 提升到了 ~0.30（约 25% 提升），但由于动作空间的上限，无法进一步提升。

## 3. 回合数早期稳定分析

### 3.1 数据

| Episode | avg_rounds |
|:---:|:---:|
| 20 | **253** |
| 100 | **243** |
| 760 | **241** |

回合数从 ep20 起就在 241-254 之间，没有"从短到长"的演进。

### 3.2 根因分析

**这不是异常**。根本原因是：

1. **baseline 对手本身就是长对局对手**：初始对手包括 `BasicTowerAI`、`BasicRandomAI`、`MediumRuleAI` 以及 3 个初始快照。经济模型文档的实测数据显示 MediumRuleAI vs MediumRuleAI 的平均对局长度为 287 回合（min 265，max 322）。
2. **agent 从 episode 0 起就有基本的建塔防御能力**：从 training.log 可以看到，episode 0 的对局就是 261 回合。这并非因为 agent"特别聪明"，而是因为：
   - 初始随机权重下的策略网络经 PPO 更新后（每个 episode 更新 1 次），在第 0 个 episode 收集了 20 场对局数据进行更新
   - 建塔是最直接的正向 reward 来源（`rw_tower_survival` 贡献了最大的正 reward 分量）
   - 初始权重 + 1 次 PPO 更新已足够学到"建塔比什么都不做更好"
3. **短对局几乎不可能出现**：在均衡对局场景下，双方都有基础建塔能力时，蚂蚁需要经过 150+ 回合才能逐渐突破防线。这是游戏机制决定的，不是训练问题。

**结论**：回合数早期稳定至 240-254 是合理的，因为 baseline 对手本身就会产生长对局。异常清单中期望的"初期 50-150 回合"是基于"双方都不会玩"的假设，但这个假设不成立——即使是最基础的 PPO agent（1 次更新后）也学会了建塔。

## 4. 最终根因判定

```
┌──────────────────────────────────────────────────────────────────┐
│                    熵值偏低的根因链                                │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ① 游戏机制 + ActionCatalog 设计                                   │
│     → 有效动作空间天然狭小（avg 1.8-2.1 个合法动作）               │
│         │                                                        │
│         ├── 金币限制：agent 策略"即赚即花" → 余额低                │
│         │   → tech_upgrade (200金币) 从不合法                      │
│         │   → super_weapons (60-135金币) 几乎从不合法               │
│         │                                                        │
│         ├── 冷却限制：超级武器使用后有长冷却期                      │
│         │                                                        │
│         └── 降级禁止：回合 < 1000 时 downgrade 硬编码为 0           │
│                                                                  │
│  ② 策略分布的偏向性                                               │
│     → agent 偏好 NO_OP (85-89%) 和 BUILD_TOWER (9-14%)            │
│     → 利用约 35-44% 的理论最大熵预算                               │
│     → 这不是崩溃，是在狭小动作空间内的合理"保守"决策               │
│                                                                  │
│  ③ warmup 机制限制                                               │
│     → entropy_coef 从 0.2 调整至最高 0.392                        │
│     → 未能触发更高的 coef（因为动作空间上限约束）                  │
│     → hard_entropy_penalty (16-18) 持续生效，但效果有限            │
│                                                                  │
│  ④ 期望基准偏差                                                   │
│     → 原始期望（1.5-2.5）是基于"大有效动作空间"的错误假设          │
│     → 在实际 ~2 个动作的条件下，0.24-0.31 的熵是"适度确定"         │
│     → 如果要提高熵，关键是扩大有效动作空间，而非调高 entropy_coef  │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

**核心结论**：熵值"偏低"的根本原因是**有效动作空间先天狭小**（avg 1.8-2.1），这是由游戏经济和 ActionCatalog 设计共同决定的。在现有约束下，0.24-0.31 的熵值代表策略在 35-44% 的理论最大熵预算内运行——这不是"策略塌缩"，而是"环境约束下的适度确定"。

**修正后的熵值期望**（基于 valid_actions ≈ 2.0）：

| 阶段 | 修正后期望 entropy | 说明 |
|------|:---:|------|
| 探索期 | 0.40-0.55 | 均匀探索各有效动作 |
| 学习期 | 0.30-0.45 | 适度偏向有效动作 |
| 收敛期 | 0.20-0.35 | 策略高度确定 |

按此修正基准，当前 0.24-0.31 的熵值在"学习期→收敛期"的过渡范围，是合理的。

---

## 5. 建议

1. **不要仅依靠调高 entropy_coef 来"修复"熵值**：在有效动作空间仅 2 个的情况下，熵的理论上限为 0.69，调高 coef 的效果很有限
2. **如果希望策略探索更多样化**：应通过 reward shaping 引导 agent 攒钱（减少"即赚即花"的行为），使科技升级和超级武器动作变得可用，从而自然扩大有效动作空间
3. **修正 train_expectation.md 中的熵值基准**：应将熵值与 valid_actions 联动，使用"熵占理论最大熵比例"而非绝对值作为健康指标
