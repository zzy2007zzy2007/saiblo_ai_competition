## 1. 调查结论摘要

**三个性能异常点的根因均指向同一个源头：agent 的策略被经济瓶颈锁定在 `{NO_OP, BUILD_TOWER, UPGRADE_TOWER}` 的狭窄动作空间中，无法访问更高维度的策略选项（科技升级、超级武器），导致策略优化已触及当前动作空间的上限。**

| 异常点 | 根因 | 严重度 |
|------|------|:---:|
| §2.3 胜率无进步 | 策略空间已穷尽，agent 无法触及性能更高的策略区域 | 🔴 |
| §2.5 奖励无增长 | 同上——action mask 限制了可获得的最高奖励 | 🔴 |
| §3.4 累计金币低 | 不升级科技 → 蚂蚁等级 L0 → 击杀奖励恒为 6 | 🟡 |

**当前 agent TrueSkill mu = 28.92**（池内排名第 5/10）

### 2.2 模式分析

1. **对初始对手（ep0）有显著优势**：胜率 58-64%，说明 agent 确实学到了超越 baseline AI 的策略
2. **对早期快照（ep40-80）五五开**：胜率 47-49%，说明 ep40-80 的 agent 快照与当前 agent 水平相当
3. **对中期快照（ep240-400）处于劣势**：胜率 41-47%，说明这些历史快照在某些方面强于当前 agent
4. **对最强对手（opp_64df9ba2, ep600）明显劣势**：胜率仅 27.3%，但样本量小（仅 11 局）

### 2.3 根因分析

表面上看，agent 确实没有随训练而进步——对越晚添加的对手胜率越低。但需要深入分析背后的原因：

**关键问题：为什么 ep240-400 的历史快照能比当前 agent（ep760）更强？**

回顾 action mask 数据：从 ep20 到 ep760，agent 的可用动作集合几乎不变（仅 NO_OP + BUILD_TOWER + UPGRADE_TOWER）。这意味着：

- **ep40 的 agent** 已经掌握了"建塔防御"的核心策略
- **ep240 的 agent** 在同样的动作空间中可能找到了略微更优的塔位置或升级时机
- **当前 agent** 在同样的动作空间中已经做了 720 次微调，但动作空间本身没有扩张

**核心结论**：胜率无进步不是因为 agent "退化"或"不学习"，而是因为**agent 的策略优化空间在 ep40 左右就已触顶**——它学会了建塔防御，但在当前经济约束下无法进一步拓展策略（如科技升级、超级武器）。所有后续 agent 都在同一个狭窄策略空间内做微观调整，宏观策略没有质变。

**TrueSkill 数据佐证**：opp_45fa2f2a (ep40, mu=28.31) 和当前 agent (ep760, mu=28.92) 的 mu 差仅 0.61，在 sigma≈1 的尺度上几乎无差异。720 次 PPO 更新后，技能评分的提升不到 1 个标准差。

### 3.2 奖励分解分析

从 `training_metrics_history.jsonl` 提取 reward 分量（每 episode 汇总，20 场对局）：

| 分量 | 典型值 | 占比 | 分析 |
|------|:---:|:---:|------|
| `rw_hp_attack` | **0.000** | 0% | 蚂蚁到达敌方基地是稀疏事件，per-step 平均为 0 |
| `rw_coin_gain` | 158-186 | ~25% | 稳定，受限于 L0 蚂蚁的低击杀奖励（6） |
| `rw_tower_survival` | 320-480 | ~55% | **最大正 reward 分量**，鼓励建塔并保持存活 |
| `rw_tech_bonus` | **0.000** | 0% | 从未升级科技 |
| `rw_die_penalty` | -3 to +2 | ~0% | 数值小，影响有限 |
| `rw_end_reward` | 70-1220 | ~10% | 胜负奖励，随对手强弱波动 |
| `rw_speed_bonus` | 180-420 | ~10% | 速胜奖励 |

**关键发现**：
- `rw_tower_survival` 占比 55%，是驱动 agent 策略的主要 reward 信号
- `rw_coin_gain` 稳定在 158-186，增长空间受限于不升级科技
- "没有科技升级 → 击杀奖励上限 6 → 金币收入上限固定" 是 reward 无增长的根本经济原因

### 3.3 奖励天花板的量化

在"仅建塔、不升级科技"的策略下：
- 每局金币收入上限 ≈ 基础收入(~384) + 击杀收入(~64只 × 6 × 60%击杀率 ≈ 230) + 到达收入(~0-2只 × 10) ≈ **614-634**
- 扣除建塔支出（反复重建 ~13 次，累计 ~200-400）后，净经济产出约为 **200-400**

对比最优策略（含科技升级 L0→L1→L2）：
- 击杀奖励从 6 → 10 → 14，击杀收入翻倍以上
- 净经济产出约为 **600-800**

**差距约 2-3 倍**。这就是为什么 reward 无法增长——当前策略的经济效率已触及天花板。

## 4. 累计金币偏低（§3.4）

### 4.1 数据

| 指标 | 实际值 | 期望值 | 差距 |
|------|:---:|:---:|:---:|
| avg_our_cumulative_coins | **900-942** | 900-1100 | 在下沿 |
| avg_enemy_cumulative_coins | **904-957** | 明显 ≤ 我方 | 敌方反而更高 |

### 4.2 根因

这与 Report 02 的调查结论直接关联：

1. **不升级科技** → 蚂蚁等级始终为 L0 → 击杀奖励恒为 6
2. 经济模型文档的实测数据：不升级科技的保守策略在阶段 3-5 的收入比最优路径低 **18-25%**
3. 归一化总累计收入：保守策略 **948** vs 最优策略 **1054**，差距 **-10%**
4. 当前 agent 的 900-942 与 MediumRuleAI 实测的 948 高度吻合——这正是"保守策略"的经济特征

**敌方金币更高的原因**：敌方（baseline AI 或历史快照）的建塔策略更加"理性"（不会像初始 agent 那样建了拆、拆了建），塔的重建开销更少，因此累计金币更高。

## 5. 为什么 PPO 指标健康但策略不进步？

异常清单 §4.1 指出 PPO 算法指标（clip_fraction、gradient_norm、policy_loss、value_loss）基本健康，这与策略停滞看似矛盾。实则不然：

1. **PPO 在做它该做的事**：在给定的 action mask 约束下，PPO 在持续优化策略网络。value_loss 从 0.85 降到 0.40 说明价值函数在改善；policy_loss 稳定在 0.14-0.18 说明策略在微调。

2. **但 PPO 无法突破 action mask 的牢笼**：PPO 只能优化"可选动作"之间的概率分布。当科技升级和超级武器的 mask 为 0 时，无论 PPO 如何优化，agent 都不可能选择这些动作。

3. **类比**：PPO 像是在一个 2 选项的"菜单"上做最优选择（NO_OP vs BUILD_TOWER），它可以把两个选项的比例调得很精确（如 85:15），但它无法"发明"菜单上没有的选项（超级武器、科技升级）。

4. **健康 PPO 指标 + 停滞策略 = action mask 瓶颈的精确诊断**：这说明算法本身没问题，问题是算法被限制在一个过于狭小的搜索空间中。

## 7. 建议

1. **P0 - 打破经济的"即赚即花"循环**：通过 reward shaping 鼓励 agent 持有更多金币（例如 `+0.01 × coins` 作为余额奖励），使得科技升级和超级武器的 action mask 变为可用

2. **P0 - 调整 reward 权重**：当前 `rw_tower_survival` 过度主导（55%），导致 agent 的策略高度偏向建塔。应将 `rw_coin_gain` 权重提升，使得"高效赚金币"比"多建塔"获得更高的综合 reward

3. **P1 - 引入阶段性的 reward 引导**：在训练早期（ep0-200）提供显式的探索奖励（intrinsic reward），引导 agent 尝试存钱并使用超级武器

4. **P1 - 考虑使用分层强化学习（HRL）**：将经济管理（何时存钱、何时花钱）作为高层策略，将具体的建塔/升级/武器使用作为低层策略
