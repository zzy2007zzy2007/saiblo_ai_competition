### 1.3 与原假设的核心差异

| 维度 | 原假设 | 实际根因 |
|------|------|------|
| **原发问题** | 初始权重或 warmup 导致熵低 | **Reward 结构**过度鼓励建塔 → 经济瓶颈 |
| **科技升级缺失的原因** | 低熵 → 不探索科技升级 | **action mask = 0**（金币从未 ≥ 200） |
| **超级武器缺失的原因** | 低熵 → 不探索超级武器 | **action mask ≈ 0**（金币 + 冷却限制） |
| **熵低的性质** | "过早收敛"（策略塌缩） | **环境约束下的合理策略**（占理论最大熵 35-44%） |
| **PPO 的角色** | 算法有效但被熵拖累 | 算法在做正确的事，但被 action mask 限制了搜索空间 |
| **最需要修复的** | entropy_coef / warmup | **Reward 结构 + 经济引导** |

## 3. 修复路线图

### 3.1 P0（立即行动）：打破经济瓶颈，扩大有效动作空间

这些是使训练产生有意义进步的**必要条件**。不改这些，训练再多 episodes 结果都一样。

| 行动 | 目标 | 预期效果 |
|------|------|------|
| **1. 引入"攒钱"奖励** | 让 agent 学会持有 200+ 金币 | tech_upgrade mask 从 0% → 偶有非零 |
| 在 reward 中添加 `+0.005 × our_coins`（余额奖励） | 引导 agent 不"即赚即花" | super_weapon mask 从 0% → 偶有非零 |
| **2. 调整 reward 权重** | 减少 `rw_tower_survival` 的主导地位 | agent 不再无脑建塔 |
| 将 `rw_tower_survival` 权重降至 ~25-30% | 给 `rw_coin_gain` 更大权重 | 经济策略从"建更多塔"转向"高效管理金币" |
| **3. 添加科技升级的 shaping reward** | 当 agent 首次升级科技时给予强正奖励 | agent 体验到科技升级的长期价值 |
| 例如 `+50 × (new_gen_level - old_gen_level)` | 示范科技升级的正向信号 | 打破"从不升级"的循环 |

### 3.2 P1（短期行动）：改善训练基础设施

| 行动 | 目标 | 预期效果 |
|------|------|------|
| **4. 提高 `opponent_update_interval`** | 从 40 → 100-160 | 对手有充足的评估时间 |
| 或改为条件触发（win_rate > 65% 才添加） | 减少无效驱逐 | 对手池更稳定 |
| **5. 添加 warmup 阶段的探索预算** | 在 ep0-200 提供额外金币（如初始 +50） | agent 在早期能体验科技升级和超级武器 |
| 或暂时降低科技升级费用（200 → 100） | 给 agent 一个"体验窗口" | 策略在 warmup 后能携带这些经验 |

### 3.3 P2（中期行动）：策略架构改进

| 行动 | 目标 | 预期效果 |
|------|------|------|
| **6. 分层强化学习（HRL）** | 高层策略管理经济节奏，低层执行建塔/武器 | 将"何时存钱"与"建什么塔"解耦 |
| **7. 课程学习** | 先教 agent 攒钱升级科技，再教对抗更强对手 | 渐进式技能获取 |
| **8. 使用"熵占理论最大熵比例"作为健康指标** | 替代绝对值熵基准 | 更准确的训练监控 |

### 3.4 P3（可选改进）

| 行动 | 目标 |
|------|------|
| **9. 移除 "1000 回合前禁止降级" 限制** | 给 agent 更多策略选项（拆除/降级也是重要的策略工具） |
| **10. 增加 opponent-vs-opponent 对战** | 构建完整 payoff 矩阵，提升 TrueSkill 准确性 |

## 5. 关键洞察总结

### 5.1 "这不是你的错"——给开发者的信息

这次 train_09 的大部分"异常"实际上不是 PPO 算法的问题，也不是模型初始化的 bug。它们是**游戏经济系统的设计特征在 RL 训练中的自然体现**：

1. **熵值不低**——是动作空间本来就小。在 2 个合法动作中，0.3 的熵意味着策略已经有一定程度的随机探索，不是"塌缩"。

2. **不升级科技不是策略失败**——是金币门槛（200）在 agent 的"即赚即花"经济模式下永远达不到。这不是 agent "笨"，而是它被 reward 信号训练成了"勤劳的工人"（一有钱就建塔），而不是"精明的投资者"（存钱升级）。

3. **超级武器不是被忽视**——是它们在实践中不可用（60-135 金币 + 冷却约束）。agent 从未体验到超级武器的价值，因为它在物理上从未有机会使用它。

4. **PPO 在做正确的事**——所有 PPO 指标（clip_fraction、gradient_norm、value_loss）都是健康的。问题在于 PPO 被限制在一个过于狭小的搜索空间中。

### 5.2 核心修复方向：一字以蔽之——"攒钱"

所有问题的根因归到一个简单的概念：agent 需要学会**攒钱**。当前 agent 的"即赚即花"策略是 reward 结构（rw_tower_survival 占 55%）自然训练出的结果。要打破这个循环，最直接的方式是：

1. **奖励 agent 持有金币**（reward shaping）
2. **降低过度鼓励建塔的 reward 权重**
3. **在 warmup 期提供"体验窗口"**让 agent 体验科技升级和超级武器的长期价值

一旦 agent 学会攒钱（金币 ≥ 60），超级武器的 action mask 将变为非零；一旦金币 ≥ 200，科技升级变为可用。从那一刻起，PPO 才能开始优化更高级的策略——而这次 train_09 的 760 episodes 中，这个时刻从未到来。
