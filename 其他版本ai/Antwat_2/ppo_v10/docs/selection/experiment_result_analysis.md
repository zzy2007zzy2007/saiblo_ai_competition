## 2. 指标定义（同 v2）

| 分类 | 定义 |
|------|------|
| **一类对战** | 提交时**一方是候选**（且无种子参与）。 |
| **二类对战** | 提交时**一方是正式种子**。 |
| **三类对战** | 结束时**双方都不是正式种子**（"白打"对局）。 |
| **有效对战** | = 总数 − 三类。 |
| **累计候选个体数** | 曾被启动过的候选个体数（去重）。 |
| **Top16 重叠率** | `\|二分Top16 ∩ GT Top16\| / 16` |
| **Recall@8** | `\|二分Top16 ∩ GT Top8\| / 8` |
| **Recall@16** | `\|二分Top16 ∩ GT Top16\| / 16`（与 Top16 重叠率等价） |

## 8. 关键结论

### 8.1 计算规模 ✅ 仍符合预期且更优

- **总对战数 706.6 ± 33.1 局**，相对全量 RR（12640 局）节省 **94.41% ± 0.26%**
- 节省率从 v2 的 92.92% **提升到 94.41%**（因 RR 翻倍但二分对战仅约 1.6 倍增长）
- **二类对战 528.2 局（占 75%）**，仍是计算主体
- **一类对战 178.2 局（占 25%）**：M 翻倍后甄别成本相应翻倍
- **三类对战 76.5 局（占 11%）**：浪费量也跟着翻倍
- **0% fallback 触发率**，方案稳定
- **平均 5.58 个候选**即可凑齐 3 个种子（与 v2 的 5.33 接近）

### 8.2 覆盖率 ⚠️ 整体提升但 bimodal 仍未解决

| 分布 | v2 Top16 重叠 | **v3 Top16 重叠** | 提升 |
|------|:---:|:---:|:---:|
| uniform | 0.700 | **0.750** | +0.050 |
| normal | 0.729 | **0.792** | +0.063 |
| **bimodal** | 0.321 | **0.329** | **+0.008（几乎不变）** |

| 分布 | v2 Recall@8 | **v3 Recall@8** | 提升 |
|------|:---:|:---:|:---:|
| uniform | 0.783 | **0.892** | **+0.108** ✅ |
| normal | 0.733 | **0.858** | **+0.125** ✅ |
| **bimodal** | 0.342 | **0.333** | **−0.008** ⚠️ |

> **核心观察**：
> 1. **uniform / normal 提升明显**：Recall@8 接近 0.85-0.90，已达较高水平
> 2. **bimodal 几乎无改善**：M 翻倍 + n_battle 翻倍后，bimodal 的 Top16 重叠率仅从 0.321 提升到 0.329
> 3. 这印证了之前的判断：**bimodal 的失败是结构性的**，靠加大对战量无法解决，需要改算法（如放宽中位区间为 Top25%-Top75%，或增加种子数）

### 8.3 增加 M 与 n_battle 的成本/收益

| 维度 | v2 → v3 | 倍率 |
|------|:---:|:---:|
| 总对战数 | 447.6 → 706.6 | **×1.58** |
| RR 对照 | 6320 → 12640 | ×2.00 |
| Top16 重叠率（uniform/normal 平均） | 0.715 → 0.771 | **×1.08** |
| Recall@8（uniform/normal 平均） | 0.758 → 0.875 | **×1.15** |

> **结论**：以 1.58× 计算量换取 **~10-15% 覆盖率提升**，对 uniform/normal 是划算的。
> 但对 bimodal 几乎无效益。

### 8.4 算法稳定性

- 二类对战数从 363 增加到 528，增加 165 ≈ 3 × 79 × 2（每对增加 2 局，符合 n_battle 从 1→2 的设计）
- std 从 8.3 增加到 17.0，比例上反而更稳定
- 总体结构与 v2 一致，参数变化未引入异常行为
