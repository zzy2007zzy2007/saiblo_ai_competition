# 价值头迭代训练循环（累积池 + 浅搜索采集）方案（2026-09-14）

## 背景：为什么要做这个

### 1. 单次训练的结论在这个数据量下全部无效（已实测）

同配置、同 value loss（0.0169）、只换 `--seed`（warm_polonly 336 局）：

| seed | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| vs rule_v4（64 局）| **50.0%** | 25.0% | 29.7% | 28.1% | 26.6% |

**4 个种子聚在 25-30%，1 个（seed 0）是 20pp 的离群点。** 即 336 局下价值头训练是
**重尾随机**：多数时候稳定，偶尔命中"幸运盆地"。我们之前的 `kgeo_gap 50.0%` 就是
抽中了那 1/5。详见 `docs/az_value_data_scale_hypothesis.md`。

→ **前几天所有基于单次训练的对比（池化/tau/kgeo/rel/v50 配方），在 ±20pp 量级全部作废。**

### 2. 根因假设：有效样本量 = 局数（336），不是帧数（287K）

terminal 标签每局一个常数；kgeo/tau 这类逐帧标签在同一局内高度相关（血量差是慢变量）。
所以独立监督单元 ≈ **局数**。336 个独立标签拟合 55 万参数 → 噪声主导。

→ 修法：**大幅增加局数**。

### 3. 数据生成的成本（已实测，16 workers）

| 采集配置 | 速度 | 500 局/轮 | 备注 |
|---|---|---|---|
| 裸策略（无搜索）| ~0.5 秒/局 | ~8 分钟 | 分布不是搜索分布（有偏差风险）|
| **浅搜索 64 iters / depth 2** | **~29 秒/局** | **~15 分钟** | 搜索分布，可接受 |
| 浅搜索 32 iters / depth 2 | ~14.5 秒/局 | ~8 分钟 | 更便宜、更弱 |
| 全强度 256 iters / depth 4 | ~30 分钟/局 | 不可行 | 现有 336 局就是它 |

裸策略的分布偏差有弱证据支持（gen120 裸策略 200 局 → 15.6%，而同量级搜索数据 23-30%），
所以**主体用浅搜索**。

## 设计

### 核心：累积式迭代（标准 AZ replay buffer 式），但**只更新价值头**

```
池子初始 = 现有 warm_polonly（336 局，全强度 256/4 搜索）
for round k = 1..N:
    1) 采集：用「az_r10 策略 + 第 k-1 轮的价值头」做**浅搜索**自对弈，采 GAMES 局
       （GAMES=500 默认；iters=64 / max-depth-rounds=2 / --native-engine）
    2) 追加进累积池
    3) 训练：从第 k-1 轮的价值头 **warm-start**，在累积池上训 EPOCHS 个 epoch
       （冻结骨干；标签用 terminal 或 kgeo，可配）
    4) 记录：held-out 局的 value MSE；每 K 轮评价一次 vs rule_v4（64 局）
```

**为什么只更新价值头**：策略固定（az_r10）可以隔离"价值迭代"这一个变量；历史教训是
联合训练会坍缩（`az_training_validation_results.md` §20），且策略-价值强耦合会让归因困难。
更新价值头会改变搜索 → 改变采集数据 → 价值头随之迭代，这就是价值迭代。

**为什么 warm-start 而不是每轮重训**：累积池会越来越大，每轮从零训会越来越贵；
warm-start 后每轮只需少量 epoch，成本可控，且更接近 AZ 的连续训练。

### 关键设计选择与风险

| 选择 | 理由 | 风险 / 缓解 |
|---|---|---|
| 浅搜索（64/2）采集 | 全强度不可行；浅搜索便宜 ~60 倍 | 弱搜索局的**标签质量更差** + 与评测配置（256/4）有分布差 → **缓解：池子保留 336 局全强度数据；把 iters 作为可调参数，必要时升到 128/2** |
| 只更新价值头 | 隔离变量、避免坍缩 | 策略固定 → 局面多样性可能收敛；**缓解：保留随机动作注入（`--random-action-prob`）作为可选** |
| 冻结骨干 | 沿用当前配方（可复现） | 与历史 v50（不冻结）不同 → 若某轮明显变好，值得单独测解冻 |

## 实现清单

改动比之前大，**先做计划（本文档）→ 评审 → 再写代码**。

1. **`value_warmup.py` 加流式加载**
   - 现状：`load_all_data` 把全部 npz 读进内存（336 局 ≈ 9-12GB，硬上限 ~400 局）。
   - 目标：`--stream` 模式——每 epoch 遍历文件（或按 N 局合并的块），逐块加载→打散→
     训练→释放。内存与池子大小解耦。
   - 参考历史方案：`docs/value_data_merge_and_train.md`（多局合并 + 分块流式）。
2. **搜索采集直接写轻量 npz**
   - 现状：`az_selfplay.py` 写 pkl（含 bundles/visit/intent_counts 等重字段）→
     `convert_pkl_to_warm_npz.py` 单进程转换（256 局要 10 分钟）→ 每轮转换会成为瓶颈。
   - 目标：一个新采集脚本/模式，跑浅搜索，**直接写** `board/stats/action_map/
     head_logits/player/value_target` 的 npz（与 `warm_polonly` 同 schema）。
3. **循环脚本 `run_value_loop.sh`**（含 `run_logged.sh` 记录）
   - 串行执行各轮；每轮打印池子大小、训练耗时、held-out MSE。
   - **硬规则：任何时刻只允许一个 eval/采集在跑**（机器 13 核，eval 已用 16 worker；
     之前并发导致两个 eval 都卡死）。

## 成本估算

| 项 | 单轮 | 10 轮（池子 ~5000 局）|
|---|---|---|
| 采集 500 局（64/2）| ~15 分钟 | ~2.5 小时 |
| 训练（warm-start，流式）| ~10-20 分钟 | ~2-3 小时 |
| 合计 | ~30 分钟 | **~5 小时** |

## 判读标准（事先定好，避免事后挑）

1. **主判据：多种子离散度**。在最终池子（~5000 局）上训 4 个种子，各 64 局 vs rule_v4：
   - 若离散 **≤ ±5pp** → 体量成功压住随机性 → 之后所有对比才有意义；
   - 若仍散（>±10pp）→ 体量不是解，回头查标签/分布/优化。
2. **副判据：held-out value MSE 是否随轮次单调下降**（训练是否在真的"学到更多"）。
3. **参考**：当前 336 局的 4 种子离散 = 25.0~29.7%（±2.3pp，但含 1 个 50% 离群）。
   注意"±2.3pp"是**典型种子**的离散；真正的风险是**离群**，所以要看是否有新的离群点。

## 不做的事（明确边界）

- 不更新策略（本循环只动价值头）。
- 不引入新的标签形式（先用现有 terminal / kgeo 两个即可）。
- 不在本循环里并行跑任何其他实验（避免重蹈并发卡死）。
