## 1. 目标与判据

| 项 | 内容 |
|---|---|
| **唯一判据（验收）** | `vs rule_v4` 的 **128 局 = 64 对镜像**，**配对胜率 ≥ 70%** |
| **统计** | n=128、p̂=0.70 的 95% 区间约 **±8pp** ⇒ 与基线（待测；历史 46.9% 是**旧协议**）差 >20pp ⇒ 能干净判定 |
| **必须同时报告** | **"变强了多少"** —— 即使没过 70%，也如实记录相对基线的变化（例如 55% 也是信息） |
| **日常迭代读数（快读数）** | **样本量由 AI 按「本次想分辨的效应量」自定**（用户 2026-10-05），**但必须在预注册里写死**（见下）；seed 只能取钉死列表的**前缀** |
| ⚠️ 两者的关系 | **快读数 = 验收 seed 列表的前缀**（嵌套 ⇒ 可比、不是两套 seed）|
| 🚫 硬约束（防 optional stopping）| **样本量（或「延长规则」）必须在看见数据之前写进预注册**；看见数据后再加样本，**只有按预先写好的延长规则加**才算数，否则那批读数**作废** |
| 📐 选 n 的依据（95%、最坏情形 p≈0.5；`n ≈ 0.96/Δ²`）| 想分辨 **20pp** ⇒ n≈**24**（12 seed）；**15pp** ⇒ ≈**43**（22）；**10pp** ⇒ ≈**96**（48）；**8pp** ⇒ ≈**150**（>64 seed ⇒ 只能靠**验收**）；**5pp** ⇒ ≈**384**（要加厚验收）|
| ⚠️ 快读数不作判定 | 无论选多大，**正式判定只认 128 局验收**（±8pp）|
| **轮次预算** | **待定**（建 goal 时设定；建议先 **30 轮**）——循环**不得自己改** |

## 2. 度量协议（**钉死；改它 = 作废并重测基线**）

- **对手**：`其他版本ai/rule_v4`，经 `code/test_match/rv4_pkg/main.py`（协议壳）。
- **我方**：`code/test_match/az_bridge_ai.py`；**环境变量就是"我们"的配置**（ckpt + 搜索参数）。
- **裁判**：`code/cpp_engine`（bridge = `code/test_match/match_via_sdk.py`）。
- **配对**：`_tmp_ladder.py`，token `N` = 我方先手、`Nr` = 对手先手 ⇒ 64 对镜像；
  **读配对分**（不是裸胜率）。
  ⚠️ **不要用 `eval.py` 当这个判据**：它按 seed 序号交替先手，**不是同 seed 镜像** ⇒ 拿不到配对量。
- **基线配置（"我们"的起点，钉死）**：

  ```
  AZAI_CKPT=training_history/vprior/posnet_A_k5_m32.pt
  AZAI_ITERS=256 AZAI_DEPTH=4 AZAI_MODE=joint AZAI_POSPIN=argmax
  AZAI_TCLASS=0.5 AZAI_TPOS=1.0 AZAI_TEMP=1e-6 AZAI_VERIFY=1 AZAI_TRACE=1
  --jobs=8
  ```
- **seed 列表（一次钉死 64 个）**：`7..70`（有序）。展开镜像：每个 seed 两个 token（`N` = 我方先手、
  `Nr` = 对手先手）。
  - **快读数**：取**前 k 个 seed**（k 由预注册决定，按上表查精度）⇒ `7 8 … (7+k-1)` 及其 `r` 变体 = **2k 局**；
  - **验收**：取**全部 64 个**（`7..70`）⇒ **128 局**；
  - ⇒ 快读数是验收的**子集**，两者**可直接比**（这也是为什么把 seed 列表一次钉死）。
- **允许改**：模型 / 训练方法 / 架构 / 超参 / 数据 / 搜索配置 —— **"我方"的任何东西**都可以换。
- **不许改**：判据、seed 集合、引擎、镜像方式。改这些就是**协议变更** ⇒ 必须记档 + 重新预注册，
  且**新旧读数不得直接相减**（2026-09-22 已量化：同 seed 只换引擎，`rule_v4` 自对弈 4/8 胜负翻转）。
- **每次读数必须记录完整配置**（进 `docs/experiment_log.md` 的 `run_logged` 条目）。
- 🚫 **禁止走"模仿前两名"的捷径（用户 2026-09-25 要求）**：
  - **不许**把 `rule_v4` / 冠军 / 亚军的**动作当模仿目标**：行为克隆、策略蒸馏、
    用它们的动作当监督标签或辅助损失（含"预测它会怎么走"这类辅助任务）——**都不行**；
  - **允许**（这些不是模仿）：把它们当**对手**（对局 / 训练环境）；把它们当**诊断参照**
    （看它们怎么打、当机制读数）；以及**我们自己的**"搜索 → 策略"蒸馏（项目主线）；
  - **理由（不是洁癖）**：① 克隆一个**更强的老师**就能跨过"vs rule_v4 ≥70%"这道门，
    而那**不能**证明"我们的方法会优化" —— 测的是代理，捷径走的正是代理与真目标之间的缝；
    ② 记忆里的 **parity ceiling** 实测结论：蒸馏上限 = 老师水平 ⇒ **克隆冠军最多持平，
    永远到不了"打败冠军"** ⇒ 这条捷径**反正到不了真目标**，封掉它不损失任何可行路径；
  - **破例必须走机械门**：写新预注册（理由 + 影响）+ 独立验证 + 记档，并明确标注
    "**这一批读数不再支持'方法有效'的结论**"；
  - **不在禁令内**：`ExampleAI`（官方样例 AI，**很弱**）—— 它只被用作**初始化**；以它当老师
    **不可能**跨过"以 rule_v4 为对手"的门 ⇒ 构不成捷径。（若将来用到 ExampleAI 的蒸馏，仍要披露。）
  - ✅ **起点血统已确认（2026-09-25，用户直接确认）**：`posnet_A_k5_m32` 的祖先只蒸馏过
    **ExampleAI**（弱老师、仅作初始化），**rule_v4 未参与初始化** ⇒ **不触碰本条禁令**，
- 🚫 **手写启发式只能当「诊断臂」，不能当交付物（用户 2026-10-05 要求）**：
  - **允许**：把人工写死的规则 / 启发式当**诊断臂** —— 用它测「空间有多大」（headroom）、定位瓶颈形状。

## 6. 环境与**恢复机制**（⚠️ 别用 `reset --hard` 回早期 tag）

- 分支：**`goal/ruleV4-70`**。**本任务的全部提交都在这里——包括章程/寄存器/objective 这些「治理文档」的修订**。
- **为什么不能 `git reset --hard <早期tag>`**：它把**分支指针**拽回去（提交本身没被删），但**工作区会退回旧版**
  ⇒ 不仅丢掉本任务此后的全部提交，而且**章程会退回旧版**（回到那个 `k=1` 的坏配置、且没有两条反捷径条款）。
  对一个"每轮都读章程"的活任务，这是最危险的一类"恢复"。
- **正确的回退方式**：
  - 撤销最近若干提交 ⇒ **`git revert <sha...>`**（生成反向提交，历史与文档都保留）；
  - 回到"某个已知良好点" ⇒ 用**滚动前进的 tag**（`goal-good-<日期>`，在"确认这段时间没问题"时打），
    **不用**起跑点的 tag；
  - 真要用 `reset --hard` ⇒ **先给治理文档的提交打 tag**，否则只能靠 `git reflog` 捞。
- **tag 现状**：
  - `goal-start-20260924` —— 起跑前的快照（含当时遗留的 17 处未提交改动）；**仅供考古，不要用它回退**；
  - `goal-ready-20260925` —— 起跑就绪点（快照 + 首版章程）；
  - `gov-20261005` —— **治理文档的当前版本**（含两条反捷径条款、64 局/自定 n 的口径）；
    **要回退代码时，先确认治理文档不回退**（必要时 cherry-pick 这个 tag 里的 docs 提交）。
