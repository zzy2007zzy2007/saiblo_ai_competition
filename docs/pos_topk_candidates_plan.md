# 计划：**位置候选"确定化"（top-k 取代采样）** —— 让候选集合成为状态的确定性函数

- 日期：2026-10-11
- 提出人：用户（"既然类完全由 MC rollout 确定，候选可以不用采样，直接取位置网分数前 k 个格"）
- 动因：本会话测出**搜索不可复现的主因是候选生成里的位置采样**（见 `docs/experiment_log.md` 86n 与
  `docs/actionnet_retrain_summary.md` §3.1）：同一局面换 `seed` 跑两次搜索，**候选集合只有 1/12 完全相同（Jaccard 0.45）**；
  把位置采样设为确定性后 ⇒ **候选集合与选择 12/12 完全一致**（但候选塌成 1 个）。且 `t_class` 完全不起作用（类是 MC 仲裁钉的）
  ⇒ **随机性全部来自"格"** ✓。

## 1. 现状（代码事实）

- `code/my_ai/az_intent/bundle_mcts.py:519-524`：`n_samples = k * sample_mult`（部署 = 24 × 15 = **360**）；
- 每次采样在"钉住的类"下从 `action_map[类]`（合法格掩码内）**采样格**（`t_pos=1.0`）并解码成束（≤3 op）；
- `:397` + 聚合逻辑：**按解码出的 key 出现次数取前 k 名**当候选 ⇒ 候选清单 = "**采样频率前 k 名**"；
- ⇒ 频率估计带噪 + `k=24` 对 ~33 个合法格已近全覆盖 ⇒ 两次搜索的清单只重叠 ~45% ✗。

## 2. 拟改动（**新增，默认关闭 ⇒ 任何既有读数逐位不变**）

新增环境开关：

| 变量 | 默认 | 含义 |
|---|---|---|
| `AZAI_CANDS` | `sample` | `sample` = 现状；**`topk` = 新行为** |
| `AZAI_CANDS_K` | = `K` | `topk` 模式下取前几个格（0 ⇒ 用 `K`） |
| `AZAI_CANDS_COMBO` | `1` | `topk` 模式下是否**附加确定性组合候选**（每头 top-1 格拼成一束），保留"多 op"表达能力 |

`topk` 模式实现（仅在 `search_mode=pos-only` 且类已钉住时生效）：

1. 取该类的合法格集合 `{(x,y)}`（复用现有 `position_mask[类]` 与解码器可执行性过滤）；
2. 按 `action_map[类, x, y]` **降序**排序，**并列按 (x,y) 字典序**（保证严格确定性）；
3. 取前 `K` 个 ⇒ 每个候选 = **单 op 束**；若 `CANDS_COMBO=1`，再追加
   "每个头 top-1 格的 op 拼成一个束"（≤3 op ⇒ 保留组合表达）；
4. 不调用 `self.rng` ⇒ 候选集合 = **状态的确定性函数** ✓（`sample_mult` 不再参与）。

## 3. 预注册门槛（跑之前写死）

| 阶段 | 指标 | 门槛 |
|---|---|---|
| **零对局预检**（~10 min，`diag_search_repro.py` 扩一个 `--cands topk`）| 同局面两次搜索候选集合相同率 | **≥ 12/12（期望 100%）** |
| 同上 | 新清单**包含"现部署所选的格"**的比例（用真实对局 dump 的 `labels[chosen]` 对照）| **≥ 80%**（预期不低：Q1 审计显示执行格 65% 在图的 top-10 内）|
| 同上 | 决策耗时 | 不劣于现状（采样 360 次解码消失 ⇒ 预期变快）|
| **判据臂**（固定段 7..70、128 局、8 线程、**只改 `CANDS=topk`**）| `p̂` | **≥ 0.6797（incumbent）** 记为"确定化不掉强度"；< 0.6497（−3pp）记为"确定化伤强度" ⇒ 停 |

## 4. 若预检+判据都通过 ⇒ 打开的新路（本计划之外，单独预注册）

候选集合确定后，**搜索的 visit 分布第一次成为良定义的目标** ✓ ⇒ 原目标的"路线 A（蒸搜索偏好）"从**结构性不可学**变为**可学**：
可以重新做"位置头 ← 搜索 visit（在确定性候选集上）"的蒸馏，并按 §8.1 的闸门 + 128 局判据评估。
⚠️ 天花板依旧是**冻结价值网**（搜索的叶评估就是它，`DEPTH=4` 只是浅前瞻）⇒ 预期收益有限，需先量"目标质量"再决定是否花判据。

## 5. 风险

1. **尾部永久排除**：`k=24` / ~33 格 ⇒ 图上排名 25 名之后的格**再也不会被考虑**（今天采样偶尔会试到）✗；
2. **组合能力**：若 `CANDS_COMBO=0`，只能出单 op（部署有 ~22% 出手回合是 2+ op）⇒ 默认设 `1` 缓解；
3. **与冻结配置的关系**：这是**配置维改动**，会让"单变量"基线从 `MC1` 变成"`MC1` + `CANDS=topk`"⇒ 判据臂必须
   与 `MC1` 同批对照（固定段 7..70），且只此一处不同 ✓。
