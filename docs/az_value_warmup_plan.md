# 价值头预热 + 策略锚定 方案（给 gen_0120 补价值头）

> 目标：给 gen_0120（扩 3 头）补一个有信息量的价值头，同时锚住它已有的强策略，
> 使 MCTS 搜索能工作（搜索 + 好价值 ≥ 原始策略），从而让 AlphaZero 自对弈有意义。
> 日期：2026-08-05。状态：设计阶段。

## 1. 背景

- gen_0120 策略强（TOP1 原始 1 头 100% 赢 ExampleAI），但**没有有信息量的价值头**
  （ES 用胜率适应度优化策略，价值头退化/常数；之前实验还把它重初始化成随机）
- 搜索需要价值引导：无信息价值（随机/常数）→ 搜索必然崩（已证实：100% → 0%）
- 不能直接从零训 AlphaZero：价值训练会通过共享 encoder 改变解码影响策略 → 需要**策略锚定**
- 参考：之前蒸馏 example 的管线（评分函数拟合，`docs/distill_example_ai.md`），但没有价值头；
  本方案借鉴其"记录完整动作输出"的思路，新增价值头训练

## 2. 数据采集（自对弈，原始策略）

**模型**：gen_0120 TOP1（修复后 `top2_params[0]`）扩成 3 头。

**对局**：双方都用**原始策略**（每回合一次前向 + decoder 解码 3 头 + 应用操作 + advance_round），
**不做搜索、不带探索**（避免引入额外变量）。

**每决策记录**（完整动作输出，作为策略锚目标）：
```
board       (28,19,19) f16
stats       (42,)      f16
action_map  (24,19,19) f16   ← 网络空间策略输出
head_logits (3,24)     f16   ← 3 个头的分类输出
player      (0/1)            ← 价值视角
```

**终局价值标签**（用户决策：血量差）：
```
value_target = clip((hp_us_final - hp_opp_final) / 20, -1, 1)   # 从 player 视角
```

**规模**：原始策略无搜索开销，一局 ~5 秒。首轮 **200 局**（~100K 决策样本，用户定）。

**多进程采集**：参考 `code/distill/collect.py` 的模式——`mp.Pool` 并行，每个 worker 加载模型打一局、
把样本存成 npz（每局一个文件），主进程收集完再统一加载训练。~8 workers 下 200 局 ≈ 3-5 分钟。

> ✅ 验证步骤 V0 已通过：**TOP1 扩 3 头原始策略 vs ExampleAI = 100%**（之前担心 3 头扩头削弱
> 策略不成立——那是弱版 model_state 的问题）。锚定将锁定强策略。

## 3. 训练（策略锚定 + 价值头）

**模型**：gen_0120 TOP1 扩 3 头，从头训练（或从采集模型初始化）。

**策略锚定损失**（作用是**不让策略跑偏**，不是学习信号——是正则器）：
```
L_anchor = CE(模型 action_map, 记录的 action_map) + Σ_head CE(模型 head_logits, 记录的 head_logits)
```
用记录的 logits 作为软目标（self-distillation）。模型初始就在目标处，损失从 ~0 开始保持低位。

**价值损失**（真正的学习信号）：
```
L_value = MSE(价值头输出, value_target)
```

**总损失**：`L = L_anchor + λ_value · L_value`（λ_value 可调，初始 1.0）

**优化器**：AdamW，lr 1e-3 量级，few epochs（锚定收敛快，价值头多训几轮）。

> 注意：策略锚定本质是自我指涉（目标来自模型自身），但**目的不同**——不是提升策略
> （那才是蒸馏文档警告的闭环问题），而是**稳定策略**、防止价值训练通过共享 encoder 拉偏它。
> 价值头接收的是真实的胜负/血量差信号，不闭环。

## 4. 验证（关键）

1. **价值头有效性**：在若干局面上预测血量差，确认不是常数（有区分度）
2. **策略保持**：重训后 vs ExampleAI（知情对手）≈ 原始 3 头水平（锚定生效）
3. **搜索健全性检查（决定成败）**：`搜索 + 重训后的价值头 vs 原始策略`
   - 若搜索 ≥ 原始策略 → 价值头是缺的那块拼图，AlphaZero 自对弈可继续
   - 若搜索仍 < 原始策略 → 问题在搜索本身（先验-解码不一致 / 3 操作循环），
     需单独修搜索（本次方案不覆盖）

## 6. 风险

| 风险 | 缓解 |
|------|------|
| 3 头扩头打法本身就弱（锚定锁定弱策略） | V0 先测；若 3 头弱，考虑 1 头 AlphaZero 或修扩头 |
| 自对弈局接近 → 血量差目标小（±0.3），价值区分度弱 | 用户选择血量差；若验证不佳可切 ±1 |
| 锚定太强阻止价值驱动的 encoder 更新 | 调 λ_value；验证价值头确实变有信息 |
| 搜索仍有先验-解码不一致（锚定解决不了） | V3 诚实暴露；若不过，单独修搜索 |

## 7. 一句话总结

**采集 gen_0120（扩 3 头）原始策略自对弈数据（完整动作输出 + 血量差），训练时用动作输出锚定策略、用血量差训练价值头，得到一个"策略保持强 + 价值头有信息"的模型；然后做搜索健全性检查，确认搜索 ≥ 原始策略后再进 AlphaZero。**
