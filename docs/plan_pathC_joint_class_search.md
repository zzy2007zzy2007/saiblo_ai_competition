# 路 C 计划：把"类"从**手搭菜单**升级为**每次决策都搜索**的一等维度

> 真实日期 **2026-10-09**。这是 `docs/goal2_path_to_80.md` 里"路 C"的**具体化**（按仓库规范：大改前先写计划）。
> 上位目标 `goal-2600a56a`。现状：判据最好 **0.7188**（`MC1 + 搜索值网`），距 0.80 差 **8.1pp**；
> 本轮（第 53 轮）已实测"**堆小杠杆饱和**"（`V+K48` = 0.7188 = 只用 V）。

## 1. 为什么必须动结构（三条实测）

| 事实 | 数值 | 含义 |
|---|---|---|
| 决策的**候选数**分布 | **91.6% 的决策只有 1 个候选**（`{1:2688, 2:12, 3:20, 4:14, 12:2, 13:6, 14:12, 21:2}`）| 搜索对绝大多数决策**无事可做** |
| **进搜索**的比例 | **80% 的决策根本不进搜索**（`SKIP1=1` 直接短路）| 搜索只在"多候选"时生效 |
| "类"由谁定 | **手搭机械菜单**（HOLD + 闪电 + top-k 经济类 + 显式升级），且**每 5 回合才仲裁一次** | 类的决策质量 = 菜单质量 + 裁判质量 |
| 当裁判的价值网 | rollout **0.9375** ▸ 三张学习价值网 **0.4531 / 0.3438 / 0.2031** | **"让价值网替代 rollout 当裁判"四次否证** |

⇒ 结论：在"类由 5 项手搭菜单决定、且 91.6% 决策单候选"的结构下，判据被**结构性锁死**在 0.72 附近。
**继续同样结构的调参（我这一 goal 已穷尽十余条轴）不会到 0.80。**

## 2. 路 C 要做什么（具体到开关与代码位置）

### C1（第一步，**已有实现、只是从未在判据尺度认真跑**）：`joint` 模式 + 有分布的类头
- **模式**：`AZAI_MODE=joint`（类与格一起进搜索），`AZAI_K>1`，`AZAI_SKIP1=0`（**不短路单候选**），
  类头用 `checkpoints/grafted_phold10.pt`（HOLD 降采样 10× 重训 ⇒ 类头**有分布**，冒烟已验证非退化）。
- **实测已知问题（churn 风暴）**：冒烟 33 次降级 / 36.5 次升级 / 79 回合 ⇒ **类头过度采样"升级/降级"**，
  而这些动作**多数不可执行**（钱不够/塔不在）⇒ 搜索在**不可行**候选上浪费预算。
- **计划修法（C1.1，~30 行，落在 `bundle_mcts` 的候选生成处）**：
  1. **可行性剪枝**：类头采样前，按**经济可行性**过滤菜单（升级需塔 & 钱 ≥ 升级价；降级需塔；建塔需钱 ≥ 价格 & 空位 & 在范围内）
     ⇒ 与 `mc_quiet` 的候选构造**共用同一套可行性判定**（避免两处口径不一致）。
  2. **不可行候选的 visit 记账**：若某类全不可行 ⇒ 记为"无效候选"（不进 PUCT），并在日志里计数（便于诊断）。
  3. **HOLD 下限**：保证每步至少留下 HOLD（禁止"必须做事"的强制 churn）。
- **成功判据（冒烟）**：每局**升级+降级 ≤ 12**（对比 churn 风暴的 ~70）、回合数 ≤ 60、闪电 0、建塔 ≥ 1。

### C2（第二步，若 C1 的判据 ≥0.72）：**每次决策都仲裁**（去掉"每 5 回合一次"）
- 现在 `MC_EVERY` 控制的是"MC 仲裁频率"，而 `joint` 模式下类由类头采样 ⇒ 两者叠加会让类决策**来源不一致**。
- 计划：`joint` 下**强制 `MC_EVERY=1`**（或直接关掉 MC，让搜索自己决定类），并记录"类决策来源"的计数。
- **风险**：慢 2.6×（`joint` 实测）⇒ 128 局约 13 h（可接受，用户允许小时级~十小时级）。

### C3（第三步，若 C1/C2 到 0.74+）：**把价值网接回 C1/C2 的叶评估**
- C1/C2 的搜索更依赖叶值 ⇒ 用**搜索值网**（`grafted_sdk_A_vsearch.pt`）；再往上可做价值迭代（护栏改为"同目标比较"）。

## 3. 实验顺序、成本与判据（先写死）

| 步骤 | 命令要点 | 规模 | 成本 | 判据 |
|---|---|---|---|---|
| **C1 冒烟** | `MODE=joint K=24 SKIP1=0 PIN=argmax CKPT=grafted_phold10.pt` + C1.1 剪枝 | 2 局 | 5 min | 上节的**机制判据**（≤12 升级+降级 等）⇒ 不过就改剪枝再冒烟 |
| **C1 判据** | `C1` vs **冻结基线**（`MC1` 口径的其余项不动）| 128 局（64 对）| ~13 h（8 线程 ~7 h）| ≥0.80 ⇒ 走成功核对清单；0.72–0.80 ⇒ 进 C2；<0.72 ⇒ 回炉剪枝一轮（最多两次） |
| **C2** | `C1 + MC_EVERY=1`（或关 MC）| 128 局 | ~13 h | 同上 |
| **C3** | `C2 + 搜索值网` | 128 局 | ~13 h | 同上 |

- **反捷径**：只用**训练专用 seed 段**（≥10000）采数据；判据段/随机段/未见段**不训练**；不模仿 rule_v4/冠军/亚军 ✓。
- **预注册**：本文件即 C1 的预注册（机制判据 + 判据尺度 + 分支）；
- C2/C3 在开始前**追加**对应的预测与阈值（不预写结论）。

## 4. 我的预测（先写死，事后对照）

- **C1 冒烟通过**概率 ≈ **60%**（剪枝逻辑直接照 `mc_quiet` 的可行性判定抄，风险主要在校准松紧）。
- **C1 判据 ≥0.72** 概率 ≈ **35%**；**≥0.80** 概率 ≈ **5%**。
- **C1+C2+C3 全部做完后 ≥0.80** 概率 ≈ **15–25%**（与目标文本里"允许数日算力做 2–4 轮策略迭代 ⇒ 25–35%"一致，我取下沿）。
- **最可能的结局**：C1 判据落在 **0.68–0.74**（结构性改动提升了"类的决策质量"，但远不足以补 8.1pp）⇒ 那时应当**如实记录并请用户决定**：改口径（+18pp 已是本项目最强效应）或投更大规模（更大网 + 更多自对弈数据 + 真正的 RL 环，量级为**数天–数周**）。
