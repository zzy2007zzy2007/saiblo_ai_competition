## 2. 主读数（判据）

**主统计量 = 配对分（paired score）**：

```
每个 seed s： 我们的得分 sc(s) = （该 seed 两局里我们赢的局数）/ 2      ∈ {0, 0.5, 1}
配对胜率 p̂ = mean_s sc(s)      （s 取 7..70，n = 64 对）
```

- 本设计里每对局数相同 ⇒ **p̂ 在数值上 = 128 局的裸胜率**；
  但**不确定性按"对"算**（对内的两局不独立），所以：
  - **主 CI** = **cluster bootstrap over seeds**（重采样 seed，10000 次，`random.seed(20261005)`）；
  - 参考值（仅参考、不作判据）= 128 局 Wilson 区间。
- **判据（验收）**：`p̂ ≥ 0.70`。
- **必须同时报**：`p̂` 的**点估计 + 主 CI**、**逐 seed 的 2-0 / 1-1 / 0-2 分布**、
  以及**相对基线的变化**（本轮就是基线本身，故填"基线 = 本节读数"）。
- **先手侧**：另报 p0/p1 胜负数（不给判据，只看有没有侧偏）。

## 3. 预注册的**预测**（把它变成一次真检验，而不是"记录一个数"）

- **P1（点预测）**：`p̂ ∈ [0.35, 0.60]`（点先验 0.45 —— 依据：历史旧协议 46.9%，
  但**旧协议不能直接比**，所以区间取得宽）。
  - 若落在区间内：符合预期 ⇒ 历史 46.9% 与当前协议**量级接近**（★注意：这只是"量级"，
    **不构成"跨协议可比"** 的结论）。
  - 若 `p̂ < 0.35`：**当前协议下的基线明显低于旧协议读数** ⇒ 记档，且"要爬的坡"更大。
  - 若 `p̂ ≥ 0.70`：**立刻走 §5 机械门**（独立验证），不得自行宣布成功。
- **P2（机制预测，观测指标）**：我方**每局建塔数中位数 ≤ 12**、**出招回合数中位数 ≤ 30**
  （依据：`B0/B1/B2` 的机制读数 12–25 回合 / 建塔 2–12 次）。
  预期 `rule_v4` 每局建塔数**显著高于我方**。
  ⚠️ 这两条是**观测**，**不是优化目标**（总章程 §2）；它们只用来回答"方法修好了没有"。

## 4. 有效性门槛（**看到数据之前写死**）

逐 token 判定，任一条件不满足即该局 `INVALID`、**不计分**：

1. 日志里有 `RESULT ... winner=...` 行，且 `winner != INVALID`；
2. `verdict == engine`（官方 5 级级联；`hp_tiebreak` 不算）；
3. `illegal == 0`（出现 `!! [round ...] ILLEGAL` 即废）；
4. `rounds > 0` 且 `terminal=True`。

另**单列告警**（不自动废，但必须报）：僵局嫌疑（双方操作总数 ≤2）、`rc != 0`。

**整批的作废门槛（先写死）**：有效局 **< 115/128（即无效 > 10%）** ⇒ 本批**标 INVALID**、
**不作为基线**；先查原因（历史：分帧 bug 会以 `need N B, have M B` 超时签名出现），修好后重测，
并记档说明"为什么这批不作数"。

🚫 **看到数据后禁止做的事**：改 seed 集合 / 改样本量 / 改判据 / 只报子集。
若想加样本，只能按**本文件里预先写好的规则**加 —— 本批**没有**延长规则 ⇒ **就是 128 局，一次到位**。
