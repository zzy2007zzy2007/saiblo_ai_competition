# 预注册：**MC 菜单加宽**（`AZAI_MC_TOPK=k`）——"让经济候选真的有多样性"

> 2026-10-07 第 2 轮写（**在跑之前**）。章程：`docs/task_ruleV4_90_charter.md`。

## 0. 假设与由来（三条硬证据）

**H-R2**：把 MC 的**经济候选从"1 个"加宽到"top-k 个互不相同的类"**，能让机制真正去比较
"建塔 / 升级 / 别的塔类 / HOLD"，从而改变我们的塔的形态（由"又宽又浅"变成有升级），
并带来 **≥ +8pp**（64 局筛选）。

1. **现有菜单的经济候选实际上只有一个**：MC dump（6,249 次决策）里全部选择只有
   `{HOLD 4145, 类 16 降级 1160, 类 0 建塔 874, 闪电 70}` ⇒ "map 最热的经济类"**永远是类 0 或类 16**
   （跨类的 `action_map` 最大值**不可比**，所以这个 `argmax` 没有意义）。
2. **由此产生一个和对手明显不同的塔形态**（256 局实测）：我方 **建塔 24–25、升级 0、降级 10–12**；
   对手 `rule_v4` **建塔 16、升级 9.4、降级~15**。
3. **败局签名**（256 局，`code/test_match/diag_loss_signature.py`）：我方"升级/降级"次数在**负局更高**
   （中位 12.5 vs 10.0，Cliff's d = **−0.302**）；且 **54% 的负局是"惜败"**（对手终局 ≤10 HP）
   ⇒ 胜负由**很小的血量差**决定 ⇒ 塔的"形态"（宽浅 vs 高深）**很可能**就是那点差。
4. **这一轴从没测过**：第 1 轮测的是**评价器**（安静/K=8/K=32）与**位置网权重**，两者都证明"换组件不改强度"；
   而**菜单构成**是另一件事——历史上它摆动过 **±23pp**（M6b `0.6641` vs M6b-ND `0.4297`）。

## 1. 臂（写死；**除菜单宽度外一切不动**）

| 臂 | `AZAI_MC_TOPK` | 菜单 | 成本/决策 |
|---|---|---|---|
| **M-1（对照）** | `0` | {闪电?, HOLD, 1 个经济类} = **现状** | ~0.5–1 s |
| **M-4** | `4` | {闪电?, HOLD, **4 个互不相同的经济类**} | ~2–3 s |

- 公共配置 = 第一里程碑达标配置原样（`M6c-ROOT`，`MC_BIDIR=0`、`MC_HORIZON=256`、`MC_EVERY=5`、`MC_ROOTONLY=1`）。
- **M-1 的同前缀读数 = `0.6562`**（已有，来自 `M6cROOT_128` 的 `7..38`）⇒ 无需重跑。
- 每臂 **64 局 = 固定段前缀 `7..38`（32 对）**，`jobs=8`。

## 2. 判据（**先写死**）

- **晋级线**：`p̂ ≥ 0.6562 + 8pp = 0.7362` ⇒ 进**两段各 128 局验收**（换配置不算换 ckpt，但结论仍走独立验证）。
- **机制读数（必报，用来解释）**：我方 **建塔 / 升级 / 降级 / 闪电** 次数（**关键**：升级数是否从 0 变成 >0）、
  出招回合、`dec_max`/`dec_slow`（成本）。
- **前置检查（跑之前就能验，离线）**：dump 复现"经济候选永远只有 1 个"这一事实（已做，见 §0）。
- **成本闸门**：单局 > 6 min（8 并行）⇒ 只跑 64 局并记档说明，不硬上验收。
- ⚠️ 单段 64 局 ⇒ **只排除 >~12pp 的效应**；⚠️ 不许看数据后改判据/改 seed。

## 3. 预测（写下来，事后对照）

- **P1（机制，几乎必然）**：M-4 的**升级数从 0 变为 >0**、降级数下降（菜单里真的有别的类可选了）。
- **P2（分数）**：若塔的"高深化"真是那点血量差的来源 ⇒ **+8pp 以上**；
  若分数依旧不动 ⇒ 与第 1 轮两条线合起来，说明**决策层整体噪声 ≫ 任何单一组件差异**，
  那就该转向"**改 MCTS 的搜索本身**（例如根节点用更多候选/更深的精化）或换训练目标"，而不是继续换菜单。
- **P3（成本）**：`dec_max` 从 ~3.5 s 升到 ~10–15 s（4 个候选 ⇒ 4 次 rollout），仍远低于 300 s 读超时。

## 4. 判定与后续

- 晋级 ⇒ 两段验收 + 独立验证 + 记档；
- 不晋级且 **机制 P1 成立** ⇒ 说明"能表达但排序不准"（与 M5 的结论同类）⇒ 菜单这条线**转冷**，
  并把力气转向"**评价器/搜索**"或"**闭环重训**"；
- 不晋级且 **P1 不成立** ⇒ 说明实现层面没生效 ⇒ 先修实现再谈结论（**不许拿没生效的臂下结论**）。
