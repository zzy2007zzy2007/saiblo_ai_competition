# 计划：**拓宽候选菜单 + 同步提高迭代数**（用户 2026-10-13 提议）—— 测"先验筛选到底亏了多少"

- 试验名：`MENU100_vs_baseline`
- **假设（用户）**：AZ 里策略网 = **算力分配器**（把算力从差动作上省下来 ✓）；若"**宽候选 + 足算力 ≈ 窄候选**"，
  则说明"**筛哪些格**"（支撑集）不是瓶颈 ⇒ 动作网的优化空间不在这一侧 ✓。
- **配置**（**单变量**：只改搜索宽度/迭代；动作网仍是 incumbent `grafted_sdk_A.pt` ✓）：
  `AZAI_K=100`、`AZAI_ITERS=2000`（`ITERS/K = 20` ✓；零对局实测**每候选访问 ≈ 10.0** ✓ 落在用户要求的 10–20 ✓）；
  其余全部冻结（`pos-only / mc_quiet / TCLASS=0.5 / MC_EVERY=1 / SAMPLE_MULT=15 / TEMP=1e-6 / BAN_CLASSES=17 / BAN_OPS=21` ✓）。
- **零对局预检（已做 ✓，`code/my_ai/az_intent/probe_menu_width.py`）**：
  * 实际保留候选数 **12.5 → 50.5** ✗（受"按采样次数取 top-k"限制：`K=100` 只留 ~50 ✓）；覆盖不同格 5.2 → 7.5 ✓；
  * **与基线同格率 66.7%** ✓ ⇒ 菜单**确实改变决策** ⇒ 实验有信息量 ✓（不是注定平 ✓）；
  * top-1 占比 **3.8% → 6.7%**（更平 ✗）⇒ 拓宽**也可能变差** ✓；
  * 单次决策 **1.37 s → 18.69 s** ⇒ 128 局 ≈ **6.2 h** ✓（小时级，符合项目允许范围 ✓）。
- **预注册判读**（固定段 seed 7..70、128 局、`-Jobs 8` ✓）：
  * **`p̂ ≥ 0.68`**（≥ incumbent 0.6797）⇒ **筛选确实亏** ✓ ⇒ 动作网获得一个**可学的目标**（"把这些格纳入候选"✓）⇒ 值得继续 ✓；
  * **0.60 – 0.68** ⇒ 与 incumbent **不可分辨** ⇒ **支撑集不是瓶颈** ✓ ⇒ 该往"排序/价值"一侧找空间（名次曲线与 Q 预检都指向那里 ✓）；
  * **`< 0.60`** ⇒ 拓宽**有害** ✗ ⇒ 与"访问分布更平 ⇒ argmax 领先边际更薄"一致 ✓ ⇒ **先验筛选其实是净收益** ✓。
- **备选更便宜点**：`K=50 / ITERS=1100`（~3 h，候选 ~25 ✓）—— 若 6.2 h 结果不显著可再补 ✓。
- 成本：~6.2 h（8 线程 ✓）；跑完在 `docs/experiment_log.md` 补 result ✓。
