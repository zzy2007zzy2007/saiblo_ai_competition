# 预注册：**方法侧 M5 —— 把"类"交给搜索，但用一个小的候选菜单**（{闪电, HOLD, 一个经济类}）

> 2026-10-06 00:0x 写（**在跑这批数据之前**）。动机来自本轮已证的两件事：
> * **候选 A2**（joint 模式：搜索在 24 类上选）历史读数 `0.375`（比 A1 差）——但那是**24 类**的菜单，
>   而**价值网在类级上没有分辨力**（实测）⇒ 24 选 1 太容易选错；
> * 手写规则（闪电优先 + 富才花）能到 `0.6641/0.7344`（diagnostic）⇒ **"要不要花"这个决策本身值 +13…20pp**；
> * M1c/M1d/M2/M3 已证：**行为克隆与 Q 回归在"被行为策略决定"的数据上都无法识别它**（识别性）。
>
> ⇒ **本实验换一条路**：不学"哪个类"，而是把类决策**交回搜索**（= 我们自己的方法），
> 但把候选**限制到 3 个**，让搜索的深度展开（depth 4）去比较它们。**没有任何手写规则**；
> 唯一的"人为"部分是**候选集合的抽象**（闪电 / HOLD / 一个经济类），属于**动作空间表示**的选择，需要披露。

## 1. 臂（写死）

| 臂 | 候选菜单 | 说明 |
|---|---|---|
| 对照 A1 | `pos_pin=argmax`（不套掩码，= 闪电优先、否则 HOLD）| `0.5312` 验收 / 新段 `0.5391` |
| **M5** | **joint 模式 + `candidate_fn` 返回 3 个 bundle**：<br>① 闪电（放在 posnet 通道 17 的最热合法格）<br>② HOLD（空 bundle）<br>③ **经济类** = 类 0..16 中"位置网最热格值最高"的那一类（放在它自己的最热合法格）| 搜索用 depth-4 rollout 在这 3 者之间排序 |

- 其余 = A1 配置（`ITERS=256 DEPTH=4 TCLASS=0.5 TPOS=1.0 TEMP=1e-6`），`--skip-single-candidate` **关闭**
  （菜单恒为 3 个 ⇒ 没有单候选回合 ⇒ 单局会慢，成本闸门见 §3）。

## 2. 假设

**H-M5**：类决策的困难**不是"没有信息"，而是"信息在 1-ply 价值里表达不出来"**。
把候选压到 3 个之后，**depth-4 rollout 的终局差**应当能把"该不该花"分出来 ⇒ 搜索自己就会
"富才花、不富就 HOLD"（不用手写规则）。

## 3. 成本闸门 + 判据（写死）

- **成本**：先跑 **1 局**看用时；> 6 min/局 ⇒ 该臂只跑 **8 局（seed 7..10）** 并在记档里标注；
- **快读数**：**16 局（seed 7..14）**（若成本允许），否则 8 局；
- **机制判据（必须报）**：我方 **建塔数 > 0**（说明搜索真的会选经济类）且 **闪电 ≥ 10**（没饿死闪电）；
- **晋级**：16 局 `p̂ ≥ 0.55` ⇒ 32 局；`≥0.70` ⇒ 128 局验收 + 机械门；
- 有效性门槛同前。

## 4. 预注册的预测

- **P-M5a（机制）**：搜索会**偶尔**选经济类（建塔 > 0 但不是"到处建"）——若建塔 ≈ 0 ⇒ 3 选 1 也没用；
- **P-M5b（数值）**：`p̂ ∈ [0.40, 0.65]`；**我偏向"略好于 A1"**（因为它至少能表达"花"这个动作），
  但也可能因为价值网分不清而退化成随机 3 选 1（那大约就是 A1 与 D 的混合）。

## 5. 判定与后续

1. **机制成立 + `p̂ ≥ 0.55`** ⇒ 这是**方法侧第一条既无手写规则、又能表达条件行为的路径** ⇒ 跑 32 局 → 128 局；
2. **机制成立但 `p̂ < 0.55`** ⇒ 记"搜索能表达但排序不准" ⇒ 下一步给搜索**更深的 rollouts**（depth 8/16）或**更好的叶评价**；
3. **机制不成立（建塔 ≈ 0 或闪电 < 9）** ⇒ 记"3 选 1 也不行" ⇒ 与 M1c/M1d/M2/M3 一起构成
   "**类轴在当前表示/算力下不可学**"的证据链，转写结论报告。

## 6. 成本

实现 ≈ 30 min（我这边）；单局 ≈ 3–10 min（3 候选恒多选 ⇒ 不能 skip）；16 局 ≈ 20–60 min。
