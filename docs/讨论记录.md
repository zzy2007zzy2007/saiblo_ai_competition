## 讨论记录

### 2026-06-29：神经网络输出方案讨论

**议题**：动作空间极大，如何设计神经网络输出方式

**方案1**：多分支输出头（操作类型、位置、塔ID等分别输出）× 复制3-5份，解码成组合动作
**方案2**：动作评分法 — 用 ActionCatalog 生成候选 bundle，网络对每个 bundle 打分，选最高分

**结论**：采用方案2（动作评分法）

理由：
- 候选动作数固定上限为 96（MAX_ACTIONS），计算开销可控
- 零非法动作问题，候选全部由 ActionCatalog 保证合法性
- 天然支持组合动作（catalog 已产出 bundle）
- 易于与 MCTS 集成
- 采用 two-tower 架构：State Encoder（一次前向）+ Action Scorer（96 个轻量评分可 batch 并行）
- 训练信号清晰，标准 policy + value loss

**架构概要**：
- State Encoder: Conv/ResNet → state_embedding (d=256)
- Value Head: state_embedding → scalar
- Bundle Encoder: 编码操作序列 → action_embedding
- Scorer: state_emb ⊕ action_emb → MLP → score

### 2026-06-29：模型输入方案确认

**官方 SDK 已提供完整特征提取接口**（`SDK/utils/features.py` — `FeatureExtractor`）：

- `encode_board(state, player)` → `(28, 19, 19)` 空间特征图
  - 通道涵盖：地形、塔位置/等级/范围/CD/伤害、蚂蚁位置/血量/等级/年龄/状态、信息素、4 种超级武器区域
- `encode_stats(state, player, context)` → 22 维全局统计向量
  - 金币、血量、武器冷却、前线距离、塔数量/等级、击杀数、基地等级等
- `encode_observation(state, player, action_mask, context)` → `{"board": ..., "stats": ..., "action_mask": ...}`
  - **可直接作为网络输入**

**模型输入设计**：
```
board (28,19,19) ──→ Conv/ResNet ──→ board_emb
                                            ↓  concat
stats (N,)       ──→ MLP          ──→ global_emb
                                            ↓
                                        state_embedding (d=256)
```
无需自行设计特征工程，直接复用官方接口。

### 2026-06-29：Encoder 架构细节确定

**卷积核选择**：
- 第一层：Conv7×7, pad=3, stride=1, 28→64（快速融合 28 通道输入，参考 AlphaGo Zero 设计）
- 后续：ResBlock × 6~10，全部 Conv3×3, 64ch（精细推理，参数量可控）
- **不使用池化层**（保留精确位置信息，棋盘游戏不需要）

**感受野演进**（7×7 initial + k 个 3×3 ResBlock）：
- initial Conv7×7 → 7×7
- +1 ResBlock → 11×11
- +2 ResBlock → 15×15
- +3 ResBlock → **19×19**（覆盖全图）
- +6 ResBlock → 27×27（远超全图，留有余量）

**Stats 处理**：
- 官方 encode_stats() 输出的 ~22 维向量
- 经 MLP [22→64] 编码为 stats_embedding
- 与 board_emb (64) concat 得到 128 维 state_embedding

**参数量估算**（6 ResBlock, C=64）：
- Initial Conv7×7: 7×7×28×64 ≈ 88K
- ResBlock ×6: 6 × (2 × 3×3 × 64×64) ≈ 442K
- Stats MLP: 22×64 + 64×64 ≈ 5.6K
- **总计：~0.54M**

### 2026-06-29：输出方案设计（空间图 + 多分类头）

**抛弃"对所有候选 bundle 评分"的方案**，改为 AlphaZero 风格的策略头：

**核心思路**：
- 空间决策（选位置）→ 用 CNN 空间特征图，保留格点空间关系
- 类别决策（选哪类动作）→ 用全连接头，轻量复制多份

**动作分类**（n=23 类）：

**设计原则：意图驱动（Intent-level）**。
网络只输出"想要什么"（塔类型、武器类型等）和"在哪做"（位置坐标），
解码器负责将意图映射为具体的合法操作（查塔ID、判断升级路径等）。

**每个 (通道, x, y) 解码为唯一确定的 Operation，无歧义**。

| 通道 | 动作类 | 解码逻辑 |
|------|-------|---------|
| 0 | Basic 塔 | 空地 → 建 Basic；已有 Basic → pass |
| 1 | Heavy 塔 | 空地 → 建 Basic；有 Basic → 升级 Heavy |
| 2 | Heavy+ 塔 | 空地 → 建 Basic；有 Basic → 升级 Heavy；有 Heavy → 升级 Heavy+ |
| 3 | Ice 塔 | 空地 → 建 Basic；有 Basic → 升级 Heavy；有 Heavy → 升级 Ice |
| 4 | Bewitch 塔 | 空地 → 建 Basic；有 Basic → 升级 Heavy；有 Heavy → 升级 Bewitch |
| 5 | Quick 塔 | 空地 → 建 Basic；有 Basic → 升级 Quick |
| 6 | Quick+ 塔 | 空地 → 建 Basic；有 Basic → 升级 Quick；有 Quick → 升级 Quick+ |
| 7 | Double 塔 | 空地 → 建 Basic；有 Basic → 升级 Quick；有 Quick → 升级 Double |
| 8 | Sniper 塔 | 空地 → 建 Basic；有 Basic → 升级 Quick；有 Quick → 升级 Sniper |
| 9 | Mortar 塔 | 空地 → 建 Basic；有 Basic → 升级 Mortar |
| 10 | Mortar+ 塔 | 空地 → 建 Basic；有 Basic → 升级 Mortar；有 Mortar → 升级 Mortar+ |
| 11 | Pulse 塔 | 空地 → 建 Basic；有 Basic → 升级 Mortar；有 Mortar → 升级 Pulse |
| 12 | Missile 塔 | 空地 → 建 Basic；有 Basic → 升级 Mortar；有 Mortar → 升级 Missile |
| 13 | Producer+ 塔 | 空地 → 建 Basic；有 Basic → 升级 Producer；有 Producer → 升级 Producer+ |
| 14 | Siege 塔 | 空地 → 建 Basic；有 Basic → 升级 Producer；有 Producer → 升级 Siege |
| 15 | Medic 塔 | 空地 → 建 Basic；有 Basic → 升级 Producer；有 Producer → 升级 Medic |
| 16 | 降级 | 查 (x,y) 塔 ID → 降级一级；已是 Basic → 拆除 |
| 17-20 | 超级武器（闪电/EMP/护盾/回避） | 验证冷却和金币 → 部署 |
| 21 | 升基地出兵速度 | 无位置参数，仅由分类头 logit 决定 |
| 22 | 升基地兵种血量 | 无位置参数，仅由分类头 logit 决定 |

**注意**：网络只需输出目标塔类型（如 Heavy+），解码器按升级树走一步。
若当前位置已是目标塔，则自动转为 pass，不浪费操作。

**模型输出结构**：
```
ResBlock输出: spatial_feat (64, 19, 19)
                      │
            ┌─────────┴──────────────┐
            ▼                         ▼
      Conv1×1, 64→23            GAP → MLP
            │                         │
      action_map (23,19,19)     policy_head_base (64)
      "各类动作在哪做"                 │
                                    ┌──┼──┐
                                    ▼  ▼  ▼
                                head1 head2 head3 (各23维)
                                "第1/2/3个操作选哪类"
```

- **空间图共享 1 份**（23×19×19 = 8,303 logits），不复制
- **分类头复制 3 份**（每份 23 维，共 69 logits），轻量
- 每个分类头额外包含一个 **pass 隐式选项** — 若所选类的空间热图在合法位置上无正响应，则解码为 pass
- 基地升级（无位置）直接由 policy_head 的分类结果决定

**解码流程**：
1. 对每个分类头，mask 掉非法动作类 → argmax 选类
2. 对有位置的动作类，从共享 action_map 取对应通道 → mask 掉非法位置 → argmax 得 (x,y)
3. 解码器根据"动作类 + 位置"查询场上状态，生成具体 Operation：
   - 升级/降级：位置查塔 ID
   - 建塔：位置验证空地
   - 武器：验证冷却/金币
4. 将 1-3 个操作合并为 bundle 发送

**Value Head**（保留）：
- state_emb (128) → Linear(128→64) → ReLU → Linear(64→1) → tanh → [-1, 1]
