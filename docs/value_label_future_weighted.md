# 价值网络标签方案：指数加权未来血量差

## 问题

当前价值网络训练使用**整局最终血量差**作为所有帧的统一标签。这意味着第 1 回合和最后一帧的标签相同，网络只能学到"开局大概会赢/会输"的整体倾向，无法区分不同局面的即时优劣势。

当 MCTS depth=3（只看 3 回合后），价值网络输出的是 100 回合后的最终结果，两者视野完全不匹配。

## 方案

### 核心公式

对每帧之后的血量差序列做**指数加权平均**作为标签：

```
d_i = hp_us_i - hp_opp_i            （第 i 帧的瞬时血量差）
γ = e^{-1/T}                         （衰减因子，T 为时间常数）

raw_label_t = Σ_{i≥t} d_i · γ^{i-t} / Σ_{i≥t} γ^{i-t}
```

### 相对变化量（推荐）

MCTS 在决策时比较的是"选哪个动作能带来更多优势"，因此更关心**未来优势变化量**而非当前绝对值。建议从原始 label 中扣除当前帧的血量差：

```
label_t = raw_label_t - d_t

         Σ_{i≥t} (d_i - d_t) · γ^{i-t}
       = ────────────────────────────────
                Σ_{i≥t} γ^{i-t}
```

第一项总是 0，网络只需预测**"从这个位置出发，未来优势会变化多少"**。当前领先多少由特征中的血量直接提供，网络不必从零去反推。

### 等价递推形式

从最后一帧反向扫描，O(n) 计算：

```
suffix_sum_t  = d_t + γ · suffix_sum_{t+1}
weight_sum_t  = 1 + γ · weight_sum_{t+1}
raw_label_t   = suffix_sum_t / weight_sum_t
label_t       = raw_label_t - d_t
```

| 方法 | 每帧复杂度 | 内存 |
|------|-----------|------|
| 直接从头算 | O(L²) | O(1) |
| 递推（上式） | O(L) | O(L) 存 d_i |
| 流式更新（近似） | O(1) | O(1) |

## 参数 T 的含义

T 是**时间常数**（单位：回合），控制价值网络的"视距"：

| T | 半衰期 ≈ T·ln2 | 含义 |
|---|----------------|------|
| 3 | ~2 回合 | 只看几步后的即时收益，适合短视战术 |
| 10 | ~7 回合 | 看到中期运营收益 |
| 50 | ~35 回合 | 近似全局最终结果 |

当 T → ∞ 时，γ → 1，退化为**简单的算术平均**：

```
label_t = (d_t + d_{t+1} + ... + d_L) / (L - t + 1)
```

当 T → 0 时，γ → 0，退化为**仅当前帧血量差**：

```
label_t = d_t
```

## 和 MCTS 的配合

MCTS depth=N 时，价值网络被用来评估 N 步后的局面。理想情况下价值网络的 T 应该和 MCTS 的深度匹配：

- **T ≈ 5~10**：价值和 MCTS depth=3 配合，评估"往后一小段谁划算"
- **T ≈ 20~30**：价值和 MCTS depth=5+ 配合，评估"中期潜力"
- MCTS 负责战术搜索（挑选当前最优专家动作）
- 价值网络负责评估"这条分支接下来一段是否有利"

两个组件视野对齐，不会出现 MCTS 看 3 步、价值看 100 步的脱节。

## 和现有方案的对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| 最终血量差（当前） | 实现简单 | 每帧标签相同，梯度信息少 |
| **指数加权未来血量差（绝对）** | 平滑连续，视野可控 | 网络需同时拟合当前基础和未来趋势 |
| **指数加权未来血量差（相对，推荐）** | 标签以 0 为中心，分布对称；和 MCTS 决策逻辑对齐 | 需后处理，多一个超参 T |
| 当前瞬时血量差 | 标签精确无延迟 | 只看现在，无长期信息 |

## 实现要点

1. 数据收集时不需要改逻辑，仍按帧记录瞬时 hp_us / hp_opp
2. 在训练脚本的 `ValueDataset` 中（或 preprocessing 阶段），对每局数据做反向递推计算 label
3. 如果一局数据分布在多个 .npz 文件中，需在同局内跨文件做计算——最好在收集时就把一局的帧存在同一个文件里
4. 训练时加 `--tau T` 参数，默认为 10
