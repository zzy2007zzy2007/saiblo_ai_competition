## 一、历史上深度学习到底赚了多少？（这是最硬的证据）

### 可验证的正收益：只有 3 个，全部集中在 2026-09-18~09-20

| 改动 | 提升 | 性质 |
|---|---|---|
| 推理期用价值网当位置先验 | 20.3% → **39.1%** | **零训练**（只是把已有网用在推理）|
| 价值偏好位置网 | 21.1% → **35.2%**（256 局复核 18.4% → 42.2%）| 训练，但小 |
| 只换价值网 | 18.4% → **32.4%**（p=0.0003）| 训练 |

### 同期工程/搜索改进的量级（对照）

| 改动 | 提升 |
|---|---|
| 某条工程修复 | **+49.2pp**（0.0391 → 0.5312）|
| 扁平 rollout 取代树搜索 | 内部 **86%**（n=100）/ vs rule_v4 0.891 → **0.984** |
| k=160 vs k=1 | **100% / +26.7hp** |
| MC 仲裁开启 vs 关闭 | 0.6797 vs 0.0312 = **+64.9pp** |

⇒ **深度学习全部历史收益加起来，小于任何一条工程/搜索改进。**

### 失败的深度学习路线（8 条重训 + 1 次端到端 RL）

```
动作网重训：−11.7 / −15.6 / 1.00% / 47% / −7.8 / −10.2 / −43.0 / −18.0 pp
端到端 RL（2026-08 自对弈）：自对弈 50%→68.8%，但对 rule_v4 只有 31.2%
   根因诊断：特征提取器坍缩（commit eeebd19）
```

### 一个反复出现的规律（5 次独立实例）

```
recall 93.9→94.4 / Spearman −0.11→+0.428 / 留出 @24 80.4→85.1 / 实体 Transformer R²=0.9969 / 低质值网 R²=0.4708
⇒ 实战全部不动或更差
"拟合变好"与"棋力变强"在本项目历史上从不相关。
```

## 二、那为什么还值得做深度学习？（三条依据）

**① 深度学习在本项目唯一的成功形态是"改进评估"，不是"替代搜索"**

上面三个正收益全是"把学习到的值/先验**用在推理期的评估环节**"，没有一个是"让网络直接做决策"。

**② 对手的设计恰好证明"评估 + 搜索"才是主线**

- 冠军：PUCT 树搜索 50 sims × 深 9 回合，**叶子值用手写估值（无 rollout）**
- 亚军：扁平 UCB1，每臂约 125 次 rollout，**终端分用手写估值 + 等价金币折算**

⇒ 他们都是"**廉价叶子值 + 多次搜索**"，我们是"**昂贵 rollout + 一次搜索**"。

**③ 我们有一条从未被真正试过的路：把 rollout 蒸馏成廉价叶子值**

```
现状：每个候选要跑 16 回合 rollout + 值网前向 ≈ 5 ms
目标：训练一个"叶子值网络"直接预测 rollout 的结果 ≈ 0.05 ms
⇒ 同样的 10 秒预算，评估次数 ×100 ⇒ 可以让 SH / 更多候选 / 小规模树搜索真正跑起来
```

**关键区别**：这条路的目标是"**让评估变便宜、从而让搜索变多**"，而不是"让网络更准"。历史上的失败都是后者。

## 三、诚实判断：能不能到"人类 SOTA"？

| 问题 | 判断 | 依据 |
|---|---|---|
| 这个游戏的"人类 SOTA"是什么水平？ | **就是冠亚军那种手工启发式 + 搜索**（我们已知他们是纯启发式）| 对手源码 |
| 深度学习能不能超过它？ | **可能，但不是靠"端到端 RL"**，而是靠"**更好的评估 + 更多搜索**" | 历史 8 次失败 + 3 次成功都指向评估 |
| 我们现在的算力够吗？ | **不够做 AZ 式**（差 100-1700×），但**够做"廉价叶子值 + SH"** | 调研 F |
| 端到端 RL 走过吗？ | **走过一次，失败**（特征提取器坍缩，31.2% vs rule_v4）| commit `eeebd19` |
| 最大的障碍是什么？ | **不是算法，是评估噪声**：47pp 座位差 + 16 局 ±25pp ⇒ 我们连"有没有变强"都测不出来 | 调研 E |

**结论**：
> 深度学习在这个游戏**有希望**，但希望不在"更大的网络/更强的 RL"，而在"**把评估做便宜、做准，然后把省下的算力花在搜索上**"。
> 而要做到这一点，**必须先解决测量问题**——否则每一次改进都会被噪声淹没，重演"离线涨、实战跌"。

## 四、建议的路线（按性价比 + 前置依赖排序）

| 优先级 | 事项 | 为什么 | 判据（先写死）|
|---|---|---|---|
| **P0** | **SPRT + 座位协变量评估协议** | 一切实验的前提；判 5pp 需 2120 局 ≈ 12.6 h | 能预估局数，且与实测吻合 |
| **P0** | **叶子值网络（rollout 蒸馏）** | 唯一能同时降成本 + 增搜索次数的 DL 路径；对手正是这么做的 | 与真实 rollout 值 Spearman ≥0.8；替换后决策耗时降 ≥10× |
| **P1** | 观测加"塔血 + 等价金币"（对手 ①）| 低风险；项目内已有 R²=0.9969 证据 | 叶子值/先验的离线指标提升，且**必须配对外 16 局判据** |
| **P1** | Sequential Halving | 历史**从未测过**；同预算精度 +5× | 零对局指标（simple regret）提升 ≥30% |
| **P2** | 竞速式逐蚁威胁度（对手 ②）| 信息量大于现有静态代理 | 同上 |
| **P3** | 座位差排查（旋转增强 + 双座位等量）| 47pp 会掩盖一切 | 两座位 action_map 相关性上升；座位差缩小 |
| **❌ 不要做** | 端到端 RL / 动作网重训 / reward shaping / 加数据加参数 / 自蒸馏搜索输出 / 规则分数蒸馏 | **历史上 8+ 次负结果**，且与对手设计方向相反 | — |

## 五、这个判断的边界（防止误用）

1. **历史负结果是在"旧特征/旧引擎"下得到的**——现在引擎已修（升级动作从未执行等），理论上部分负结果可以重测；但**不应指望它们翻盘**，因为负结果的共同原因是"评估信息量不足"，而不是引擎 bug。
2. **对手源码只读了约 6%**（冠军 27k 行读了约 1,600 行），"借鉴清单"里可能有更优项未被发现。
3. **本文档的推算（100× 提速、SPRT 局数）都是估算**，需要实测校正。
4. **"人类 SOTA"没有客观定义**：本项目的实际目标是"打败冠亚军"，而那是一个**具体的启发式系统**，不是抽象的人类上限。
