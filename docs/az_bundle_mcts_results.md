# Bundle 采样 MCTS：从 0% 到"搜索增强"的完整记录

> 日期：2026-08-05 ~ 2026-08-06
> 一句话：意图空间 AlphaZero 的搜索从"完全摧毁策略（0%）"修到"有效增强策略
> （自对局 67-69%）"，根因是搜索动作空间与解码器不一致，修复是单一事实来源。

## 1. 背景与问题

为 AlphaZero 自对弈准备的 MCTS 搜索，最初采用"意图格 top-k 剪枝"设计，结果
**搜索把 gen_0120 的强策略（100% vs ExampleAI）打成 0%**。一路调试发现多层根因。

## 2. 根因链（按发现顺序）

### 2.1 先验-解码不一致（意图 MCTS）
分解先验 `P(c)·P(p|c)` 对超级武器不公平（~200 落点稀释概率），闪电被 top-k(24)
**硬剪枝掉**——搜索结构上够不到 gen_0120 的真正策略（闪电流）。

**证据**：诊断根节点 top-12 全是建塔意图，闪电不在其中。

### 2.2 bundle 采样的候选-解码不一致
改为"策略采样完整动作组"后，仍有三处分叉：
1. **intent-decoding 回退缺失**：decoder 把买不起的闪电解码成"拆塔补钱"，
   sample_bundle 只做 HOLD → 搜索不用闪电、不降级
2. **先验计算错误**：位置概率在"动作实际使用位置"前就计入（失败尝试也计）；
   z-score 归一化缺失（平坦 logits 下温度无意义）
3. **去重保留第一个**：同一动作的不同意图组合分数差 10 个数量级，应保留最高分

**证据**：WAIT bundle 先验从 -3.5（闪电类水平）被算成 -20（3 个罕见类），
归一化后 0.000，搜索从不探索。

### 2.3 根本教训
搜索的动作空间必须**严格等于**解码器的动作空间。任何"搜索看到的动作 ≠
实际能执行的动作"都导致结构性失败。修复 = **单一事实来源**：`sample_bundle`
直接调用 decoder 的 `decode_head`，解码逻辑不再有两份。

## 3. 修复清单

| 修复 | 作用 |
|------|------|
| 意图 MCTS → bundle 采样 MCTS | 候选空间 = 解码器的采样空间 |
| z-score 归一化 | 跨模型温度有意义，闪电可达 |
| 位置概率只在动作使用位置时记录 | WAIT 先验恢复闪电类水平 |
| 去重保留最高分 | 同一动作的最优意图组合代表它 |
| intent-decoding 回退 | 闪电买不起 → 拆塔补钱（核心策略） |
| **sample_bundle 复用 decode_head** | 单一事实来源，消除代码漂移 |

## 4. 验证结果

### 4.1 vs ExampleAI（弱对手）

| 配置 | 胜率 |
|------|------|
| 原始策略（不搜索） | 100% |
| 意图 MCTS（top-k 剪枝） | 0% |
| bundle 采样（无修复） | 0% |
| bundle 采样 + 全部修复 | **90%** (9W/1L, 10 局) |

### 4.2 vs rule_v4（强对手）

| 配置 | 胜率 | 平均血量差 |
|------|------|-----------|
| 原始 gen_0120（1头） | ~20% | — |
| 原始 gen0120_warm（3头） | 10% | -11.9 |
| bundle MCTS（128迭代/深度4） | 10% | — |
| bundle MCTS（192迭代/深度6） | ~10%（0/8 与 10% 自洽） | -10.0 |

### 4.3 自对局：搜索版 vs 原始版 gen0120_warm（核心验证）

| 配置 | 样本 | 总胜率 | 搜索先手 | 搜索后手 |
|------|------|--------|---------|---------|
| 128迭代/深度4 | 48局 | **66.7%** (32W/16L) | 50% | **83%** |
| 192迭代/深度6 | 16局 | **68.8%** (11W/5L) | 50% | **87.5%** |

## 5. 结论

1. **搜索确实增强**（自对局 67-69% > 50%）——"搜索 ≥ 原始策略"成立，
   AlphaZero 训练有改进信号
2. **增强集中在后手（P1，知情方）**：搜索后手 83-88% vs 先手 50%——搜索把
   "P1 能看到 P0 操作"的信息优势利用得比原始策略好；作为盲动先手无增强
3. **价值头是天花板**：192/深度6 ≈ 128/深度4（更深搜索无提升）——价值头精度
   决定搜索能榨出多少
4. 附带发现：
   - gen0120_warm 原始（3头）10% < gen_0120 原始（1头）~20%——value_warmup
     的锚定（0.147）让策略漂移了约一半强度
   - 搜索的价值头必须强，否则搜索退化为"中性探索"

## 6. 下一步

1. **Bundle MCTS 的 AlphaZero 训练**：bundle 访问分布需**边际化**成每头意图目标
   （网络输出意图空间 ≠ MCTS 的 bundle 空间，不能直接套标准 CE）
2. **加强价值头**（更大数据/±1 目标/更强锚定）——突破天花板的关键
3. 两者结合：训练用更强的搜索（128迭代/深度4 已够）产生访问分布目标
