# 值网重训：数据采集 + 标签 计划

> 状态：**已定方案，待实现**。目标 = 让值网学会"金币×冷却"的分段定价，进而让统一搜索能正确权衡"建塔 vs 攒闪电"。

## 0. 一句话目标

让值网从"线性、无视冷却、量级比位置噪声小一个数量级"（现状，`docs/value_net_coin_probe_20261030.md`），变成"90 币处有折点、冷却快好时金币更值钱"，验收就用现成的 P0-2 / P0-3 探针。

## 1. 诊断结论（为什么这么采）

- 值网金币估值线性无阈值（P0-2：90 币处斜率突变仅 3.0%），冷却条件斜率比 0.99（P0-3）。
- 根因：terminal 标签一局一值 → 对"花 vs 攒"零监督（`train_value_net.py:265-267`）；训练分布"有塔局面 0%"（inject_ex02 前）。
- kgeo 逐帧标签**能承载钱的价值**（我们自己的对局里 `≥90` vs `60-89` = +0.088 ≈ 0.56 std，方向为正；lowq 上 −9.2% ⇒ 是分布问题不是标签问题）。
- 但"coins≥90"在我们自己的对局里只占 **3.0%**（每局 1–3 次），对手（亚军）却占 69% ⇒ 稀缺状态太少，且被"花钱净亏"混淆。
- bootstrap 死循环：要采到"做得好"的对局，需要一个"会定价"的值网。破法 = **规则注入**（外部塞入正确动作）。

## 2. 采集策略：规则注入 + 逐帧标签

**基础**：统一搜索（`AZAI_CAND_MODE=unified`）正常下，天然产生"花钱 → 穷 → 输"的负例。

**规则注入（关键）**：在"金币×冷却"的临界时刻，以概率 `p` 覆盖 AI 的动作：

| 条件 | 覆盖动作 | 目的 |
|---|---|---|
| `coins ∈ [60, 90)` 且 `cd` 将好 | 强制 HOLD（攒钱） | 造"攒到 90"的正例 |
| `coins ≥ 90` 且 `cd == 0` | 强制 LIGHTNING | 造"放闪电 → 赢"的正例 |

- `p ≈ 0.5`：保留一半"AI 乱花钱"的负例，与正例形成"花 vs 攒"分叉对照。
- 注入的是**手写规则**，不是亚军 oracle（亚军金币太充足、覆盖不到稀缺区间；冠军 oracle 有 desync bug）。
- 样本记录 `inject_src`（0=AI 自己 / 1=规则注入），便于后续按来源分层分析。
- **存完整 board + stats**（训练要用；progress trace 只有 HP/金币/op，不能当训练数据）。

## 3. 标签

- 逐帧 **kgeo / abs**（`tau=50`），复用 `build_rel_labels.py` 的现成实现。
- 正确的 `--label-scale`：kgeo50 ≈ 1.5、rel50 ≈ 4.0（否则值网输出小 2.6–3.4 倍，`docs/value_net_label_pipeline_survey_20261031.md` §4）。
- 先跑 P1 四臂小规模对照（各 ~25 min）：terminal / abs+kgeo τ50 s1.5 / rel+kgeo τ50 s4.0 / abs+geo τ10。

## 4. 验收（现成探针，不新写）

- **P0-2**：V(coins) 在 90 币处斜率突变 **≥20%**（现状 3.0%）。
- **P0-3**：`∂V/∂coins | cd=0` / `| cd≥0.6` **≥2**（现状 0.99×）。
- **回归门**：有塔 MSE / 整体 r / 128 局胜率 不劣化。

## 5. 数据规模

- ~2000 局，KPI = **闪电事件 ≥ 1 万次**（确保"跨越 90"样本够；不只看局数）。
- 采集用 `az_selfplay`（16 workers，约 10–25 h；时间充裕，可接受）。

## 6. 实现改动（粗估 ~100 行）

1. `az_selfplay.py` 加 `--inject-coin-rule` 开关 + 规则覆盖逻辑（在动作选择后、执行前，按 §2 条件覆盖）；（~50 行）
2. 样本落盘加 `inject_src` 字段；（~5 行）
3. 复用现有 kgeo/abs 标签计算（`build_rel_labels.py` / `az_train.py:119-129`），不改；
4. 确保采集走 `AZAI_CAND_MODE=unified`（采集时用统一搜索，让它探索塔/升级的其余部分）。

## 7. 风险 / 负先验（必须记住）

- 历史 rel/kgeo **128 局 −7~−13pp**（标签换过、但数据没换 ⇒ 这次关键是**换数据**，不是只换标签）。
- 32 局快读数会骗人（历史 +9.4 → 128 局 −7.0）⇒ 验收看 P0-2/P0-3 曲线，别只看小样本胜率。
- 规则注入若 p 太高（>0.7），数据会退化成"规则对局"，失去"花 vs 攒"的分叉 ⇒ p 先取 0.5。
- 若 P0-2/P0-3 仍不达标 ⇒ 才上后备方案：显式金币 hinge 特征 / 续盘回归真实汇率。
