# 搜索退化根因诊断（2026-08-05）

> 问题：意图空间 MCTS 搜索把 gen_0120 的强策略（100% 赢 ExampleAI）打成 0%。
> 价值头预热（gen0120_warm）后仍 0%（64 迭代 10 局全输）。
> 本文记录诊断程序 `code/my_ai/az_intent/diagnose_search.py` 的原始结果与分析。

## 1. 诊断方法

一局（search vs ExampleAI，32 迭代，depth 2，seed 0），逐回合对比：
- `raw`：原始策略（decode argmax）在该状态解码的操作
- `search`：3 次搜索（每头一次）选出的操作

首个分歧回合（第 0 回合）重新搜索并 dump 根节点：top-12 意图的
先验 / 访问数 / 平均价值。

## 3. 根因分析

**先验-解码不一致（分解先验对超级武器不公平）**，证据链：

1. **gen_0120 的头 argmax 是闪电（class 17）**（早前探测确认），decoder 逐级解码
   （先按 head_logits 选类、再类内选位置）会打闪电策略
2. **分解先验 P(c)·P(p|c) 把闪电稀释掉了**：闪电有 ~200 个合法落点，
   每个位置的先验 = P(闪电)/200 ≈ 0.0015，**被 top-k(24) 剪枝筛掉**
   —— 根节点 top-12 里根本没有闪电
3. **建塔类意图占满 top-k**（class 0-15 都在 (6,9)，先验 ~0.043），
   且它们实际都解码成同一个动作"建塔@(6,9)"
4. **价值头对这些建塔子节点几乎无区分度**（mean_val 全 ~0.014）
5. **访问数极稀疏**：32 迭代 / 24 孩子 → 每孩子 1-2 次访问，argmax 访问数是噪声

**结果**：搜索在结构上选不了闪电，只能建塔——打的策略和 gen_0120
（攒钱等闪电）完全不同 → 0% 输给 ExampleAI。

## 4. 修复方向

**把 top-k 从"按原子先验取 top-24"改成"类优先"**：
1. 先按类先验 P(c) = softmax(head_logits/T_class) 取 top-k 类
2. 再在每类内按 P(p|c) 取 top-k 位置
这样闪电（若 P(17) 高）会作为"类"被选中，搜索才可能选到 gen_0120 的真正策略。

附带可调项：
- 访问数太稀疏 → 加大迭代数 / 降低 root_topk / 调 c_puct
- 价值头对相似子节点无区分度 → 价值头质量问题（当前方案下可接受，先修先验）

## 5. 影响

之前所有搜索相关测试（原始 0%、价值预热后 0%、先验选择 20% 等）都受此
先验-解码不一致影响——**根因不是价值头，而是搜索的先验结构选错了动作空间**。
