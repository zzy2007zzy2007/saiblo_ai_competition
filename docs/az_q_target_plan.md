# 计划：把位置目标从「1-ply 叶子价值」换成「搜索的根节点子值 Q」

> 日期：2026-09-19。状态：**计划阶段，暂不实现。**
> 依据：`docs/experiment_log.md` 的 `vprior_*`、`rv4_lightning`、`rv4_lightning_only`；
> `docs/az_value_prior_plan.md` §0.3.1。

## 1. 为什么要换（三条独立证据，同一个排序）

| 设定 | 落点来源 | 结果 |
|---|---|---|
| 我们自己的镜像台 | `value 1-ply argmax` vs `256 迭代搜索` | **1.3125 vs 1.8125** |
| 完整 rule_v4，只换闪电落点 | `rule_v4规则 / 我们的网 / 1-ply价值 / 搜索` | 0.5000 / 0.4922 / **0.3281** / **0.5391** |
| **只放闪电**（落点是唯一决策）| 同上 | 22 / 25 / 23 / **43**（赢/128，z=3.20）|

⇒ **搜索（访问累积）的选点远好于任何"一次性"选点**，包括 rule_v4 的手写规则、我们训好的位置网、
和 1-ply 价值 argmax。
⇒ 现有目标（1-ply 叶子价值）**已经被榨干**（learned ≈ oracle），但它**不是搜索手里那份知识**。

## 2. 一个必须先澄清的区别：N（访问）≠ Q（价值）

| 量 | 含义 | 备注 |
|---|---|---|
| **N（visits）** | 搜索往该子节点降了多少次 | AZ 的策略目标；**受先验塑形**；整数、粗（256 次分给 24 个候选 ≈ 每家 11）|
| **Q = W/N** | 该子节点所有回传值的**平均** | 搜索对"这步值多少"的估计；连续 |

**我们之前失败的正是 N**（visit 分布的一致率只有 0~42%，余弦 0.35）；而被 `mcts` 臂证明好用的
**选点**也是靠 N 选的。所以本计划要换的是**目标的量**：从「叶子价值」→「回传均值 Q」，
即**更深**，而不是回到 N。理由：Q 是连续均值、会随访问次数收敛，且不直接含"先验诱导的探索量"。

⚠️ **但不保证 Q 就一定可复现**：我们测到的"不稳定"是关于**价值近乎并列**的，不是关于计数的。
Q 的 argmax 在并列时同样会被噪声翻转。**所以本计划的第一步是便宜的先行检验，不是采集。**

## 3. 第一步（先行检验，几分钟）：Q 比 N 稳吗？

复用已有的"同一局面跑两遍、只换 rng seed，比目标"的台子
（`_tmp_search_target_similarity.py` / `_tmp_search_consistency_sweep.py`），但把被比的量从
**visit 分布**换成**根节点子节点的 Q 向量**：

- 指标：两遍的 Q 向量**余弦**、top-5 重叠、以及"Q 的 argmax 与 N 的 argmax 是否一致"。
- 参照基线（已知）：同一设定下 N 的余弦 **0.35**、bundle 同 42.5%、`value` 目标余弦 0.67。
- **绿灯**：Q 的余弦明显高于 N（比如 ≥0.7）⇒ 继续第 2 步。
- **红灯**：Q 与 N 一样烂 ⇒ **病根在"价值并列"，加深目标救不了**，本计划到此为止，
  转去查价值网/候选集（那时"提高价值网精度"或"让候选集确定"才是方向）。

## 4. 第二步（若绿灯）：目标定义

对每个决策点、每个头 `h`，钉类 `c = argmax(head_logits[h])`（与 pos-only 一致），
`c != HOLD`：

1. 跑一次 `BundleMCTS`（k=24 / 迭代 256 / 深度 4，`search_mode="pos-only"`）；
2. 取**根节点的每个子节点**的 `Q = mean_value`（`BundleNode.mean_value`，
   来源 `m.last_root.children[i].mean_value`）；
3. 把每个子节点的 Q **摊到它自己占的格子上**（与现管线对 visit 做的边际化同构：候选 j 的
   Q_j 按"该候选在各头上的格"分配），得到"类 `c` 的每个合法格"上的值 `a(x,y)`；
4. 在合法格上 z-score 后 `softmax(z / τ_Q)` ⇒ 目标（与现有目标同一形态，只是 `a` 的来源从
   1-ply 叶子价值换成回传 Q）。

⚠️ **待核实项**：`BundleNode.value_sum` 的**符号/视角**约定（是谁的视角、要不要取负）。
写代码前必须先量一个具体例子核对，不能凭猜（项目里踩过"视角"的坑：`feedback_az_value_player_perspective`）。

## 5. 第三步（接口改动清单，实现时才动）

| 文件 | 改动 |
|---|---|
| `collect_value_prior.py` | 新增 `--target {leaf,q}`：`q` 时跑一次搜索取 Q（**成本 ≈ 每出招回合 2.3 秒**，见 §6）|
| `train_value_prior.py` | 不用改（它只吃 `(cells, adv)`），但 `--target-tau` 的语义/默认可能要重标 |
| `evaluate` | 用现成的 `vprior_r1_eval` 那一套（256 局打 rule_v4，四批 seed）|

## 6. 成本（按 2026-09-19 更正后的数字）

- **一次完整搜索（k=24/迭代 256）= 2.3 秒**（不是旧文档里的 0.65 秒）。
- 400 局 × ~23 个出招回合 × 2.3 秒 / 16 worker ≈ **25 分钟额外采集**（第一轮是 53 分钟）。
- 训练 5 分钟；评测 256 局 ≈ 40 分钟。

## 7. 预注册判据

1. **先行检验**（§3）：Q 的余弦 vs N 的 0.35。不过就不做。
2. **训练侧**：目标 CE 是否低于均匀基线（与第一轮同口径），top1 命中是否上升。
3. **先验质量**：`_tmp_prior_quality.py` 的**峰的价值分位**（现基线 8.8%，随机 50）。
4. **最终（唯一硬判据）**：**k=24 打 rule_v4、256 局（四批 seed）**，对照
   第一轮 `posnet_r1` 的 **42.2%** 与旧基线 **18.4%**。
   ⚠️ 单批 64 局的 seed 集波动有十几 pp（本会话反复踩到），**必须四批合计**。

## 8. 风险 / 待定

- **Q 可能同样不可复现**（§2 末）—— 先行检验就是为了在花 25 分钟前把它挡掉。
- **Q 的噪声**：每子节点只有 ~11 次访问 ⇒ Q 是 11 个回传值的均值，本身也有噪声。
  迭代数是否要一起加大（k 与迭代同步放大是项目的老教训）待定。
- **视角/符号约定**（§4 末）。
- **若 Q 也不行**：这条线（"用搜索的更深估计当目标"）就基本走到头；届时应转向
  「提高价值网精度」或「让候选集确定」——见 `az_value_prior_plan.md` §0.3 的候选列表。
