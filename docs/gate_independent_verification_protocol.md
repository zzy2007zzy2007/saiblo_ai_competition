# 机械门：**无上下文独立验证**的固定协议（宣布成功时必用）

> 2026-10-05 建。依据：`docs/goal_longrun_plan.md` §4 规则 6（"宣布成功 ⇒ ① 命中预注册判据
> **且** ② 过**无上下文的独立验证** **且** ③ 记档；缺一不可"）+ `task_ruleV4_70_charter.md` §5。
> 目的：把"独立验证"从**临时想起来的一句话**，变成**可照抄执行的流程**——
> 否则每次到关键节点都要重新即兴发挥，而**即兴发挥正是这条纪律要防的东西**。
>
> ⚠️ 适用对象：**任何**"达到了某个判据"的宣称（第一个里程碑 70%、中期 90%、以及将来任何自定义判据）。
> ⚠️ 不适用：日常快读数（它们本来就**不作判定**，见章程 §1）。

## 1. 给验证者的**唯一**输入（"只给产物"）

把下面**全部**交给一个**没有任何对话上下文**的 agent（新开的 subagent 或人工第三方），
**不要**给它我的结论、不要给本文之外的摘要、不要口头提示"我算出来是 X"：

| # | 产物 | 路径（示例：B3 基线） | 为什么必须给 |
|---|---|---|---|
| 1 | **判据定义**（预注册） | `docs/prereg_20261005_baseline_vs_rulev4_128.md`（§2 统计量、§4 有效性门槛、§5 机械门） | 判据不能由验证者自创 |
| 2 | **逐局原始日志**（全部） | `match_results/ladder_logs/<tag>/*.log`（每局一份，含 `RESULT`/`ILLEGAL`/逐回合 trace） | 唯一的事实来源 |
| 3 | **实际运行命令与环境快照** | `training_history/runs/<ts>_<tag>/{cmd.txt,env.txt,meta.txt}` | 证明"跑的确实是预注册的那套配置" |
| 4 | **统计脚本**（可选，供对照） | `code/test_match/analyze_paired.py` | 我只提供工具，**不提供我的读数** |
| 5 | **统计脚本的自检** | `code/test_match/selftest_analyze_paired.py` | 让"复算"变成"对着已知答案跑" |

**不给**：`_analysis.txt` / `_analysis.json`（那是我这边的中间产物）、任何聊天记录、任何结论句。

## 2. 验证者**必须独立做**的事（一条都不许省）

1. **自己写代码**（≥30 行，不许 import 我的 `analyze_paired.py`）从**原始日志**里重算：
   - 每局：`winner`、`verdict`、`illegal` 次数、`terminal`、`rounds`、双方标签；
   - 每对（seed 的两个 token `N`/`Nr`）：我方得分 = 我方在该 seed 两局中赢的局数 / 2；
   - **主读数** = 各 seed 得分的均值（= 配对胜率）；
   - 分布：2-0 / 1-1 / 0-2 各多少；
   - 95% CI：**按 seed 重采样**的 bootstrap（不要按"局"重采样）。
2. **核对样本完整性**：token 集合必须**恰好**是 `{7…70} × {"", "r"}`（128 个），
   一个不多、一个不少；报告缺失/多余的 token。
3. **核对有效性门槛**（预注册 §4）：逐 token 检查 `winner≠INVALID`、`verdict=engine`、
   `illegal=0`、`terminal=True`；列出所有被排除的局与原因；算"无效+缺失比例"，
   若 >10% 必须**明确说"这批不能当验收"**。
4. **核对"谁是我们"**：`N` token 里我方（标签 `az_bridge_ai`）执 p0、`Nr` token 里我方执 p1；
   抽查 ≥5 局，**在日志里找出双方标签并确认**（不要信我的话）。
5. **反查一个"看起来会翻盘"的局**：从日志里任挑 3 局，人工读该局的终局信息
   （`base_hp`/`coins`/`rounds`）并与 `RESULT` 行对照，确认脚本没有把"败"读成"胜"。
6. **报告 5 个数**：`n 有效局 / 配对数 / p̂ / CI / 是否 ≥ 判据阈值`，外加一份
   "我做的每一步 + 我看到的原始行"的清单。
7. **若与宣称不一致**：**先报不一致**，给出差异最大的 token 列表与原始行；
   **不要**自行改判据、不要重跑对局。

## 3. 什么算通过（写死）

- **通过**：验证者独立重算的 `p̂` 与我宣称的值差 ≤ **0.5pp**，且判据阈值结论一致，
  且验证者也报出"样本完整 + 无效比例 ≤10%"。
- **不通过（任一）**：`p̂` 差 > 0.5pp / 样本不完整 / 无效比例 >10% / 标签判读不一致 /
  发现任何一局被误记胜负。
- **不通过时**：① 该宣称**立即降级为「存疑」**写进寄存器；② 差异定位（先查解析口径，
  再查有效性门槛）；③ 修正后**重新走一遍本协议**（不许"打折通过"）。


## 6. 已知的"这条纪律容易被绕过"的点（自省清单）

1. **给验证者"我的数"** ⇒ 变成橡皮图章。⇒ 只给产物（§1）。
2. **让验证者复用我的中间 JSON** ⇒ 一旦解析口径错了，错误会被"独立"复现一遍。⇒ §2.1 强制自己写。
3. **把"快读数"当验收** ⇒ 章程 §1 已禁止（快读数是 seed 前缀、n 小、不作判定）。
4. **在别处偷偷改判据/seed 集合** ⇒ 必须走"新预注册 + 记档"，且新旧读数不得相减（章程 §2）。
5. **配置修复当方法有效**（本任务 2026-10-05 刚踩到的那类）⇒ 结论里必须写明性质
   （工程修复 vs 方法改进），并说明它**不能**支持"我们的方法会优化"。
