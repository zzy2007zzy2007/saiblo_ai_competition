## 0. 要回答的两个问题

1. **那 +42pp 来自哪个头？** 部署是 `pos-only`（类被钉住、搜索只排位置），所以**猜测**是**动作图（位置）头**带来了提升，而**类头**在 pos-only 下作用有限（旁证：第 14/15 轮"类头蒸馏 ⇒ 0/32 对局变化"）。→ 用**单头训练**消融验证。
2. **把"类"这一维真正交给学习（`joint`）行不行？** 之前的 `joint` 臂全退化，但那是**旧塌缩头**（采样到 HOLD）。现在头有信号，但 `distill_data` 的类分布是 **91.2% HOLD** ⇒ 先做 HOLD 降采样重蒸，再测 `joint`。

## 2. 判据（先写死）

**消融判读（回答"哪个头"）**：以 vs example 的固定段 `p̂` 比。
- `maponly ≥ 0.70` 且 `clsonly ≤ 0.45` ⇒ **动作图是主因**（与 pos-only 的机制预期一致）；
- `maponly ≈ clsonly ≈ 0.38`（= S0）⇒ **两个头单独都不够**，提升来自两者配合/整体重训；
- `clsonly ≥ 0.70` ⇒ 我此前"类头在 pos-only 下没用"的判断**错了**，必须改写结论。

**goal 判据（回答"能不能打基线 80%"）**：候选臂在**两段**（固定段 + 随机段，各 128 局）上对**基线** `p̂ ≥ 0.80`
⇒ 走机械门（含"两侧配置指纹确实不同"核对）+ 无上下文独立验证。`p̂ ≤ 0.2828`（基线减 30pp 量级）⇒ 判有害。
**任一臂只要在固定段上 `≥ 0.80` 就必须去跑随机段**；只有固定段过线 ⇒ 按目标规则**如实记"未达标"**。

## 3. 预测（事后对照）

- **A `maponly`**：`p̂ ≈ 0.65–0.80`（我押"大部分提升来自动作图"）。
- **B `clsonly`**：`p̂ ≈ 0.35–0.45`（≈ S0；若显著更高，说明我错了）。
- **C `phold10`**（在 pos-only+宽菜单下）：`p̂ ≈ 0.75–0.85`（HOLD 降采样会让 agent 更主动，可能略好或略差）。
- **D/D2 `joint_full`**：**大概率仍偏被动**（头分布 91% HOLD）⇒ 预计冒烟就可能被判退化，或在 0.5–0.7。
- **E `joint_phold10`**：本批**唯一有"上台阶"上限**的臂（若类头分布真的可用）⇒ 我给 `≥0.80 打基线` 的概率 **15–25%**。
- **F `masked_phold10`**：介于两者之间（类头在合法类上 argmax ⇒ 比 joint 稳，但可能仍偏 HOLD）。
