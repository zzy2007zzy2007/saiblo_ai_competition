# 蒸馏训练实验记录

## 问题背景

对神经网络进行行为克隆（Behavior Cloning）蒸馏训练时，模型始终无法学到与状态相关的行为。诊断显示：无论输入什么棋盘状态，所有policy head都输出相同的类别。

具体表现：
- 全模型训练 → 全部预测 HOLD（占91%的多数类）
- 加权训练 → 换一个类全部预测BUILD_TOWER
- 非HOLD训练 → 过拟合到12K样本，新状态仍输出单一类

## 所有尝试过的方案

### 方案1：基础BC训练
在133K样本上用交叉熵训练553K参数的全模型。
- 结果：全部预测HOLD（91%的数据是HOLD，模型学会了偷懒）
- 问题：类别极度不平衡

### 方案2：类别权重
对HOLD类降权，对稀有类加权。
- 结果：从预测HOLD变成预测BUILD_TOWER（最大的非HOLD类）
- 问题：只是换了个"安全默认值"，并没有学到状态依赖

### 方案3：标签平滑
添加 label_smoothing=0.1 防止模型过度自信。
- 结果：损失略有改善，但预测仍然单一
- 问题：治标不治本

### 方案4：Head多样性损失
鼓励3个head产生不同的分布（对称KL散度）。
- 结果：不同head学会不同的单一类（head1→Grass, head2→Evasion, head3→Grass）
- 问题：每个head仍然是单一类，没有随状态变化

### 方案5：ActionCatalog软标签
用ActionCatalog的评分作为软目标（KL散度损失）。
- 结果：软目标太稀疏（仅8.9%的回合有非默认分数），帮助有限

### 方案6：预训练编码器 + 冻住编码器
先用自监督重建训练编码器，然后冻住编码器只训练head。
- 结果：损失稳定在2.35（高于HOLD基线），但实战诊断仍然单一类
- 问题：BN统计信息在保存/加载时丢失

### 方案7：BN校准
发现 `set_parameters_from_vector` 只恢复权重偏置，不恢复BN的 running_mean/running_var。尝试校准BN。
- 结果：校准后编码器输出恢复正常，但预测仍然单一类
- 问题：根因不在这里

### 方案8：移除LayerNorm
发现board_emb的方差主要在幅度（magnitude）而非方向。LayerNorm把幅度方差标准化掉了，导致所有输入产生的embeddings几乎一样。
- 移除LayerNorm
- 结果：编码器输出现巨大方差（norm~14000, std~1370），但logit方差仍然极小（std=0.002）
- 问题：policy_base和head的权重吸收了编码器的变化

### 方案9：小模型（87K参数）
从553K参数降到87K参数（32通道，2个ResBlock，1个head），防过拟合。
- 结果：在非HOLD数据上训练，实战仍然预测单一类0
- 问题：非HOLD数据只有12K样本，远远不够

### 方案10：平衡批次采样
使用WeightedRandomSampler让每个类在每批中占比大致相等。
- 结果：**首次出现状态依赖！** 模型能预测2个不同类（1和13）
- 进步：模型开始根据输入切换预测类

### 方案11：全数据 + 平衡采样（最终方案）
之前所有方案都只用了非HOLD数据（12K样本，占9%）。把HOLD也加回来，用全部133K样本，但每批中24个类各占1/24。
- 关键优势：编码器看到全部133K棋盘状态，学会了更通用的特征
- 结果：**实战中预测3个不同类**（HOLD 69%, BUILD 26%, MAGNET 5%）
- 对战ExampleAI胜率：**50%**（10局5胜）

### 方案12：数据增强
在方案11基础上添加高斯噪声和随机裁剪。
- 结果：4个不同类（HOLD 86%, BUILD 12%, MAGNET 1.5%, Deflector 0.4%）
- 但胜率降到30%，模型更保守了

## 关键洞察

1. **LayerNorm有害**：编码器的方差主要在幅度而非方向，LayerNorm把有效信息标准化掉了。

2. **BN统计信息丢失**：`set_parameters_from_vector` 不恢复BN的running_mean/running_var。保存/加载时必须显式处理。

3. **数据多样性 > 模型容量**：87K模型在133K全数据上训练的效果，远超553K模型在12K非HOLD数据上。

4. **平衡采样是关键**：在每批中让24个类各占1/24，强制模型学习区分。

5. **HOLD不是噪声，是信号**：把HOLD从训练数据中移除，反而让编码器失去了大部分学习信号。

## 当前最佳方案

```
模型: small=True (32通道, 2 ResBlock, 1 head, 87K参数)
数据: 500局ExampleAI对战数据（全部133K样本，含HOLD）
采样: WeightedRandomSampler, 每类权重 = 1/count[class], 归一化到均值1
训练: 200 epochs, AdamW(lr=1e-3, wd=1e-4), CosineAnnealingLR
损失: CE + Map KL + 0.5*Soft KL + 0.01*BiasReg
结果: 实战3个不同类, 对战ExampleAI 50%胜率
保存: distill_data_v2/model_all_bal.pt
```

## 还需要做什么

模型当前预测3/8个训练类别，看不到的类别会默认到HOLD。改进方向：

1. **收集更多数据**：特别是稀有类（Lightning 6样本, Heavy 13样本）
2. **多种教师**：不同AI策略产生不同的棋盘状态分布
3. **稀有类增强**：对稀有类的样本做专门的数据增强
4. **多head模型**：重新引入多head，不同head专精不同类
