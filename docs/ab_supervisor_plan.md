# 计划：两体架构（AI A 监督方向 / AI B 干活）

> 日期：2026-09-23（用户提出）。**状态：计划阶段，未做任何改动。**
> 关联：`docs/goal_longrun_plan.md`（长任务章程）、`docs/goal_register.md`（结论寄存器）。

## 0. 一句话

把「把握全局」和「干活」拆成**两个上下文**：**A** 的输入极少、增长极慢、因此**几乎不压缩 ⇒
全局视野不丢**；**B** 承担全部 token 消耗、上下文可以随时丢。A 承担**目前由人承担的监督角色**
（但人的位置不会消失，见 §5.3）。

## 1. 动机

### 1.1 问题：长时程 = 反复压缩 = 丢记忆 / 甚至把事说反

压缩丢掉的是"**总结者当时判断不重要的细节**"，而它不知道哪个细节以后会要紧；反复压缩会复合，
甚至**把某件事说反**（比"不记得"更危险）。业界的旁证：2026 年初 Claude Code v2.1.62 的 bug ——
KV cache 命中率提高但**没在压缩时让缓存失效**，于是把**压缩前的陈旧前缀**喂进了压缩后的轮次。
⇒ 操作推论：**压缩之后要重新读文件，别信"好像还记着"**。

### 1.2 用户的观察（本计划的经验基础）

**人不读代码、不读工具输出**，只靠文档 + 偶尔抽检一下对局记录正不正常，就能判断状况、纠正 AI。
⇒ **掌握全局所需的比特数 ≪ 执行所需的比特数。**

今天这条会话本身就是证据：上下文几乎被工具输出灌满（日志、清单、diff、进程表……），
而**真正需要跨周保留的东西不到一页**（`goal_register.md` 现在就是这么一页）。

## 2. 设计

### 2.1 两个角色

| | **A（监督）** | **B（执行）** |
|---|---|---|
| 输入 | **极少且固定**：`goal_register.md` + B 的**一页**工作报告 + 按需抽检的原始产物 | 全部工具输出、代码、日志、diff |
| 目标 | 搞清全局、把握方向、维护寄存器 | 真正干活：写代码、跑实验、留档 |
| 上下文 | 增长慢 ⇒ **几乎不压缩** ⇒ 全局视野持久 | 巨大、**可丢** |
| 产物 | 每轮：结论行 / 抽检记录 / 给 B 的任务说明 | 每轮：`run_logged` 实验 + `experiment_log` 读数 + **指向产物的一页报告** |

### 2.2 A 的固定输入（每轮）

1. `docs/goal_register.md`（含顶部三行「当前方针」）；
2. B 的**一页**工作报告 —— **必须指向可复核的产物**（run 名 / 日志路径），而不是只有结论；
3. **按需**抽检的原始产物（某个 run 的 `output.log`、某条测试输出、某个 stderr 片段）。

### 2.3 A 的权限与禁止

**可以**：读文件；向 B 提问；**抽检原始产物**（不是读 B 的转述）；下令跑某个**预注册**实验；
写/改 register 的结论行与「当前方针」。

**不可以**：自己判"成功"、自己改判据（要问用户）；读 B 的全部工具输出；亲自跑实验（会污染它的上下文）。

### 2.4 B 的职责

干活 + 留档 + 一页报告。**可选改进（倾向采用）**：**B 每次是全新上下文的一次性 worker** ——
它做的每件事本来就是自包含的实验单元（`run_logged` 已保证），干完即丢、下一件事开新的 B
⇒ **B 永远不会 context rot**，它的"记忆"就是文件，**连续性全部由 A 持有**。
代价：A 每次要给 B 一份自包含的任务说明。

## 3. 三条硬机制（防止这个架构失效）

1. **一页报告必须指向可复核的产物**（run 名 / 日志路径）——否则 A 只能吃 B 的叙事。
2. **A 每轮至少抽检一件原始产物**，并回答"B 的报告与产物是否一致"。
   ⇒ 这是防止 **A 变成橡皮图章**（几轮之后只会在 B 的叙事里点头）的唯一机械手段。
3. **重要结论仍要过"无上下文的独立验证"**：开一个第三个临时小 agent，**只给产物、不给叙事**，
   让它独立复算并给通过/不通过。A 自己做不了这件事——它已经读过 B 的说法了。

## 4. 与既有产物的关系

`charter` / `register` / `experiment_log` / `run_logged` 已经提供了**"小而持久的产物层"**；
本计划只**新增"角色"**，不推翻任何现有约定。`register` 的「当前方针」正是 A 的固定输入。

## 5. 残余风险（诚实）

1. **小上下文 ⇒ 早期结论错了会自信地带偏**：证据少、不容易被动摇。缓解：A 必须写 falsifier +
   定期（很少）整篇重读寄存器。
2. **A 也会"看起来在干活"**（和 B 同病），而且**更难被查**，因为它只做判断。
   缓解：A 的每轮输出必须**可检查**（结论行 + 抽检记录）。
3. **人的位置不会消失，只会换工作**：从"盯每一步"变成"**审计 A + 掌舵取舍**"。
   "值不值得做 / 该不该放弃"是 taste 和 stakes，A 拿不到（它没有外部优先级）。
4. **转述偏见**：若不强制抽检，A 的全局视野 **= B 的自我报告质量** —— 这正是
   "解读受主观性影响"的另一种形态。
5. **成本/轮次**：A 的每轮问答也要消耗 B 的上下文；往返多了 B 反而更快被压缩。
   ⇒ 若采用 §2.4 的"B 每次全新"，这条基本消除。

## 6. 验证方式（**先小规模，再决定是否推广**）

**A 跑 3–5 轮**（B 照常干活），判据**跑前写死**：

| 判据 | 通过条件 |
|---|---|
| 态势维持 | A 能在**不看工具输出**的前提下说出：当前在攻什么、依据哪条证据、下一步是什么 |
| 抽检生效 | A 每轮≥1 件原始产物抽检，且能回答"报告与产物是否一致" |
| 不绕圈 | 不重复"已排除"方向；若重开，必须回答那两问 |
| **抓错过** | 这几轮里出现 **≥1 次"A 抓到 B 的偏差/遗漏"**；若一次都没有 ⇒ 判"抽检没起作用" |

**失败判据**：若 3–5 轮里 A 只是在复述 B 的说法 ⇒ 判**无效，回退**（不推广）。
