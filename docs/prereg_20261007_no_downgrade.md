# 预注册：**诊断臂「抑制降级」**（`AZAI_NO_DOWNGRADE=1`）——"churn 是不是在自毁？"

> 2026-10-07 第 4 轮写（**在跑这批之前**）。章程：`docs/task_ruleV4_90_charter.md`。
> 性质：**手写干预的诊断臂**（章程 ②：只能当诊断、判法 = 消融）——**不是交付物**。

## 0. 由来（全部来自我们自己的读数）

1. **败局签名**（256 局，`code/test_match/diag_loss_signature.py`）：我方"升级+降级"次数在**负局更高**
   （中位 **12.5 vs 10.0**，Cliff's d = **−0.302**，是除闪电外最强的区分量）。
2. **动作直方图**（256 局，双方）：我方 **建塔 24.84 / 降级 10.82 / 闪电 10.50 / 升级 0.00**；
   对手 建塔 16.02 / 降级 14.89 / 闪电 9.43 / **升级 9.52**。
   ⇒ 我们**只建不升**，却**大量降级**——即"建塔 → 降级（拿回钱）→ 再建"的**churn**。
3. 第 3 轮已查明：升级**此前根本表达不出来**（op 参数错 + class 通路限制）；**降级**是 class 16 解码出来的、参数正确、**真的会执行**。
4. ⇒ **可检验的问题**：把这 10.8 次/局的降级**拿掉**，棋力是涨是跌？

## 1. 干预与判据

| 项 | 内容 |
|---|---|
| 干预 | `AZAI_NO_DOWNGRADE=1`：AI 返回的 op 里**剔除 `DOWNGRADE_TOWER(13)`**；若该回合只剩空 ⇒ 等于 **HOLD**（返回 `[]`）。**不动搜索、不动候选、不动网络** |
| 对照 | `M6cROOT_128` 同前缀 `7..38` = **0.6562** |
| 样本 | **64 局**（32 对，固定段前缀），`jobs=8` |
| 机制读数（必报） | 我方 `DOWNGRADE_TOWER` 应从 10.8 → **≈0**；建塔/闪电/出招回合的变化；`dec_max` |

**判定（诊断臂，方向）**：
- `p̂ ≥ 0.7362`（+8pp）⇒ **churn 是真实亏损** ⇒ 下一步做**方法侧**改造（让机制自己学会"不降级"/"降级要有依据"），
  且这条与"升级"合起来说明**塔的生命周期管理**是下一个杠杆；
- `0.6062 < p̂ < 0.7362` ⇒ 方向不明，记档不结论；
- `p̂ ≤ 0.6062` ⇒ **降级不是亏损**（可能还有用：回钱/换位）⇒ 该轴关闭。

⚠️ 64 局只分辨 >~12pp；单段不作结论；看数据前判据已写死；**即使大涨也不能当交付物**。

## 2. 预测

- **P1（机制，必然）**：我方降级 10.8 → ~0，出招回合略降（被剔除的那些回合变 HOLD）。
- **P2**：我预计**持平到略正**（若 churn 是亏损则正），不太可能大幅正（因为降级也给回钱）。
- **P3**：若显著为负 ⇒ 说明"降级"在我们的经济里承担了真实功能（回钱再投），教材级反例。
