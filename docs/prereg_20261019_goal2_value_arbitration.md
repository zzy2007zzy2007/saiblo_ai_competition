# 预注册（本 goal 第 19–23 轮）：**价值网仲裁 MC 菜单**（`AZAI_MC_SCORE=delta|value_only`）

> 2026-10-19 写（**在跑之前**）。上位目标 `goal-2600a56a`（打冻结基线 `grafted_sdk_A.pt` 两段各 ≥80%，双方禁闪电）。
> 章程：`docs/task_ruleV4_90_charter.md`。相关：`..._mc_coverage.md`（MC 覆盖度）、`..._s2_value.md`（价值网重训）。

## 0. 为什么这条比"重训价值网"更对症（三条机制依据）

1. **架构核查（2026-10-19）**：三网是**三个独立模型**（`load_three_models`）⇒ **价值网无法改变策略头**，
   它只有两条通道：① 搜索的叶评估；② **MC 菜单的评分**（`bundle_mcts.py:624`：`if self.mc_score in ('delta','value_only')`）。
   ⇒ 历史两次"价值网重训 → 棋力不动"**结构上就该如此**（网根本没接到会改变的决策上）。
2. **MC 就是"类决策"的决策者**，而头消融显示**类这一维扛 47%** 的提升（单独只训类头 = 0.5781 vs S0 0.3828）。
3. **现有评分器（安静 rollout）有明显缺陷**：**23.6% 的仲裁是精确平局**，平局按菜单顺序兜底（≈任意）
   ⇒ 换成**连续值**的价值网评分，平局会大幅减少（**这是本臂可验证的机制预测之一**）。
4. 附带好处：`value_only` 模式下 MC **不再跑 256 回合的引擎 rollout** ⇒ 单局可能快 **~10–30×**（K=1 那次 33× 的同源效应）。
   **注意**：跑得快**不算成绩**（判据只看胜率），但会让筛查成本骤降、也让"策略迭代"变得可负担。

## 1. 臂（**只动 `AZAI_MC_SCORE`**，其余一切 = 冻结基线；不重训任何网）

| 臂 | 改动 | 说明 |
|---|---|---|
| **VONLY** | `MC_SCORE=value_only` | 候选分数 = 价值网对该候选结果的估值 |
| **DELTA** | `MC_SCORE=delta` | 候选分数 = 估值**变化量**（`bundle_mcts.py:624` 附近的 `V(before)` 口径）|
| **（对照）基线** | `MC_SCORE=''` | 安静 rollout 评分（= 冻结基线）|

- 冒烟守卫照旧（我方建塔 ≤0.5/局 ⇒ 跳过；闪电必须 0）；**新增机制读数**：从 trace 里取 MC 的**平局率**
  （基线 23.6%）⇒ 若新评分器平局率没有下降，说明"改评分器"没生效，必须先查实现而不是继续跑。
- **两段式**：先 **vs example**（同尺子，基线 = 0.8016）跑 **64 局前缀 `7..38`**；
  `p̂ ≥ 0.85` 的臂再跑 **vs 冻结基线的全固定段 128 局**；只有对基线 `≥0.80` 才去随机段。

## 2. 判据（先写死）

- 对基线 `p̂ ≥ 0.80`（**两段**：固定段 + 随机段）⇒ 候选 ⇒ 机械门（`goal_gate_vs_baseline.py`，含"两侧配置指纹不同"核对）+ 无上下文独立验证。
- `0.50 ≤ p̂ < 0.80` ⇒ 记"价值网通道确有作用但幅度不够"；`p̂ < 0.50` ⇒ 记"价值网评分不优于 rollout 评分"。
- 逐段报 CI 与执先/执后；刚压线必须写明"点估计达到阈值 ≠ 统计上证明 >阈值"。

## 3. 预测（事后对照）

- **VONLY**：我押对基线 **`p̂ ≈ 0.40–0.60`**。理由：旧价值网是在**真实对局**数据上训的（对子博弈分布有偏移），
  且它的离线 MSE 历史并不好；但平局减少可能带来一点净收益。**给"≥0.80"≤5%**。
- **DELTA**：同量级；`delta` 用"变化量"口径，理论上更贴近"这一手值不值"，我略更看好它一点点（但仍在噪声内）。
- **机制预测（独立于胜率，可先看）**：两臂的 **MC 平局率应显著低于 23.6%**；若没有 ⇒ 先修实现。
- **成本预测**：`value_only` 单局应显著快于基线（MC 不再跑 rollout）⇒ 若胜率不差且快很多，**即使不达标也值得作为新基线候选**（这条要如实写进结论，因为它影响后续所有实验的机时）。
