## 1. 假设与动机

- **观察（实测）**：A1 配置下我方 **建塔 = 0 / 升塔 = 0**、只出闪电（11.3 次/局），
  因为 `pos-only` 把**类钉在策略 argmax**，而类头是**继承来的**（`cmp_three_net_heads.py`：
  `class_state` 与 `valnet_A2`/`three_mix` 逐位相同）⇒ **类轴从来没被这条线的数据训过**。
- **候选 C 的假设**：把**同一条数据**里已有的**逐类优势**（`adv`）当成**类级**学习目标，
  可以把这个继承的类头往"我们自己的 1-ply 价值排序"上拉。
- **前提检验（已做，2026-10-05）**：`code/test_match/diag_class_axis_vs_value.py`
  —— 在**同一组被评估的类**上比较"价值先验 top-1"与"策略头 top-1"：
  一致率 **39.7%**（分歧 60.3%）；但**分歧幅度双峰**：**~80% 是并列**（z 幅度 = 0），
  **z 幅度 > 0.5 的只占全部可比对的 12.0%**、> 2.0 占 8.8%。
  ⇒ **可测的、有明确方向的分歧 ≈ 12% 的决策**；这与项目自己的 H1（"决定胜负的是那 ~4% 决策"）同量级
  ⇒ **值得试，但期望值要诚实：小效应、只在少数决策上生效**。

## 2. 数据与目标（**不加新数据**）

数据 = `training_history/vprior/vp_A_k5_m32.npz`（350,793 行 / **28,989 个决策**，`--multi-class-k 5`）。
每个"决策 × head"有若干个（≤5）被评估的类，每类带最多 32 个候选格与其 `adv`。

对每个 (决策 d, head h)，设被评估类集合 `C_dh`（|C|≥2 才算有信号）：

1. `a_c = max(cells 上的 adv)`（"该类里最好那个格"的价值）；
2. 在 `C_dh` 内对 `a_c` 做 **z-score**（与 `train_value_prior.py:153-158` 的位置头同口径）；
3. 软目标 `p = softmax(z(a_c) / target_tau)`（`target_tau=1.0`，与位置头一致；**并列 ⇒ p 接近均匀**，
   正好把"分不出高下"如实表达出来，而不是硬塞一个 argmax）。

**损失 = 只在 `C_dh` 上做条件 CE**：

```
L = -Σ_c p_c * log( q_c / Σ_{c'∈C_dh} q_{c'} ),   q = softmax(head_h_logits 在 C_dh 上的取值)
```

⚠️ **为什么必须"条件化"（除以 Σ_{c'∈C} q）**：每个决策只评估了 5 个类，
若直接用普通 CE（分母是全 24 类），就等于**把没评估的合法类强行压下去**
⇒ 会注入一个我们并不知道的（且错误的）先验。条件化只约束**这 5 个类之间的相对偏好**，
对其它类**不做任何断言**——这正是我们的数据能支持的最强结论。

## 3. 模型手术（单变量：只换 `class_state`）

- `load_three_models(ckpt)` 载入三网；**冻结 `pos_model`/`value_model`**，只 `class_model.train()`；
- 前向只走 `class_model`（3 个 head 的 logits）；
- 用 `az_train.save_three_net` 写回三网 ckpt（键集合与现在一致）⇒ **`pos_state`/`value_state` 逐位不动**。

## 4. 实现

新脚本 `code/my_ai/az_intent/train_class_prior.py`（**不改** `train_value_prior.py`，避免动到已验证的路径）：

- 复用：`group_decisions` 的分组思想（按相邻 `stats+player` 相同切段）、`FeatureExtractor`、
  `load_three_models`、`save_three_net`；
- 参数：`--ckpt --data(npz) --epochs --batch-size --lr --target-tau --val-frac --seed --device --out`；
- 打印：每个 epoch 的 train/val 条件 CE、**"策略 argmax 与价值 top-1 的一致率"**（训练前/后对比，

  所以只能按位置切；同局的行是连续的 ⇒ 尾部切**近似**局级切分，但**必须**在文档里标注这个近似
  （项目历史上 `--val-frac` 按行切被记为"val CE 偏乐观"）。

## 6. 判据与预注册（**要另写**）

- 主读数 = `analyze_paired.py` 的配对分（A1 配置）；
- 对照 = `C1_a1_hist32`（同 32 局、同配置、同 seed）的 **`p̂ = 0.5000`**；
- 晋级：`p̂ ≥ 0.55`（= 对照 + 5pp，比配置阶梯的 10pp 更严，因为期望是小效应）
  **且** 方向为"类轴上的选择确实变了"（用脚本打印的"一致率变化"当**机制旁证**，不当判据）；
- 若 `p̂` 落在 0.45–0.55 ⇒ 记"**类头蒸馏在本判据下测不到**"（进寄存器），转候选 V / 新数据循环。

## 7. 风险清单（每条都有依据）

1. **~80% 的分歧是并列** ⇒ 大多数决策上软目标接近均匀、梯度信号很弱（§1 的实测）。
2. **每决策只评估 5 个类** ⇒ 只能约束这 5 类的相对偏好（已用条件化处理；但覆盖面有限）。
3. **数据来自"贪婪 1-ply"轨迹**（`collect_value_prior.py` 没有搜索），而部署用 k24/sm15 搜索
   ⇒ 状态分布不完全一致。
4. **`adv` 由 `valnet_A2` 产生** ⇒ "类头模仿价值头"这件事的天花板就是该价值头的**类级排序质量**；
   若价值头自己的类级排序是噪声，C 只会把噪声学进策略。
5. **验证集只能按行块切**（无 game id）⇒ val CE 偏乐观，**不许**拿它当判据。
6. **单变量**：只换 `class_state`；`pos_state`/`value_state` 不动 ⇒ 若 A1 的强度主要来自价值头的
   位置排序，C 的可见增益会很有限（这也正是"先做前提检验"的原因）。
