# 自适应 Leaderboard 对手采样

## 问题

当前 `get_opponents()` 使用 `0.5^{rank}` 加权采样，越强的条目被抽中的概率越高。当 LB 满了 20 个条目后，最强者（rank 0）占 50% 采样权重。结果：

- 种群中绝大多数个体完全打不过 rank 0，大量得 0 分
- `best_fitness` 持续下降（不是模型退步，是对手太强）
- 平均 fitness 趋近 0，选择信号弱，排序几乎靠随机种子

## 思路

评估阶段不追求"最强对手"，而是**能产生信息量的对手**。理想状态：对手胜率约 70%，即个体 vs 该对手的胜率约 30%（个体大部分打不过但能啃几口，不会被碾压）。

对 LB 中的每个条目，维护一个自适应权重 λ，用于调节采样概率：

```
P(entry_i) ∝ 0.5^{rank_i} × λ_i
```

λ_i 在（0.5，2.0）之间浮动，趋向"该条目被抽中时，个体的平均胜率为 target_wr"。

## 更新逻辑

每代评估完成后，统计本代所有个体对每个 LB 条目的平均胜率：

```
wr_i = 本代个体 vs entry_i 的平均得分（个体视角）

adjust = wr_i - target_wr      # 正 → 太弱（个体胜率偏高），需提权
                               # 负 → 太强（个体胜率偏低），需降权
λ_i_{new} = λ_i × (1 + lr × adjust)

clip(λ_i, 0.5, 2.0)
```

用动量平滑随机波动：

```
λ_i_{t+1} = momentum × λ_i_t + (1 - momentum) × λ_i_new
```

**示例**：target_wr=0.3（个体胜率）
- entry A 太强，个体平均 wr=0.05 → adjust = 0.05 - 0.3 = -0.25 → λ ↓（少抽它）
- entry B 太弱，个体平均 wr=0.60 → adjust = 0.60 - 0.3 = +0.30 → λ ↑（多抽它）

新条目加入时 λ 初始化为 1.0，几代后自动收敛到合适值。

## 特性

- **不需要额外评估局数**——复用本代已有的评估结果
- **自动适应**——新加入的强条目初始 λ=1.0，如果它碾压所有人，λ 逐代下降，减少被抽中概率
- **无需手动调参**——target_wr, lr, momentum 都有默认值，可热加载

## 与现有设计的关系

只有 `_select_opponents` 和 `leaderboard.py` 需要修改：

```
当前: get_opponents(rank_weighted) → 0.5^{rank} 采样
改为: get_opponents(adaptive_weighted) → 0.5^{rank} × λ 采样

新增:
- leaderboard 条目新增 λ 字段
- 每代评估后更新 λ
```

LB 挑战逻辑不变——挑战永远打 rank 0，保证入库的个体是真正最强的。

## 参数

```python
"lb_target_wr": 0.7    # 目标胜率
"lb_adapt_lr": 0.1     # 学习率
"lb_momentum": 0.9     # 动量系数
"lb_lambda_min": 0.5   # λ 下限
"lb_lambda_max": 2.0   # λ 上限
```

## 注意事项

- λ 只影响评估阶段，不影响 LB 挑战（挑战永远打 rank 0）
- λ 不应让最强条目完全不被抽中——所以 λ_min=0.5 而非 0
- 新条目加入时 λ 初始化为 1.0，经过几代评估后自适应到合适值
