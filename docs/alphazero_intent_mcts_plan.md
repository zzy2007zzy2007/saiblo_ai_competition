## 实验结果（2026-08-05 首轮过夜实验，12 batch × 4 局全长，热启动 gen_0120）

### 训练收敛（强）
- policy_loss：1.88 → 0.086（降 22 倍）；value_loss：0.037 → 0.003（降 15 倍）
- 网络几乎完美复刻了 MCTS 的访问分布；自对弈管道（3 头/回合、温度、Dirichlet、快照、resume）全部工作正常
- 与玩具网络（policy_loss 全程平稳 ~0.7）形成鲜明对比：**机制层面 AlphaZero 完全能学**

### 对局特征（重要发现）
- 所有自对弈局 ~240 回合结束，胜者仅剩 **1-6 血**——游戏高度接近，胜率 ~50/50（微弱先手优势）
- 终局血量差 ≤6 → 价值目标全在 ±0.3 内 → **血量差价值目标在接近对局中信号弱**

### 对 rule_v4 的评估（关键负面结果）
| 模型 | 32 迭代搜索 |
|------|------------|
| gen_0120 基线（热启动 + 搜索） | 0/10 |
| batch 2 快照 | 0/10 |
| batch 6 快照 | 0/10 |
| **batch 12 最终** | **0/10** |

**训练前后对 rule_v4 全部 0%——损失大幅下降没有转化为胜率提升。**

### 解读（待 100 迭代诊断确认）
- 可能性 A：搜索太浅（32 迭代/深度 2）榨不出策略真实水平 → 判别测试：最终模型 + 100 迭代
- 可能性 B：策略真没变强——loss 下降只是"网络复刻弱搜索"，自对弈共同适应导致绝对强度不涨
- 候选机制：接近对局 + 血量差目标 → 价值信号弱 → 搜索缺乏价值引导 → 训练数据质量停滞
- 候选修正：改用 ±1 胜负目标（接近对局照样给强信号）；更强搜索；更多训练量

### 已确认的机制（2026-08-05 判别测试）
- **搜索本身把强策略玩坏**：同一评估设定下，gen_0120 原始策略 62.5% 赢 ExampleAI，**套上 32 迭代搜索后 0%**。→ 不是训练过程的问题，是搜索劣于原始策略
- 根因：价值头无信息（重初始化随机 / gen_0120 原始 ~-1.04 常数）→ 搜索 Q 无引导 → 加上 25% 根噪声 + c_puct 探索，选的动作比原始策略差
- 训练目标 = 搜索的（坏）选择 → 监督回归把策略拽坏（vs ExampleAI 100% → 0%）
- **rule_v4 过强，作为基准区分度不足**：gen_0120 + 100 迭代搜索对 rule_v4 仍 0W/8L
- 结论：**当前搜索预算（Python 引擎 32-100 迭代）+ 无信息价值头下，AlphaZero 自对弈会退化策略而非提升**——"弱搜索 AlphaZero 在此游戏不工作"

### 评估设定差异（重要背景，2026-08-05）
- **eval_checkpoint.py 是"盲对手"**：双方在同一个状态上各自决策，后手看不到先手的操作 → 更弱、更简单
- **az_intent/eval.py 是"知情对手"**：先手操作应用后后手才决策（真实比赛协议，README 明确 P1 收到 P0 操作后决策）→ 更难、更贴近比赛
- gen_0120 vs ExampleAI：盲对手 **100%**（用户 eval_checkpoint 实测 16/16），知情对手 **62.5%**（1 头原始策略）
- 头数影响较小：3 头扩头版 50-60% vs 1 头 62.5%
- **含义**：之前 ES 模型的 67-90% 胜率是在盲对手设定下测的；知情对手下会低一些。评估应统一用知情对手（贴近比赛）

### 搜索劣于原始策略的完整证据（全部知情对手 vs ExampleAI）
| 配置 | 胜率 |
|------|------|
| gen_0120 原始 1 头（知情对手） | 62.5% |
| gen_0120 原始 3 头（扩头） | 50-60% |
| gen_0120 + 搜索(32迭代, 选访问数) | **0%** |
| gen_0120 + 搜索(32迭代, 选先验) | **20%** |
| 训练后模型(12 batch) + 搜索 | 0% |
| gen_0120 原始 1 头（盲对手, eval_checkpoint） | 100% |

**搜索+选先验(20%) ≠ 原始解码(62.5%) 的原因**：分解式先验的联合 argmax（最大化 P(c)·P(p|c)）与 decoder 的逐级 argmax（先类后位置）**不一致**——某类 logits 略低但位置分布尖时，联合 argmax 会选它，与 decoder 不同。搜索从根上选的是和原始策略不同的动作。

**综合结论**：意图空间 AlphaZero 配置在多层连环出错——(1) 先验-解码 argmax 不一致 (2) 价值头无信息 (3) 搜索预算小+探索噪声 (4) 3 操作范式 (5) 知情对手评估更难。**搜索在任何层面都劣于原始策略，训练回归向坏选择。** 修复需先验证"搜索 ≥ 原始策略"（搜索健全性检查），再谈 AlphaZero 自举。

### ⚠️ 热启动权重 bug（2026-08-05，重大）
- ES/GA checkpoint 含三套参数：`top2_params[0]`（TOP1 强个体）、`mean`、`model_state`
- **`top2_params[0]` == `mean`（完全相同，100% 赢 ExampleAI），`model_state` 与它们差 0.008（弱版，62.5%）**
- 原 `load_hotstart` 优先用 `model_state` → **整个过夜实验从弱版 gen_0120 热启动**
- 已修复：优先 `top2_params[0]` > `mean` > `model_state`（与 eval_checkpoint 一致）

### 🎯 决定性结论：搜索本身摧毁策略（2026-08-05）
| gen_0120 配置 | vs ExampleAI（知情对手） |
|------|------|
| TOP1 原始策略（1 头，修复后） | **100%** |
| 弱版（model_state）原始 | 62.5% |
| TOP1 + 32迭代搜索 | **0%** |
| 弱版 + 搜索 | 0% |

**搜索把 100% 的策略打成 0%，与热启动强度无关。** 过夜实验失败的主因是搜索本身，不是热启动/训练/评估设定。嫌疑原因：分解先验 argmax ≠ decoder 逐级 argmax（搜索+选先验也只有 20%）、3 操作/回合循环、价值头无信息、搜索预算小。

## 1. 背景与要验证的假设

官方脚手架那轮实验（玩具 MLP + 96 槽位接口 + ActionCatalog 候选）的失败**无法归因**——分不清是"AlphaZero 不行"还是"展平 MLP + 动态槽位 + 经济卡死"不行。方案 B 把三个污染源全部换掉：

| 污染源 | 玩具网络实验 | 方案 B |
|--------|-------------|--------|
| 网络 | 展平 MLP（无空间结构） | **AntWarNetwork CNN**（空间特征，平移等价） |
| 动作接口 | 96 动态槽位（语义每回合漂移） | **意图空间**（类×位置，语义稳定，decoder 确定性解码） |
| 候选生成 | ActionCatalog（覆盖上限 + 经济塌缩） | **网络自身的意图输出**（不依赖外部候选列表） |

**要回答的问题**：一个空间网络 + 意图空间先验 + MCTS 自对弈，能否在自对弈中持续提升策略（对 ExampleAI 和现有 ES 模型都更强）？

**如果方案 B 还学不动 → 强证据表明 AlphaZero 不适用于这游戏 → 停止投入 C++ 引擎（M0/M1）**。如果学得动 → 再投钱做引擎加速扩规模（M4）。**引擎重写不是本方案的前置。**

已知背景：现有 ES 训练 CNN 打 ExampleAI 已有 67-90% 胜率（gen_0030 90.6%、gen_0101 67.2%）。所以"强 CNN 策略能打过 ExampleAI"已证明；要验证的是**自对弈能否继续推高**。

## 2. 总体架构

```
自对弈游戏循环（双方共用同一网络）
        │  每决策调用
        ▼
意图空间 MCTS（PriorGuidedMCTS 自写版）
  树节点 = (游戏状态, 本回合已累积操作, 轮到谁, 第几个头)
  分支 = 原子意图动作 top-k（类 0-20 × 位置 + 21/22/23 类级）
  先验 = P(c) × P(p|c)，类 softmax 与位置 softmax 独立温度
  值   = 网络价值头（裸 Linear，目标 = 饱和血量差）
        │  收集 (观测, 每头访问分布, 血量差目标)
        ▼
torch 监督更新：3 个头 CE 损失 + 价值 MSE（目标 = 饱和血量差）
```

复用的现有组件：
- `my_ai/network.py`：AntWarNetwork（CNN encoder + action_map + 3 头 + 价值头）
- `my_ai/decoder.py`：`make_position_masks` / `make_class_mask` / 意图→Operation 确定性解码
- `SDK/backend/engine.py`：Python 引擎（`clone` / `apply_operation_list` / `advance_round`）
- `SDK/backend/state.py`：`DecisionContext` 的交替结构（P0 → P1 知情 → 结算）

## 3. MCTS 树结构（核心：意图空间，6 层/回合）

**每个头 = 树的一层**。回合内 6 层：`P0-head1 → P0-head2 → P0-head3 → P1-head1 → P1-head2 → P1-head3 → 结算 → 下回合`。

- **节点 = (游戏状态, 已累积操作列表, 相位, 头索引)**。游戏状态在 6 层内**不变**（操作只累积在 pending 列表里，结算时才 `resolve_turn`）。
- **只在结算边界克隆/推进状态**：P1-head3 选完后，把双方累积操作交给引擎 `resolve_turn`，产生下回合状态。**这避免了每层克隆状态（克隆是 Python 引擎的大头开销）**。
- **掩码随已选操作累积更新**：头 k 选出意图→解码出操作 o 后，后续头的 `position_mask` 要反映 o（例如在 (x,y) 建塔后，`position_mask[:, x, y] = False`；`can_apply_operation` 兜底）。复用 `decode_network_output` 里的累积逻辑。
- **top-k 剪枝**：每头的意图空间很大（24 类 × 361 格 ≈ 8664，含 2 个无位置基地升级 + HOLD）。展开时按先验取 top-k（root 16~32 / child 8~16），**HOLD（类 23）始终保留**（允许该头跳过）。

### 先验计算（每节点一次网络前向，3 头全给）

**采用分解式先验：类 softmax × 类内位置 softmax，两个独立温度**（2026-08-04 用户提议定稿）。对头 h 在状态 s：

```
P(c)   = softmax(head_h_logits[c] / T_class)[c]                 # 类的边际（合法类）
P(p|c) = softmax(action_map[c, p] / T_pos)[p]                   # 类内位置（合法位置）
prior(c, p) = P(c) × P(p|c)                                     # 原子动作 (c,p) 的先验
类 21/22/23（无位置）：P(p|c) = 1，仍是类级原子动作
```

- 默认 `T_class = 1.0`、`T_pos = 1.0`，可配置（两个温度独立控制类/位置的探索-利用）
- **位置 softmax 按通道独立**：`P(p|c)` 固定类 c，只在该类自己的合法位置集合上归一化，与其他类无关（和 decoder 的 `_sample_position(action_map[class_id], ...)` 行为一致——本来就只对选中通道做掩码 softmax）。每类位置概率恒和为 1，**合法位置数不影响类的先验总量**（1 个位置和 200 个位置的类贡献相同）
- **T_pos 吸收 decoder 的 `÷100` 固定缩放**：decoder 位置采样前先 `channel_map / 100`（action_map 原始值可达 ±960，直接 softmax 过尖）。等价于 `T_pos = 100`。P1 实现时先打印真实 action_map 数值范围再定默认 T_pos，不拍脑袋
- **为什么不用联合 softmax（`softmax(head_logits[c] + action_map[c,p])`）**：两者指数部分相同（加权和），但归一化不同——联合 softmax 按全体原子动作归一化，**位置多的类会被稀释**。本游戏超级武器（17-20）有 ~200 个合法落点而建塔只有 ~33 个高地格，联合 softmax 会让武器类靠"位置多"白拿概率质量。分解式先验保持**类边际 = softmax(head_logits)**，与 decoder 类优先采样的训练/推理语义一致
- 原子动作 = 类 0-20 的每个合法 (c,p) + 类 21/22/23 各一个，在这个原子动作列表上做 top-k

### 意图→操作的确定性解码

复用 `decoder.py` 的 `_decode_tower_action` / 超级武器 / 基地升级逻辑：给定 (class, x, y) 和状态，唯一确定一个 Operation。**意图空间里不存在多对多**——每个意图格就是一个动作。

**关键决策：MCTS 内使用 `intent_decoding=False`**（超级武器类按金币掩掉）。意图解码的"金币不足自动拆塔"回退会让"意图=闪电"实际执行"拆塔"，树里产生意图↔操作错位。MCTS 里保持严格掩码，意图永远解码成字面操作。

## 4. 价值头

**价值目标 = 饱和血量差**（2026-08-04 定稿，用户决策）：

```
v_terminal = clip((hp_us_final - hp_opp_final) / 20, -1, 1)
若 hp 相等但引擎判了胜者（平局规则，实测极罕见）：v = ±0.1
```

理由：
- 本游戏胜利条件就是基地血量，sign(血量差) ≈ 胜负符号，最大化期望血量差 ≈ 最大化胜率，不会和比赛目标脱节
- **连续目标比 ±1 二值目标更好拟合**，小样本实验更容易看到学习信号
- **与现有价值头训练目标（`(hp_us - hp_opp)/20`，见 `dual_expert_mcts_plan.md`）同尺度** → 热启动兼容
- 钳到 [-1,1] 保证 PUCT 的 Q 有界

**价值头网络结构不改**（保持裸 Linear）：目标有界 [-1,1]，MSE 回归即可，无需 tanh（PPO 时代去掉 tanh 是因为血量差无界，现在目标有界）。**但搜索包装层对 value 过 tanh** 保证 Q 始终有界（实测见下）。

**热启动策略（P1 实测修正）：只加载 encoder + 策略头，价值头重新初始化。** 实测现有 ES checkpoint（gen_0118）的价值头在所有局面输出 ~1.5×10⁷——ES 的胜率适应度不监督价值头，其权重漂移成了垃圾，直接用于 PUCT 会摧毁搜索。策略头则是好的（ES 优化的就是策略，冷启动测出能选出合理动作）。所以：encoder + 策略头提供强先验（自对弈从强策略对打开始），价值头重新初始化并在有界目标上快速重学。

## 5. 自对弈流程

- 双方共用同一网络，交替决策（`DecisionContext`：P0 盲动、P1 知情）。
- **温度**：前 N 回合温度 1.0（按访问分布采样），之后 1e-6（argmax）。N 可配（默认 ~30 回合）。
- **Dirichlet 根噪声**：α=0.35, ε=0.25（官方脚手架默认），保证探索。
- 每决策：MCTS 搜索 → 选动作 → 记录（观测, 每头访问分布, 状态）→ 终局后赋 ±1 目标。
- **已知近似（记录在案）**：P1 决策时**不额外编码 P0 本回合的待决操作**（同回合内 P0/P1 共享同一次前向，特征不含 pending ops）。真实比赛里 P1 看得到 P0 的操作。这个近似对"时机/位置"类博弈有信息损失，但 MCTS 的价值回传会部分补偿；先接受，作为后续改进点。

## 6. 训练

- 损失：`L = -Σ_head Σ_intent target_h * log p_h + λ_v * MSE(value, v_terminal)`。策略目标 = MCTS 访问分布（温度缩放），价值目标 = §4 的饱和血量差（`--value-target {hp_diff, win}` 可切回标准 ±1 做消融）。
- 3 个头各自在对应层级的访问分布上训练（head1 学"第一个操作"，head2 学"给定 head1 后的第二个操作"，依此类推）——与多头的语义一致。
- 优化器：AdamW，lr 1e-3 量级，weight_decay 1e-4。
- 训练样本 = 每决策的（观测, 3 头各自的访问分布, 血量差目标）。一局 512 回合 ≈ 1024 决策 ≈ 3072 头样本。
- **热启动**：加载现有 ES checkpoint 的**全部权重**（encoder + 策略头 + 价值头），初始先验 = 已有强策略。

## 7. 性能估算（Python 引擎，无 C++ 重写）

| 项 | 成本 |
|----|------|
| CNN 前向 | 15-50ms（CPU） |
| 每次决策搜索 | ~20-40 节点展开 ×（前向 + 掩码计算）≈ 0.5-1.5s |
| 一局（512 回合上限） | ~600 决策 × ~1s ≈ **8-12 分钟** |
| 小型验证实验（3 batch × 4 局） | **约 1.5-2 小时** |

优化点（后续，非首版必须）：同回合内 3 头共享一次前向（掩码不同即可）；叶子评估批量前向（虚拟损失式，回到最早讨论的 batch 推理）；这些是 M4 的事。

| 风险 | 缓解 |
|------|------|
| P1 不感知 P0 待决操作（信息损失） | 记录在案；MCTS 价值回传补偿；后续可加 pending-ops 特征 |
| 512 回合局太长、实验太慢 | 每 batch 少局数（2-4），先看趋势；max_rounds 可调 |
| 热启动权重与 AlphaZero 目标分布不完全一致 | 策略头/encoder 直接加载（输出空间一致，随训练适应）；**价值头必须重新初始化**（实测 ES 价值头输出 ~1.5e7 不可用），搜索层对 value 过 tanh 兜底 |
| 意图空间 top-k 剪枝漏掉关键动作 | HOLD 保底 + root top-k 大一点（32）；剪枝后覆盖度校验 |
| 多头训练信号不均匀（某头常被跳过） | 记录每头被选中的频率；必要时给稀疏头加权 |
| 自对弈局质量差（双方都乱走）导致目标噪声大 | 用小 temperature + Dirichlet 平衡；热启动 ES encoder 提供强先验 |

## 11. 一句话总结

**方案 B = 意图空间 MCTS（6 层/回合，先验 = head_logits + action_map 的 masked softmax，decoder 确定性解码）+ 自对弈（温度/Dirichlet/终局 ±1）+ torch 训练（3 头 CE + 价值 MSE），复用现有 CNN 与 Python 引擎；慢但足够回答"AlphaZero 有没有效"，若有效再投入 C++ 引擎扩规模。**
