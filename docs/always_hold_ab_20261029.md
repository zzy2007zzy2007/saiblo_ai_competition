# HOLD 恒为候选（`AZAI_ALWAYS_HOLD`）A/B 消融 —— 替代 E4（2026-10-29）

> **这篇管什么**：冠军 oracle 实测恒给 `()`（`force_pass_` 锁死，§1.1），亚军注入臂里被采纳的"新候选"
> **70.5% 也是 HOLD** ⇒ "注入有效"很可能只是"**把 HOLD 补进候选集**"这一个效应。
> 本实验把它**单独**做出来（不需要任何 oracle）：同一套 BASE、同一批 seeds/座位，
> 只差一个开关 `AZAI_ALWAYS_HOLD`。

## 2. 实现（默认关、逐位不变）

`code/test_match/az_bridge_ai.py`：

| 位置 | 改动 |
|---|---|
| 模块级 `_AHOLD` | `{on, dec, hold, added, chose_after_add, present_kept, present_moved, last_added, err}` |
| `_ahold_enable()` | 读 `AZAI_ALWAYS_HOLD`（**不设/0 ⇒ 直接 return**，连日志都不打） |
| `_ahold_step()`（搜索**前**） | 把 `()` 追加进 `mcts.extra_bundles`（**已有的额外候选通道**）；已存在则不追加；记 `added` |
| `_ahold_after_search(res)`（搜索**后**） | 记"最终是不是空 op"，并按 `added` 拆成 `chose_after_add` / `present_*`；每 50 决策打一行 `[ahold] 累计:` |
| `_report()` | 收尾打 `[ahold] 统计:`（bridge 硬杀时可能丢，所以周期行才是主读数） |

`code/test_match/_us_vs_external.sh`：`AZAI_ALWAYS_HOLD` 也要在"清空继承的 `AZAI_*`"之前抓住再放回
（那段循环会把所有 `AZAI_*` unset 掉 —— 与 oracle 的四个开关同一处理）。

`code/test_match/_always_hold_ab.sh`：两臂顺序跑 + 逐臂读数 + 最后 `--pair A B`。

**为什么走"额外候选通道"而不是改候选构造**：`flat_rollout_greedy._collect_extras()` 已经实现了
"按顺序去重、保留 HOLD、追加在末尾、网络候选在前"的规则（注入/安慰剂/升级候选都走这条路），
所以本开关**不改搜索算法**，只喂一个 bundle ⇒ A/B 的差别被限制在"候选集里有没有 HOLD"这一个自由度上。

## 3. 零影响证明（指标 6）

**做法**：用**当前代码**、`AZAI_ALWAYS_HOLD` **不设**，重跑历史批次的同一个 token
（`INJECT_VS_RU_B` 的 `7`：同 BASE、同 seeds、同对手），与历史日志逐字节比较。

| 比较对象 | 结果 |
|---|---|
| `RESULT` 行 | **完全相同**：`winner=runnerup winner_side=p1 verdict=engine rounds=497 terminal=True base_hp=0,32 coins=62,373 illegal=0` |
| 我方（p0）逐回合 op | **497/497 回合完全相同**（第一个不同的回合 = 无） |
| 对手（p1）逐回合 op | **497/497 回合完全相同**（第一个不同的回合 = 无） |

⇒ 新代码（oracle 重建/重启 + `AZAI_ALWAYS_HOLD` + `_us_vs_external.sh` 的开关传递）在开关关掉时
**对决策零影响**，而且顺带证明了这条链路（我们 + 亚军 + 引擎）是**确定性**的 ⇒ 两臂的差别只能来自开关。

## 5. 结论与下一步

### 5.1 落在预注册的哪一档：**②「HOLD 只是部分原因」**

| 档 | 门槛 | 实测 | 判定 |
|---|---|---|---|
| ① 复现大部分增益 | A ≥ **25.6%** | **25.0%** | ✗（差 0.6pp，落在门槛内侧） |
| **② 部分原因** | 12.5% < A < 25.6% | **25.0%** | **✅ 本档** |
| ③ 负效应 | A < B（12.5%） | 25.0% | ✗ |

**配对口径**：+12.5pp（+3 −1 个胜场）、McNemar **p = 0.6250**、配对 Δhp **+5.00** [−5.82, +15.82] ⇒ **不显著**。

⇒ **一句话**：把"恒为候选的 HOLD"单独补上，能拿回 **+12.5pp**（约为亚军注入臂 +37.5pp 的 **1/3**），
但**远不够**解释全部增益，而且 16 对配对**没有统计力**（p=0.625）。
所以"注入有效"**不是**单纯的"补了一个 HOLD 选项"——剩下 ~2/3 必须由**非 HOLD 的外部动作**
（亚军注入里那 15.5%）或它与 HOLD 的**交互**来解释。

### 5.2 三条副产物（比主结论更硬，因为不依赖 n.s. 的胜率）

1. **我们的候选集有 26.8% 的回合"看不到 HOLD"**（`added = 2089/7800`）——
   父任务从 pin 分布估的 22% 得到独立复现。这是**候选生成的结构性缺陷**，与"知识注入"无关。
2. **一旦 HOLD 在候选里，评估器总是选它**（HOLD 率 75.7% → 87.5%）；
   在"本来没有 HOLD"的回合里，把 HOLD 补进去后评估器**约一半（52.2%）会选它**
   ⇒ 那 26.8% 的回合里，**一半的决策被架构剥夺了**（1300 局×回合量级的机会）。
3. **增益全在"我们执后手"**：@P1 1/8 → **4/8**（hp −14.50 → **−2.38**），@P0 1/8 → 0/8。
   与 E1→E2 的座位方向一致 ⇒ 值得单独预注册一个 **@P1 专项、32+ 局**的批次（`n=8` 说什么都不算）。

### 5.3 下一步（按性价比排）

1. **先修候选生成**（这是工程改动，不是实验）：让 `mc_quiet` 仲裁在"动/不动"上不再独占——
   候选集里**无条件保留一个空 bundle**（就是本开关的行为），或者把类 23 的 pin 改成"必含"。
   依据：本批 A 臂 **+12.5pp / Δhp +6.69 / 降级 churn −5.5pp**，且**没有任何代价**（B 臂零改动、`illegal=0`）。
2. **要判"评估器够不够用"，样本量要重算**：+12.5pp 的配对检验需要 ~100-150 对才可能到 p<0.05；
   16 对只能分辨 ≥±25pp 的效应。下一轮若要结论，**每臂 64 局起**（对手=亚军，jobs=9，约 3-4 h）。
3. **拆剩下那 2/3**：跑一个"**只注入亚军的非 HOLD 动作**"的臂（把 HOLD 的那 84.5% 过滤掉，
   同时保留 ALWAYS_HOLD）⇒ 直接看"真外部动作"值多少。这个臂不需要冠军、不需要新 oracle，
   只要在 `_oracle_bundle/_oracle_bundle_b` 外面加一个"HOLD 不注入"的过滤器。
4. **不要再在"冠军 oracle"上花时间**：它需要**闭环执行**（它挑的招必须真的被执行），
   oracle 天生不满足；重建/重启/回放都改变不了（`docs/e4_only_extra_20261029.md` §1.4）。
