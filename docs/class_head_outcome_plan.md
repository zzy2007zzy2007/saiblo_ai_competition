# 计划：**用"对局结果"训练类头**（候选 R）—— 把常数类头变成依赖状态的策略

> 2026-10-05 14:4x 写（**动手写代码之前**，按 CLAUDE.md 要求）。触发它的实测（同一天）：
> * `code/test_match/diag_class_logit_gap.py`：类头的 **各类 logit 跨局面标准差中位仅 0.024**，
>   而 **top1−top2 的差恒为 0.21±0.02** ⇒ **类头是个常数函数：它根本不看局面**
>   （不是"排错"，是**没有函数关系**）。⇒ 部署永远选闪电；买不起闪电的回合整回合 HOLD。
> * `diag_value_class_choice.py`：**价值先验在类级上没有分辨力**（闪电可执行时 65% 仍选闪电；
>   不可执行时在塔类之间≈均匀；~80% 的分歧是并列）⇒ **"价值 → 类"这条蒸馏路没有可学的东西**
>   （候选 C 的零结果由此解释）。
> * ⇒ **唯一带类级分辨力的信号是"对局结果"**：哪个类在什么局面下带来胜利，只能从胜负里学。
>   **而这在这条线上从未发生过**（类头要么是继承的常数、要么只在被评估类之间被重排过）。
>
> ⚠️ **反捷径检查**：目标 = **我们自己对局的胜负**，**不模仿任何对手的动作**（不是行为克隆/蒸馏，
> 也不用 rule_v4 的动作当标签）⇒ **不触碰任务章程 §2 的禁令**。
> ⚠️ 部署侧**照旧**（`pos-only` + `pos_pin=argmax`）：本计划只**改 `class_state`**，不动 pos/value。

## 1. 假设

**H-R**：类头是常数函数，是因为它**从来没有拿到带类级分辨力的训练信号**。
给它一个（哪怕很弱的）**结果加权**信号，它就会变成**依赖状态**的类策略；
而这个变化**可能**提高 `vs rule_v4` 的配对胜率（方向未知：可能学到"该建塔时建塔"，
也可能像候选 D 那样把经济烧光 ⇒ **必须用判据说话**）。

## 2. 数据（"探索 → 结果"配对）

需要 **(state, 我方实际选的类, 该局结果)**：

1. **探索**：部署时以概率 p **按头随机钉类**（复用今天实现的 `class_pin_random_prob`，
   在 bridge 里用新环境变量 `AZAI_CLASSPIN_PROB` 打开；**只在采集批开**，正常读数不开）。
   p 取 **0.15**（比采集自对弈时的 0.02 大得多：要的是"类有变化"，代价是对局变差 —— 但
   数据只需要"类 → 结果"的对照，不需要对局好看）。
   ⚠️ 已知风险：p 越大，采集到的局面越偏离部署分布（历史校准：5% 的**类和位置都随机**会让胜率 −19pp）；
   0.15 的**类随机 + 位置仍由搜索排序**，预计伤害小于同率乱走，但仍会显著偏离 ⇒ **必须记档**。
2. **记录**：把 bridge 的裸 dump 每条记录**再加 3 字节**（三个 head 各自**实际选中的类**，
   `chosen_bundle` 里每个 op 的 op_type → 类；缺的 head 记 255）。
   ⇒ `ingest_bridge_dump.py` 相应扩展，pkl 里多一个 `chosen_cls[3]`。
3. **标签**：仍然用 ladder 日志的 `base_hp` 反推（`v_p0`），样本标签按 player 取符号（已有）。

## 3. 目标函数（先写死）

**结果加权的行为克隆（AWR）**，只训**类头**：

```
advantage a = (该样本的 v_p0，按 player 取符号)        # ∈ [-1, 1]，胜为正
loss = - mean_over_decisions [ w(a) * Σ_{h∈有效head} log q_h(chosen_cls[h]) ]
w(a) = exp(a / beta) 归一化（beta 先取 0.5）
```

- `q_h` = 类头第 h 个 head 在**当回合合法类**上的 softmax（用记录下来的 `class_mask`）；
  ⚠️ 合法掩码要**记录**（bridge 能算：`make_class_mask`）——否则会把不可执行的类也往上推。
- 只在**有合法类**的 head 上算；`chosen_cls == 255`（HOLD/无操作）的 head 跳过
  （HOLD 不是"选择的类"，是"没选出来"）。
- **只训 `class_state`**（pos/value 冻结、逐位写回；`save_three_net` 已有）。

## 4. 判据与预注册（**要另写**）

- 对照 = A1（seed `7..22` 前缀 `0.5000`）；
- 快读数 32 局（seed `7..22`，**A1 配置、不开探索**）；
- 晋级 `p̂ ≥ 0.55` 或 `≥ 0.70`；验收 128 局。
- **机制侧必须报**：① 训练后类头的**跨局面 logit 标准差**（`diag_class_logit_gap.py`）——
  **若仍 ≈0.02 ⇒ 它还是个常数函数 ⇒ 训练没进去**（这一条比分数更能说明问题）；
  ② 部署时的建塔数/出招数（应仍≈0/11，因为部署配置没变；若变 ⇒ 说明探索漏进了部署）。

## 5. 成本与最小版本

| 步 | 成本 |
|---|---|
| 代码（bridge 记录类+掩码、ingest 扩展、新训练脚本）| ~1 h |
| 采集 128 局（开 p=0.15 探索 + dump）| ~35 min（比 A1 慢，探索回合不触发 skip）|
| ingest + 训练（类头，几万条）| ~10 min |
| 快读数 32 局 + 判据 | ~10 min |
| **合计** | **≈ 2 h** |

**最小先行版（先验证"能不能训进类头"，不先看棋力）**：
采 **16 局**（seed `7..14`，p=0.15）⇒ ingest ⇒ 训 10 epoch ⇒
**只跑 `diag_class_logit_gap.py` 看跨局面标准差有没有从 0.02 抬起来**。
若抬不起来 ⇒ 先修训练（信号/权重/mask），**不浪费后面的 128 局**。

## 6. 风险（逐条）

1. **结果信号极弱**：~400 步一局、只有二值结果 ⇒ REINFORCE/AWR 的方差很大；
   128 局 ≈ 128 个独立结果，可能不足以分辨"哪个类在哪种局面下更好"。
2. **探索改变局面分布**：p=0.15 的类随机会让对局明显偏离部署分布（但**位置仍由搜索排序**）。
3. **可能学坏**：像候选 D 一样把金币花在没用的类上 ⇒ 判据会显示崩塌（那是有效信息）。
4. **掩码/类映射正确性**：`op_type → 类` 的映射要用解码器的口径（`decoder.py:34-71`），
   且**必须**把"自动降级"的坑考虑进去（超武买不起会执行 DOWNGRADE ⇒ 该类标注不可信）。
5. **不做**：不动 pos/value；不模仿对手；不用 val 损失当判据。
