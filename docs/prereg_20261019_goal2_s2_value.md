# 预注册（本 goal 第 8 轮起排队）：**S2 —— 用子博弈自对弈重训价值头**（闸门 = 评价器的**棋力**）

> 2026-10-19 写（**在动手之前**）。上位目标 `goal-2600a56a`（打冻结基线 `grafted_sdk_A.pt` 两段各 ≥80%，双方禁闪电）。

> `prereg_20261019_goal2_az_loop.md`（AZ 环，带进入条件）。

## 0. 动机（为什么价值网排在第 ⑤ 步而不是更早）

- 现在的部署里**价值网仍是旧的**（嫁接时特意保留 `value_state`）；它是**搜索的叶评估**、也是将来"更深搜索"的地基。
- 历史两次价值头重训都是"**离线 MSE 变好、棋力变差**"（val MSE 0.10145→0.09763 却筛选 −1.6pp）⇒ 所以本文件的**闸门必须是棋力**，不是 MSE。
- 目标文本里就写了这条闸门：**"作为评价器，同 128 局 ≥ 安静 rollout"**。

## 1. 数据

- **双方禁闪电**、我方用**当前基线配置**（`grafted_sdk_A` + pos-only + mc_quiet + 宽菜单）自对弈 **N=300–600 局**
  （训练专用 seed 段 `6001..6600`，**与判据段/随机段/未见段全不重叠**；**判据 seed 一律不入训**——章程③）。
- 落点：桥接端已有 `AZAI_DUMP_RAW_DIR`（每决策点 dump 观测）+ `code/.../ingest_bridge_dump.py`（从 ladder 日志补标签）
  ⇒ **不写新代码**，只按既有路径采集；标签 = 该局**从我们视角的最终胜负**（0/1），可加"未来加权/多尺度"变体（另立预注册）。
- ⚠️ 对手是 `base_pkg`（同一套配置、同一 ckpt）⇒ 自对弈是**同策略镜像**，局面分布会偏（这是已知局限，写进结论）。
  若需要更丰富的局面，可改用"候选 vs 基线"的对局数据（即 E 臂的日志）——但那会把评估与训练数据搅在一起，**默认不用**。

## 2. 训练

- 只训**价值头**（`value_state`），class/pos 网**冻住**（= 现有 `add_value_baseline.py` 一类脚本的做法；先核对脚本是否已支持"只训 value"）。
- 从现有 `value_state` **热启动**（微调），学习率取 1/5；训练/验证按"局"切分（**不能把同一局的相邻局面分到两边**，否则泄漏）。

## 3. 闸门与判据（**先写死**）

**闸门 A（机制/离线）**：验证集 MSE **不高于**旧网（否则直接判"这批数据没带来更好拟合"）。
**闸门 B（棋力，决定性）**：把新价值网接进部署（`grafted_sdk_A` 的 class/pos + **新** value）⇒ 与**旧价值网同配置**在**同一 128 局**上正面交手：

| 结果 | 判读 |
|---|---|
| 新 value 侧 `p̂ ≥ 0.60` | 价值网**确实更强** ⇒ 可以继续做"更深搜索 + AZ 环"（④ 的地基变好）|
| `0.45 ≤ p̂ < 0.60` | 等价（无信号）⇒ 记档；价值网**不是**本管线的瓶颈，回到 ③④ |
| `p̂ < 0.45` | 新网**更差** ⇒ 回滚，并如实记录"在我们这套配置下价值头重训再次失败（第三次）" |

（`p̂` 按边判、无效+缺失 ≤10%、判词全 engine；逐段报 CI 与执先/执后。）

## 4. 预测（事后对照）

- 闸门 A：我估 **通过概率 ~70%**（只是拟合同一批自对弈数据）。
- 闸门 B：我给 **"新 value 侧 p̂ ≥ 0.60" 约 20–30%**。理由：历史上两次重训都失败；而且我们的搜索只在一小部分决策上真正用价值网（MC 用的是**安静 rollout**，不是网）⇒ 网换了也未必改变行为。
- 若闸门 B 失败（第三次），我会把结论写成："**价值网不是本管线的瓶颈**，真正缺的是**目标/信用分配**"——这条若成立，也基本宣告"在现有流水线内做 AZ"上限很低。
