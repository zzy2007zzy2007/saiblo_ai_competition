# 猜想：价值头训练被"局数太少"的随机性主导（2026-09-13）

## 猜想（用户提出）

**几百局的数据量对价值网络训练可能根本不够**，导致实测效果/泛化能力**很大程度由训练随机性决定**，
而不是由我们控制的实验变量决定。

## 为什么这个猜想很有说服力

### 1. 有效样本量是"局数"，不是"帧数"

- 我们的价值头用 `warm_polonly` = **336 局**，约 287,546 帧。
- 但 terminal 标签**每局一个常数** → 独立标签数 = **336**。
- 即使用 kgeo/tau 这类逐帧标签，同一局内的帧**高度相关**（血量差是慢变量，
  见 `az_pool_tau_label_plan.md` 里的自相关实测），有效独立单元仍 ≈ **局数 = 336**。
- **336 个独立样本去拟合 55 万参数的价值网络 → 噪声必然主导。**

### 2. 历史上确实用过"几千局"

| 数据目录 | 规模 | 脚本 |
|---|---|---|
| `value_data/` | 677 局 | — |
| **`value_data_v2/`** | **7,988 局**（2.8GB）| `code/my_ai/train_value_net.py`（`--epochs 50`，支持 tau 标签 + 流式训练）|

即 **AZ 线现在的 336 局，比那条线少约 24 倍**。（注意：`value_data_v2` 是另一条线的
格式 `board/stats/class_/action_map/head_logits/value(T,2)` + 独立 `ValueNetwork`，
**不能直接复用**，但"量级"这个信息是关键的。）

### 3. 这几天的异常结果全部符合"噪声主导"的画像

| 现象 | 若变量有效应应有的样子 | 实际 |
|---|---|---|
| 同策略同标签、只换数据池 | 差异可解释 | **polonly-336 50.0% vs az_cpp-336 13.5%** |
| 同样"加 80 局" | 同方向 | polonly **+23pp** / az_cpp **−15pp**（方向相反）|
| 两个不同的价值头 | 结果应略有不同 | **完全相同**的 15W/49L |
| 三次"显著"发现（gapmax / C2 头 / 先后手不对称）| 应可复现 | 复测全部消失 |

**"同一个操作在不同池子上给出相反方向、且幅度都很大"** 是噪声地板高于效应的典型特征。
这也解释了我们反复踩到的假阳性。

### 4. 一个此前被忽略的约束

`value_warmup` **把全部 npz 一次性读进内存**（336 局 ≈ 9-12GB，机器 15GB）。
所以**当前流水线在物理上无法训练超过约 400 局**——不是我们没想堆数据，而是加载器
不允许。**要上量必须先解决流式加载**（历史上那次 5000 局方案正是这么做的：
`docs/value_data_merge_and_train.md` 的"多局合并 + 分块流式"）。

## 验证方案

### ① 先测"噪声地板"（最关键的缺失步骤）

**用完全相同的配置、只换训练随机种子**（`--seed`：影响价值头初始化 + 批顺序），
各评价 64 局。**它们的离散程度就是这张配置的噪声地板。**

- 若离散 **±10pp** → 这几天所有 ±10pp 级的结论**全部不可靠**，必须重做；
- 若离散只有 **±3pp** → kgeo 的 +20pp 是真的，可以继续追。

实现：`value_warmup --seed {1,2,3,4}`（seed 0 = 已有的 `kgeo_gap` 50.0%），
其余配置逐字相同（polonly 336 / kgeo tau50 abs s1.5 / 冻结骨干 / 10 epochs）。

### ② 再上量

需要先加**流式加载**（不改则受 ~400 局内存上限约束）。可选的量级：
- `az_cpp/data` 现有 **1104 局**（搜索自对弈，但来自坍缩策略）；
- gen120 式**裸策略无搜索**采集**~5 秒/局** → 8000 局约 40 分钟（16 workers），**最便宜**；
- 混合。

## ✅ 验证结果（2026-09-14）：猜想成立，而且是"重尾"而非均匀噪声

**同配置只换 `--seed`**（warm_polonly 336 / kgeo tau50 abs s1.5 / 冻结骨干 / 10 epochs /
64 局 vs rule_v4）：

| seed | 结局 | value loss 终值 | 来源 |
|---|---|---|---|
| **0** | **50.0%** | 0.0169 | `_tmp_poolweight.sh`（09-12，未传 --seed）|
| 1 | 25.0% | 0.0169 | seed_rep |
| 2 | 29.7% | 0.0169 | seed_rep |
| 3 | 28.1% | 0.0169 | noise_floor_extra |
| 4 | 26.6% | 0.0169 | noise_floor_extra |

**五个种子的训练 loss 完全相同（0.0169），棋力却从 25.0% 到 50.0%。**

- 4 个种子紧密聚在 **25.0-29.7%**（均值 27.4%、标准差 2.1pp）
- **seed 0 的 50.0% 是 20pp 的离群点**（≈ 11σ）

### 直接结论：kgeo 的 50.0% 是"抽中了彩票"

- `kgeo_gap` = seed 0。**典型**的 kgeo 结果是 25-30%，与 terminal 基线
  （29.7%）**无法区分** → **kgeo 并非真的更好**。
- 5 次里 1 次落进"幸运盆地"（≈20% 命中率）。

### 这解释了此前所有解释不通的现象

| 现象 | 原因 |
|---|---|
| 34.4% 复现失败（CPU/GPU 不同解）| 幸运盆地 |
| gapmax +11pp / C2 头 / 先后手不对称 —— 三次"显著"后消失 | 单种子对比 = 幸运 vs 不幸运 |
| 池子 × 标签 2×2 方向相反、幅度巨大（19%~50%）| 每臂只是一次抽签 |

**核心教训：本项目所有基于"单次训练"的对比，在 ±20pp 量级上全部无效。**
之前三天的池化/tau/kgeo/rel/v50 结论，**需要全部重估**。

### 后续

1. **确认机制**：重训 seed 0 → 若仍得 ~50%，说明"幸运盆地"是种子的确定性结果
   （则可复现，只是稀有）。
2. **真正的修法 = 上量**：更多数据应让 loss landscape 的盆地更少/更易命中
   → 这也是唯一能同时改善"稳定性"和"上限"的方向（呼应最早"数据是唯一有效杠杆"）。
3. **方法学**：任何比较都必须**每臂跑多个种子比分布**，不能跑单次。

## 对已完成结论的影响

若①显示噪声地板很大，则以下结论都需要重新评估（它们全部基于 256-336 局的单次训练）：

- 池化消融（5 种全灭 / gapmax 40.6%）
- tau 标签（tau50/tau100 各 6 臂，均值 18%）
- kgeo / rel（kgeo_gap 50.0%、svs 57.0%）
- 坍缩悖论（39-42% vs 29.7%）
- v50 配方（pool × label 2×2）
