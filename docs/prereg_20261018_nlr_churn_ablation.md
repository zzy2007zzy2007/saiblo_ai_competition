# 预注册：**NL-R 的 churn 消融**（NL-R + `NO_DOWNGRADE=1`）—— 损伤是"churn 造成的"还是"移开闪电造成的"？

> 2026-10-18 写（**在跑之前**）。章程：`docs/task_ruleV4_90_charter.md`。
> 上位预注册：`docs/prereg_20261018_mc_nolight_real.md`（NL-R 本体：固定段 **0.6094 = −12.5pp**）。

## 0. 由来（三条读数）

1. **NL-R 本体**：`MC_NO_LIGHT=1 + MC_UPG=1 + MC_TOPK=3` ⇒ **p̂ 0.6094**（对照 0.7344）；
   机制：**升级 0 → 1.2/局**（解锁成功）✓、闪电 9.9（没塌）✓，但 **降级 25.2 > 建塔/2**（churn 闸门不过）、净塔 10.2（对照 13.9）。
2. **按局相关（本轮新增）**：NL-R 的**负局里"建↔降翻转"中位 7 vs 胜局 5（Cliff d = −0.402）**，
   是全表最强的负相关；对照组这个量只有 d = −0.033。
3. **历史对照臂**：`NO_DOWNGRADE=1` 在**对照配置**里是 **0.4531（−20.3pp）** ⇒ 说明"降级"本身是**金币回收**机制，不能一概而论。

⇒ **要判的是**：NL-R 的 −12.5pp 是（a）**churn（过度循环）造成的**，还是（b）**把闪电移出 MC 菜单本身造成的**？

## 1. 臂（**一次只动一个开关**）

| 臂 | 配置 | 对照读数 |
|---|---|---|
| 对照 | `M6c-ROOT` | 0.7344 |
| **NL-R** | `MC_NO_LIGHT=1 + MC_UPG=1 + MC_TOPK=3` | **0.6094** |
| **NL-R+ND** | 同上 **+ `AZAI_NO_DOWNGRADE=1`**（执行层剔除降级）| **本臂** |
| （参考）对照+ND | 对照 **+ `NO_DOWNGRADE=1`** | 0.4531（已有）|

- **样本**：固定段 **128 局**（64 对），`jobs=8`，判词全 engine、无效+缺失 ≤10%。
- **机制前置判据（必须先过，否则不作结论）**：① **降级 ≈ 0**（执行层门生效）；
  ② **升级 > 0**（解锁没有被消融掉）；③ **闪电 ≥ 8.0/局**。
  ⚠️ 若 ① 不成立（降级仍高）⇒ 说明门没生效，本臂作废。

## 2. 判据（**先写死**）

- **p̂ ≥ 0.7044**（在对照 3pp 内）⇒ **churn 是损伤主因**（移开闪电本身可接受），
  且"**有升级、无循环**"这个方向**仍然活着** ⇒ 下一步做**方法侧**（不是手写门）：让机制自己学会"少循环"；
- **0.6094 < p̂ < 0.7044** ⇒ churn 只是**部分**原因（记档，方向不活）；
- **p̂ ≤ 0.6094** ⇒ **churn 不是主因**：把闪电移出 MC 菜单本身就有害 ⇒ **整条 NL-R 线关闭**（不再做方法侧）。
- ⚠️ 与 **对照+ND（0.4531）** 的比较是**辅助**读数：若 `NL-R+ND` 明显好于 0.4531，说明"NL-R 的经济量"
> 把"无降级"的代价补回来了一些。

## 3. 预测

- **我估 p̂ ∈ [0.55, 0.70]**（偏向"churn 有一部分责任，但移开闪电本身也在伤害"）。
- 依据：① NL-R 的闪电只掉 6%（10.5→9.9）⇒ "移开闪电"的直接代价不大；
  ② 但 NL-R 的**净塔更少**（10.2 < 13.9）⇒ 它花的钱没有变成塔，这是 churn 的直接后果（与"净塔 d=+0.358"一致）。
- **若 p̂ ≥ 0.7044**，我下一步会写**方法侧**预注册：目标 = "在有闪电的真实对局里，学到**何时升级/何时不循环**"
  （即把 NL-R 解锁出来的"升级能力"配上**时机判断**）——这需要新的信用信号，属于大改。
