# 预注册：**诊断臂「强制升级」**（`AZAI_FORCE_UPG=2`）——"投资轴"到底值不值？

> 2026-10-07 第 3 轮写（**在跑这批之前**）。章程：`docs/task_ruleV4_90_charter.md`。
> 性质：**手写干预的诊断臂**（章程 ②：手写启发式只能当诊断臂，判法 = 消融/方向判断）——**不是交付物**。

## 0. 由来（第 3 轮查明的三件事，都可复核）

1. **我们从不升级**：分侧统计 196 局 ⇒ 我方 `UPGRADE_TOWER = 0`（对手 `rule_v4` **9.4/局**、且**确实升到 level 1**）。
2. **为什么不能**：`UPGRADE_TOWER` 的参数是 **`(tower_id, target_type)`**（SDK 官方样例：
   `Operation(OperationType.UPGRADE_TOWER, tower.id, int(target))`）——**不是坐标**。
   我们整条 `class + position` 通路**表达不了升级**（尖峰探测：**类 0–15 全部解码成"建塔"，类 16 = 降级**）。
   ⇒ 我用**正确参数**强制发送后，**塔真的升到 level 1/type 1**（`SMOKE_forceupg2` trace `lv=[(5,7,1,1)]`）。
3. **评价器低估它**：把正确的升级候选放进 MC 菜单后（`AZAI_MC_UPG=2`，22/70 次决策出现在菜单里），
   **每次都输给 HOLD**（HOLD −0.15 vs 升级 −0.25；HOLD +0.10 vs −0.15；HOLD 0.40 vs 0.35）——
   与"安静 rollout 里**没人再出招**、投资的回报在后续才体现"这一**结构性偏差**一致。

## 1. 假设与判据

**H3-1**：**"把钱用在升级（把塔做高）"对我们更好**；MC 的安静 rollout 因为看不到后续而系统性低估投资。
**判法（诊断臂，方向判断）**：`AZAI_FORCE_UPG=2` = **只要有塔且买得起就升级**，其余照旧（否则正常 MC）。

| 读数 | 判定 |
|---|---|
| `p̂ ≥ 0.6562 + 8pp = 0.7362` | **投资轴是真的** ⇒ 下一步应做**方法侧**的改造（让评价器/搜索看见投资的回报），**而不是**保留这条手写规则 |
| `0.6562 − 5pp ≤ p̂ < 0.7362` | 方向不明 ⇒ 记档，不据此下结论 |
| `p̂ ≤ 0.6562 − 5pp` | **投资轴为负** ⇒ 评价器是对的，**该轴关闭**（并在寄存器写明理由，防重复试）|

- 每臂 **64 局 = 固定段前缀 `7..38`（32 对）**；对照 = `M6cROOT_128` 同前缀 **0.6562**。
- **必报机制读数**：我方 `UPGRADE_TOWER` / `BUILD_TOWER` / `DOWNGRADE_TOWER` / 闪电（**升级应从 0 变为 >0**）、
  塔类型分布（trace 里的 `lv=(x,y,level,type)`）、`dec_max`。
- ⚠️ 64 局只分辨 >~12pp；单段不作结论；不许看数据后改判据。
- ⚠️ 这条是**诊断**：即使它大涨，也**不能**把它当交付物（章程 ②）；要的是"方向 + 下一步怎么做"。

## 2. 预测（写下来，事后对照）

- **P1（机制，必然）**：`UPGRADE_TOWER > 0`，且塔类型从 0 变成 1（HEAVY）。
- **P2**：`BUILD_TOWER` 明显下降（钱被升级吃掉）、闪电可能下降。
- **P3（方向）**：我预计**略负或持平**（因为"一直升级"会挤掉建塔/闪电的节奏）——
  真正的信息在"**是不是显著为负**"：若明显为负 ⇒ 评价器没冤枉升级；若明显为正 ⇒ **评价器是瓶颈**。
