# 模型行为诊断工具

`code/test_match/diagnose_model.py` — 分析模型在与 ExampleAI 对战时实际选择了哪些动作，用于诊断模型退化或行为异常。

## 用法

```bash
# 默认：10 局，只输出每局汇总
python code/test_match/diagnose_model.py <checkpoint.pt>

# 1 局 + 逐回合输出每个动作
python code/test_match/diagnose_model.py <checkpoint.pt> --games 1 --verbose

# 分析种群均值（非 top1）
python code/test_match/diagnose_model.py <checkpoint.pt> --games 5
```

## 选项

| 参数 | 默认 | 说明 |
|------|------|------|
| `ckpt` | 必填 | checkpoint 路径 |
| `--games` | 10 | 对局数 |
| `--verbose, -v` | 否 | 逐回合打印模型选择的动作 |

## 输出说明

- 每局结束后打印：种子、胜负、双方血量、回合数、操作数、HOLD 次数
- 汇总部分打印：
  - 胜率、平均回合数
  - **每回合平均操作数**（远小于 3 说明模型频繁 HOLD）
  - **HOLD 占比**（什么也不做的回合比例）
  - **操作类型分布**（BUILD / UPGRADE / DOWNGRADE / 超级武器 / 基地升级）

## 诊断记录

### 训练 3 gen_0015 top1 — 2026-06-30

**命令**：`python code/test_match/diagnose_model.py training_history/20260630_182516/gen_0015.pt --games 1 --verbose`

**结果**：

| 指标 | 值 |
|------|:----:|
| 胜率 | 1/1（100%，巧合） |
| 总回合 | 258 |
| 总操作 | 23 |
| **HOLD 占比** | **91.1%**（235/258 回合什么也不做） |
| 每回合操作数 | 0.089 |

**操作类型分布**：

| 操作 | 次数 | 占比 |
|------|:----:|:----:|
| BUILD（建 Basic 塔） | 19 | 82.6% |
| UPGRADE（升 Producer） | 4 | 17.4% |

**诊断结论**：

模型完全退化，表现如下：
- **91% 的回合选择 HOLD**，不执行任何操作
- 仅有的动作全是**在自家高地建 Basic 塔**，或**升级成 Producer**
- **从不使用**：超级武器、基地升级（出兵速度/蚂蚁血量）、降级/拆除
- **从不升级**：Heavy / Quick / Mortar 等进攻型防御塔分支

这种"只建塔挂机"策略在 50 局测试中胜率 0%，偶尔靠拖满 512 回合侥幸取胜。

## 头行为诊断工具

`code/test_match/diagnose_heads.py` — 用 NeuralAgent 完整跑一局游戏，逐回合调用 decoder 解析每个头的意图，展示每个头实际想做什么操作。

### 用法

```bash
python code/test_match/diagnose_heads.py <checkpoint.pt> [--seed N]
```

### 输出示例

```
Checkpoint: training_history/ss_20260702_170653/gen_0010.pt
num_heads=3, params=553,313
Seed=0, turns=256, result=WIN (25 vs 5)
Bundle: 26 ops, 230 holds across 256 turns

  Head   Ops   Rej   Top-3 classes (what head wants to do)
  H1:    11/12  91%   ↓(9) B(1) S(1)
  H2:     5/8   62%   ↓(5) B(2) I(1)
  H3:     7/8   87%   ↓(6) B(1) M(1)

  Total head-decode attempts: 28 = 0.11/turn
```

### 各字段含义

| 字段 | 说明 |
|:----|:-----|
| Ops | 该头的被 decoder 接受（合法）的操作数 |
| Rej | 被 decoder 驳回（非法）的操作数 |
| Top-3 classes | 该头最频繁选择的 3 个动作类及次数 |
| ↓ | DOWNGRADE/拆除 |
| B | BUILD Basic 塔 |
| S/M/I | SNIPER / MORTAR / ICE |

`Ops/(Ops+Rej)` = 该头在合法范围内的命中率。如果某个头一直在输出非法操作（Rej 很高），可能说明它的位置图输出和 class 输出不协调。

## 重要发现：自对弈 vs 真实对战能力完全无关

从训练 4 各代的测试数据可以明显看出，模型在自对弈中的表现（head-to-head 胜率）与对阵 ExampleAI 的胜率**几乎不相关**。
...
**结论**：所有模型都塌缩到"建塔挂机"策略，但不同的塔阵型之间存在石头剪刀布关系。ES 的自对弈适应度（种群内互打分）完全不能反映模型对阵真实对手（ExampleAI）的能力，这是 ES 训练无法继续进步的根因。

## 补充发现：轨迹分析 & 代际对比（训练 6，2026-07-01）

### 参数轨迹分析

对训练 6 全部 32 代 checkpoint 的均值向量进行轨迹分析，评估 ES 优化方向：

| 指标 | 值 | 含义 |
|:----|:--:|:------|
| **Efficiency (disp/path)** | **0.66** | 不是随机游走——66% 的路径长度指向最终方向 |
| **Shift 自一致性** | **~0.60** | 前后代参数变化方向中等正相关（随机应为 0）|
| **步长 \|\|shift\|\|** | ~2.5 (恒定) | 没有萎缩，说明没卡死在极小局部最优 |
| **Last 10 gen stuck** | 0/10 | 没完全卡住 |

**结论**：ES 确实在沿一个大致一致的方向进化（非随机游走，非完全卡死），但信噪比偏低（自一致性 0.60，不强于 0.8），因为自对弈的适应度函数本身就是个弱信号。

### 代际 head-to-head 对比

让 gen_0028 分别与过去的自己（gen_0026、gen_0016、gen_0009）对战各 30 局（4 进程）：

| 对阵 | gen_28 胜率 | 双方 vs ExampleAI |
|:---:|:----------:|:-----------------:|
| gen_28 vs **gen_26** | **56.7%** (17/30) | 52.7% (150局) vs 48.7% (150局) |
| gen_28 vs **gen_16** | **63.3%** (19/30) | 52.7% (150局) vs **61.3%** (150局) |
| gen_28 vs **gen_9** | **56.7%** (17/30) | 52.7% (150局) vs **56.7%** (150局) |

**关键发现**：
- gen_28 能赢历代的自己（包括 vs ExampleAI 表现最好的 gen_16），说明 ES 确实让模型**在变强**
- 但 gen_16 打 ExampleAI 有 61.3%，gen_28 只有 52.7%
- **elite pool 机制导致种群针对历史版本进化**，不代表对 ExampleAI 的能力提升
- 这进一步验证了：自对弈适应度函数 ≠ 真实对战能力，需要引入外部对手来评估

### 传递性检验：gen_18→gen_28 每隔一代的 chain

为了验证模型有没有真正的传递性进步，让相邻偶数代进行 head-to-head 对战（20 局 4 进程）：

```
gen_18 ← gen_20:  20 胜率 45%  ← 倒退
gen_20 ← gen_22:  22 胜率 65%  → 进步
gen_22 ← gen_24:  24 胜率 40%  ← 倒退
gen_24 ← gen_26: 50%            → 平手
gen_26 ← gen_28:  28 胜率 56.7% → 进步
```

**完全看不出传递性**！gen_20 不如 gen_18，gen_22 能赢 gen_20（65%），但 gen_24 又输给 gen_22（40%）。

**结论**：种群在"建塔挂机"的不同塔阵型之间纯石头剪刀布循环。参数空间的位移虽然 3.7x 大于随机游走，但这只是一个**循环轨道**，不是**向上爬坡**。

### 最终诊断结论

经过训练 3/4/5/6 的反复测试和多角度分析，ES 训练无法突破 50% 基线的原因已完全明确：

1. **行为层面**：所有训练出来的模型都塌缩到同一种策略——**90% 回合 HOLD，只在自家高地 BUILD Basic 塔**。好坏模型的唯一区别是塔阵型不同，行为模式完全一样。

2. **适应度函数层面**：自对弈的适应度（种群内互打分）与真实对战（vs ExampleAI）的胜率**几乎完全不相关**。石头剪刀布效应让种群的"进化"变成纯循环。

3. **优化动力学层面**：参数轨迹不是随机游走（位移 3.7x 大于随机期望），确实在沿一致方向移动，但这个方向是**循环轨道**而非**向上爬坡**——传递链检验证明相邻代之间没有单调进步。

4. **elite pool 的效果**：用精英池作为对手有效防止了完全塌缩（不会掉到 0%），但无法帮助模型逃离"建塔挂机"这个局部最优解，因为 elite pool 中的对手也都是"建塔挂机"风格。

**根本原因**：ES 的适应度来自同一种群内部的互打，而种群内所有个体都共享同一个"行为基类"（塔阵型），无法提供跳出局部最优的梯度信号。需要引入**固定外部对手**（如 ExampleAI）来做评估，才能真正衡量进步。
