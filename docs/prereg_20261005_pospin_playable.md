# 预注册：**候选 D —— 把"钉住的类"从 `argmax` 改成 `playable`**

> 2026-10-05 07:5x 写（**在跑这批数据之前**）。触发它的实测（同一小时做的只读诊断）：
>
> * `code/test_match/cmp_class_head_argmax.py`：类头对**全 24 类**的 argmax 在 **9,663/9,663**
>   个 (决策, head) 对上**恒为类 17（LIGHTNING）**——新旧类头都是 100%；
> * `bundle_mcts.py:304-311`：`pos_pin=argmax` 时钉的是 **`int(np.argmax(hl))`（不套类掩码）**；
> * 于是"闪电买不起/冷却中"的回合，钉住的类**不可执行** ⇒ 整回合退化成 HOLD
>   （`bundle_mcts.py:405-407` 自述："类头塌缩 ⇒ argmax 类经常不可执行 ⇒ pos-only 下 ~97% 回合只剩 1 个候选"）；
> * 与观测吻合：我方**出招 11.2 回合/局**（403 回合的 2.7%）、**建塔恒为 0**；
> * 而 `playable_class()`（`bundle_mcts.py:52-79`）**正是为这种情况写的**：
>   "highest-logit class that decodes to a real (non-None) operation"（探测 logits 前 8 名）。
>
> ⚠️ **性质**：这仍是**部署语义的配置修复**（不是"方法学会了优化"），必须如实标注。
> 判据/seed/镜像/引擎不动；ckpt **不动**（只改一个环境变量 `AZAI_POSPIN`）。

## 1. 臂

| | ckpt | 配置 |
|---|---|---|
| **对照 D0 = A1** | `posnet_A_k5_m32.pt` | `k24/sm15/pos-only/skip1` + **`AZAI_POSPIN=argmax`**（读数取 `C1_a1_hist32`：seed `7..22` 上 **`p̂ = 0.5000`**）|
| **臂 D1** | 同左（**不动**） | 同左，**只把 `AZAI_POSPIN` 改成 `playable`** |

## 2. 样本量与判据（**先写死**）

- **快读数** = seed `7..22`（16 对 = 32 局），`--jobs=8`（预期 ~8–12 min）；
- **验收** = seed `7..70`（64 对 = 128 局），**只在快读数达标时跑**；
- 主读数 = `analyze_paired.py` 的配对分；
- **晋级**：`p̂ ≥ 0.55`（对照同 seed 前缀 `0.5000` + 5pp）或 `p̂ ≥ 0.70`；
- 有效性门槛同前（`verdict=engine`、`illegal=0`、无 INVALID、`terminal=True`；无效+缺失 >10% ⇒ 作废）；
- **禁止**看数据后改样本量/seed/只报子集；**没有**延长规则。

## 3. 预注册的预测（**机制预测是这条实验的主要价值**）

- **P-D1（机制，硬预测）**：我方**出招回合数**应从 ~11.2 **大幅上升**（对照：`rule_v4` 是 51）。
  若它**没上升** ⇒ "类头塌缩导致空过"这个解释**错了**，本实验的数值读数也就无从解释。
- **P-D2（机制，硬预测）**：我方**建塔数**应从**恒为 0** 变成 **> 0**（因为"买不起闪电"的回合
  会被钉到某个可执行类上，而可执行的类里最常见的就是建塔/升级）。
- **P-D3（数值）**：`p̂ ∈ [0.40, 0.75]`（方向未知：动得更多既可能更强，也可能因为
  "被逼着乱花金币"而更弱——**这是两种都合理的先验**，所以给它一个宽区间）。
- **P-D4（解释性）**：若 D1 成立而 `p̂` 反而下降 ⇒ 记"**类塌缩不是瓶颈、闪电策略才是有效的**"，
  并回到"怎么让类轴学到有用东西"（C 的失败说明**蒸馏目标选错了**：见下）。

## 4. 为什么它和候选 C 的失败是同一件事

候选 C 的快读数 `p̂ = 0.5000`、**32 局日志与对照逐字节相同**（`7.log` sha256 一致）
⇒ C 改的只是"在被评估的 5 个合法类里的相对偏好"，而**部署用的是全 24 类的 argmax（恒为 17）**
⇒ **改动完全没进入部署路径**。这解释了 C 的零结果，也说明：
**只要 `pos_pin=argmax` 而类头塌缩在闪电上，任何"在合法类之间重新排序"的训练都不可能改变行为。**
⇒ 要么改部署语义（本实验 D），要么把**可执行性**显式纳入类头训练目标（后续另写预注册）。

## 5. 成本与后续

- 快读数 **~8–12 min**；若晋级，128 局验收 **~30 min**（A1 配置下 1.7 min/局）。
- 若 D1 通过且 `p̂ ≥ 0.55` ⇒ 跑验收；若验收 ≥0.70 ⇒ **走机械门**（独立验证 + 记档 + 用户确认）。
- 若 D1 通过但 `p̂` 明显下降 ⇒ 仍是有价值的机制结论（见 P-D4）。

## 6. 不做的事

不动 ckpt/判据/seed/镜像/引擎；不模仿对手动作；不把"配置修复"写成"方法有效"。
