### 0.4 一句话结论（先给结论，后面全是证据）

**AZ 家族里，唯一同时解决"分支多 + 每次采样带噪 + 预算极薄"三件事的是 Gumbel 系（Gumbel-Top-k + Sequential Halving + `σ(q)` 缩放 + `π_MPO` 目标）；唯一解决"数据贵、算力贵、要榨干每一局"的是 KataGo 系（playout cap 分层预算 + policy target pruning + 辅助头）；其余大部分变体（learned model、连续动作、随机环境、大规模分布式）对我们属于负收益。**

## §2 逐个变体详解

> 每条固定四问：**解决什么 / 核心机制 / 代价·前提 / 我们能否用**。
> 公式与超参尽量给原始写法；凡是标 `[二手]` 的数字，说明我没读到原文，只有别人论文里的复述。

### 2.1 起点

#### 2.1.1 AlphaGo（Nature 2016）`[正文]`

- **解决什么**：围棋合法点数 361、棋局长，纯 MCTS 的随机 rollout 评估方差太大。它要解决的是"**叶子评估不准**"。
- **核心机制**：三个网络 + 两段式混合评估。SL 策略网 `p_σ`（13 层、`k=192` 滤波、19×19×48 输入平面）；快速 rollout 策略 `p_π`（线性 softmax，**2 µs/次**，而策略网 **3 ms/次**）；价值网 `v_θ`（同结构，输出标量）。
  MCTS 叶子评估为 `V(s_L) = λ·v_θ(s_L) + (1−λ)·z_L`，**`λ = 0.5`**；`z_L` 是用 `p_π` 走到终局的回报。
- **代价/前提**：rollout 策略必须手工特征化、且要按 CPU 线程跑到 ~1000 次/秒/线程；价值网要 5000 万 mini-batch 训练。
- **我们能否用**：**不能**。理由不是"过时"，而是**接口不匹配**——它的收益来自"用便宜 rollout 降低贵价值网的方差"，而我们恰好相反：值网是我们唯一的便宜评估（单次前向 ~ms 级），rollout 是我们的昂贵项（16 回合 ×122 µs）。把 `λ` 混合搬过来只会**同时引入两倍方差**。
- **可迁移的一点**：它验证了"`v_θ` 比 100 次快策略 rollout 更准，甚至等价于 15000 倍慢的强策略 rollout"（正文原话级结论）⇒ **在我们的预算里，值网打分应该占主导，rollout 次数应尽量少**，这与我方"16 回合 rollout 取均值"的方向一致，但提示我们 n=16 可能已经偏多。

#### 2.1.2 AlphaGo Zero（Nature 2017）`[二手]`

- **解决什么**：去掉人类棋谱与手工特征，纯自对弈能否超越 AlphaGo Lee。
- **核心机制**：单网双头 `(p,v)=f_θ(s)`，残差塔；MCTS **1600** 次模拟；价值目标 **`z ∈ {−1,+1}`**（二分类语义，无和棋）；策略目标 = 根节点访问计数分布（`π_a = N(a)^{1/T}/Σ`）。
  **AGZ 的四个关键超参（`[二手]`）**：根节点先验混 `ε=0.25` 的 Dirichlet 噪声、`c_puct = 5`、前 **30 手** `T=1` 之后 `T→0`（近似贪心）、每手 1600 模拟、约 490 万局自对弈。
- **代价/前提**：`[二手]` 20 块 × 256 通道、TPU 集群、3 天级训练；且 AGZ 有 **gating**（新网对旧网胜率 >55% 才替换）。
- **我们能否用**：**需改造**。可迁移的是"**先验噪声 + 温度退火**"这两件纯超参的事；不可迁移的是 gating 与 1600 模拟（见 2.1.3 与 §3）。
- **对我们最扎心的一条**：AGZ 的 `T=1` 只持续**前 30 手**，之后变贪心。我们单局 ~1000 决策、400–512 回合，**等于全程都是"前 30 手"**；照搬"前期高温"会把 1000 步全部变成高熵，这一点在 §3 第 3 条里改。

#### 2.1.3 AlphaZero（arXiv 1712.01815）`[正文]`

- **解决什么**：证明同一套算法、同一套超参，不调参就能通吃象棋/将棋/围棋。
- **核心机制**（正文 Methods 抄录）：
  - 损失：`l = (z − v)² − πᵀ log p + c‖θ‖²`；`z∈{−1,0,+1}`（**AlphaZero 相对 AGZ 的唯一算法差异：从"预测胜率"改成"预测期望结果"，从而能吃和棋**）。
  - 搜索：每次 MCTS **800 模拟**；动作按根节点访问计数比例选取；非法手概率置零再归一化。
  - 噪声：`Dir(α)` 加到根节点先验上，**α 与"典型合法手数"成反比**，取 `α = {0.3, 0.15, 0.03}`（象棋/将棋/围棋）。
  - 训练：**700,000 步**、batch **4096**、LR **0.2** 并三次衰减到 `0.02 / 0.002 / 0.0002`；自对弈 **4400 万局（象棋）/2400 万（将棋）/2100 万（围棋）**；生成端 5000 个一代 TPU、训练端 64 个二代 TPU。
  - **没有 gating、没有"最佳选手"替换**：一张网连续更新（正文明确写"省略了评估步骤与最佳选手选择"）。
  - 评估速度（Table S4）：象棋 **80k 位置/秒**、将棋 40k、围棋 16k —— **对比我们的 8,200 次状态转移/秒，慢约 2–10 倍**（这正是题设"慢 1-2 个数量级"的原始出处）。
  - 数据增广：围棋用 8 重对称；**象棋/将棋不增广**（规则不对称）。
- **代价/前提**：800 模拟 × 1000 决策/局 × 4400 万局 ≈ 天文数字；且前提是"每个叶子的 NN 评估比真实一步便宜"——**我们不满足**（见下）。
- **我们能否用**：**需改造**。三处**结构性不匹配**（不是调参能救）：
  1. **深度 vs 宽度**：它每个节点平均分到 `800/361 ≈ 2.2` 次访问、但**树深足够**（围棋每步有效分支约 10–30，20 层深时叶子被复用几十次）。我们若把 800 模拟摊到 266 候选 = 每候选 3 次，且**无树** ⇒ 完全没有"复用"带来的方差下降。
  2. **模拟成本**：它 1 次模拟 = 1 次 NN 前向（~0.1 ms）。我们 1 次模拟 = 16 回合真实 rollout ≈ 2 ms + 值网前向 ⇒ **单次模拟贵 20 倍**，同时可用模拟数少 1–2 个数量级。
  3. **`π = N^(1/T)` 的前提**：访问计数只有在"访问数 ≫ 分支数"时才是好的策略估计；266 分支下 `N(a)∈{0,1,2}`，`N^{1/T}` 几乎就是"谁先被抽到"的记录，**噪声主导**（与我方实测 371 vs 71 一致）。
- **但有一条可直接抄**：`α` **随合法手数反比缩放**。我们的合法候选数在 1–266 之间剧烈波动（91.6% 的决策只有 1 个候选），若用固定 `α`，在 1 候选时等于加了 100% 噪声、在 266 候选时等于没加。**改为 `α = 10.83 / n_legal`（KataGo 的"总 α 恒定"写法）** 是一行改动。

### 2.2 MuZero 系

#### 2.2.1 MuZero（Nature 2020 / arXiv 1911.08265）`[正文]`

- **解决什么**：真实环境不可微、且**模拟器可能不存在或很贵**时，怎么在隐空间里做 MCTS。
- **核心机制**：三函数 `h(o)→s₀`、`g(s,a)→(r,s')`、`f(s)→(p,v)`；展开 K 步损失
  `l = Σ_{k=0}^{K} [ l_p(π_k,p_k) + l_v(z_k,v_k) + l_r(u_k,r_k) ] + c‖θ‖²`；
  棋类 `z_k` 直接用终局 `z`（**不混 n-step**），Atari 用 **n=10 步回报**（正文明确"棋类直接到终局 z、不混合"）。
  值/奖励编码：`h(x)=sign(x)(√(|x|+1)−1+εx)`、`ε=0.001`；**601 个支撑（−300..300）**，目标写成"相邻两个支撑的线性组合"（即 two-adjacent / two-hot）。
- **代价/前提**：learned model 的误差会污染整棵树；需要 16 块 ×256 面、1M 局回放、1000+ TPU。棋类仍是 **800 模拟**（与 AZ 同），Atari 才 50。
- **我们能否用**：**不能**（学模型这一层）。我们**有真模拟器且只要 122 µs**；MuZero 的动力学网单次要 ~0.1 ms 且引入模型误差，**任何一项都不比 122 µs 便宜**。这是全篇最干脆的一个"不能"。
- **能抄的两件**：①**值目标编码**（two-hot → 见 2.4.2）；②**PUCT 的动态常数** `c(s)=c1+log((1+c2+N)/c2)`（下一节给公式）。

#### 2.2.2 Sampled MuZero（arXiv 2104.06303）`[正文]`

- **解决什么**：动作空间**大到无法枚举**（连续/高维）时，将 MCTS 从"枚举所有孩子"改成"**只展开采样出的 K 个孩子**"，并保住策略改进的收敛性。
- **核心机制**（三个必须一起看的点）：
  1. 采样分布 `β = π(·|s)`（可带温度）**并混入 Dirichlet 噪声**，"确保低先验动作也有机会被采到"。
  2. **重要性修正**：PUCT 的先验项从 `π(s,a)` 换成
     `(β̂/β · π)(s,a)`，其中 `β̂` 是采样得到的经验分布。**这是把"只看了 K 个动作"这件事还原成无偏的关键一步**——不写这一项，截断就是纯偏差。
  3. 访问计数照常在 K 个子上归一化成 `Î^π_β`，即策略目标仍可来自访问计数。
  PUCT 完整式：`argmax_a Q(s,a) + c(s)·(β̂/β·π)(s,a)·√(Σ_b N(s,b))/(1+N(s,a))`，`c(s)=c1+log((1+c2+Σ_b N)/c2)`，**`c1=1.25, c2=19652`**。
- **代价/前提**：K 必须比"有效分支数"大才有意义；论文实测 **K=3 就能学会 Humanoid（56 维连续控制）、K≥10 再无收益**（"Surprisingly K = 3 is already competitive ... not improved by sampling more than K = 10"）；且**只有"依分布收敛"的结论**（Corollary 由中心极限定理给出 O(1/√K) 正态近似），**没有带噪 `q̂` 的有限样本界**。
- **我们能否用**：**能，而且是最被低估的一条**。我们其实**已经在做"采样"而不是"枚举"**（266 个候选是采样/枚举的混合），但**我们没有写 `β̂/β` 的修正项**。后果：我们算出的"候选均值"是 `β̂` 下的均值，却当成 `π` 下的期望策略目标用 ⇒ **截断引入的偏差没人修正**。加上 `(β̂/β)` 项是把"截断"从偏差变成"方差放大器"的最小改动。
- **一个直接推论**：既然 K=3 在 56 维连续控制上就够，那**我们 266 个候选里"真正需要打的"可能不到 10 个**——这与我方实测（91.6% 决策只有 1 个候选、80% 被 SKIP1 短路）互相印证。

#### 2.2.3 Gumbel AlphaZero / Gumbel MuZero（ICLR 2022）`[二手原文]` + `[正文复述]`

> **注意**：原论文正文我**没读到**（OpenReview 403、arXiv 无收录）。以下公式来自 **MiniZero [正文] §II-C** 与 **MA Gumbel MuZero [正文] §3** 的逐式复述，两者互相一致，可信度高；但"`c_visit=50, c_scale=1` 这类默认常数"只有 `[二手]`。

- **解决什么**：**模拟数 `N_sim ≪ |A|`** 时，AlphaZero 的两个根本毛病：①确定性 PUCT 会让大多数动作**永远不被访问**（无法探索）；②访问计数分布在每个动作只被访问 0–2 次时**不是好的策略目标**（= 我们的现状）。
- **核心机制**（五处改动，逐条对我们都有意义）：
  1. **根节点候选集用 Gumbel-Top-k 采**：`A^k_top = argtop_k( log π_θ(a) + g_a )`，`g_a ~ Gumbel(0)` i.i.d. ⇒ 无放回地按 `π_θ` 采 k 个候选。
  2. **选中者用同一组 g 决定**：`a_root = argmax_{a∈A^k_top} ( g_a + log π_θ(a) + σ(q(a)) )`。
     **这就是"同一组噪声同时决定候选集与选中者"**——不是先按 logits 取 top-k 再独立加噪（那会丢掉无偏性，见 A 线已有结论）。
  3. **`σ(q)` 是缩放函数**：`σ(q) = (c_visit + max_b N(b)) · c_scale · q`（`c_visit>0, c_scale>0` 为常数，`[二手]` 取 50 与 1.0）。它的作用是把 Q 的量纲**拉到与 logits 可比**——`c_visit` 是"冷启动下限"（N 很小时不至于把 Q 压成 0），`max_b N(b)` 让**搜索越充分、Q 越可信、权重越大**。这是整个 Gumbel 系**最该抄的一行**。
  4. **根节点用 Sequential Halving** 花掉 `N_sim`：分 `log₂k` 阶段，每阶段按上式排序、砍掉后一半 ⇒ 预算自动集中到好动作。`N_sim = k` 时退化为"每候选恰好一次"。
  5. **策略目标改成 `π_MPO`（即 completed-Q 目标）**：`π_MPO(a|s) = softmax( log π_θ(a) + σ(q̂(a)) )`，训练时最小化 `D_KL(π_MPO ‖ π_θ)`。
     `q̂` 的定义：**被访问过的孩子用采样到的 Q；未访问的用值网 v 代替**（MiniZero 原文："For visited children, we use the sampled Q value. For those that have not been visited, we use the value network instead."）——这就是"completed Q-value"。
- **代价/前提**：`σ(q)` 的正确性依赖 **q 是"同一量纲下的可信估计"**；如果 q 本身噪声大，`σ` 会把噪声放大（论文的前提是"q 被正确评估时保证策略改进"，`[正文]` 原文 "guarantees a policy improvement **when q values are correctly evaluated**"）。另外 SH 要求 `k` 是 2 的幂附近才好分（`log₂k` 阶段）。
- **我们能否用**：**能，且是本文档第一优先**。三点具体理由：
  1. 我们的结构（固定候选束 + 每候选固定次数 + 取 max）**恰好是 Gumbel 要修的坏情况**；
  2. `σ(q)` 提供了"**把 Q 和先验放在同一把尺子上**"的机制，而我们当前的病根正是"先验尺度 vs 分差尺度 vs 噪声尺度三者没对齐"（噪声偏差 371、真实分差 71，且 logits 是另一套单位）；
  3. `π_MPO` 让我们**不需要树也能产生比"argmax 一个候选"信息量大得多的策略目标**（一条分布，而不是 one-hot）。
- **代价（必须写清楚）**：我们 `k≈266`、`N_sim` 只有 16 ⇒ `log₂ 266 ≈ 8` 阶段、每阶段只剩 2 次采样/候选，**SH 的分辨率不够**。正确做法是**先把 k 砍到 8–16**（用先验 top-k 或按金币/冷却过滤后的合法集），再跑 SH。即"**SH 的效果取决于你先把候选集缩到多小**"，这一步比 SH 本身更重要。

#### 2.2.4 EfficientZero（arXiv 2111.00210）`[正文]`

- **解决什么**：MuZero 在 **Atari 100k**（≈2 小时真实游戏数据）上样本效率极差。它的靶子是"**样本效率**"，不是"模拟效率"。
- **核心机制**（三件，正文明确说是 essential）：
  1. **自监督一致性损失**：用一个额外分支从 `(s_t, a_t)` 预测 `ŝ_{t+1}`，与 `s_{t+1}`（SimSiam 式，stop-grad + predictor）做余弦相似度；系数 `λ3`（附录超参表）。作用是让隐状态**在时间上连续可预测**，缓解 learned model 在少数据下的崩坏。
  2. **Value prefix**：端到端从 `s_t` 直接回归 `Σ_{k=0}^{l} r_{t+k}`，把"奖励累计"从递归变成一次前向，缓解稀疏奖励下价值传播慢。
  3. 601 维分类值头（同 MuZero）。
- **代价/前提**：需要"有可预测的动力学"；奖励若稠密，value prefix 收益变薄。
- **我们能否用**：**需改造，且优先级低**。①一致性损失的前提是"学动力学"，我们**有真动力学**（不用学）；②value prefix 针对"奖励稀疏 + 长程"——我们的奖励是终局胜负，**确实稀疏**，这一条值得单独评估（等价于"从中间状态直接预测最终分差"，我们已经用值网做了，所以其实是重复）；③它真正的启示是**"少数据时，辅助任务比主任务更能救训练"**，对应我们该加的是**辅助预测头**（KataGo 路线），而不是学模型。

#### 2.2.5 MiniZero（arXiv 2310.11305，TCIAIG 2024）`[正文]`

- **解决什么**：AZ / MuZero / g-α0 / g-μ0 四个算法**在同等算力下的横向可比**，尤其"**模拟数能小到什么程度**"。
- **核心机制 / 实测结论**（这是本文档里唯一给出"n=2 可用"正文证据的地方）：
  - 训练配置：AZ 与 MuZero 用 **200** 模拟；**g-α0 与 g-μ0 各训两个模型，分别用 n=2 与 n=16**（Go/Othello）；Atari 上 g-μ0 用 n=2 与 n=18。
  - 结论 1（围棋 9×9）：**模拟越多越强**，"训练时用更多模拟通常得到更强结果"；n=2 明显不足。
  - 结论 2（黑白棋 8×8）：**Gumbel 系在 n=2 时就能有竞争力**，"fewer simulations might be sufficient in exploring optimal strategies"——即 **Gumbel 的收益强依赖游戏性质**。
  - 结论 3（Atari）：存在反例（如 Gravitar），**模拟数越少反而训练更好**，说明"多模拟"不是单调收益。
  - 提出的 **progressive simulation**：训练总预算固定，前期只给 `N_min=2`，随迭代逐步升到 `N_max=200`（棋盘）/`50`（Atari）；算法把剩余预算"每次最多分一半"给需要提升的目标模拟数。棋盘游戏上**优于固定 n=16**；Atari 上则因游戏而异（部分游戏下降）。
- **代价/前提**：progressive simulation 的前提是"**训练是分迭代的、总预算固定**"；它靠"前期省下的模拟数"换取"后期更多迭代数"。
- **我们能否用**：**能，两条都用**：
  1. **Gumbel + n 小到 2–16** 有正文实测支撑（黑白棋/Atari 成立，围棋不成立）——我们更接近"Atari 型"（每步奖励结构不同、状态复杂）还是"围棋型"（深度战术）需要自己测，但**至少 n=16 不是下限**；
  2. **progressive simulation 的思想可直接改造为"按决策难度分配预算"**：我们 91.6% 的决策只有 1 个候选，把省下的预算灌给剩下的 8.4%，等价于全局预算不变、有效模拟数提升一个量级。这比"均匀 16 次"严格更好（详见 §3 第 2 条）。

#### 2.2.6 MuZero Unplugged / Reanalyse（arXiv 2104.06294）`[正文]`

- **解决什么**：**数据比算力贵**。已有的一局数据，能不能反复"重算"出更好的目标，而不是重新采集。
- **核心机制**：
  - Reanalyse：用**最新**网络对**旧轨迹的每个状态重跑 MCTS**（"During reanalysis, no actions are selected"——只算目标，不采样动作），把新的搜索策略/价值当训练目标。
  - **Reanalyse fraction**：训练目标里"来自重算"的比例，0%–100% 连续可调；正文用它统一了"提样本效率 / 纯离线 RL / 从示教学习"三种场景（100% = 纯离线）。
  - 优先级采样：`P(i) ∝ p_i^α`，**`p_i = |ν_i − z_i|`**（搜索值 vs n-step 回报的差），`α=β=1`，并用 `w_i=(1/(N·P(i)))^β` 做重要性修正。
  - 价值目标：**5 步 TD** 指向 target network（每 **100** 训练步更新一次）。
  - 配套（MuZero 原论文附录 H 的 Reanalyze 版）：**80% 的策略目标来自重算**；每状态采 **2.0** 个样本（原 0.1）；价值损失权重降到 **0.25**（策略/奖励为 1.0）；n 从 10 降到 **5**。
- **代价/前提**：重算要花前向/搜索算力；`p_i=|ν−z|` 的优先级会**偏向"当前网还看不懂"的状态**，可能过拟合难例（正文靠 importance weight 缓解）。
- **我们能否用**：**能，而且是最"白捡"的一条**。我们的数据:训练算力 = **1100:1**（KataGo 24:1）——这意味着"**再采集**的边际成本远高于"**重算**"。我们每月有 386 万个被搜索决策，用当前网重跑一遍（不做树，只做"候选束 + rollout + 值网"的确定性重评）就是 Reanalyse 的一个特例，**成本是一次前向 + 若干 rollout，不需要 10 s 预算**（离线做）。
- **注意**：`p_i=|ν_i − z_i|` 用在我们这里要小心——我们的 `z` 是终局结果，`ν` 是 rollout 均值，二者差距本身就含 rollout 噪声（σ≈111），**优先级会被噪声主导**。改造：用"多次重算的均值之差"或"值网与终局的 Brier 分数"当优先级。

#### 2.2.7 "无模型 / 无搜索" 派：ReZero 与 Amortized Planning

- **`ReZero`**：检索无果 ⇒ **`[未找到]`**。arXiv 上的 `ReZero`（2504.11001）是 LLM 检索方向，与 AZ 无关（详见 §5）。**我们不要在这里浪费时间**。
- **Amortized Planning with Large-Scale Transformers（arXiv 2402.04494）`[正文]`**：
  - **解决什么**：搜索能不能被"**摊还**"进一个大网络——即"不搜索也能到大师水平"是否成立。
  - **核心机制**：监督学习（不是 RL）。ChessBench：**1000 万局**、**150 亿个数据点**，标签来自 Stockfish 16 的**动作价值**；训练 Transformer 到 **2.7 亿参数**；推理时**零搜索**，直接贪心取 argmax Q。
  - **结果**：Lichess blitz **2895 Elo**（大师级），能解 Lichess 难题；作者同时给出与 Lc0 / AlphaZero "有/无搜索"的对比，结论是"**Stockfish 的搜索可以被蒸馏出一个惊人好的近似，但完美蒸馏仍不可及**"。
  - **代价/前提**：2.7 亿参数 vs 我们 **0.55M**（**约 490 倍**）；1000 万局 vs 我们 2.88 万局/月（**约 350 倍**）；且标签来自一个**已经很强的搜索引擎**（我们没有 Stockfish）。
  - **我们能否用**：**不能直接抄，但结论对我们极重要**：它证明"**蒸馏搜索 > 自己搜索**"在数据充足时成立；而我们月产 386 万决策、数据:算力 1100:1 ⇒ **把搜索成果蒸馏回先验**这条路在方向上是对的，只是我们的瓶颈在"教师不够强 + 网络太小"，不在算法。

### 2.3 工程化变体

#### 2.3.1 KataGo（arXiv 1902.10565）`[正文]`

- **解决什么**：AZ 的**自对弈效率**。原文首句："achieving a **50x reduction in computation** over comparable methods"。它要解决的是"**同一块 GPU 上，单位算力换来的棋力**"。
- **核心机制（四件通用 + 两件围棋专用）**：
  1. **Playout Cap Randomization（分层预算）**：在**一小部分 `p`** 的回合做**全搜索**（cap `N`），其余回合做**快搜索**（cap `n<N`）；**只有全搜索的回合被记录为训练样本**；快搜索还**关掉 Dirichlet 噪声**以最大化强度。主 run 设 **`p=0.25`、`(N,n)=(600,100)`，两天后退火到 `(1000,200)`**。
     动机原文很关键：价值目标"每局只有一个带噪的二值结果"，数据极度受限 ⇒ 想把算力花在"多打几局"上；但策略学习又需要大 playout ⇒ **二者冲突，用随机 cap 解耦**。
  2. **Forced Playouts + Policy Target Pruning**：对根节点每个已访问孩子强制最少
     `n_forced(c) = k · P(c) · √( Σ_{c'} N(c') )`，`k=2`（实现方式：把该孩子的 PUCT 置为 ∞）。指数 `1/2<1` 保证强制次数**随搜索增长而相对衰减**（坏棋的强制比例趋于 0）。
     然后**策略目标剪枝**：找出访问最多的 `c*`，从其他孩子各减去至多 `n_forced` 次访问（条件是减完后 `PUCT(c) < PUCT(c*)`、且保留其效用估计），被减到 1 次访问的孩子**直接剔除**。
     **它的意义（原文）**：让"策略目标"与"搜索的探索性分散"**解耦**——"没有理由认为 MCTS 里最优的 playout 分散度，也正好是策略目标的最优分散度"。
  3. **Global Pooling**：卷积只能看局部，加全局池化把全局统计量注入各层（`1.60×`，最大单项）。
  4. **Auxiliary Policy Targets + Ownership/Score 辅助头**：额外预测"对手下一手"（aux policy）与"每点归属 `ô`、终局分差分布 `p̂_s`（pdf 与 cdf 两种损失，`w_scdf=0.02`）"。消融：aux policy `1.30×`、ownership+score **`1.65×`**。
  5. 训练细节：19 天、**24 张 V100 自对弈 + 1 张 V100 训练**（⇒ 题设"24:1"的出处）、241M 样本 / 420 万局；batch 256、每样本 LR `6e-5`、前 500 万样本 LR 降 3 倍；**训练窗口按 `N_window = c(1+β((N_total/c)^α−1)/α)` 次线性增长**（`c=250k, α=0.75, β=0.4`）。
  6. 探索调度：**`T` 从 0.8 平滑衰减到 0.2，半衰期 = 棋盘宽度 `b` 手**（原文说"效果等价于 AZ/ELF 的前 30 手温度调度，但随棋盘大小缩放、更平滑"）；**2.5% 的局面被"分叉"**去试一手替代着法（用策略网按 T=1/2/∞ 采样），并**对分叉局面做全搜索以产出策略样本**。
  7. **Gating**：候选网需在 200 局里赢 **100** 局才替换（比 AGZ 的 55% 宽松），gating 局固定 300 节点 cap。
- **消融倍率（Table 2，达到 2.5G 等效查询时的"慢几倍"）**：playout cap `1.37×`、forced playouts+pruning `1.25×`、global pooling `1.60×`、aux policy `1.30×`、aux ownership+score `1.65×`、围棋专用特征 `1.55×`；**乘积 ≈ 9.1×**（与"50×"的差距来自初始化/其他细节）。
- **代价/前提**：需要"**能在一个回合内自由选择搜索深度**"（我们是固定 16 回合 rollout，但可以选"候选数 × rollout 数"）；辅助头需要**额外的标签**（ownership/score 在围棋是天然存在的终局量）。
- **我们能否用**：**能，是第二优先**。理由见 §3 第 2、3、4 条。特别是 **policy target pruning 的动机与我们完全同构**：我们的策略目标就是"16 次 rollout 后的 argmax"，其中大量分散来自探索/噪声，不是真实偏好。

#### 2.3.2 Leela Chess Zero（Lc0）`[正文]（仅搜索实现文档）`

- **解决什么**：**分布式众包**训练（成千上万志愿者 GPU 自对弈）+ 国际象棋工程化。
- **核心机制（我能读到正文的部分）**：
  - **批并行 MCTS**：主循环是"收集 minibatch → 跑 NN → 回填 → 传播"，每个待处理节点带 `multivisit`（**visits-in-flight，即 virtual loss 的计数形式**）。原文："a visit-in-flight does not guarantee any evaluation of any descendent node, however ... still gives useful information about how good the node is in comparison to its siblings"。
  - **`maxvisit` 的 PUCT 增量重算**："only recalculate PUCT-scores of the children if the best child has maxvisit lower than multivisit" —— 即**多数情况下不需要重算全部孩子的 PUCT**，这是批搜索的关键常数优化。
  - **NNCache**："Stores NN evaluations, which can be reused if the same position is reached by **transposition**"；另有 `depth` 字段专门用于"检测重复局面（draw by repetition）"。
- **代价/前提**：virtual loss 会**暂时低估**正在搜索的分支（引入系统性偏差，靠"回填时更正"处理）；批越大偏差越大。
- **我们能否用**：**部分能**。①**我们不是树搜索，virtual loss 没有直接用处**；但我们的"并行 rollout 批处理"有同构问题——如果多个线程同时评估同一候选，需要用 in-flight 计数避免重复劳动。②**NNCache/转置复用对我们有用**：塔防里"同一盘面不同建造顺序"会造成大量重复状态，按 `(盘面 hash, 资源, 冷却)` 建缓存能直接省 rollout。③`maxvisit` 的增量重算思想可搬成"增量维护 top-k 而不是重排全部 266 个"。
- **没能读到的**：Lc0 的**训练配方**（温度、WDL 头、syzygy 表）——官方 wiki 的训练页是个索引页，本环境的其它镜像也不通 ⇒ 这一块标 `[二手]`，§5 有记录。

### 2.4 其它值得注意的（按"改哪一块"分组）

#### 2.4.1 策略目标

**(a) 访问计数的温度/变换** `[正文]`
AZ 用 `π_a ∝ N(a)^{1/T}`，`T=1` 采样 / `T→0` 贪心。KataGo 的替代方案更细：**对"剪枝后"的分布做 `^{1/T}`，`T` 从 0.8 指数衰减到 0.2、半衰期 = 盘宽手数**。
**要点**：温度作用在"目标分布"上，而**采样温度**是另一件事（KataGo 前 `r` 手直接按原始策略 `p` 采，`r ~ Exp(mean=0.04b²)`）。二者混用是最常见的实现 bug。
**我们**：需改造。我们单局 1000 决策 ⇒ 不能让"高温期"占满全程；应按**局面不确定性**（候选数、先验熵）而不是"步数"调温。

**(b) 用 completed-Q 当策略目标（`π_MPO`）** `[正文复述]`
`π_MPO(a|s)=softmax(log π_θ(a) + σ(q̂(a)))`，`q̂` = 访问过的用 Q、未访问的用 `v`。这是 Gumbel 系"外层策略改进"的全部内容，也是"**不需要访问计数就能得到分布目标**"的关键。
**为什么对我们特别重要**：我们的搜索**根本产生不了像样的访问计数**（每候选 16 次、无树、取 max），但**我们能产生每个候选的 `q̂`（16 次 rollout 均值）**。所以 `π_MPO` 是**与我们现有产物最匹配的策略目标形式**——几乎零额外计算，只改标签生成。
**风险**：`q̂` 的噪声大时 `softmax(log π + σ(q̂))` 会接近 one-hot（因为 `σ(q̂)` 的跨候选差异被噪声拉大）。必须配 `c_scale` 调小 + 温度。

**(c) top-k 截断 / policy target pruning** `[正文]`（KataGo §3.2；Sampled MuZero 的 `β̂/β`）
两种不同的"截断"：KataGo 是**剪掉探索造成的多余访问**（保结构），Sampled MuZero 是**只算 K 个但用 `β̂/β` 还原无偏**（保期望）。
**我们**：两种都需要，且要先想清楚我们的"多余访问"从哪来——我们的候选是"枚举 + 先验筛"，所以主要偏差来自**先验筛**（等价于 `β=π` 的采样），**这正是 Sampled MuZero 的 `β̂/β` 要修的东西**。

**(d) KL 正则 / 与先验的耦合** `[正文]`（Gumbel 的 `D_KL(π_MPO‖π_θ)`；KataGo 的 policy surprise weighting）
- Gumbel 的训练目标本身就是 KL（等价于"向改进策略靠，但保留先验的熵"）。
- KataGo 的 **policy surprise weighting**：把"全搜索回合"的**样本频率权重**重新分配——**一半权重均匀**（每个 `0.5`），**另一半按 `KL(先验 ‖ 训练目标)` 比例分配**，再按 `floor(w)` 重复写入、小数部分按概率写入。效果 = "**搜索越惊讶的局面被写得越多**"。
**我们**：能。这是"**优先采样**"的一个极简替代（不需要 PER 的 sum-tree，只需在采集时算一次 KL 并重复写入），而我们的数据:训练比 1100:1 意味着**重复利用**比"采更多"划算。

#### 2.4.2 价值目标

**(a) categorical / two-hot / HL-Gauss** `[正文]`（MuZero §F；Stop Regressing §3.1）
- MuZero：601 支撑、目标写成**相邻两个支撑的线性组合**（`x = x_low·p_low + x_high·p_high`，例：`3.7 → 0.3@3 + 0.7@4`）。
- Stop Regressing 的对照实验：**Two-Hot 在在线 RL 上不如 MSE**；**HL-Gauss**（把高斯 CDF `N(μ,σ)` 投影到 `m` 个 bin 上，`σ ≈ 0.75 × bin 宽`；实践取 `6σ/ς` 个 bin 承载 99.7% 质量）**显著优于 MSE / Two-Hot / C51**，在"无搜索国际象棋"上把与 Stockfish 的差距**缩小 70%**、机器人操作峰值 **+67%**。
- 机理（原文）：缓解**噪声目标**与**非平稳**，并且"分布到邻近 bin"起到**标签平滑**作用（消融显示 `σ` 的最优值与 bin 宽 `ς` 无关 ⇒ 不是单纯的平滑）。
- **我们**：能，**改动最小的一条**。我们的值标签 = "16 次 rollout 的均值"，**天然带噪且噪声量级已知（σ≈111）**——HL-Gauss 的 `σ` 可以直接设成 `SE = 111/√16 ≈ 28`，这是一个**有物理意义的超参**，不是玄学。

**(b) value target 归一化** `[正文]`
MuZero 的 `h(x)=sign(x)(√(|x|+1)−1+εx)`（`ε=0.001`）是**可逆压缩**：把 `[−300,300]` 压到 `[−16.3,16.3]` 的量级再分 601 个 bin，等价于"**在小值域上密、大值域上疏**"。
**我们**：需改造。我们的分差在几百到上千点量级，**直接分 bin 会导致 bin 宽 >> 真实分差 71**⇒ 分类退化成回归。必须先做**尺度归一化**（用分差标准差做 z-score，或按 Elo 的 logistic 映射成"胜率"再分 bin）。

**(c) WDL 三头 / 混合来源** `[正文]`（KataGo §3.4 的 ownership+score 是"结构化版 WDL"；MuZero 的 value + reward 双头）
KataGo 没有用"WDL 三分类"，而是把它拆成**更细的监督**：终局胜负（value）+ 归属（ownership，逐点 `{0,0.5,1}`）+ 分差分布（pdf + cdf 两个损失）。**拆得越细，梯度信号越多**：`1.65×` 加速。
**我们**：能。我们有"血量差 / 塔数差 / 金币差"这些**天然的结构化中间量**，等价于 ownership 头；把它们做成辅助头比"直接预测胜负"信号密度高得多。

#### 2.4.3 搜索侧

**(a) virtual loss / batched MCTS** `[正文]`（Lc0）
机制：并行选择时给"正在搜索"的边加一个虚拟损失，让后续线程选到别处；回填时撤销。Lc0 用 `multivisit` 计数 + `maxvisit` 判断"是否需要重算 PUCT"。
**代价**：引入负偏差（被搜索中的分支被低估），批越大越严重；必须靠"回填时精确更正"兜住。
**我们**：不能（无树）。但**批处理的收益是真的**：我们的 rollout 是串行 16 次；若改成"一次提交 16 个 rollout 的批"，值网前向可批量化（RTX 5060 上小 batch 的吞吐提升通常 3–8×）。这里"virtual loss"对应的正确做法是 **in-flight 计数去重**，不是加虚拟损失。

**(b) transposition / 前缀共享 / 树上复用** `[正文]`（MCGS；Lc0 的 NNCache）
- MCGS 把树变成 **DAG**：用 hash 检测转置，**转置键里包含 step counter**（这样同一条轨迹内不可能再到达同一状态 ⇒ **禁环**）。两个坑：①朴素实现要深拷贝策略/值 ⇒ 内存不省；②只沿"被走过的那条轨迹"回传 ⇒ **信息泄漏**（父节点的 Q 只基于子树的一部分，却用整棵子树做选择）。解决办法：**Q 同时存"边"和"点"**，区分"当前信念"与"更精确的节点估计"。
- 收益（crazyhouse）：MCGS 单独 `≈+110 Elo`，ε-greedy `≈+100`，全组合 `≈+310`；国际象棋全组合 `≈+69`（模型是监督学的，所以收益小）。原文注："amount of nodes per game generally increases ... because the subtree of the previous search is reused"。
- **我们**：**需改造，但价值高**。我们不做树，但**"前缀共享"是同一件事的低配版**：266 个候选里有大量**相同的第 1 回合动作**（比如"造塔 A"后接不同的第 2 步），若按"第 1 回合动作"分组做 **rollout 前缀缓存**，可省掉重复的 122 µs 转移。这与 MCGS 的"转置复用"是同一机制在不同粒度上的应用。

**(c) PUCT 常数调参 / 动态 cPUCT** `[正文]`（KataGo Methods；MuZero 的 `c(s)`）
- MuZero/Sampled MuZero：`c(s)=c1+log((1+c2+ΣN)/c2)`，`c1=1.25, c2=19652` ⇒ 访问数 `≪c2` 时退化为常数 `c1`，访问数大时**对数增长**。
- KataGo 更进一步：**cPUCT 应正比于效用差的尺度**（"if the scale of utility differences between moves changes, the optimal cPUCT should change proportionally ... using a constant value for cPUCT for the entire game does not make sense"）。它现在的实现是"**每个节点的 cPUCT 按该节点子节点效用方差的开方缩放**"，并报告：配上 uncertainty-weighted playouts 后 **≈+75 Elo**；若只把旧版常数 cPUCT 调到最优，也只能拿 **≈25 Elo**。
- **这直接命中我们的病**：我们的噪声 `σ≈111`、信号 `Δ≈71` ⇒ **信噪比 <1**。KataGo 的逻辑说：当"效用差尺度"变化时，`c` 要跟着变。反过来说——**当噪声尺度远大于信号时，探索项的相对权重必须被压小**，否则搜索被噪声牵着走。我们的"候选被截断到 k 时噪声偏差 σ√(2ln k)"正是一个"**探索项=噪声项**"的极端例子。

**(d) depth-limited search + 价值自举** `[正文]`（MuZero 的 n-step；EfficientZero 的 value prefix）
MuZero 的 K 步展开 + `z_k` 自举；EfficientZero 的 value prefix 把 `Σr` 变成一次前向。
**我们**：**已经在用**（16 回合 rollout 后取值网打分，就是 depth-limited + bootstrap）。真正的问题不是"要不要自举"，而是"**自举点的值网语义是否与搜索深度匹配**"——F 线已指出：我们的值网语义是"16 步 rollout 后的期望"，**用它给浅层叶子打分是语义错位**。这一条在 §3 里作为风险标注。

#### 2.4.4 训练稳定性

**(a) Reanalyse buffer** `[正文]`（见 2.2.6）。要点：fraction 可调、优先级 `|ν−z|`、目标网络每 100 步、5 步 TD。
**(b) 优先采样** `[正文]`（同上 + KataGo 的 policy surprise weighting）。两种实现：PER（sum-tree + 重要性权重）vs 按 KL 重复写入（更简单）。
**(c) 自对弈温度与探索噪声衰减** `[正文]`（AlphaZero/AGZ 的前 30 手；KataGo 的 `T:0.8→0.2`、half-life=盘宽；MuZero Atari 的 `T:1→0.5→0.25` 按训练步数）
**共同结构**：**三个不同的"温度"**——①目标分布温度（`N^{1/T}` 里的 `T`）、②动作采样温度、③先验噪声 `α`/`ε`。KataGo 把 ① 做成"随盘宽/手数衰减"，把 ③ 做成"shaped Dirichlet"（总 α 恒定 `=10.83`，一半 α 均摊、一半 α 集中到"先验 logit 明显高于其他"的少数着法上，用来**专打盲点**）。
**我们**：能。我们的"噪声衰减"应该是**随训练进程衰减 `α`**（而不是随手数），因为我们的难点是"前期探索 / 后期利用"，不是"开局探索 / 中局利用"。

**(d) gating / 评估协议** `[正文]`
- AGZ `[二手]`：新网需 >55% 胜率。
- AlphaZero `[正文]`：**取消 gating**（一张网连续更新）。
- KataGo `[正文]`：**保留 gating**，但很轻（200 局赢 100 局 ≈ 50%），gating 局用固定 300 节点 cap。
⇒ **结论：gating 不是必需品，且阈值都在 50–55% 的"几乎不筛"区间**。这一点与 E 线（评估协议）呼应：**在胜率 50% 附近做 gating，统计上等于抛硬币**（E 线已算过判 5pp 需 3468 局）。

### 2.5 反面证据：AZ 在什么条件下失效

| # | 论文 | 失效条件 | 原文级证据 | 是否命中我们 |
|---|---|---|---|---|
| 1 | **Gumbel MuZero**（`[正文复述]`） | `N_sim < |A|`，即模拟数小于动作数 | 方案的存在本身就是证据："some actions may never be selected especially when N_sim < |A|"；其策略目标必须换成 `π_MPO`，因为"we cannot use the search visit count distribution as the policy network training target" | **强烈命中**（266 候选 / 16 次采样） |

## §3 对我们最有用的 5 条（按可落地性排序）

> 判据统一：**先离线可测、再上对局**。E 线已算过"判 5pp 需最坏 3468 局 ≈ 12.6 小时"，所以任何需要靠对局才能验证的改动都应该排在后面。
> 我们的事实底座（全文复用）：`k≈266` 候选、每候选 16 回合 rollout、单次状态转移 **122 µs / 8,200 次/秒**、单次 rollout 的 σ **≈111**、n=15 时 SE **≈29**、真实 top1−top2 分差中位 **≈71**、266 候选取 max 的噪声偏差 **≈σ√(2ln 266) ≈ 371**、91.6% 的决策只有 1 个候选。

---

### 第 1 条：把"独立加噪取 max"换成"同一组 Gumbel 决定候选集与选中者"，并给 Q 加 `σ(q)` 缩放

- **改哪里**：
  1. **候选筛选**：现在是"先验 top-k / 枚举 + 独立加噪"。改成 `A^k = argtop_k( log π_θ(a) + g_a )`，`g_a ~ Gumbel(0)` i.i.d.（Gumbel-Top-k 无放回采样）。
  2. **最终选择**：现在 `argmax_a q̂(a)`。改成 `argmax_{a∈A^k} ( g_a + log π_θ(a) + σ(q̂(a)) )`，**用的是同一组 `g_a`**。
  3. **`σ` 的定义**：`σ(q) = (c_visit + max_b N_b) · c_scale · q`。我们 `N_b ≤ 16` ⇒ `max_b N_b` 很小 ⇒ 实际系数 ≈ `c_visit·c_scale`。**必须先把 q̂ 无量纲化**（建议 `q̂ / 200`，把"分差"换成"约 ±1 的尺度"，与 logits 可比），再让 `c_scale ≈ 1`。
- **为什么这是第 1 条**：我们的病根是"**选择被噪声主导**"（371 vs 71）。而 `argmax` over k 个独立噪声样本的偏差 `σ√(2ln k)` 是**纯选择偏差**；Gumbel 系的做法不是"减少噪声"，而是**让噪声与先验、Q 在同一个可比的尺度上联合决定**，从而把"取 max"这个非线性放大器的偏差消掉。
- **预期收益**：①偏差从 371 量级压到 `Δ` 量级（即从"5 倍于真实分差"降到"与真实分差同阶"）；②离线指标 **top-1 命中率 / simple regret**（相对 n=128 的参考排序）应显著提升——这是**不需要对局**就能测的。
- **风险**：
  - `σ(q̂)` 会把 q̂ 的噪声按 `c_visit·c_scale` 放大；若 `c_scale` 调大，会从"噪声主导"变成"Q 主导但 Q 是噪声"。**必须先扫 `c_scale ∈ {0.1,0.3,1,3}` 看离线 regret 的 U 形**。
  - Gumbel 的正确用法容易写错：**按 logits 取 top-k 再独立加噪会丢掉无偏性**（A 线已有此结论，我这次在 MA Gumbel 的式 (8) 里再次确认：必须是 `argtop_k(log π + g)`，`g` 与后续选择**共用**）。
  - 我们的 `π_θ` 在 k 大时非常平（0.55M 参数的位置先验），`log π` 的动态范围小 ⇒ 实际"候选集"可能近似随机。**所以这一步要和"先缩小 k"绑定做**（见第 3 条）。

---

### 第 2 条：策略目标从 `argmax` 换成 `π_MPO = softmax(log π_θ + σ(q̂))`（即 completed-Q 目标）

- **改哪里**：只改**标签生成**，不改网络结构。现在每个被搜索决策产出一条 one-hot（argmax 的那个候选）。改成一条**分布**：
  `π_target(a) = softmax( log π_θ(a) + σ(q̂(a)) )`，
  其中 `q̂(a)` = 该候选 16 次 rollout 的均值（**已访问过的就直接用**）；**未被评估的候选一律填 `v(s)`**（值网输出的局面值）——这就是 completed-Q 的定义，它保证分布定义在**整个候选集**上而不是只有被搜过的子集。
- **为什么排第 2**：我们**已经有 `q̂`**（每个候选的 rollout 均值），所以这是"零额外计算"的改动；而且它顺带解决了"**我们产生不了像样的访问计数**"这个结构问题（Gumbel 系的原文理由：模拟数远小于动作数时"cannot use the search visit count distribution as the policy target"）。
- **预期收益**：
  - 策略目标从"1 bit/决策"变成"`k` 个浮点/决策"⇒ 同样 386 万决策/月的信息量提升一个量级（直接对应我们"数据:算力 1100:1、该榨数据"的结构）；
  - 与第 1 条**共用 `σ`**，调一次超参两处受益。
- **风险**：
  - **q̂ 噪声大 ⇒ softmax 退化成 one-hot**（`σ(q̂)` 的跨候选差被噪声拉大）。诊断：算目标分布的**熵**；若熵接近 0，说明 `c_scale` 太大或 rollout 次数太少。
  - 若 `q̂` 系统性有偏（比如 rollout 策略与最终策略不一致），`π_MPO` 会把偏差**固化进先验**，比 one-hot 更难纠正。**缓解：目标里留一个"回到 one-hot"的混合项 `(1−ε)·π_MPO + ε·onehot`**，`ε` 从 0.3 降到 0.05。

---

### 第 3 条：分层预算——按决策难度分配"候选数 × rollout 数"，而不是全局均匀 16 次

- **改哪里**：把"266 候选 × 16 次"这个**全局常数**换成**按决策自适应**：
  - `n_legal == 1`（占 91.6%）⇒ **0 次 rollout**，直接取该动作（现在是 16 次，纯浪费）；
  - `n_legal ∈ [2, 8]` ⇒ 每个候选 `n_r = 32~64` 次（因为候选少，预算够）；
  - `n_legal > 8` ⇒ 先按先验截到 `k=8~16`（第 1 条的 Gumbel-Top-k），每个 `n_r = 8~16`。
  这是 KataGo **playout cap randomization** 的同构改造：它的 `p=0.25` 是"**只有 25% 的回合做全搜索、且只有这些回合被记录**"，对应我们"**只有少数决策值得花满预算，且只有这些决策值得写成训练样本**"。
- **数量级估算**（用我方实测比例）：若 91.6% 的决策从 16 次 rollout 降到 0 次，则**总 rollout 次数下降约 91.6%**；把省下的预算全部给剩下 8.4% 的决策 ⇒ 这些决策的每候选样本数可提升 **~10 倍**（SE 从 29 降到 ~9）。**同样的墙钟时间，关键决策的精度提升一个量级**。
- **为什么排第 3**：它不改算法语义、只改预算分配，**风险最低**，但收益取决于"难度分布是否稳定"——需要先统计"每步合法候选数的分布 + 有多少步真的需要比较"。
- **风险**：
  - **训练数据分布会偏移**：只记录"高预算决策"会让训练集偏向复杂局面。KataGo 的解法是"快搜索回合也照常下棋、只是不记录"，我们同样必须**照常下棋**（用便宜的 argmax），只跳过记录。
  - 我们的"1 个候选"里有一部分是 **HOLD（不动）**，而 HOLD 常是正确决策 ⇒ **不能因为"候选少"就认为决策简单**。所以判据不是 `n_legal` 而是"**top1 与 top2 的先验差 + q̂ 差**"是否超过噪声（`Δ > 3·SE`）。

---

### 第 4 条：值头改**分类**（HL-Gauss）+ 加**结构化辅助头**（血量差 / 塔数差 / 金币差）

- **改哪里**：
  1. 值头从"回归一个标量"改成"**对分差的分箱分类**"：把分差 z-score 后映射到 `m` 个 bin（建议 `m=101`，range `±40` 个 bin 宽，参考 Stop Regressing 的象棋设置），用 **HL-Gauss**：目标分布 = `N(μ=z, σ=SE)` 在相邻 bin 上的 CDF 差，`SE = 111/√n_r`（**有物理意义，不是超参**）。
  2. 加辅助头：预测**终局血量差 / 塔数差 / 金币差**（类比 KataGo 的 ownership + score 双头，消融 `1.65×`）；损失权重按"量纲归一后同阶"设。
- **为什么排第 4**：它需要**重训一次**，但改动是"最后几层"，不动搜索。
- **预期收益**：
  - Stop Regressing 的正文结论：**分类 > 回归**（尤其"噪声目标 + 大网"场景），在无搜索象棋上把差距缩小 **70%**；而 **Two-Hot 反而不如 MSE** ⇒ **别抄 MuZero 的 two-hot，要抄 HL-Gauss**。
  - KataGo 的消融：辅助结构化头 `1.65×` 加速，是所有单项里最大的。
- **风险**：
  - **bin 宽必须 << 真实分差 71**，否则分类退化成回归（这正是我们要先做"分差 z-score / 分位数标定"的原因）。若分差分布重尾，用分位数分箱而不是等宽分箱。
  - 辅助头会**抢容量**（我们只有 0.55M 参数）。缓解：辅助头放在**共享主干之后的浅层**，且先只加 1 个（血量差），验证不伤主任务再加第 2 个。
  - 与第 1、2 条**有交互**：值网变准会让 `σ(q̂)` 的合适取值变小。**先做 1–3，再做 4**。

---

### 第 5 条：离线 Reanalyse——用当前网重标存量 386 万决策/月，而不是去采集更多

- **改哪里**：写一个**离线脚本**（不动对局代码）：
  1. 从 `value_data*/`、`distill_data*/` 和自对弈日志里取出所有"被搜索过的决策"（状态 + 候选集 + 当时的 q̂ + 终局 z）；
  2. 用**当前**网重算 `q̂_new`（候选束 + rollout + 值网），得到新的 `π_MPO` 目标（第 2 条）；
  3. 用 **`p_i = |q̂_new − z|`** 当优先级（MuZero Unplugged 原文），做**优先采样**；
  4. Reanalyse fraction 从 0.3 起，逐步升到 0.8（MuZero 正文的 Reanalyze 版用 80%）。
- **为什么排第 5（但重要性不低）**：我们的数据:训练算力 = **1100:1**（KataGo 24:1）⇒ 按 F 线的结论，"投训练收益天花板极低、投采集吞吐收益极高"。这条**不动采集**就能增加有效训练信号，是"用算力换数据质量"的唯一免费路径。排第 5 只是因为工程量大（要写数据管道 + 一次重训）。
- **预期收益**：MuZero Unplugged 的正文结论是"**只调 Reanalyse fraction 就足以在数据少时高效学习**"；对照我们：每月 386 万被搜索决策，若其中 30% 被重标，等于**训练集信息量翻倍**而不增一局对局。
- **风险**：
  - **优先级会被 rollout 噪声主导**（`σ=111`），`|q̂−z|` 里噪声占比可能超过 50%。改造：优先级用 **Brier 分数**（对胜负概率）或**多次重算的均值**，不要用单次 q̂。
  - **自我确认偏差**：用当前网重标，会把当前网的偏见固化。MuZero 的做法是配 **target network + 5 步 TD**；我们至少要保留"原始标签"作为对照臂。
  - 别一次全换：**保留 fraction 作为可调旋钮**，先 0.3，离线看验证集 Brier 是否下降。

---

**候补第 6 条（一行改动，附带做）**：Dirichlet `α` 改成"**总 α 恒定**"——`α = 10.83 / n_legal`（KataGo 的写法，`10.83 = 361 × 0.03` 对齐 AZ 的围棋设置）。理由：AlphaZero 原文就是"`α` 与典型合法手数成反比"，而我们的合法候选数在 1–266 之间剧烈波动（91.6% 只有 1 个），固定 `α` 会在 1 候选时注入 100% 噪声、在 266 候选时等于没加。这一条**不需要验证就几乎一定是对的**，但收益小，别当主线。
