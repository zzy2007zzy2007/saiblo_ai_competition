# H 线：actor-critic / PPO 家族 —— 在"大动作空间 + 稀疏奖励 + 长视野"上的实践调研

> 调研日期：2026-10-29。作者：DSH agent（subagent，会话 `88fcb779`）。
> 范围：A2C/A3C、PPO、GAE、IMPALA/V-trace、APEX/R2D2 系，以及**最接近我们处境的四次大规模实践**
> （OpenAI Five / AlphaStar / FTW-CTF / GT Sophy），外加与本线强耦合的 SIL、UPGO、PPG、Kickstarting、PopArt、Maskable PPO。
>
> **一句话结论**：PPO 这一族在"长视野 + 稀疏奖励 + 大动作空间"上**确实被证明能行**，但每一次都需要
> 三件套同时到位：**① 动作被分解成若干小 head 并逐 head 更新；② 奖励被某种方式加密（形状化 / 自我模仿 / 教师锚）；
> ③ 极大规模的数据（10⁹ 量级决策）**。三者缺一，历史案例都是失败。
> 我们三样都不占优（数据 10⁶–10⁷ 有效决策、不能加密奖励、已有 08 月失败史），所以**不应把 PPO 当主线**；
> 唯一值得考虑的是"**在已有监督先验上做 KL 锚定的轻量策略改进**"，见 §6.3。

本文件与同目录 A–G 线交叉引用但不重复：A（大动作空间搜索）、B（结构化动作）、C（奖励形状）、
D（先手承诺）、E（评估协议）、F（低算力可行性）的结论直接沿用，只在需要时标注。

### 0.5 本线的六条结论（先给结论，后面逐条给证据）

1. **PPO 能处理"上万动作"**，但前提是动作被**分解成若干小 head、每 head 一个 softmax、非法项 mask 掉**——
   OpenAI Five 的联合空间是 1,837,080 维，实际每步只在前 8 个 primary action 上选；AlphaStar 的联合空间 10²⁶，
   用**自回归**逐因子采样。**没有一篇大动作空间实践是用"一个 flat softmax 覆盖全部联合动作"做的** `[正文]`。
2. **PPO 能处理"稀疏奖励"，但代价是样本效率明显变差**（原文只说 "a large penalty to sample efficiency"，**没给倍数**）。OpenAI Five 自己做过纯 0/1 奖励的消融：
   能学（TrueSkill 155 > 脚本 AI 100），但必须把 γ 从 0.9993 拉到 0.99996（视界 3 分钟 → 1 小时）`[正文]`。
   而 FTW 在 CTF 上的纯胜负奖励基线"**什么都没学会**"`[正文]`。两条结论不矛盾：**规模**决定稀疏奖励能不能扛。
3. **PPO 能处理"长视野"，靠的是把 γ 显式换成"游戏时间视界"H = T/(1−γ)**，并且**H 可以被继续调大而继续涨**（OpenAI Five Fig.6：45/90/180/360/720 s 单调改善，720 s 仍有增益）`[正文]`。
   这一点对我们最关键：**1000 步不是"太长"，只要 γ 设对**。
4. **PPO 的崩溃几乎都发生在"结构化输出的 log-prob 剧变"上**，而不是在"奖励稀疏"上。我们 08 月踩的
   "位置图进 ratio ⇒ KL 184063" 在文献里有对应解法：AlphaStar 明确说"**假设 action type / delay / 其它参数相互独立，分别更新**，以缓解大动作空间导致的 trace cutting" `[正文]`。
5. **"搜索 + 蒸馏"在文献里不是 PPO 的下位替代，而是同等甚至更优的策略改进算子**：ExIt 在与 REINFORCE
   同架构同起点的对照里稳定胜出；MuZero-Reanalyze 在同样 2 亿帧下中位分 731% vs IMPALA 192%（≈3.8×）`[正文]`。
   我们的历史（自对弈 68.8% / 真对手 31.2%）与这条文献**不冲突**，冲突的是**评估协议**（E 线）。
6. **我们最该抄的不是 PPO 的 clip，而是 OpenAI Five 的"辅助头 + 自举标签"**：在没有终局标签的中间片段上，
   用"模型自己在片段末端的预测"当标签训练 win-prob / net-worth 等辅助头 `[正文]`。这正好是我们的强项（监督蒸馏 + 值网），
   而且它**不改变动作选择逻辑**，风险最低。

## §2 逐个方法详解（公式与关键超参）

### 2.1 A2C / A3C

**目标**（A3C 原文 §3，advantage actor-critic）：

```
A(s_t, a_t) = Σ_{i=0}^{k-1} γ^i r_{t+i} + γ^k V(s_{t+k}) − V(s_t)          # k-step 回报减 baseline
∇θ log π(a_t|s_t; θ) A(s_t, a_t) + β ∇θ H(π(s_t; θ))                      # 加熵正则
```

- 关键超参（A3C 附录）：**γ = 0.99，RMSProp α = 0.99，熵权 β = 0.01**，n-step 用混合长度（1 步与 n 步都更新） `[正文]`。
- A3C 的价值不在"异步"，而在**"用 V 当 baseline 把方差压下来"**——这一点被 PPO/GAE 全盘继承。
- 对我们的意义：**A3C 无任何"处理大动作空间 / 稀疏奖励"的机制**，08 月我们实际上写的就是"PPO+GAE"，
  所以本线真正要讨论的是 PPO 及其工程外壳。

### 2.2 PPO

#### 2.2.1 目标函数（原文 Eq. 7 / Eq. 9）

```
r_t(θ) = π_θ(a_t|s_t) / π_θold(a_t|s_t)
L^CLIP(θ) = Ê_t [ min( r_t(θ) Â_t , clip(r_t(θ), 1−ε, 1+ε) Â_t ) ]        # Eq.7, ε=0.2
L^CLIP+VF+S = Ê_t [ L^CLIP − c1 L^VF + c2 S[π_θ](s_t) ]                    # Eq.9, c1,c2 为系数
```

- 原文对 clip 的定性：**`L^CLIP` 是未裁剪目标的悲观下界（lower bound）**，只裁"让目标变好"的那一侧 `[正文]`。
- 原文明确 **ε 取 0.2**；Atari 上取 `0.1 × α`（α 从 1 线性退火到 0）`[正文]`。

#### 2.2.3 论文里**没有**、但实现里必须有的三件事

原文 grep `normaliz` 只命中"normalized score"，**没有任何一处讲优势归一化或奖励缩放** `[正文]`。这三件是后来实现层补的：

1. **advantage normalization（per-minibatch 零均值单位方差）**：`What Matters` 的结论是"**影响不大**"（continuous control）`[正文]`。
   但在**奖励稀疏、绝大多数 Â≈0** 的场景（就是我们，HOLD 常最优 ⇒ 大量决策 Â≈0），归一化会把
   "微弱信号"放大成"满幅信号"，**同时也放大噪声**——这是双刃剑，必须配 clip_frac 监控（§5）。
2. **reward scaling**：OpenAI Five 的做法是"**用回报的滑动标准差归一化奖励**，value loss 权重在归一化之后施加" `[正文]`（Table 2 脚注 c）。
   这和我们"血量差无界"直接相关，见 §5 的 PopArt/transformed Bellman。
3. **value clipping**：`What Matters` 明确测过——**PPO 式 value loss 裁剪在 5 个环境里全部有害**，
   Huber loss 也不如 MSE `[正文]`。这是一个"反直觉但被大规模实验证伪"的常见做法。

#### 2.2.4 两个大规模的"实现研究"（本节是全篇最省时间的部分）

**`What Matters In On-Policy RL`（25 万+ 个 agent 的训练）** `[正文]`：

| 结论 | 细节 |
|---|---|
| 观察归一化 | **所有环境都关键**（Hopper 除外） |
| 值函数归一化 | "**出乎意料地强**"：HalfCheetah/Humanoid 关键，Walker2d 反而有害 ⇒ 需要 per-task 试 |
| per-minibatch 优势归一化 | **影响不大** |
| 梯度裁剪 | 小幅提升，阈值几乎无所谓 |
| GAE λ | **0.9 就行**（GAE 与 V-trace 表现相当；n-step 更差） |
| 正则化（熵/KL/约束） | **除 HalfCheetah 外没有显著收益**；作者推测"PPO 的 clip 已经提供了信赖域，精心初始化已经提供了探索" |
| 策略初始化 | "**最令人惊讶的发现**"：让初始动作分布**零均值、低标准差、且与观测无关**，能显著加快学习 |
| 学习率 | 3e-4 是安全默认；退火有小幅收益 |

> ⚠️ 适用范围：该文的实验域是 **MuJoCo 连续控制**，不是 Atari/棋类。引用时不可外推到"离散大动作空间"。

**`Implementation Matters`（PPO vs TRPO）** `[正文]`：PPO 相对 TRPO 的优势**主要来自 9 项 code-level optimization**
（论文逐项列了九条，含奖励缩放、观测/优势归一化、value clipping、学习率退火等；**我未逐项抄录**），
而不是 clip 目标本身。**推论（对我们的意义）**：如果我们要复现"PPO 能不能行"，**必须把这些实现细节一次到位**，
否则实验结论没有意义——这恰好是我们 08 月那次失败的一个可能混杂因素（当时连 z-score logits 都写错过）。

### 2.3 GAE（λ 与 γ 的分工，是我们最该内化的一条）

```
δ_t = r_t + γ V(s_{t+1}) − V(s_t)
Â_t^GAE(γ,λ) = Σ_{l=0}^∞ (γλ)^l δ_{t+l}                    # Eq.16
λ=0 ⇒ Â_t = δ_t（低方差、V 不准时就有偏）
λ=1 ⇒ Â_t = Σ γ^l r_{t+l} − V(s_t)（无偏、高方差）
```

原文的核心论断 `[正文]`：

> "**γ 最重要的是决定值函数的尺度**……γ<1 会给策略梯度引入偏差，与 V 准不准无关；
> 而 λ<1 **只在 V 不准时才引入偏差**。经验上，**最好的 λ 远小于最好的 γ**。"

对我们的直接含义：
- **λ 可以放心取 0.95**（甚至 0.9），它不改变"值尺度"；
- **γ 才是"视界"旋钮**，而我们 1000 步的视界必须用 γ≈0.999+ 才覆盖得到；
- 但 γ 一高，**值函数的动态范围就爆炸**（血量差 × 1000 步求和），这就是 §5 里"值尺度漂移"的根源，
  必须配 PopArt/回报归一化。

`[推算]` 视界换算（用 OpenAI Five 的 H = T/(1−γ)，这里把"一步"取成"一个回合"，即 T=1）：
要在 90% 权重内覆盖 **512 回合**，需 `γ = 1 − 1/512 ≈ 0.998`；覆盖 200 回合需 `γ ≈ 0.995`。
**我们 08 月用的是 γ=0.99 ⇒ 有效视界 ≈100 回合，只覆盖全局的 1/5**，这是"长视野"没做到的直接原因之一。
（注：若按 400–512 回合的实际长度还要打折——回合越靠后，越接近"被截断"，见 §3.1.3 第 3 点。）

### 2.4 IMPALA / V-trace（什么时候才需要它）

```
v_s = V(x_s) + Σ_{t=s}^{s+n−1} γ^{t−s} (Π_{i=s}^{t−1} c_i) δ_t V           # Eq.1
δ_t V = ρ_t ( r_t + γ V(x_{t+1}) − V(x_t) )
ρ_t = min(ρ̄, π(a_t|x_t)/µ(a_t|x_t)) ,  c_i = min(c̄, π(a_i|x_i)/µ(a_i|x_i))
```

- **两个截断常数分工不同**：`ρ̄` 决定不动点（收敛到哪个策略的值），`c̄` 决定方差 `[正文]`。
- 当 `π = µ` 且 `c̄ ≥ 1` 时，V-trace **退化为 on-policy n-step Bellman** `[正文]`——这是它比 Retrace 好用的原因。
- 工程收益：**250,000 帧/秒，比单机 DQN 快 30 倍以上** `[正文]`。

对我们的判断：**只有当"采样进程"和"学习进程"必须解耦（比如采样跑在 16 核上、学习跑在 GPU 上且批大小不匹配）时才需要 V-trace**。
单机 16 核 + RTX 5060 的规模下，**policy lag 可以压到 0**（同步 PPO），引入 V-trace 只会增加"trace cutting"这个新失败模式
——AlphaStar 自己就报告：**大动作空间下 V-trace 的 trace cutting 过早发生**，他们靠"假设参数相互独立、分别更新"来缓解 `[正文]`。

### 2.5 APEX / R2D2（对比，不必用）

- Ape-X：1 个 learner + 多个 actor + **优先回放**，本质是 **off-policy** ⇒ 数据可重复用 `[正文]`。
  我们"数据:训练算力 = 1100:1"（KataGo 24:1，见 F 线）本来最该羡慕"样本复用"，
  但**结构性动作空间 + HOLD 主导 + 非法即判负**让 Q 学习很难有像样的泛化；
  而且项目史上真正做"数据复用"的两条线（ES/GA）**收益为 0** `[项目文档]`。`[推算]`
- R2D2：加值缩放 + burn-in + 零初始化 LSTM。**本次 PDF 被 403 挡住，未读正文**（§7），只作为"DQN 系也有值尺度问题"的旁证。
- 结论：**DQN 系不适合我们**——动作是结构化的、要 mask、HOLD 占比极高，Q 值在"266 束 × 位置"上无法共享泛化；
  且我们的仿真不便宜，replay 的样本复用优势被"122 µs/转移"抵消。

### 2.6 与本线强耦合的六个"补丁"

| 方法 | 一句话 | 公式/机制 |
|---|---|---|
| **SIL** | 把"回报 > V(s)"的片段存回 buffer 反复模仿 | `L_sil = E[ −log π(a \mid s)·(R−V(s))_+ + β_sil·½‖(R−V(s))_+‖² ]` `[正文]` |
| **UPGO** | AlphaStar 版 SIL：`G_t^U = r_t + G_{t+1}^U` 若 `Q≥V`，否则 `r_t+V` | 见 §3.2 `[正文]` |
| **PPG** | 策略阶段与"价值蒸馏"阶段交替；辅助阶段用 `L_joint = L_aux + β_clone·KL[π_old‖π_θ]` | `[正文]` |
| **Kickstarting** | `ℓ_kick = ℓ_RL + λ_k·H(π_T‖π_S)`，`λ_k` 可随学生追平教师而退火 | `[正文]` |
| **PopArt** | 用学到的 μ、Σ 归一化**值目标**，再把输出层权重反缩放以保持不变函数 | `[正文]` |
| **transformed Bellman** | `h(z)=sign(z)(√(abs(z)+1)−1)+εz`，**ε=10⁻²**；压缩值目标的动态范围 | `[正文]` |

关于 transformed Bellman 的两个精确点（值得抄之前先知道）：
- 原文只在 **h 为线性**或 **MDP 确定性**时给出"唯一不动点 = h∘Q\*"的命题；一般随机 MDP 下是近似 `[正文]`。
- 它本来是 **DQN 系的 Q 目标变换**；我们要用只能用在 **critic 的 V 目标**上，属于外推 `[推算]`。

> `[正文]` GAE 论文 §4 有一个对我们特别重要的等价：**"以 Φ=V 做 potential-based shaping，等价于对 δ_t 做 (γλ) 折扣求和"**——
> 这就是 C 线"`Φ=V` 在 actor-critic 里精确抵消优势"的出处。**所以"给 PPO 加 shaping"在带 critic 的实现里通常是空操作**。

### 3.1 OpenAI Five（Dota 2）—— 与我们处境最接近的一次工程

规模先摆出来，避免"抄配方不抄规模"的错觉 `[正文]`：

| 项 | 数值 |
|---|---|
| 每局步数 | 30 fps，**每 4 帧决策一次 ⇒ ≈20,000 步/局**（棋类 80–150 步） |
| 动作空间 | 离散化后**每步 8,000–80,000 个动作**（因英雄而异） |
| 观测 | ≈16,000 维（1,200 类别 + 14,534 连续/布尔） |
| 网络 | 5 个 LSTM 副本，**LSTM 4096**，总参数 **158,502,815** |
| 总批大小 | **983,040 → 3,145,728 timesteps**（每个 optimizer GPU 120 样本 × 16 帧 × 512–1536 GPU） |
| 步/迭代 | 32 |
| γ（视界） | 180 s ⇒ γ=0.9993；Rerun 升到 60→840 s |
| GAE λ | 0.95 |
| clip | 0.2 |
| entropy | 0.01 → 0.001 |
| lr | 5e-5 → 5e-6 |
| 值损失权重 | 1.0（**奖励先按运行标准差归一化，再乘权重**） |
| 梯度裁剪 | 逐参数裁到 ±5√v（v 为二阶矩运行估计） |

#### 3.1.1 动作空间：分解 + mask + "稀有动作单独开头"

- 动作 = **1 个 primary action（≤30 个）+ 3 个参数**：`Delay`(4)、`Unit Selection`(189)、`Offset`(81) `[正文]`。
- 联合空间上界 `30 × 4 × 189 × 81 = 1,837,080`，**但每步实际可选 primary action 平均只有 8.1 个** ⇒ 实测 8,000–80,000 个可选动作 `[正文]`。
- **非法组合不靠"学"，靠 mask**：`"attempting an action with an invalid target results in a noop"`，且"忽略的参数在优化时被 mask 掉，因为它们的梯度纯属噪声" `[正文]`。
- **关键工程细节（我们最该抄的一条）**：Unit Selection 本来是一个头，但他们发现
  **"teleport" 这类稀有但语义完全不同的动作会被淹没**，于是**单独开一个 Teleport Selection 头**；
  同理 Offset 拆成 Regular / Caster / Ward 三个头 `[正文]`。
  → 这与我们"升级/超武是稀有动作、被 HOLD 淹没"的处境**同构**（参见 `docs/why_no_upgrade_20261028.md`）。
- 还有 **scripted actions**：不是所有操作都交给 RL（买装备、信使等由规则接管），"每把一个动作从脚本交给模型，RL 系统就…" `[正文]`。

#### 3.1.2 奖励：形状化 + 零和 + 时间衰减 + team spirit

奖励函数是**手写权重表**（Table 6），我摘关键项 `[正文]`：

| 事件 | 权重 | 归属 |
|---|---|---|
| Win | **5** | Team |
| Ancient HP Change | **5** | Team（按最大血量比例） |
| Hero Death | −1 | Solo |
| XP Gained | 0.002 / 单位 | Solo |
| Gold Gained | 0.006 / 单位 | Solo |
| Health Changed | 2 | Solo（按最大血量比例，**四次插值** `(x+1−(1−x)⁴)/2`） |
| Killed Hero | **−0.6** | Solo（**负的**：抵消金币/经验奖励，避免刷人头） |
| Last Hit | −0.16 | Solo（同上，净奖励 ≈0.4） |
| T1/T2/T3/T4 Tower | 2.25 / 3 / 4.5 / 2.25 | Team（2/3 按血量线性、1/3 按击毁一次性） |
| Barracks | 6 | Team |
| Lane Assign | −0.15 / 秒 | Solo（在错误分路的时间） |

四个非权重设计，每一个都直接对应我们踩过的坑：

1. **零和化**："subtracting from each hero's reward the average of the enemies' rewards" —— 保证奖励严格零和 `[正文]`。
2. **时间衰减**：`ρ_i ← ρ_i × 0.6^(T/10min)`（**除 win/loss 外全部**）。
   理由原文写得很直白：**不这样做的学习过程会"完全聚焦后期、忽略前期"** `[正文]`。
   → 这正是 C 线"重后期/攒金币"类退化的通用解药：**不是改奖励符号，而是改奖励随时间的权重**。
3. **team spirit**：`r_i = (1−τ)ρ_i + τ·mean(ρ)`，τ 从 **0.3 退火到 0.8–1.0**。
   理由：**低 τ 降低早期梯度方差**（每个英雄先学自己的机械操作），最终目标是 τ=1（团队最优）`[正文]`。
   → 我们的对应物是"多座塔/多目标之间的信用分配"，可以用同样的"先局部后全局"退火。
4. **他们的 shaping 不是 potential-based**：原文自己承认 "modeled loosely after potential-based shaping,
   **though the guarantees therein do not apply here**" `[正文]`。→ 这给 C 线"要么安全要么无用"的结论加了一个重要补充：
   **大规模实践里大家明知不安全也照用，靠的是"权重表 + 消融 + 监控"**，而不是靠理论保证。

#### 3.1.3 长视野：三个具体装置

1. **把 γ 换算成"游戏时间视界"**：`H = T/(1−γ)`，T=0.133 s（4 帧）`[正文]`。
   180 s ⇒ γ=0.9993。**Horizon 消融（Fig.6）：45/90/180/360/720 s，单调改善，720 s 仍有增益但边际递减** `[正文]`。
2. **片段化 + 自举**：不整局回传，**每 30 秒（256 步）一段**送优化器；每段用 16 步截断 BPTT。
   原文明确：**"因为我们用 GAE λ=0.95，GAE 奖励需要在 ≫1/λ=20 个时间步上平滑；用 256 步的损失很小"** `[正文]`。
   → 这条对我们极其重要：**n-step/片段长度不是随便取的，要 ≥ 1/(1−γλ) 的量级**。
3. **截断/超时处理**：`[未找到]` —— 论文正文与附录**都没有**写"超时判和/判负"的具体规则，
   我能找到的只有"训练用 30 s 分段、段末自举"这一事实 `[正文]`。
   **一般性文献结论**（`Time Limits in RL`，Pardo et al. 2018）：把"时间上限截断"当作"终止"会引入 **state aliasing**，
   并使 value 估计失效；正确做法是**对截断做 bootstrap，而不是当作 terminal** `[正文]`。
   → 对我们的意义：**我们的 512 回合是"真终止"（HP 差定胜负），所以不需要 bootstrap**；
   但如果为了省时间**截断训练局**（例如只打前 200 回合），就必须保留 bootstrap，否则值网会学出"200 回合必死"的假终止。

#### 3.1.4 他们自己做的"稀疏奖励"消融（本文件最重要的一张图）

Fig.16 + 附录 G 正文 `[正文]`：

- 设置：**只用 0/1 胜负奖励**，视界拉到 **1 小时（γ=0.99996）**，其它超参与 shaped 基线完全相同。
- 结果：**能学**，TrueSkill 到 **155**（对照：手写脚本 AI = 100）。
- 代价：原文写 "**with a large penalty to sample efficiency relative to the shaped reward baseline**"，
  且"该策略前期打得不好，只是学会了在后期协调团战"。

**这条是我们最该记住的定量事实**：在 10⁹ 量级决策 + 1536 GPU 的规模下，纯稀疏奖励"能学但慢一个档次"；
换算到我们 10⁶–10⁷ 决策、1 张 5060 的规模，**"慢一个档次"就是"永远学不到"** `[推算]`。

#### 3.1.5 稳定性工程（比算法更重要）

| 装置 | 数值/做法 | 作用 |
|---|---|---|
| sample reuse | **目标 ≈1**；实测"复用 2–3 次就慢一倍，复用 8 次可能完全学不会" | on-policy 纪律 |
| 数据新鲜度 | rollout 每 30 s 游戏时间推一次数据、参数约每分钟更新一次 | 控制 staleness |
| entropy 退火 | 0.01 → 0.001 | 先探索后收敛 |
| lr 退火 | 5e-5 → 5e-6 | 后期稳定 |
| 梯度裁剪 | ±5√v（自适应，不是固定范数） | 防爆 |
| surgery | 换环境/换网络时**保持"观测→动作分布"函数不变**，再继续训 | 跨版本续训 |
| 辅助头 | win-prob / net-worth rank / team objectives，**段内无标签时用"段末模型自预测"当标签**（Eq.10） | 表征学习 + 校准 |

最后一条（辅助头 + 自举标签）是 §0.5 结论 6 的出处，也是我认为**我们唯一低风险可抄的 RL 部件**：
它不改变动作选择，只是给骨干加"预测胜负/经济排名"的辅助监督，而**这些标签我们本来就有**（终局血量差、金币曲线）。

### 3.2 AlphaStar（SC2）—— 监督 + league 自对弈 + 自回归动作头

#### 3.2.1 动作空间：10²⁶ 的联合空间，用"自回归 + 指针"逐步采样

- 每个动作 = **动作类型（数百种）→ 施放对象（任意子集单位）→ 目标位置（地图格/相机内单位）→ 下一次决策延迟** `[正文]`。
- 联合空间 **≈10²⁶** `[正文]`。
- 实现：**"action arguments 是自回归采样的（auto-regressively），条件于 LSTM 输出与观测编码器"**；
  空间目标用 **recurrent pointer network** `[正文]`。
- 网络：**139M 权重，推理只用 55M** `[正文]`。
- **对我们最有用的一句**（V-trace 与动作分解的关系）：
  > "To mitigate early trace cutting due to the large action space, **we assume independence between the action type,
  > delay, and all other arguments, and so update them separately.**" `[正文]`
  → 即：**在大动作空间里，别把整个联合动作塞进一个 ratio；按因子拆开、各算各的 ratio。**
  这直接对应我们 08 月"位置图进 ratio ⇒ KL 184063"的失败：**位置本该单独一路 ratio（甚至不进 ratio），而不是和 class 共用一个 ratio。**

#### 3.2.2 监督 → RL 的三层锚

1. **行为克隆初始化**：971,000 局 replay（MMR>3500，前 22%），对每个 action argument 算 **KL(human‖policy)**；
   再用 16,000 局 MMR>6200 的**胜局**微调（Elite AI 胜率 87%→96%，MMR 3947/3607/3544）`[正文]`。
2. **策略条件化在 z 上**（z = 前 20 个建筑/单位的 build order + 累计统计），SL 时 10% 置零 ⇒ **多样性** `[正文]`。
3. **RL 期间持续 KL 锚到监督策略**（"continually minimise the KL divergence between the supervised and current policy"）`[正文]`。
   另有 **pseudo-reward**：跟随 z 的 build order（**编辑距离**）与累计统计（**汉明距离**），各以 25% 概率激活，**每个 pseudo-reward 单独一个 value 函数** `[正文]`。

→ 这是"**稀疏胜负奖励 + 强先验**"的标准配方：**先验不是初始化一下就丢掉，而是全程用 KL 拽着**。
我们 08 月的 AZ 自对弈恰恰**没有这个锚**（只有 anchor loss，且被搜索坍缩带跑），这是"特征提取器坍缩"的文献对照解释 `[正文]`+`[项目文档]`。

#### 3.2.3 损失：终局奖励**不打折** + TD(λ)/V-trace/UPGO 混合

- 奖励：**"match outcome (−1/0/+1) as the terminal reward, without a discount to accurately reflect the true goal of winning games"** `[正文]`。
  → **γ=1**。这是"长视野"的另一条路：**不贴现，靠 λ 和 value 控制方差**。
  对我们的意义（**这条要小心**）：γ=1 在我们这里**只有在奖励有界时才安全**——AlphaStar 的奖励是 ±1/0，
  值天然落在 [−1,1]；而我们的血量差无界（±数千），γ=1 会让值目标的动态范围直接爆炸（§2.3 的警告）。
  ⇒ **若要用 γ=1，必须先把奖励归一化**（除以初始/最大血量），或干脆只用"终局胜负"当奖励、血量差降级为辅助信号。
  若做不到归一化，就退回 `γ≈0.998`（视界 512 回合）。`[正文]`+`[推算]`
- 价值用 **TD(λ)**（不做 off-policy 修正）；策略用 **V-trace**（做修正）`[正文]`。
- **UPGO**：`ρ_t (G_t^U − V(s_t)) ∇ log π`，其中
  `G_t^U = r_t + G_{t+1}^U` if `Q(s_{t+1},a_{t+1}) ≥ V(s_{t+1})` else `r_t + V(s_{t+1})`；
  因大动作空间难估 Q，**用一步目标 `Q = r_t + V(s_{t+1})`** `[正文]`。
- **价值的方差缩减**：训练时**把对手的观测也喂给 value 函数**（评估时不需要）`[正文]`。

#### 3.2.4 league / PFSP：解决"自对弈指标虚高"

- **PFSP 采样概率**：`p_B ∝ f(P[A beats B]) / Σ_C f(P[A beats C])`；
  `f_hard(x) = (1−x)^p`（**只打打不过的**；`f_hard(1)=0` ⇒ 已赢的不再打），`f_var(x) = x(1−x)`（打势均力敌的）`[正文]`。
- 主 agent：**35% 自对弈 + 50% PFSP（对全部历史）+ 15% PFSP（对"已打不过的旧主 agent"与旧 exploiter）**；
  每 **2×10^?** 步加一个快照进 league（**该指数的上标在 PDF 文本抽取中丢失，见 §7**，这里不复述数值）`[正文]`。
- 规模：3 主 + 3 主 exploiter + 6 league exploiter；每个 agent **32 TPU、44 天**；全程 **≈900 个 player**；
  每个训练 agent **16,000 场并发对局** `[正文]`。

→ 我们的教训（68.8% 自对弈 / 31.2% 真对手）在文献里的标准解不是"换个 RL 算法"，而是
**"固定外部对手池 + 只打打不过的对手"**。这一点 E 线（评估协议）已经独立得出，**两条线在这里收敛**。

### 3.3 FTW / Capture the Flag（Quake III）—— 注意：**它不是 PPO**

任务书写的是"Capture the Flag / Quake 等：大规模 PPO 的经验"。**事实核对结果：FTW 用的是 Ape-X DQN 家族，不是 PPO** `[正文]`：

- 算法：**Ape-X DQN + transformed Bellman operator + temporal consistency (TC) loss**（"RLED" 框架）`[正文]`。
- 结构：**两个时间尺度**的 RNN（快/慢），慢层带随机潜变量并用慢先验正则 `[正文]`。
- 奖励：**不是纯胜负**。每个 agent **自己学一个内部奖励** `r_t = w(ρ_t)`（ρ_t 是游戏点数），
  **w 由 PBT 在"外层的胜率目标"上进化** `[正文]`。
- **稀疏奖励的对照实验（Fig.1b 正文）**：
  > baseline agent 用"手调 reward shaping"能到一个平台；**"does not learn anything without reward shaping"**（纯胜负奖励什么都没学到）`[正文]`。

→ 这是全篇**最强的反例**：在 DeepMind 的算力下，**3D 多人的纯胜负奖励学不动**，必须"学出来的内部奖励 + 进化"。
和 OpenAI Five 的结论并列，得到**规模阈值**的图景：
**纯稀疏奖励要在 ~10⁹ 决策 + 密集自举信号下才勉强可行**（Five），**在 FTW 的规模/结构下直接为零**。

### 3.4 GT Sophy（Gran Turismo）—— 不是 PPO，但奖励设计的教训值钱

- 算法：**QR-SAC**（quantile regression soft actor-critic），**异步**训练 `[正文]`。
- 奖励：**"progress reward"（沿赛道推进的速度）+ 出界/撞墙/失去抓地力的罚分** `[正文]`。
- **两个"必须加"的补丁**（都是 reward hacking 的现场记录）`[正文]`：
  1. **只有 progress reward 不够**：agent 会**跟着对手跑**、无风险地攒进度 ⇒ 必须加**"超车奖励"**（按与对手的局部相对位置，**对称**：被超也有等额负奖励）。
  2. **体育精神罚则**：由**规则层判定、游戏引擎强制执行**（切弯、撞人等会被强制减速），而不是靠奖励项"教"。
- 规模：未读到大篇幅训练规模（`[未找到]`，§7）。

→ 对我们的意义：**"规则层强制" > "奖励层教"**。我们"非法即判负"其实就是引擎层强制（好事），
但"攒金币不做事"这种**合法但退化**的行为，**引擎管不了**——只能靠 C 线的形状分析或评估函数，而不是靠 PPO 自己悟出来 `[正文]`+`[推算]`。

### 3.5 搜索 vs model-free：文献里**直接对比**的四组数字

任务书 §4 要求"文献里有没有直接比较 model-free RL vs 搜索蒸馏"。**有，但都不是"塔防"，且都偏向搜索一侧**：

| 对比 | 设置 | 结果 | 等级 |
|---|---|---|---|
| **ExIt vs REINFORCE**（Hex 棋） | **同架构、同热启动、都不用价值网**；ExIt 用 MCTS 当"专家"、策略网当"学徒"；对照是 Silver 2016 式 IL 初始化 + REINFORCE | **"ExIt learns stronger policies faster"，且"no sign of instability: 每次迭代都改善，run 间方差很小"**；在线 ExIt 显著优于批量 | `[正文]` |
| **MuZero-Reanalyze vs model-free**（Atari，**同样 2 亿帧**） | 中位归一化分 | **MuZero 731% vs IMPALA 192% / Rainbow 231% / LASER 431%**（≈3.8× IMPALA） | `[正文]` |
| **MuZero vs R2D2**（Atari，57 游戏） | 平均/中位分 | MuZero 在 **42/57** 上超过 R2D2（model-free SOTA） | `[正文]` |
| **EfficientZero**（Atari 100k = 2 小时游戏时间） | 模型基 + 搜索 | **194.3% 均值 / 109.0% 中位**人类归一化分 | `[正文]` |

理论侧的两条支撑：
- **MCTS ≈ 正则化策略优化的近似解**：AlphaZero 的 search heuristic（含 UCT）都可写成"求解某个 KL 正则化策略优化问题"的近似；
  用精确解替换后**在多个域稳定优于原算法** `[正文]`。
- **Gumbel MuZero**：把"策略改进算子"抽象成 `Iπ(s,a)`，指出 **action-independent** 形式才能扩展到任意大/连续动作空间 `[正文]`。
  → **"搜索"和"PPO 的策略梯度"在这套语言里是同一件事的两个算子**，差别只在"改进算子的强度/成本"。

**因此，"PPO vs 搜索蒸馏"在文献里不是"两种范式之争"，而是"用哪个算子做策略改进"的性价比问题** `[正文]`+`[推算]`。

| | 大动作空间 | 稀疏奖励 | 长视野 |

## §4 针对我们三个痛点的可落地方案（5 条，含"改哪里/预期收益/风险"）

> 前置说明：本节**假设**我们决定引入 PPO 族（是否该引入见 §6）。每条都给出"最小验证"，即**不花对局预算就能否掉它**的办法。

### H1（动作）束级动作空间 + 每因子独立 ratio + mask 进 logπ

- **改哪里**：
  1. 动作分布定义在**现有 ~266 个候选束**上（一个 softmax，266 维），**不**定义在"上万维"的联合空间上；
  2. 束内部的位置/塔型由**现有确定性解码器**给出（不采样、不进 ratio）；
  3. 若将来要学位置：**单独一路 ratio + 单独的 clip + MSE trust-region**（`docs/ppo_position_true_optimization.md` 已验证"约束能防爆"）；
  4. mask 必须在**每次前向时重算**，并进 `logπ`（B 线结论）。
- **文献依据**：OpenAI Five 的"分解+mask+稀有动作单独头" `[正文]`；AlphaStar 的"因子独立、分别更新" `[正文]`；Maskable PPO 的"mask 进 logπ" `[正文]`。
- **预期收益**：把 08 月的"位置进 ratio ⇒ KL 184063"这类崩溃**从必现变成不可能**；束级 266 维 softmax 每维分到的梯度信号比"上万维联合 softmax"多 **1.5–2 个数量级** `[推算]`。
- **风险**：束内位置不可学 ⇒ 策略只能在"给定候选集"里挑；**而我们的候选集本身已被证明覆盖率不足**（D 线：91.6% 决策只有 1 个候选）。
  ⇒ **H1 的天花板是候选生成器**，不是 PPO。
- **最小验证（零对局）**：用现有离线数据，比较"266 维 softmax 的 top-1"与"搜索的 argmax"的一致率；<70% 才值得做。

### H2（长视野）把 γ 换成"回合视界"，片段长度 ≥ 1/(1−γλ)

- **改哪里**：
  1. `γ` 从 0.99 → **0.998**（视界 ≈512 回合）；或**γ=1**（AlphaStar 的选择，配合 GAE λ=0.95，**前提是奖励有界**）；
  2. `n-step`/片段长度从"整局"改为 **≥ 1/(1−γλ)**：γλ=0.948 ⇒ 约 20 步，取 **64–256 步**（OpenAI Five 用 256 且说"损失很小"）；
  3. 若为省时间**截断训练局**，必须**对截断 bootstrap**（Pardo 的结论），否则值网学出假终止。
- **文献依据**：GAE §5（γ 决定值尺度、λ 只管偏差）`[正文]`；Five Fig.6（H 越大越好，720 s 仍有增益）`[正文]`；AlphaStar"无折扣" `[正文]`；Time Limits `[正文]`。
- **预期收益**：**这是"长视野"唯一有直接证据的一招**。`[推算]` 我们 08 月 γ=0.99 ⇒ 有效视界 100 回合，只覆盖全局的 1/5。
- **风险**：γ=1 会让值目标变成"整局回报"（血量差 ±数千），**必须**配 H4 的值缩放；否则值网直接发散。
- **最小验证（零对局）**：用现有 value 数据，算"γ=0.99 vs 0.998 vs 1"下 value target 的方差与动态范围；若 γ=1 的 target 标准差 >100× 现有值域，先做 H4 再谈。

### H3（稀疏奖励）不做 shaping，做"三条不加密奖励的路"

按性价比排序：

1. **值网/优势预训练（我们已有）**：把现有监督训练的价值网**直接当 critic 初始化**，并在 RL 中用"辅助头 + 自举标签"
   （OpenAI Five Eq.10：段内无标签时用段末自预测）持续喂监督信号 `[正文]`。
   → **改哪里**：`network.py` 的 value head + 一个 win-prob/经济排名辅助头；**不改动作选择**。
   → **预期收益**：critic 一开始就准 ⇒ GAE 的 λ 才能取大 ⇒ 稀疏奖励才有可能。**风险最低的一条。**
2. **SIL / UPGO（自我模仿）**：维护"回报 > V(s)"的片段 buffer，按 SIL 损失反复利用 `[正文]`；UPGO 是它的低方差变体 `[正文]`。
   → **改哪里**：训练循环加一个 replay buffer + 一段额外 loss；**不改采样**。
   → **预期收益**：稀疏奖励下把"偶然的好局"重复利用——这正是我们最缺的（好局面样本稀少）。
   → **风险**：buffer 里的旧策略数据会让 `π` 偏离 on-policy；SIL 本身就是 off-policy 算法，**必须监控 KL**。
3. **Kickstarting / KL 锚（我们有强先验）**：`ℓ = ℓ_RL + λ_k·H(π_T‖π_S)`，λ_k 随学生追平教师而退火 `[正文]`；
   AlphaStar 的"全程 KL 锚到监督策略"是同一件事的另一种写法 `[正文]`。
   → **改哪里**：PPO loss 加一项 KL 到**冻结的位置先验网**。
   → **预期收益**：直接对症"特征提取器坍缩"（08 月根因）；给 RL 一个"不许跑偏太远"的护栏。
   → **风险**：λ_k 太大会把 RL 退化成 BC（**这正是我们 8 条监督重训全负的场景**）；必须按"离线 top-1 提升"而不是"KL 下降"来调。

明确**不推荐**：RND / 内在奖励（Agent57 那套）`[二手]`（仅摘要）——工程量超过我们全部算力预算，且我们的探索瓶颈不在"没见过状态"，而在"合法动作里哪个更好"。

### H4（稳定性）三道闸：值缩放 / 每因子 ratio / 熵地板

| 闸 | 做法 | 文献 | 我们对应的历史故障 |
|---|---|---|---|
| 值缩放 | **PopArt** 自适应归一化值目标 + 输出层反缩放；或 Five 式"按回报运行标准差归一化奖励"；无界奖励可先做 transformed Bellman 的 `h(z)` | `[正文]` | 血量差无界 ⇒ 08 月"无界价值头"（`action_net_retrain_index_raw.md:56` 记录 PPO 用"无界价值头"） |
| ratio 闸 | **每因子独立 ratio + 独立 clip**；结构化输出（位置图）**要么不进 ratio，要么加 MSE trust-region**；监控 `approx_kl`、`clip_frac`、`max ratio` | `[正文]` | **KL 184063、熵 0.23**（`project_history.md:241`） |
| 熵地板 | 熵系数 0.01→0.001 退火；**策略初始化成"零均值、低标准差、与观测无关"**（What Matters 的最强发现）；必要时加熵下限约束 | `[正文]` | 类头坍缩到闪电 99.3%、91% 回合 HOLD |

补充两条"防坍缩"的非常规手段（都便宜）：
- **周期性 reset 后几层**（Primacy Bias）：`[正文]` 摘要+§4 —— 对"早期数据锁死特征"有效，**正好对应我们诊断的"特征提取器坍缩"**。
- **冻结骨干、只训头**：我们 09 月的位置轴经验已经证明"冻结骨干 + 重训头"能拿到 +14~24pp；RL 阶段沿用同一纪律。

### H5（评估/预算）先算清"一次 PPO 迭代值多少局"，再决定要不要做

`[推算]`，全部基于项目实测数（2.88 万局/月、1000 决策/局、91.6% 决策单候选、122 µs/转移、E 线 SPRT 公式）：

1. **有搜索的采样**：一局 ≈1000 决策，每步上限 10 s。满配（k=160/N=15/h=16）实测 **4.67 s/决策**，
   若每步都满配则单核 **78 min/局**；但实测 80% 决策被 SKIP1 短路、91.6% 只有 1 个候选。
   用项目产能反推：2.88 万局/月 ÷ 30 = **960 局/天**；16 核满负荷 = 1.382×10⁶ 核时秒/天
   ⇒ **≈1440 核时秒/局 = 24 min 核时/局 ⇒ 平均 ≈1.44 s/决策**（≈满配的 31%）。
   **结论：搜索的成本几乎全部由"候选生成器 + 短路规则"决定，而不是由搜索算法决定。**
2. **无搜索的采样（PPO rollout 的真实成本）**：一次前向（0.55M 参数，batch=1，估 **≈2 ms**）+ 一次引擎步（122 µs）
   ⇒ ≈2.1 ms/决策 ⇒ **≈2.1 s/局**；12 进程 ⇒ ≈5.7 局/s ⇒ **≈4.9×10⁵ 局/天（理想上限）**，
   打五折也有 **≈2.4×10⁵ 局/天**。
   ⇒ **PPO 的"采样"不是瓶颈：单局比搜索便宜 2–3 个数量级（2 s vs 1440 核时秒）。**
3. **但"有效决策"极少**：91.6% 的决策只有一个候选 ⇒ 每局真正有梯度的决策 ≈**84 个**（乐观按 8.4%）。
   ⇒ 一个月全部对局（2.88 万局）只有 **≈2.4×10⁶ 个有效决策**；即使 rollout 全速跑一个月（≈7×10⁶ 局）也只有 **≈6×10⁸**。
   ⇒ 对照：Atari PPO 用 **10⁷ 帧**、DQN **5×10⁷**、MuZero **2×10⁸**、OpenAI Five **10⁹–10¹⁰**。
   **我们在"总决策"上和 Atari 同量级，但在"有效决策"上少 1–2 个数量级。**
4. **评估 vs 训练，谁更贵取决于"行为策略是谁"** `[推算]`：
   - E 线：判 5pp 最坏 3468 局 ≈ **12.6 h 墙钟**。若每 5 轮评估一次、共 40 轮 ⇒ 8 次评估 ≈ **100 h**。
   - 训练侧 A（**搜索当行为策略**）：每轮 256 局 × 1440 核时秒 ÷ 16 核 ≈ **6.4 h**；40 轮 ≈ **256 h ≈ 10.7 天满负荷**。
     ⇒ 训练主导，且**吃掉了整个月的搜索数据预算**（蒸馏/值网也要用）。
   - 训练侧 B（**策略网当行为策略**）：每轮 256 局 × 2.1 s ÷ 12 进程 ≈ **45 s**；40 轮 ≈ **30 min**。
     ⇒ 评估主导。
   - 两条路成本差 **≈500 倍**，而且这条分叉**同时决定了方法的天花板**：
     A 的 PPO ≈ ExIt/搜索蒸馏（我们已经在做，只是换了名字）；B 的 PPO ≈"单次前向的策略"
     （正是 08 月对 rule_v4 只有 31.2% 的那种形态）。
   ⇒ **没有第三条路：要么付搜索的钱，要么接受"无搜索策略"的上限。** 这一点比"用不用 PPO"更重要。

⇒ **H5 的操作含义**：任何 PPO 实验**必须先声明"用哪个离线指标代替对局评估"**（top-1 一致率 / KL / 熵 / 值网校准），
否则 100 小时的评估预算会把实验设计压死。

### 5.1 被广泛使用但**被大规模实验证伪**的"标准做法"

这一节专门用来防止"照着教程写 PPO"。以下都是**常见默认值，但文献里测出来是有害或无用的**：

| 做法 | 常见理由 | 实测结论 | 来源 |
|---|---|---|---|
| **value loss clipping**（PPO 式裁 value） | "和 policy 一样加信赖域" | **五个环境全部有害**，与阈值无关 | `[正文]` What Matters §3.4 |
| **Huber loss 替代 MSE** | "抗离群值" | **全部环境不如 MSE**，与阈值无关 | `[正文]` 同上 |
| **per-minibatch advantage normalization** | "稳定训练" | **影响不大**（连续控制） | `[正文]` 同上 §3.3 |
| **熵奖励/KL 约束** | "防熵坍缩" | 除 HalfCheetah 外**无显著收益**；作者归因于"clip 已提供信赖域 + 好的初始化已提供探索" | `[正文]` 同上 §3.8 |
| **c1 = 0.5（value 权重）** | 教程默认 | PPO 原文 Atari 用 **c1 = 1**；且 Five 是在**奖励归一化之后**再乘权重 | `[正文]` PPO Table 5、Five Table 2 脚注 c |

⚠️ 适用边界：What Matters 的实验域是 **MuJoCo 连续控制**；把它当"普适真理"同样是错的。
但它至少说明：**这些"标准做法"没有强证据支撑，不要因为"别人都这么写"就照抄**。

## §6 结论：该不该用 PPO？最小可行形态是什么？

### 6.1 坦率判断

**不该把 PPO 当主路线；可以作为"最后一公里"的轻量策略改进器，且必须先满足三个前提。**
理由按重要性排序（每条都可被证伪）：

1. **我们的瓶颈不是"策略改进算子的强度"，而是"有效决策太少 + 评估太贵"** `[推算]`。
   91.6% 的决策没有选择 ⇒ 每局只有 ≈84 个有梯度的决策；判 5pp 要 12.6 h。PPO 是一个**需要大量 (s,a,A) 三元组**的算子，
   而我们是**需要把每一个三元组榨干**的场景。这与文献里所有成功案例的前提**相反**
   （Five：10⁹–10¹⁰ 决策；AlphaStar：44 天 × 32 TPU × 16,000 并发对局；FTW：DeepMind 级并行 + 进化出的内部奖励）。
2. **纯稀疏奖励在我们的规模下没有成功先例**。Five 的消融能成立是因为 γ 拉到 1 小时 + 1536 GPU；
   FTW 在 DeepMind 级并行下、纯胜负奖励"什么都没学到"。我们有强先验、有搜索、有值网，**这些都是"非 PPO 的改进算子"**，
   用它们去替代"1e9 步 PPO"是**文献支持**的选择（ExIt、MuZero、KataGo、AlphaStar 的 SL 初始化 + KL 锚）。
3. **我们已经有两次"端到端 RL"的失败，且根因与 PPO 没有直接关系**（搜索坍缩 / 特征坍缩）。
   **换算法不解决根因；PPG 式的"价值蒸馏 + 分阶段"、Kickstarting 式的"教师锚"、Primacy-reset 才解决根因。**

### 6.2 但有一种"文献支持、我们没试过"的组合值得试

**关键观察**：文献里所有"PPO 成功"的案例，**PPO 都不是从零学表征**——
Five 有辅助头 + LSTM 预训练、AlphaStar 有 SL、GT Sophy 有大量仿真与形状化奖励。
**我们恰好有"从零学表征"之外的一切条件**（监督先验、值网、搜索教师）。

所以正确的问法不是"要不要 PPO"，而是：
> **"能不能用一个 KL 锚定的、只更新少量参数的策略梯度，去修正一个已经有强先验的策略？"**

这在文献里有三个成功先例，且都不需要 10⁹ 步：
- **Kickstarting**：`ℓ_RL + λ_k H(π_T‖π_S)`，λ_k 退火，学生可超过教师 `[正文]`；
- **AlphaStar 的 KL 锚**：全程 KL 到监督策略，论文明确说 human data（含此锚）对 RL 性能"critical"（Fig.3E）`[正文]`；
- **ExIt**：搜索当教师、策略网当学徒，**同架构下稳定胜 REINFORCE** `[正文]`。

### 6.3 最小可行形态（MVP）："KL 锚定的束级策略梯度"

| 组件 | 具体规格 | 依据/风险 |
|---|---|---|
| 动作空间 | **266 维束级 softmax**，mask 进 logπ；束内位置**不进 ratio** | H1；风险：天花板 = 候选生成器 |
| 可训练参数 | **只训 class 头 + 一个小的束打分头**（骨干冻结，或 lr×0.1） | 09 月位置轴经验 + Primacy bias |
| 行为策略 | **搜索（现有 266×16 rollout）**，但**只记录其 top-k 的分布**（不是 argmax） | ExIt/AZ；风险：与"蒸馏"高度重合，可能只是换名字；**成本见下** |
| 优势 | **γ=1 + GAE(λ=0.95) + 64–256 步片段**；value 用现有值网初始化；**γ=1 前必须把奖励归一化到有界** | H2 + AlphaStar 无折扣；否则值目标爆炸 |
| 正则 | **KL(π‖π_prior) 权重 β**（退火，且以"离线 top-1"为判据而非 KL 下降） | Kickstarting/AlphaStar |
| 稀疏奖励补丁 | **SIL buffer**（回报 > V 的片段）+ **辅助头**（win-prob/经济） | H3 |
| 值缩放 | **PopArt** 或回报运行 std 归一化 | H4 |
| 数据量 | 每轮 **256 局**（≈2.6×10⁵ 决策，含 ≈2×10⁴ 有效决策）；**≤40 轮** | `[推算]`：40 轮 ≈1e7 决策 ≈ Atari PPO 量级 |
| 闸门（先写死） | G1 离线 top-1 一致率 ≥ 搜索 argmax 的 90%；G2 `approx_kl < 0.02` 且 `clip_frac < 0.2`；G3 值网校准（MSE 相对基线下降） | E 线 + H4 |
| 判据 | 三个闸门全过才上对局；对局用 SPRT，**<8pp 不判** | E 线 |

**成本估算** `[推算]`，取决于行为策略（§4 H5 第 4 条）：
- **搜索当行为**：每轮 256 局 × 1440 核时秒 ÷ 16 核 ≈ 6.4 h ⇒ 40 轮 ≈ **256 h ≈ 10.7 天满负荷**，
  且把整月的搜索数据预算吃掉。**评估（8×12.6 h=100 h）是次要项。**
- **策略网当行为**：每轮 256 局 × 2.1 s ÷ 12 进程 ≈ 45 s ⇒ 40 轮 ≈ **30 min**。**评估变成主导项（100 h）。**
- 无论哪条，**先做 G1/G2/G3 离线闸门**（成本以分钟计），过不了就不该花对局预算。这就是为什么 §6.4 的"改口条件"必须写死。

### 6.4 什么情况下我会改口（falsification，先写下来）

- 若 G1（离线 top-1 一致率）能到 **≥95%**，且 SIL/辅助头让**离线 top-1 超过搜索 argmax 本身**（即策略比教师更好），
  说明"束级 + 强先验"的确有可学的残差 ⇒ **值得加预算**。
- 若 H2 的 γ 扫描显示 **γ=1 时值网能收敛**（校准 MSE 不炸），说明"长视野"不是拦路虎 ⇒ PPO 的成本估算要下调。
- 若 E 线把评估成本压到 **<2 h 判 8pp**（例如用值网当代理评估，`docs/surrogate_eval_with_value_net.md`），
  PPO 的迭代经济性会完全改变 ⇒ 重新评估"是否当主线"。

### 6.5 明确不建议的形态（避免重蹈覆辙）

1. ❌ **从零自对弈 PPO**（08 月已失败；Five 的稀疏奖励消融也说明那需要 10⁹ 量级决策）。
2. ❌ **把位置图塞进 ratio**（KL 184063 已证明；AlphaStar 的"因子独立"是正解）。
3. ❌ **用 Q 头/DQN 替代**（动作结构化 + HOLD 主导 ⇒ Q 值在"束 × 位置"上难泛化；replay 的样本复用救不了这个）。
4. ❌ **靠 shaped reward 教新行为**（C 线：安全与无用一体两面；Five 自己也承认"保证不适用"）。
5. ❌ **不加 KL 锚就让 RL 改骨干**（08 月特征坍缩的直接原因）。
6. ❌ **用自对弈胜率当主指标**（68.8% vs 31.2%；PFSP/固定对手池是文献解）。
