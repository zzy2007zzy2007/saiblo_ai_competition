## 1. 事实基础（2026-09-20 全部复核过，不是记忆）

**1.1 现在的 `posnet_r1` 学的是「1-ply 价值偏好」，不是 MCTS visit。**
`collect_value_prior.py:86` 是 `c = int(np.argmax(hl[h]))`（注释明写"与 `--search-mode pos-only`
一致"），逐 (决策点, 头) 记录 `(board, stats, player, head, cls, cell, adv)`，其中
`adv` = **价值网**在每个候选 post-state 上的打分；`train_value_prior.py` 的目标是
`p = softmax(z(adv)/target_tau)`，预测 `q = softmax(z(action_map[cls])/t_pos)`。

**1.2 用 1-ply 而不是 visit 的原因是成本。** `az_value_prior_plan.md` §2 原话：visit 目标要
k=200/it=8192 才稳定，而当时测得"visit 的排序主要由价值驱动 ⇒ 高 k/it 的 visit 目标
≈ 价值 1-ply 的 softmax 目标" ⇒ 拿 1-ply 当**便宜的代理**。

**1.3 现在的数据只用到局面的极小一部分（两个"1"）。**
- **只记 1 个类**：`for h in range(3): c = argmax(...)`，每个 (回合, 头) 只记录 argmax 类的行。
  直接数 `training_history/vprior/vp_400.npz`：**24,972 行，`cls` 全是 17**，涉及不同类数 = 1。
- **只在"该类可执行且有 ≥2 格"时才记**：所以连这一类的行都只覆盖"闪电买得起"的那些回合。
- 而**同一局面里其实有 ~19 个类可用**（我实测 2 局、逐 (回合,头) 数
  `{c != HOLD : class_mask[c] 且 position_mask[c].any()}`）：
  **均值 18.9 / 中位 19 / 最大 20（共 23 类）**。
  ⇒ **现状把每回合的信息用了约 1/19（按类算）、且只用了 ~1/9 的回合（按"可记回合"算）。**

**1.4 🔴 它模仿的那个目标本身是弱点。** `az_value_prior_plan.md` §0.3.1 的分布外检验
（**只换闪电落点**、打完整 rule_v4）：

| 落点来源 | rule_v4 规则 | 我们的网 | 1-ply 价值 | **256 迭代搜索** |
|---|---|---|---|---|
| 胜率 | 0.5000 | **0.4922** | 0.3281 | **0.5391** |
| 只放闪电（赢局数 /128）| 22 | 25 | 23 | **43** |

⇒ **搜索（访问平均）的选点远好于任何"一次性"选点**，包括我们的位置网**和它模仿的那个目标**。
位置网作为"1-ply 目标"的拟合器已经满分（learned ≈ oracle），但**那个目标不是搜索手里的知识**。

**1.5 价值网刚被改进（今天）。** 只换 `value_state`（注入数据微调，权重相对变化 4.1%），
vs rule_v4 **18.4% → 32.4%（+14.1pp，McNemar p=0.0003）**。因为 1-ply 目标是**从价值网导出的**
⇒ **第一段的教学信号现在本身就变好了**，而采集成本不变。

**1.6 ✅ 已解答：网（0.4922）比它模仿的目标的 argmax（0.3281）好，是因为"硬取 max 被 winner's curse 带偏"。**

1. **不是配置不对称**（用户提出的可能解释）：核了当时的脚本 `_tmp_rv4_lightning.sh`
   与实现 `其他版本ai/rule_v4_mcts_lightning/mcts_lightning.py:122-160` ——
   `net` 臂 = `action_map[17]` 在合法格上取 argmax（**一次前向、无搜索**），
   `value` 臂 = 逐格建 post-state 过价值网取最大（**无搜索**），只有 `mcts` 臂跑 256/4 搜索
   （且它是另一次 run）。三个臂的价值网也是同一个。⇒ **疑点是真疑点。**
2. **机制**：`value` 臂在 **~271 个带噪的 1-ply 估计上取最大值** ⇒ 挑的是"**估计值**最高"的格，
   噪声让这个选择系统性偏乐观（winner's curse）。而位置网是对 `softmax(z(adv)/τ)` 的**平滑拟合**，
   不做硬 max ⇒ 避开离群格。
   **实测支持**（`vp_400.npz` 24,972 个决策点跑 `posnet_r1` 的 `pos_state` 前向）：
   **网的 argmax 与 1-ply 价值 argmax 只有 39.0% 同格（61.0% 不同）** ⇒ 网**不是**忠实复制
   目标的 argmax。这与"τ=1 让目标接近平坦 ⇒ CE 由分布主体主导 ⇒ 网学的是平滑结构"一致。
   ⇒ **不要为了"更贴近目标"去调小 τ**（那会去拟合噪声峰）；`target_tau = t_pos = 1.0` 是对的。

**1.7 ⚠️ intent decoding 带来的一个坑（本次修订才发现，必须显式处理）。**

"哪些类这回合可用"**不需要手推**：`make_class_mask` / `make_position_masks(intent_decoding=True)`
已经算好了（随机钉类抽的就是这个集合）。但要注意三件事：

1. **"可用"≠"它的通道会被读"**。`intent_decoding=True` 下**买不起的超武类仍在 mask 里**
   （实测：coins=50 时 `pm[17]` 仍有 271 格、`cm[17]=True`）。
2. **买不起的超武会被解码成"降级"，而且读的是通道 16 的图**。于是收集器"把某格强行顶到最高"
   这个手法**失效** ⇒ 若此时通道 16 有格（= 你有塔），**每个格都会返回同一个降级操作**
   ⇒ 该行的 `adv` 会**全相等（退化/错标）**。
3. **现有数据没有这种坏行是侥幸**：旧对局**从来没有塔** ⇒ `pm[16]` 恒空 ⇒ 自动降级找不到位置
   ⇒ `decode_head` 对每个格都返回 `None` ⇒ 整行被 `if op is None: continue` 丢掉。
   我实测 `vp_400.npz` 的 24,972 行**没有一行退化**（adv 标准差 0 的行 = 0%，271 个值全不同）。
   ⇒ **新设计一定会遇到塔，所以必须显式校验。**

⇒ **强制要求（写进实现）**：记录一行之前，校验 `decode_head` 返回的操作**真的落在被顶起来的
那一格上**（`op.arg0/arg1 == (x, y)`），否则丢弃该行。这一条同时封掉"自动降级错标"和其他
任何"顶格没生效"的情形，并**打印被丢弃的行数**。

## 2. 两段式目标（核心主张）

| 段 | 目标 | 成本 | 覆盖通道 |
|---|---|---|---|
| **第 1 段** | 1-ply 价值偏好 `softmax(z(adv)/τ)` | 中（**不需要搜索**，只要价值网前向）| **全部可用的类**（靠 §3 的多类记录）|
| **第 2 段** | 真正的 MCTS visit / 根节点子值 | 高（要搜索、且要"有选择余地"） | 取决于配置（见 §4）|

**为什么两段而不是直接上第 2 段**：① 第 2 段目标**噪声大**（每次裁决只有极少访问次数，见 §4），
直接拿它训是拿噪声当标签；第 1 段目标是**状态的确定性函数**（平滑），适合先把地图的大形状学出来。
② 第 1 段便宜得多 ⇒ 可以先把所有通道都铺上监督。③ 第 1 段的原料（价值网）刚变好。

## 3. 第一步（本计划要实现的）：多类记录 + 按通道加权（**行为不变**）

**3.1 机制改动（只有采集端，训练端不动）**

把 `collect_value_prior.py` 的"每个头只记 argmax 那一类"换成**记录一批合法的类**：

```
可用类集合 = { c : c != HOLD, class_mask[c], len(position_mask[c]) >= 2 }      # 用 mask 推，不手写规则
记录的类   = argmax 类  ∪  从其余可用类里均匀抽 (K-1) 个                        # K 为旋钮
每类记录的格 = 从该类的合法格里取 min(M, 全部) 个                              # M 为旋钮
```

- **总是包含 argmax 类**（它是部署时唯一真正被用的那一个 ⇒ 不能让它缺数据）。
- **其余类随机抽**（而不是固定取前几个）⇒ 跨回合覆盖所有通道，且每个通道拿到的局面多样。
- **每类最多 M 格**：目标仍是"这个子集上的 softmax 偏好"（语义不变——部署时解码器也只是在
  这一类的合法格里挑），但成本可控。
- 训练端（`train_value_prior.py`）不变：仍逐行做位置 CE；现在会有多个 `cls` 值，
  **自动就训到了所有被记录过的通道**。

**3.2 成本（实测，必须知道）**：不做任何限制地"记全部合法类 × 全部格"的代价是

| | 现状（只记 argmax 类）| 记全部合法类（无上限）| 倍数 |
|---|---|---|---|
| 目标行数 | 414 | 80,196 | **193.7×** |
| 价值网前向（格数）| 112,194 | 5,773,788 | **51.5×** |

（2 局实测。）⇒ **不能裸做**，必须靠 M/K 压回。例：每类 M=32 格（约 1/2.3）、每回合 K=5 类
（约 1/3.8）⇒ 约 5~6× 现状，可接受。**先冒烟量真实倍率，再定 400 局的规模。**

**3.3 ⚠️ 按通道加权（否则会把闪电通道训坏）**：现状闪电占 **100%** 的行；多类记录后
它会掉到约 **1/19**。而闪电是**部署时唯一被使用的通道** ⇒ 必须加权：

```
行权重 = 1.0   （argmax 类，= 部署时真正会用的那类）
       = λ     （其余类；λ 为待标定旋钮，先取 0.2）
```

**守护读数（判据的一部分）**：闪电通道的 CE 与"同格率"**不得劣化**（对照 §5）。

**3.4 ✅ 行为与监督解耦：对局仍然用 argmax 类出招。**
这一步**不改行为** ⇒ 采集到的局面分布**仍是部署分布**，**不引入分布外风险**
（这是相对"随机钉类"方案的一个实质改进：随机钉类会改变对局分布）。
⇒ `az_posnet_random_class_plan.md` 的钉类机制在本计划里**不再用于第一段**；它保留的角色只剩
"让对局走到塔态"的行为干预（而那个目的 (a) 已经用注入做过）。

**3.5 ⚠️ 代价与诚实标注**：行为不变 ⇒ 其他通道的目标是**反事实**的（"这些局面下如果改做那个
动作会怎样"），它们在对局里**从未真实发生**。这个目标可不可信，**取决于价值网在那些
post-state 上的精度**——而这恰好是 (a) 刚改善过的东西（价值网在塔态上的误差 −9%）。
**两条线在这里互相支撑**：先让价值网会判塔态，再用它给位置网的所有通道铺监督。
但要如实记住：**反事实目标的质量上限 = 价值网的精度上限**。

**3.6 归因要求（判据要干净）**：`train_value_prior.py --ckpt X` 会把 `X` 的
`class_state`/`value_state` **照抄**进输出 ⇒ 判据里的对局会被价值网污染。
所以让被比较的两个位置网**共用同一个价值网**（都用 `valnet_A2.pt`），只差"记录口径"：

- run-A：多类记录（K=5, M=32）→ `pos_state_A`
- run-B：`K=1`（= 现状的单类记录）→ `pos_state_B`

⇒ **A vs B 只差"多类 vs 单类"**；历史 42.2% 只当粗参照。

## 4. 第二步（本计划**不做**，但要把障碍写清）

**4.1 障碍：现在这个配置下几乎没有"选择余地"。** `eval.py` 的 diag 行实测：

```
turns=264  room(>=2 cands)=2.7%  same-as-raw=99.2%  diff[class=0 pos=2 both=0]
```

⇒ 在 `pos-only + argmax 钉类 + skip-single-candidate` 下，**只有 ~2.7% 的回合有 ≥2 个候选**。
**visit 目标在 97% 的回合上退化成"唯一候选"，没有信息。**（今天那 +14.1pp 就是在这个约束下拿到的。）

**4.2 ⇒ 要学"真正的 visit"必须换一个有选择余地的配置**（joint 搜索，或至少放宽钉类）。
但那时的目标会**同时覆盖类轴和位置轴** ⇒ 与 `az_class_axis_plan.md` §5(b)（重训类网）
**范围重叠**，顺序和范围必须先一起定。

**4.3 候选口径（供后续讨论）**：joint 搜索的 visit 边缘化到 (类, 位置)（= 标准 AlphaZero
策略目标，`az_selfplay` 的 pkl 里已有 `bundles/visit/intent_counts`，基础设施现成）；
难度在"访问次数够不够稳定"，而 §1.2 的旧记录说 k=200/it=8192 才稳（未实测过与我们配置的相对代价）。

## 5. 预注册判据（第 1 段；跑前写死）

**主判据**（沿用文档既有口径，不新造尺子）：

1. **只换闪电落点 vs 完整 rule_v4**（`az_value_prior_plan.md` §0.3.1 那个台子）：
   新位置网 **> 0.4922** 才算赢；同时报 1-ply 价值那一栏的变化。
2. **vs rule_v4 256 局**（4 批 seed × 64，`eval.py` 同协议）：对照 ① `pos_state_B`（§3.6）
   与 ② 历史 `posnet_r1` 的 42.2%。

**守护判据（不得劣化）**：
- **闪电通道**的 CE 与"网的 argmax vs 目标 argmax 同格率"（现 39.0%）——加权/多类不应把它训坏。

**诊断读数**（不判成败，但必须打印）：
- **逐通道的 CE / top1 / 记录行数** ⇒ 确认机制真生效（应有 ~19 个通道拿到数据，而不是 1 个）
- **`cls` 直方图**（应覆盖多个类，而不是 100% 集中于 17）
- **强制格校验丢弃的行数**（§1.7；非零说明自动降级那类问题被正确挡住了）
- 实际成本倍率（行数 / 价值网前向数，对照 §3.2）
- raw 镜像（新位置网 vs 旧位置网，不搜索）
- `posnet_v2` 的 `class_state`/`value_state` 是否 = `valnet_A2` 的（逐位校验，防归因被污染）

**失败判据**：判据 1 与 2 都不涨 ⇒ "更深的目标"（§4）是唯一出路，回头做 §4 的范围决策。

## 6. 风险

| 风险 | 说明 |
|---|---|
| **稀释闪电通道** | 它从 100% 的行掉到 ~1/19 ⇒ 必须按通道加权，且要盯"闪电通道不得劣化"的守护读数 |
| **反事实目标** | 行为不变 ⇒ 其他通道的目标从未真实发生；质量上限 = 价值网的精度上限（§3.5）|
| **成本 51×** | 裸做不可行；靠 M/K 压回，**先冒烟量真实倍率**再定规模（§3.2）|
| **自动降级错标** | 买不起的超武会解码成读通道 16 的降级 ⇒ 必须显式校验"顶格生效"（§1.7）|
| **§1.6 的机制** | 网的优点是"不做硬 max" ⇒ **别把 τ 调小**去拟合噪声峰 |
| **通道间干扰** | 24 个通道共享骨干 ⇒ 其他通道的梯度会流进闪电通道的特征（老风险）；多类记录会**放大**它，所以守护读数不是可选项 |
| **K/M/λ 未标定** | 三个新旋钮都没有实测；先小规模冒烟，不要一次性投 400 局 |

## 8. 实施顺序

1. `collect_value_prior.py` 加多类记录（`--multi-class-k K`、`--max-cells M`、`--row-weight-lambda λ`）
   + **强制格校验**（§1.7）；**默认行为完全不变**（K=1 时逐位等价于现状）
2. **冒烟**：`K=5, M=32` 跑 2~4 局，核对 ① 实际成本倍率、② `cls` 覆盖的类数、
   ③ 强制格校验丢弃的行数、④ 闪电通道的行数占比
3. **run-A**（多类）与 **run-B**（`K=1`，= 现状）各 400 局，`--ckpt training_history/inject_ex02/valnet_A2.pt`
4. `train_value_prior.py` 各训一个 ⇒ `posnet_A.pt` / `posnet_B.pt`（顺带换 `--seed` 复训一次）
5. 判据 1（闪电落点台子）+ 判据 2（vs rule_v4 256 局，A 与 B 同协议）+ 守护读数
6. 记档：逐通道 CE、`cls` 直方图、丢弃行数、判据 1/2，然后决定 §4 的范围
