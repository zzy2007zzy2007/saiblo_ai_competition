# 策略采样 Bundle 候选 MCTS 方案（修复先验-解码不一致）

> 目标：用"策略采样生成完整动作组候选 + 在候选内搜索"替代"意图格 top-k 剪枝"，
> 从根上修复先验-解码不一致 bug（闪电被 top-k 剪掉，搜索选不了 gen_0120 的真正策略）。
> 日期：2026-08-05。状态：设计阶段。

## 1. 背景（诊断结论，见 `az_search_diagnosis.md`）

- 旧设计：意图格 top-k 硬剪枝（root 24 / child 12）+ 分解先验 P(c)·P(p|c)
- **bug**：分解先验对超级武器不公平（~200 落点稀释概率），闪电（gen_0120 的
  真正策略）被 top-k 直接剪掉 → 搜索结构上够不到闪电 → 只能打"建塔"这种
  完全不同的（输的）策略 → 0% vs ExampleAI（价值头预热后仍 0%）
- 附加问题：逐头搜索（6 层/回合）+ 硬剪枝 → 候选动作空间 ≠ 解码器的动作空间

## 2. 核心思想

**候选生成 = 解码器的采样方式**（类温度采样 → 位置温度采样 → 解码），
采样 k 次得到 k 个**完整动作组**（bundle），**只在这 k 个 bundle 内搜索**。

```
对每个头:
  ① 从类头温度采样: c ~ softmax(head_logits / T_class)      （只对合法类）
  ② 若 c 需要位置(0-20): 从位置图温度采样: (x,y) ~ softmax(action_map[c] / T_pos)  （只对合法位置）
  ③ 解码出 Operation（和 decoder 一致），记录 log 概率
3 个头 → 1 个完整 bundle（含 log 概率和 = log P(组)）
重复 k 次（重复就重采）→ k 个候选 bundle
```

**为什么修复 bug**：闪电的类概率高 → 温度采样经常采到闪电 → 闪电**进入候选集**，
搜索够得着了。候选空间 = 解码器的采样空间 → **先验-解码天然一致**。

## 3. 先验（组联合概率）

3 个头是顺序采样的（head2 合法性依赖 head1 的选择），所以：

```
log P(组) = Σ_头 [ log P(c) + log P(p|c) ]   # log P(p|c)=0 for 类21/22/23
P(组)     = exp(log P(组))                    # 归一化到 k 个候选上
```

- 每个动作的 log 概率在采样时记录（类 softmax 和位置 softmax 的分母都是合法集）
- **用 log 和（= log 联合概率），不是简单分数相加**（用户方案的一个修正点）

## 4. 树结构（2 层/回合）

```
回合 R:  P0-bundle 节点 → P1-bundle 节点 → 结算 → 回合 R+1 的 P0-bundle 节点
```

- 每节点：为当前玩家采样 k 个 bundle → k 个子节点
- P0 边：应用 P0 的 bundle（状态更新）
- P1 边：应用 P1 的 bundle + `advance_round()`（回合结算）
- 深度限制按**回合**计（如 3-5 回合 = 6-10 层），叶子用网络价值评估
- 相比旧设计 6 层/回合，同样搜索预算下**前瞻更深**

## 5. 参数

| 参数 | 建议 | 说明 |
|------|------|------|
| k（每节点候选数） | 16-32 | 覆盖度 vs 计算量 |
| T_class / T_pos | 待定（采样温度） | 高→多样，低→集中；初始可对应对应训练温度 |
| max_depth_rounds | 3-5 | 前瞻回合数 |
| iterations（模拟数） | 32-64 | 每决策搜索预算 |
| c_puct | 1.25 | 标准 |

## 6. 与旧设计的对比

| | 旧（意图格 top-k） | 新（bundle 采样） |
|--|------------------|------------------|
| 候选来源 | 意图格先验 top-k | 策略采样 k 次 |
| 动作单元 | 单头单动作 | 完整 3 动作组 |
| 树结构 | 6 层/回合 | 2 层/回合 |
| 先验-解码一致性 | 不一致（bug） | 一致（采样=解码） |
| 闪电可达性 | 被剪掉 | 可被采样到 |
| 硬剪枝 | 有（top-k 硬剪） | 无（采样覆盖） |

## 7. 依赖与未决问题

- **价值头仍然必需**（叶子评估）：方案解决"候选对不对"，评估还靠价值头。
  先用当前 `gen0120_warm.pt` 的价值头验证搜索行为，价值头质量后续再训。
- 对方层级同样采样 k 个候选（自对弈一致性）。
- 采样是**随机**的（温度采样）→ 每节点候选每次搜索都不同 → 搜索确定性下降
  （对训练数据多样性可能是优点）。
- 重复候选处理：去重（用户已提）。

## 9. 一句话总结

**用解码器同款的温度采样生成 k 个完整动作组候选，在候选内做 bundle 级 MCTS
（2 层/回合），组先验 = 3 动作 log 概率之和（联合概率）——从结构上保证搜索的
候选空间和解码器的动作空间一致，闪电不再被剪掉。**

## 10. 实验结果（2026-08-05，突破）

| 配置 | vs ExampleAI |
|------|-------------|
| gen_0120 原始策略（不搜索） | 100% |
| 意图 MCTS（top-k 剪枝） | 0% |
| bundle 采样（无修复） | 0% |
| **bundle 采样 + 两个修复** | **60-80%**（5 局 4W1L / 3W2L，16 局验证中） |

### 两个关键修复（调试中发现）

1. **z-score 归一化**（类 logits）：跨模型温度才有意义（gen_0120 类 logits 极平，
   闪电 0.049 其余 ~0.01，原始 softmax 下闪电仅 ~4%，z-score 后 ~31%）
2. **位置概率只在动作实际使用位置时记录** + **去重保留最高分**：
   - 同一解码动作可来自多种意图组合（如 WAIT 可来自 3×闪电 或 3×EMP），分数差 10 个
     数量级；去重保留最高分让最优意图代表该动作
   - 无操作头（HOLD）只记类概率不记位置 → WAIT（等待闪电）先验从 -20 变 -3.5，
     搜索开始探索它 → 搜索选对"等待闪电"策略

### 调试中发现的其他问题

- gen_0120 的"等待闪电"策略是 argmax 行为（头 argmax 闪电但买不起→等），
  不是分布层面的——采样方法需用 z-score + 类级先验才能捕获
- 价值头（value_warmup 训的）正确区分等待(0.092)>建塔(0.014)，价值不是瓶颈

### 最终修复（2026-08-05，90%）

| 修复 | 作用 |
|------|------|
| z-score 归一化 | 跨模型温度有意义（平坦 logits 下闪电可达） |
| 位置概率只在动作实际使用位置时记录 | WAIT 先验从 -20 变 -3.5（闪电类水平） |
| 去重保留最高分 | 同一动作的最优意图组合代表它 |
| **intent-decoding 回退** | 闪电买不起时拆塔补钱（gen_0120 核心策略） |
| **sample_bundle 直接调用 decoder.decode_head** | 单一事实来源，消除两条代码路径漂移 |

**结果：bundle MCTS vs ExampleAI = 90%（9W/1L，10 局）**，接近原始策略 100%。
搜索正确执行"等待→降级补钱→放闪电"策略（诊断局 11-0）。

**根本教训**：搜索的动作空间必须严格等于解码器的动作空间——任何"搜索看到的
动作 ≠ 实际能执行的动作"都会导致结构性失败。单一事实来源（搜索复用解码器）
是根治方案。

## 11. 自对局验证：搜索是否增强（2026-08-06）

**搜索版 gen0120_warm vs 原始版 gen0120_warm（同网络自对局）：**

| 配置 | 样本 | 胜率 | 先手 | 后手 |
|------|------|------|------|------|
| 128 迭代 + 深度 4 | 48 局 | **66.7%** (32W/16L) | 50% | **83%** |
| 192 迭代 + 深度 6 | 16 局 | **68.8%** (11W/5L) | 50% | **87.5%** |

**关键发现**：
- **搜索确实增强**（66.7%/68.8% > 50%），"搜索 ≥ 原始策略"成立，AlphaZero 训练有信号
- **增强完全集中在后手（P1，知情方）**：搜索后手 83-88% vs 先手 50%——搜索把
  "P1 能看到 P0 操作"的信息优势利用得比原始策略好得多，但作为盲动先手无增强
- **更深搜索无提升**（192/深度6 ≈ 128/深度4）——**价值头精度是天花板**
- 这解释了 vs ExampleAI 90%（知情方碾压弱对手）、vs rule_v4 10%（rule_v4 太强，
  信息优势弥补不了强度差）

**对 AlphaZero 训练的含义**：搜索增强真实存在但来源是信息优势利用；训练时
应关注搜索的访问分布（尤其作为 P1 时），价值头精度是提升空间。
