# 计划：把位置网的训练目标换成"价值网的偏好"（第一轮）

> 日期：2026-09-18。状态：**计划阶段，待过目。**
> 依据：`docs/experiment_log.md` 的 `tpos_prior_quality` / `tpos_similarity` / `tpos_rule_v4` /
> `tpos_rule_v4_mild` / `value_prior_ab` / `value_prior_rule_v4` / `value_prior_verify`，
> 以及 `docs/az_t_pos_default_fix.md`。
> 前置共识（用户 2026-09-18）："越尖越差"是**当前先验太烂**的性质，不是规律。

## 0. 2026-09-18 的重大更新：Oracle 先验已经证明这条路的值

在动手训练之前，先用"暴力算出来的价值先验"（`eval.py --pos-prior value`，
根节点枚举钉类全部合法格过价值网）当**上限**测了一遍（128 局打 rule_v4）：

| 配置 | vs rule_v4（128 局）|
|---|---|
| 位置网先验，k=24（现状基线）| **21.1%**（27W/101L），95%CI 14.9–29.0 |
| **价值先验（oracle），k=24** | **37.5%**（48W/80L），95%CI 29.6–46.1 |
| 价值先验（oracle），k=8 | 27.3%（35W/93L）|

* **+16.4pp，z = 2.93，两批 seed（0–63 / 64–127）同向同量级** ⇒ 这是本项目对 rule_v4 的
  **第一次可复现提升**。其中约 +6.3pp 来自"只提出可执行动作"（`--pos-prior uniform` 对照 = 26.6%），
  剩下 ~+12.5pp 才是**价值信息**本身。
* ⚠️ **"缩 k 免费"被推翻**：k=8 比 k=24 低 10.2pp，且在换 seed 那批上已与基线分辨不出。
  ⇒ 本计划的**目标形态改为「k 保持 24，把 270 次暴力前向换成 1 次网络前向」**
  （成本回到基线、期望上限 +16.4pp），而**不是**"缩 k"。
  缩 k 是**另一个**问题，现有证据说明 8 个候选不够用（很可能又是多样性塌缩，只是区域由价值挑）。

⇒ 本计划因此从"一个待验证的假设"变成"**已经知道值多少、只待把 oracle 学出来**"。

### 0.1 两条必须一起说的修正（2026-09-18，用户指出）

1. **"目标可复现性"这个指标不能用**（`valprior_similarity` 实测）：位置网先验在 tp0.5 的
   余弦 **0.827/0.891** 反而**高于**价值先验的 **0.588/0.670**，可价值先验才是好先验
   （打 rule_v4 +16.4pp）。原因是该指标**奖励"确定性"本身**——位置网先验 tp0.5 时目标有
   **25.1%** 的质量压在一个格子上（价值先验只有 19.3%），所以两遍更像，纯属平凡原因。
   顺带查过用户担心的"低温 k 填不满"：**候选数恰好 = 24.0 / 48.0，退化率 0%**，不存在该假象。
   ⇒ **判断目标好坏只能用行为判据（打 rule_v4），不能用可复现性。**
2. **"搜索蒸馏不如价值目标"没有被证明过** —— 当前策略确实是 `az_r10`（跑过 10 轮搜索蒸馏），
   那 10 轮也确实没带来提升；但**当时的目标在可负担设置下几乎是垃圾**（一致率 0~42%），
   所以"没提升"完全可以用"目标坏"解释，而**那正是本计划要解决的问题**。且上面那个
   oracle 对比是"一边 oracle、一边训过的产物"，不对等。
   ⇒ 价值目标的优势应表述为**落地风险低**（确定性、~0.8 秒/出招回合、不用调 k/it、
   无可复现性问题），**不是"已被证明更好"**。两个目标都还没被证明"可学"。
3. **两段式而非二选一**：① 先用便宜的价值目标拿到一个像样的先验（本计划）；
   ② 有了它，小 k 搜索才稳得住，那时再谈用**搜索目标**去蒸馏（更标准的 AlphaZero 对象）。
   先做 ① 既低风险，又正好给 ② 铺路。

## 0.2 τ：与 t_pos 耦合在同一根轴上，但**不是**空操作（2026-09-18，含一次被推翻的预测）

**我原先的推导（错）**：令 ∂L/∂m = 0 ⇒ q = p ⇒ `m/t_pos = z(adv)/τ + 常数` ⇒ **m ∝ z(adv)**，
与 τ 无关；而采样侧解码器会重新 z-score（`(m−mean)/std`）⇒ τ 与地图的绝对尺度一起被约掉
⇒ 预测 **τ 是重参数化、空操作**。

**实测把这个预测推翻了**（`_tmp_vprior_map_compare.py`，200 个决策点，无对局噪声）：

| | 原始地图 std | t_pos=1.0 下有效候选 |
|---|---|---|
| τ=1.0（`posnet_r1`）| 1.454 | **176.3** |
| τ=0.25 | 0.532 | **44.3** |

归一化地图余弦 **0.698**、分布余弦 0.574、top1 同格 **34%** ⇒ **地图不是"只差一个尺度"**，
τ=0.25 训出来的图**本征上就尖得多**。
**错在哪**：那段代数假设网络能精确实现 `m ∝ z(adv)`（任意尺度）。实际卷积网络学的是
**受损失加权的近似**，权重随 τ 变 ⇒ 实现的**形状**也随 τ 变。我推的是极限，网络离它很远。

**行为上也一致**（128 局打 rule_v4）：τ=0.25 → **30.5%**、τ=0.5 → **36.7%**、τ=1.0 → **35.2%**
⇒ **τ ∈ {0.5, 1.0} 不可分，τ=0.25 略差**；机制就是"图本征更尖 ⇒ 在固定 t_pos 下更靠近太尖那一档"。

⇒ **正确结论：τ 与 t_pos 作用在同一根轴（采样时的有效尖锐度）上、相互耦合**，
而不是"τ 是空操作"。**实用上：别再单独调 τ**（默认 1.0；{0.5,1.0} 都行），要调就调 `t_pos`
（那一维已测：0.5~2.0 都可、≤0.3 要避免，见 `tpos_curve_priors`）。
⇒ 命名：脚本参数是 `--target-tau`，与价值标签的时间衰减 τ
（`az_train.add_weighted_labels`，γ=exp(−1/τ)）**无关**。

## 1. 一句话

现在位置网学的是 **MCTS 的 visit 分布**；改成学**价值网在钉类合法格上的偏好**。

## 2. 为什么换（三条实测依据）

| 事实 | 出处 |
|---|---|
| 先验与价值的对齐**很弱**：地图峰的价值分位 **30.3%**（随机 50%），即只有弱信号 ⇒ 锐化它丢掉的探索远大于换来的信息 | `tpos_prior_quality`（软指标版）|
| 强度随锐化**单调下降**：t_pos 0.3→1.6% / 0.5→7.8% / 0.7→18.8% / 1.0 与 2.0→20.3%（打 rule_v4） | `tpos_rule_v4(_mild)` |
| 搜索**选中的那一步不是局面的函数**：强度平台（t_pos=1.0）上同一局面换 rng 重抽，目标余弦仅 **0.350**、bundle 同 42.5% | `tpos_similarity` |

**2026-09-18 追记：五个来源不同的先验都只有弱信号，没有一个是"方向反了"。**
把位置网换成启发式评分蒸馏版（`distill_data/model.pt`、`distill_data_v2/model.pt`、
`score_distill_*/epoch_0030|final.pt`，均已造成三网 ckpt 并存到
`training_history/az_fixed/three_mix_pos_{distillV1,distillV2,scoredistill_*}.pt`）后
量同一批参照局面：峰的价值分位 22.3%~39.7%，**都显著优于随机（50%）但都远离对齐**；
彼此差 ~8pp（约 1.3σ）分辨不出。⇒ 用户"蒸馏版位置图相对更好"的假设**未被证实**；
但"现有先验内容差"这个结论也要修正成**更精确的"信号弱"**（而不是"没有信号"）。

**而搜索的强度恰恰来自价值网的排序**：同一候选集、同一出招率（2.8%）下，
按 visit 选 = 90.6%，**随机选 0/32、按先验选 0/32**。
⇒ 别蒸馏搜索的噪声输出，**直接蒸馏让它变强的那个原因**。

**一个便宜的等价物**：k 大到覆盖全图（k=200 / 271 格）时，先验几乎不起作用（t_pos=1.0 近均匀），
而此时 visit 的排序主要由价值驱动 ⇒ **"k200/it8192 的 visit 目标" ≈ "价值 1-ply 的 softmax 目标"**，
但成本差约 100 倍（见 §4）。所以第一轮不必贵。
⚠️ 唯一可能丢掉的是**深度**（k200 的 visit 背后有 4 回合展开，1-ply 只有一步）——
即 `pos_greedy_vs_raw` 那条未结的口径差。若第一轮显示"1-ply 目标不够好"，
下一个怀疑对象就是它。

## 3. 目标定义

对每个"钉类有 ≥2 个合法格"的决策点、每个头 `h`：

1. 钉类 `c = argmax(head_logits[h])`（与 `--search-mode pos-only` 一致），`c != HOLD`；
2. 枚举 `c` 的全部合法格 `{(x,y)}`（`make_position_masks`）；
3. 对每格构造 post-state（`apply_operation_list`），用价值网评估**对手视角**的价值，取负 = 我方优势 `a(x,y)`；
4. **在合法格上 z-score**：`z = (a - mean) / (std + 1e-8)`（与采样器同一套尺度，见 §5）；
5. 目标 = `softmax(z / τ)`，`τ` 是唯一超参。

⇒ 目标是**局面的确定性函数**：无 rng、无 seed 依赖 ⇒ 可复现性是构造性的。

## 4. 采集（新脚本，不碰现有 pipeline）

**新脚本 `code/my_ai/az_intent/collect_value_prior.py`**：用 raw 策略推演对局
（同 `_tmp_pos_greedy_vs_raw.py` 的循环），在每个符合条件的决策点记一条
`(board, stats, head_idx, class_id, cells[(x,y)], probs[...])`，存 npz。

- **成本实测外推**：`_tmp_pos_greedy_vs_raw.py` 32 局 73s（16 worker）⇒ **约 36 s/局**（单核）
  ⇒ **400 局约 15 分钟**（16 worker）、1500 局约 1 小时。**这是本方案最大的好处**：
  第一轮从"数十小时"变成"十几分钟"，所以第一轮本身就可以同时当"上限检验"。
- 样本量：每局约 23 个决策点 ⇒ 400 局 ≈ 9.2k、1500 局 ≈ 34k 个位置样本。
- **不需要** visits/bundles/intent_counts ⇒ 完全不走现有 pkl 格式，也不受
  `--skip-hold-search` 那个 `intent_counts=None` 的历史坑影响。

## 5. 训练

复用现有 `--pos-only-net` 路径（类网/价值网冻结），只把位置 CE 的**目标来源**换掉：

- `_sample_policy_loss` 的位置部分现在从 `intent_counts` 边际化出目标；新增一个分支：
  样本带 `value_target` 时直接用 `softmax(z/τ)`，其余（z-score、CE、anchor）逐字不变。
- **z-score 必须用同一套**：目标侧 `z = (a-mean)/std`（合法格）、网络侧 `am_c` 同样
  `(am-mean)/std`（合法格）、两边都除 `t_pos`（训练侧）/`τ`（目标侧）。
  ⚠️ 这正是 2026-09-17 那个 100× bug 的教训：**两侧尺度必须逐字核一遍**。
- 起点：`training_history/az_fixed/three_mix_r10p_vw_pol_frozen.pt` 三网拆分版。

## 6. 预注册判据（跑之前写死；第一轮的主判据**不是棋力**）

1. ✅ **主判据：先验本身变好了吗** —— 在同一批参照局面（`_tmp_prior_quality.py` 的口径）上量
   **峰的价值分位**（0 = 地图的峰落在价值最好的格上，50 = 随机）。
   参考基数（2026-09-18 实测，n=22）：原位置网 **30.3%**、蒸馏 V1 28.6%、蒸馏 V2 39.7%、
   score_distill e30 **22.3%**、score_distill final 33.6%（标准误约 6pp）。
   ⇒ **第一轮跑完它应该显著低于 30%，且朝着 10% 量级走**（那才叫"锐化它不再亏"）。
   **它是参数无关的直接量、便宜、和棋力噪声无关。**
   ⚠️ **不要再用"逐格精确命中"**：价值最好的 ~20 格近乎并列，精确命中率的上限本来就只有
   ~5%，n=22 测不出来（我第一版把它当主判据，五个先验全部 0/22，是判据的错不是先验的错）。
2. **锐化是否还掉强度** —— t_pos∈{0.7, 1.0} 打 rule_v4 各 64 局、同 seed 配对。
   现在 0.7 是 18.8% 而 1.0 是 20.3%（差 1.5pp，"轻度锐化已经有代价"）；
   先验修好后这个差应该收窄。
3. **网络自身变强了吗** —— raw(新) vs raw(旧) 镜像配对 64 对（**不用 search-vs-raw**：
   它起点就 90.6%、天花板只剩 ~9pp，看不见绝对进步）。
4. **（第二轮才谈）缩 k/it** —— 有了好先验后测 k 从 24 降到 16/12 时强度是否保持。

**噪声地板**：64 局 ±5pp（2σ）。所以判据 2/3 要 ≥64 局配对，且成功线定在"显著优于旧"，
不看"看着好一点"。**判据 1 不受这个限制**（是逐样本的一致率，不是对局胜率）。

## 7. 风险 / 未决

- **τ 未标定**：目标 softmax 的温度。建议先跑 τ∈{0.5, 1.0, 2.0} 三档看训练后的
  峰对齐价值与目标熵，再定。默认 1.0（= 单位方差 z-score 本身）。
- **可能丢掉深度**（§2 末）：若判据 1 起来了但棋力不动，怀疑对象是 4 回合展开。
- **先验可能仍然不够好**：0/22 → 有对齐，但"够不够锐化"是另一回事。判据 2 才是那一步。
- **状态分布**：用 raw 策略推演的状态，与"搜索真正走的局面"有偏（`depth0` 的教训）。
  第一轮接受；若判据 1 好而判据 3 坏，第一件事就是换采集策略（用搜索推演）。
- **不做**：本方案**不动**类网与价值网；也不动 `bundle_mcts.py`。
