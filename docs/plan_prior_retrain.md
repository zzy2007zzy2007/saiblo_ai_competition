# 位置网/类头重训方案（2026-10-23 起草）

> 背景：我们最近一直在优化**推理端**（候选数、rollout 采样、记忆化），而**网络端（先验）从没动过**。
> 本文档记录"为什么必须动网络端"、以及具体怎么做。

## 一、诊断：先验是坏的（不只是弱，而是接近反相关）

`code/test_match/diag_prior_quality.py`，三个局面各枚举 300 个候选、全部跑 h=16 rollout 估值：

| 局面 | Spearman(先验, 估值) | 估值最优动作的**先验排名** | recall@64 | 信先验 top-1 的估值损失 |
|---|---|---|---|---|
| seed1540 r60 | **−0.015** | **293 / 300** | ❌ | −0.066 |
| seed1540 r140 | **−0.015** | 152 / 300 | ❌ | −0.124 |
| seed1541 r200 | **−0.037** | 217 / 300 | ❌ | −0.199 |

- `recall@1/4/8/16/32/64` **全部未命中**（随机猜 64/300 = 21%，我们 3 次全没中）；
- 早前读数：建塔位置通道 vs `adv` 的 Spearman 仅 **+0.046**；只有**闪电通道**是好的（**+0.738**）；
- 类头 argmax 分布：lightning 61.1% / HOLD 38.9%，**22 个类从不被选中**。

**后果链**：
```
先验指不准 ⇒ 候选只能靠广度硬扫（k=24→160，+15.6pp；全枚举 k=300 再 +6.2pp）
          ⇒ 每候选分不到算力 ⇒ 想提高评估质量就堆采样（N=128，7.4 s/决策，贴 10 s 上限）
          ⇒ 而且 k=160 是按先验加权采样，**最优动作可能根本没进候选集**
```

## 二、教师信号：用"枚举 + 值网排序"当 ground truth

我们现在的搜索本身就是一个**比先验强得多的评估器**：

```
对每个局面：枚举全部合法动作（~300 个）→ 每个跑 1 次 h=16 rollout → 值网打分 → 排序
```

这个排序就是"**该局面下哪些动作好**"的干净标签。而我们想训练的，正是"看一眼局面就给出这个排序"的网络。

**为什么这个教师信号可信**：
- 值网仲裁已经证明"值网的比较判断"是有信息的（+19pp）；
- 搜索价值实验：k=160 vs k=1 = **100% 胜** ⇒ 这套"枚举+估值排序"确实远强于网络直接输出。

## 三、目标与验收

**目标**：把位置网的建塔通道从 Spearman ≈ 0 提升到可用的水平（先定 +0.35 为第一阶段目标，
闪电通道当前 +0.738 作为参照）。

**验收**（就用现成的诊断脚本，不用打对局）：
1. `diag_prior_quality.py` 的 Spearman 提升；
2. `recall@16` 从 0 → ≥ 50%；
3. 端到端：**k 从 160 降到 24** 时，内部胜率不明显下降（说明先验能替代广度）。

## 四、实施步骤

### 步骤 1：采集教师数据（`code/test_match/collect_prior_labels.py`，待写）

对每个决策：
- 枚举全部候选（`_expand` 用 k=300）；
- 对每个候选算 rollout 值（h=16，采样 1）；
- 记录：局面特征（已有 `FeatureExtractor`）、候选动作（类/位置/塔 id）、估值。

输出：`training_history/prior_labels/<tag>.npz`（每行一个 (state_id, action, value)）。

成本：**≈2.8 s/决策 × ~450 决策 ≈ 21 分钟/局**；先采 8 局（≈3 小时）做第一版。

⚠️ 注意：候选空间随局面变化（60-300），需要 padding + mask，或按"每个动作一行"存稀疏格式。

### 步骤 2：训练（`code/my_ai/train_prior_distill.py`，待写）

- **建塔通道**：输入 = 局面特征，输出 = 每格一个分数；标签 = 该格 BUILD 的估值（归一化后）；
  损失 = 只在合法格上算（listwise softmax 或 pairwise ranking，比回归更贴合"排序"目标）。
- **类头**：标签 = "枚举+仲裁后选中的类"（多分类），度量 top-1/top-3 一致率。
- 从 `checkpoints/posnet_A_k5_m32.pt` 微调（保留闪电通道的能力，避免灾难性遗忘：
  可以对闪电相关权重用小学习率，或混合旧标签一起训）。

### 步骤 3：验收与迭代

跑"三、验收"的三条；若端到端 k=24 不掉，则说明先验可用，接着把省下的算力给采样。

## 五、风险与备选

| 风险 | 说明 | 备选 |
|---|---|---|
| 教师信号本身有噪声 | 单次 rollout 的估值方差大（尤其后期局面） | 用 N=8 采样均值当标签；或只用"top-16 vs 其余"的粗标签 |
| 标签分布偏移 | 教师来自我们自己的对局（弱自对弈） | 混入打亚军的 101 局状态 |
| 灾难性遗忘 | 微调会毁掉闪电通道 | 混合旧任务/低学习率/只训建塔头 |
| 候选集随局面变化 | 训练时长度不齐 | mask + listwise loss |

## 六、与"推理端"工作的关系

推理端的结论已经很清楚（今天全部实验）：
- rollout 是确定性的 ⇒ 采样 1 就够（除非用随机化）；
- 广度 k=160 是甜点，全枚举 300 再小幅提升（56.2%，CI 跨 0）；
- 随机化 + 大 N 有信号但被"重复样本自我稀释"拖累（需去重加权）；
- **先验坏 ⇒ k 降不下来 ⇒ 算力被广度吃掉**。

⇒ 网络端一旦修好，推理端的"广度 vs 采样"权衡会整体松动，这是目前**唯一的结构性改进方向**。
