# 预注册：**诊断臂「建塔花钱门槛」**（`AZAI_BUILD_MIN_COINS=τ`）——"少 churn、把钱留给闪电"

> 2026-10-07 第 7 轮写（**在跑这批之前**）。章程：`docs/task_ruleV4_90_charter.md`。
> 性质：**手写干预的诊断臂**（章程②：只能当诊断、判法 = 消融）——**不是交付物**。

## 0. 由来（四条读数指向同一个嫌疑）

1. **行为对比**（256 局，双方 op 直方图）：我方 **建塔 24.84 / 降级 10.82 / 闪电 10.50 / 升级 0**；
   对手 **建塔 16.02 / 降级 14.89 / 闪电 9.43 / 升级 9.52**。
2. **败局签名**（同一批）：**建塔数在负局更多**（胜 24 / 负 26，Cliff's d = **−0.148**）、
   **降级+升级在负局更多**（d = **−0.302**）⇒ "多建塔"与"多 churn"都**与失败同向**。
3. **两端的消融都已证明**：**A1（建塔 0）= 0.5312**（太少）、**E-2（建塔 35.5）= 0.5156**（太多）
   ⇒ **建塔数量有内部最优点，而现状 24.8 未必在峰上**（对手 16）。
4. **闪电是承重的**：`L180`（金币 <180 不放闪电）= **0.2031（−45.3pp）** ⇒ **绝不能碰闪电**；
   而"省钱"若能把金币从**塔的 churn**转到**闪电**，方向就对了（这正是当年手写储备规则起作用的机理，
   只不过当年是在"没有 MC"的 A1 上）。

## 1. 干预与判据

| 项 | 内容 |
|---|---|
| 干预 | `AZAI_BUILD_MIN_COINS=τ`：AI 返回的 op 里，**若金币 < τ 且该 op 是建塔(11)，则剔除**（该回合等于 HOLD）|
| **臂（2026-10-07 冒烟后修正：见 §1.1）** | **τ=90（主臂）** 与 **τ=60（次臂，较弱）**，各 64 局；**先跑 90** |
| 对照 | `M6cROOT_128` 同前缀 `7..38` = **0.6562** |
| 样本 | 每臂 **64 局**（32 对），`jobs=8` |
| 机制读数（必报）| 我方 **建塔**（应明显下降）、**闪电**（**关键**：是否上升）、降级、出招回合、`dec_max` |

### 1.1 ⚠️ 臂的修正（**在看任何分数之前**，理由 = 冒烟实测阈值绑定情况）

- 原写 τ=45 / τ=60。**冒烟实测**：**τ=45 基本不绑**（一局只触发 **6** 次、建塔 24≈对照 22、闪电 9≈对照 10）
  ⇒ 那个臂**测不到假设的机制**（按本预注册 §2 P1，机制没激活就不该下结论）。
- **τ=90 绑得很准**（同一局）：**建塔 22→12、降级 12→3、闪电 10→12** ⇒ **正是"少 churn、把钱给闪电"**。
- ⇒ **主臂改为 τ=90**；τ=60 作为"较弱一档"（可选，用于检验符号是否稳健，见 P3）。
- 本修正发生在**任何棋力读数之前**（只看过机制计数），判据（§1 判定栏）**一字未改**。

**判定（诊断臂，方向；每条臂独立按此判）**：
- `p̂ ≥ 0.7362` ⇒ **"churn 是亏损、省下来的钱该给闪电"成立** ⇒ 下一步做**方法侧**版本
  （把"金币/塔数"进状态、用训练而不是阈值决定何时建塔）；
- `0.6062 < p̂ < 0.7362` ⇒ 方向不明，记档不结论；
- `p̂ ≤ 0.6062` ⇒ 建塔的钱**不能省**（可能塔本身是承重的）⇒ 该轴关闭。

⚠️ 64 局只分辨 >~12pp；单段不作结论；看数据前判据已写死；**即使大涨也不能当交付物**。

## 2. 预测

- **P1（机制，必然）**：建塔明显下降；**闪电是否上升是本臂的核心机制读数**
  （若不升 ⇒ 省下的钱没被用掉 ⇒ 大概率是净损失）。
- **P2（分数）**：我估 **偏负到持平**（理由：塔的伤害是"安静 rollout"里唯一能看见的东西，
  而 MC 的整个价值就在于"该不该花"；强行设门槛等于把 MC 的判断压掉一半）。
  但我给 **≥+8pp 留 ~25%**——因为"建塔数与失败同向"这条相关**还没在当前配置上被消融过**。
- **P3**：若 τ=45 与 τ=60 **同向** ⇒ 这条轴的符号是可信的；若**反向** ⇒ 记为"对阈值不稳健"，不作结论。
