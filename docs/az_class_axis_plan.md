# 计划：把「闪电以外的动作」做起来（类轴）

> 日期：2026-09-19。状态：**计划阶段，待过目。**（用户提出方向 + 我的评估与排序）
> 前置：`docs/az_posnet_random_class_plan.md`（随机钉类）、
> `docs/az_value_prior_plan.md`（位置线）、`docs/experiment_log.md` 的 `rv4_lightning_only`。

## 1. 前提（有实测支撑）

`rv4_lightning_only`：一方**只放闪电**（不建塔/不升级/不拆塔）、位置用 rule_v4 的启发式规则，
打完整 rule_v4 ⇒ **128 局只赢 22 局（17.2%，t=−10.97）**。
⇒ **"不放塔"这件事本身值 ~80pp**，所以闪电以外的动作（建塔/产兵/升级/拆塔）作用很大。
（相对地：位置网那条线做到现在值 +23.8pp。**类轴的潜在量级更大。**）

## 1.1 🔴 2026-09-19 实测补充：类轴是**动态经济**问题，不是"每回合排序"问题

三组实测（`experiment_log.md` 的 `cand_pick*` / `rv4_lightning_only`）把类轴的内容定出来了：

| 打法 | vs rule_v4 | 动作构成（建塔/降级/升级/闪电）|
|---|---|---|
| 只放闪电（不建塔）| **17.2%** | 0 / 0 / 0 / ~100% |
| 只按官方启发式建塔 | **0.0%** | 93 / 1 / 5 / **0** |
| 启发式 + "能放就放"（不攒钱）| （冒烟全负）| 94 / 0 / 6 / **0**（**买不起**：一直建塔 ⇒ 攒不到 90）|
| 启发式 + "冷却≤2 就攒钱" | **0.0%** | 85 / 2 / 2 / 11 |
| **rule_v4** | （参照）| **33 / 28 / 22 / 18** |

⇒ **① 建塔和闪电缺一不可**（只建塔 0%、只闪电 17.2%）。
⇒ **② 光"加闪电"不够**：`hl_save` 真的放出了闪电（11%），仍全败。
⇒ **③ rule_v4 的强度来自"活跃的经济循环"**：它**降级拆塔 28%**（换钱 → 放闪电 / 去别处重建）
   和**升级 22%**，而官方启发式几乎只会建塔（85%）。
⇒ **类轴要学的是这套动态经济（建塔/升级/拆塔换钱/按冷却打闪电），而不是每回合给动作类排序。**

**这也直接印证了本计划 §5(c) 的必要性**：降级/升级/建塔这些行为在我们的自对弈数据里
**出现率≈0**（类头塌缩成闪电），所以价值网判不了、类头学不到 —— 而随机钉类正是产生那些
数据的机制。**同时也说明 (b) 的目标里必须包含闪电**（不能"用别的动作替掉闪电"）。

## 2. 核心诊断：价值网对其他动作"是瞎的"

三个旁证拼起来：

1. **数据覆盖**：我们的自对弈里智能体几乎只放闪电（类头塌缩 ⇒ 三头 argmax 都是 17），
   所以价值网**几乎没见过"有塔的局面"** ⇒ 它无法判断"在这里建塔"值多少。
2. **旁证**：项目早先的 stats-probe 记过**价值头 87-92% 的方差来自 `stats`（棋盘只占 8-13%）**
   ⇒ 它对**棋盘上的动作后果**本就不敏感。
3. **这解释了"类轴搜索增益 = 0"**（`search_axis_ablation`：`class-only` 与 raw 逐回合**逐位相同**）：
   不是"类别无关紧要"，而是**价值网给不出其他类的有效排序**，于是类搜索在类轴上挑来挑去还是回到闪电。
   ⚠️ 另一条同样成立的解释：`t_class` 下采样从未真正探索其他类。**两者要先分开。**
   ⇒ 这正是要插"第 0 步"的原因。

## 3. ⚠️ 一个必须写清的陷阱（bootstrapping trap）

**在我们智能体的局面里，"建塔"确实是差的** —— 因为它从来没有塔、没有产兵、没有经济，
在那样的局面里建一座孤塔救不了它。⇒ **类头偏好闪电，是对"它自己那个分布"正确的判断。**
⇒ 于是：不建塔 ⇒ 局面永远没有塔 ⇒ 在那儿建塔确实差 ⇒ 类头继续偏好闪电。**自洽的坏不动点。**

**所以这条方向不可能靠"在当前分布上重训类头"打开**，必须同时做两件事：
① 用**分布外**的数据让价值网学会判断"有塔的局面"；
② 用**强制探索**让智能体真的走到那些局面里去。
这两条正好对应下面的 (a) 和 (c)。

## 4. 第 0 步（建议先做，很便宜）：量"瞎"到什么程度

> 🔵 **2026-09-19 已有读数**（`_tmp_rank_quality.py`，局面级无噪声判据）：
> 价值网选中的候选在官方启发式排序里处于 **56.4 百分位**（随机 = 49.6，Spearman ρ = 0.139）。
> ⇒ **"弱"而不是"瞎"**。所以 §4 的判读落在"部分成立"那一档：不是"全类≈随机 ⇒ 回去修价值网"，
> 也不是"其他类也不低 ⇒ 省下整条计划"，而是"有一点信号、远不够"⇒ 继续做 (a)。
> 判据 2 就是拿同一把尺子量 (a) 之后有没有显著上升。

**目的**：在花几天之前，先验证 §2 的前提。若价值网其实没那么瞎，整个计划的排序要改。

做法（几分钟）：拿 **rule_v4 对局中的局面**（它会产生大量建塔/升级/拆塔），对每个决策点：

- 取该局面下 rule_v4 实际选的类 `c*`（强启发式，可当弱参照）；
- 取**价值网**在同一批候选上的偏好（1-ply 价值 argmax 的类）；
- **按动作类分组**统计两者的一致率。

**判读**：
- 闪电上一致率高（比如 >50%）而 0-16 类上**≈随机（1/24）** ⇒ 前提成立 ⇒ 做 (a)。
- 全类都≈随机 ⇒ 价值网整体不行，问题比"覆盖"更根本 ⇒ 先回去修价值网。
- 其他类上也不低 ⇒ 前提不成立 ⇒ 省下整条计划。

## 5. 三步计划（用户提出，我按依赖排序）

### (a) 采含其他动作的对局 + 重训价值网  —— ✅ 已实现（2026-09-19）
- **落地方案（不是 rule_v4）**：`az_selfplay.py --inject-example-prob p` —— 以概率 p
  把**搜索选的动作**换成 **ExampleAI 的动作**。只改**实际执行**；记录进样本的
  `bundles`/`visit` 仍是搜索的 ⇒ **不污染策略目标**，纯粹是把对局推到"有塔的局面"。
  - 为什么不用 rule_v4 当数据源（用户 2026-09-19）：它建塔位置只有 4 个、
    且只会升级成 producer 一种高级塔 ⇒ 多样性太差。ExampleAI 的目录覆盖全部合法位置与塔型。
- **实测（`docs/experiment_log.md` 2026-09-19 那四条）**：
  - p=0.02 ⇒ 2536 回合 / 出招 10.3% ⇒ `BUILD 164 / LIGHTNING 137 / DOWNGRADE 49 / UPGRADE 6`；
  - p=0.05 ⇒ 2396 回合 / 出招 18.2% ⇒ `BUILD 384 / DOWNGRADE 161 / LIGHTNING 120`（2.3x 覆盖）；
  - `--pos-pin playable`（无注入，本以为是更干净的路）**不通**：BUILD 704 / DOWNGRADE 700 疯狂循环。
- ⚠️ 修正 §2 的一个归因：拆塔有**两个**来源 ——(a) 官方启发式 `bundles[1:8]` 自己会拆
  （跳过 index 0 的 hold；`_tmp_probe_example_pick.py` 实测其出招的 26%~39% 是降级）；
  (b) **我们自己的意图解码** `code/my_ai/decoder.py:358-372`（买不起闪电 ⇒ 自动降级）。
  我们智能体轨迹里的拆塔是 (b)。
- 这一步的目标**不是**提升棋力，而是**让价值网在有塔的局面里能排出序**（§6 判据 2）。
- ⚠️ 这是我们智能体的**分布外**数据 ⇒ 只有配合 (c) 的强制探索才能真正进入决策。
- ⚠️ **风险最高的一步**：项目历史上"重训价值头"是最反复的领域（kgeo / 池 / 迭代循环多为负面）。
  本计划的**新意**在于从"标签设计"换到"**数据覆盖**"，但成功与否未验证。

### (b) 重训动作类网络
- 目标 = 类搜索的类偏好（`class-only`）—— **前提是 (a) 让类搜索第一次有信号**。
- 可能需要同时提高 `t_class` 或加显式探索，否则采样仍在闪电附近打转（见 §2 的两条解释）。
- ⚠️ 类网是**每个头 24 类**；目标要对齐到现有 `head_class_probs` 的 z-score 口径
  （2026-09-17 那个 100× 教训：采样侧与损失侧的尺度必须逐字一致）。

### (c) 1-2% 随机钉类，给位置网的其他通道铺覆盖
- 已有方案：`docs/az_posnet_random_class_plan.md`（**按头独立、p=0.01**，要求该类
  `position_mask[c].any()` 且 `c != HOLD`）。
- **它在本计划里的作用变了**：原来只是"给位置网其他通道铺监督"，现在它同时是
  **打破 §3 陷阱的强制探索机制**（让对局真的走到有塔的局面）。
- ⚠️ 两条已知副作用：① 位置网 24 个通道**共享骨干** ⇒ 其他通道的梯度会流进闪电通道的特征；
  ② `anchor` 会反对新通道的学习（对从不使用的通道，记录值就是旧原值）。
  在本计划里这些风险**应该变小**：因为 (a) 之后那些通道的目标是**价值偏好**（有意义的信号），
  而不是随机的搜索噪声。**顺序不能颠倒。**

## 6. 预注册判据

1. **第 0 步**（§4）：按类分组的一致率。闪电 >50% 而其他类 ≈1/24 ⇒ 继续。
2. **(a) 之后**：价值网在"有塔局面"上的类排序质量（第 0 步同口径重测，应显著上升）；
   **而不是棋力**（此时棋力不该动）。
3. **(b)(c) 之后**：①**出招构成**的分布（各动作类的使用率，不再 100% 闪电）；
   ②`raw` 镜像（新 vs 旧，不搜索）；③**vs rule_v4，四批 seed 共 256 局**，
   对照旧基线 18.4% 与当前最好 `posnet_r1` 42.2%。
   ⚠️ 单批 64 局不可比（seed 集波动十几 pp，本会话反复踩到）。

## 7. 风险汇总

| 风险 | 说明 |
|---|---|
| (a) 无效果 | 项目历史上重训价值头多为负面；本计划赌的是"覆盖"而非"标签" |
| 分布外 | 用 rule_v4 的数据训出的价值网，在我们自己的局面里未必校准 |
| 反面代价 | (c) 的强制探索会让**采集到的局面偏离部署分布**；且 p=0.01 的合适值未标定 |
| 顺序 | 三步必须按 (a)→(b)/(c) 顺序，否则 (c) 会灌入噪声目标（见 §5(c) ⚠️） |
| 判据 | 棋力噪声大 ⇒ 必须用 256 局 + 出招构成这类**直接**读数辅助 |
