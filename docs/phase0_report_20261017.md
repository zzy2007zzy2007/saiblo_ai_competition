## 3. 四个问题的答案

- **Q1 胜率**：对官方 example（**无论它能不能放闪电**，它本来 0.0–0.2 次/局）我们 **0.0156（31/32 对 0-2）**；
  对 rule_v4 禁闪电副本我们 **1.0000**（因为**它退化成完全不出招**：0/0/0/0）。
- **Q2 噪声/成本**：32 对的 CI 半宽 ~11pp（无异于真实对局）；对局仍打满 512 回合；**单局 0.9–1.4 min（比真实对局 2.9 min 更便宜）**。
- **Q3 经济面有没有杠杆**：**有，但要先把它"解锁"**（见 §4）。
  主批里我方**只做 11.5 个经济动作/局、升级 0**；`MC_EVERY=1` 只把它抬到 16.4（仍升级 0）；
  **`MC_UPG=1`+`MC_TOPK=3` 才第一次让它变成"中等强度、不 churn"的经济打法**（20.2/8.7/**2.8**）。
- **Q4 关键证伪（用户的"抢金币"假设）**：**churn 与"升级 0"在禁闪电后依旧**（A1/A2/A3 的降级 = 0、升级 = 0；
  而"能花就花"的 `playable` 直接变 **100.5 建 / 98.5 降**的 churn 风暴）。
  ⇒ **去掉闪电/去掉金币竞争，并不会自动变出经济能力** ⇒ "抢金币"不是病根。

## 4. 🔑 意外有用的发现：**经济动作是被"闪电候选"在决策层挤掉的**

- 事实：`MC_UPG=1 + MC_TOPK=3`（放宽菜单）在**真实对局**里（第 3 轮）**完全没激活**（升级始终 0）；
  但在**闪电被禁**（=菜单里没有闪电）时，同一个开关**立刻让升级从 0 变成 2.8/局**，
  并把对 example 的胜率从 **0.0156 → 0.4375（+42pp）**。
- ⇒ **机理**：MC 菜单里的**闪电候选几乎总是赢**（它的安静 rollout 分数最高/最稳），
  于是经济与升级候选**永远轮不到**；**闪电一移开，它们才被公平比较**。
  这同时解释了第 3 轮"菜单加宽在真实对局里没激活"那三个阴性臂。
- ⇒ **可搬运的假设（已预注册并在跑）**：真实对局里让 **闪电不进 MC 菜单**（`AZAI_MC_NO_LIGHT=1`，
  闪电仍由非 MC 回合的默认"买得起就放"负责）+ `MC_UPG=1` + `MC_TOPK=3`
  ⇒ 经济/升级候选获得公平比较。预注册 `docs/prereg_20261018_mc_nolight_real.md`（判据尺度：两段各 128 局；
  机制闸门：**升级 > 0、闪电 ≥ 8.0/局、不 churn**）。

## 8. NL-R 搬运测试：**失败（固定段 `p̂ = 0.6094`，−12.5pp）** —— 机理不迁移

预注册 `docs/prereg_20261018_mc_nolight_real.md`；**判据尺度固定段 128 局**（无效 0、判词全 engine）：

| 建 / 降 / **升** / 闪（每局）| 24.8 / 10.9 / **0.0** / 10.5 | 35.3 / 25.2 / **1.2** / 9.9 |
| 相邻"建↔降"翻转 / 净塔 / 有操作回合 | 12.0 / 13.9 / 21.7 | **27.5 / 10.2 / 42.4** |

- 📌 **随机段未跑**（为把机时让给下面的 churn 消融）：本线已按**棋力**判死（固定段 CI 不含对照），
  而章程的"两段都报"针对的是**采纳类**结论；此处属于**被否候选**，如实记录该取舍。

### 8.1 按局归因（`code/test_match/churn_vs_win.py`，CPU 轻）

**但相关 ≠ 因果**（第 4/6 轮教训）⇒ 需要消融：`NL-R + NO_DOWNGRADE=1`
