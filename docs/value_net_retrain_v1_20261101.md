- `--label-scale` 的定标：让每个标签的 std ≈ terminal 的 0.531（例外：`rel+geo τ50` 用计划里写死的 4.0）。
  ⚠️ **val MSE 不能跨臂横比**（标签不同、量纲不同）；它只用来挑"这一臂自己的最好 epoch"。
- 训练耗时：每臂 3 epoch ≈ **1.7 min**（GPU），9 臂合计 ≈ 16 min。

### 1.1 `aux2` 臂的实现要点（用户 2026-11-01 定义）

- 结构：`state_emb(128) → value_head[0]:Linear(128,64) → ReLU → h(64)`，在 `h` 上分叉
  `V = value_head[2](h)` / `aux_self = Linear(64,1)(h)` / `aux_enemy = Linear(64,1)(h)`。
  **辅助头只在训练时存在，保存时丢弃** ⇒ 产出的三网 ckpt 与现役**同构**，可被探针/部署直接消费。
- 目标（与主标签**同核同 tau**，只是不取差）：
  `label = wf(HP_self − HP_enemy)`、`aux_self = wf(HP_self)`、`aux_enemy = wf(HP_enemy)`，`wf(·)=Σ k γ^k (·)_{t+k}/Σ k γ^k`。
  恒有 `label = 2.5·(aux_self − aux_enemy)`（`/20` 与 `/50` 的换算）。
- **血值取整数精确值**：`stats[24]=hp/50` 是 float16（~5e-3 量化），所以
  `HP_self = round(50·stats[24])`、`HP_enemy = HP_self − stats[1]`（`hp_delta` 精确）⇒ 主标签与
  `az_train.add_weighted_labels(abs+kgeo)` **逐位一致**（脚本自检：`max|diff| = 0.00e+00`）。
- 辅助头量纲取 **HP/50**（与 `stats[24]` 同尺度）：否则 HP∈[0,50] 的 MSE ~O(100)，λ=0.5 会直接压过主项。
- 实测：主头 val MSE 0.0375（常数基线 0.2116，r=+0.907）；`aux_self` MSE 0.0411（var 0.0684）、
  `aux_enemy` MSE 0.0344（var 0.0685）⇒ 两个辅助头都学到了东西（R²≈0.4–0.5）。

## 2. 筛子：P0-2 / P0-3（探针 = `probe_value_coin_curve.py`，样本 = 3 局真实日志的 103 个有塔局面）

| 臂 | **P0-2 折点%**（现役 3.0–4.3） | **P0-3 条件斜率比**（现役 0.99） | `∂V/∂coins\|cd=0` | `\|cd≥0.6` | 90 币左/右斜率比 |
|---|---|---|---|---|---|
| `incumbent`（= `valnet_A2`） | 4.3 | 0.99 | +0.0371 | +0.0375 | 0.98–1.04 |
| `terminal`（重训对照） | 3.2 | 0.98 | +0.0277 | +0.0283 | 0.99–1.02 |
| `kgeo50` ★ | 5.8 | 1.09 | +0.0323 | +0.0296 | 1.00–1.02 |
| `kgeo25` | 5.2 | **1.12** | +0.0281 | +0.0252 | 0.98–1.04 |
| `kgeo10` | 4.4 | 1.05 | +0.0205 | +0.0195 | 1.00–1.03 |
| `kgeo100` | 4.6 | 1.00 | +0.0375 | +0.0377 | 0.95–1.03 |
| `rel50`（rel+geo） | **23.0** | 0.47 | +0.0018 | +0.0039 | 0.85–1.10 |
| **`relk50`（rel+kgeo）** | **26.1** | **2.05** | −0.0060 | −0.0029 | 1.00–1.00 |
| `abs50`（abs+geo） | 5.6 | 1.17 | +0.0285 | +0.0243 | 1.00–1.03 |
| `aux2` | 3.9 | 0.93 | +0.0504 | +0.0543 | 0.98–1.01 |
| **判据** | **≥20%** | **≥2.0×** | — | — | 应显著偏离 1.0 |

### 2.1 读法

1. **只有 `relk50` 同时过两条**：折点 **26.1%**（≥20 ✓）+ 条件斜率比 **2.05×**（≥2 ✓）。
2. **`rel50` 折点也到了 23.0%**，但条件斜率比只有 **0.47×**（方向反）⇒ geo 权重把它带偏。
3. **`abs` 家族（kgeo10/25/50/100、abs50）几乎不动**（折点 4.4–5.8%、比值 1.00–1.17）：
   与"`abs` 标签 87% 方差可由 `stats[1]` 抄到"一致 —— 网络学的是"血差 → 金币"的旁路，
   没有学到"90 币的门槛价值"。**这也说明"只换逐帧标签"不足以撬动金币定价**。
   （唯一的小幅正向：`kgeo25` 的比值 1.12、`abs50` 1.17，都在噪声量级。）
4. **`aux2` 没帮上忙**（折点 3.9%、比值 0.93）：辅助头确实学会了预测双方未来血量（R²≈0.45），
   但**没有把这个信息转成金币的条件定价**（至少 3 epoch / λ=0.5 下没有）。金币的绝对斜率反而是最大的
   （+0.050 vs 现役 +0.037），只是不分冷却。
5. ⚠️ **`relk50` 的金币斜率是负的**（cd=0 时 −0.0060）：探针是在真实局面上**只改 `stats[22]`**，
   所以它测的是"网络学到的函数"，不是数据里的相关性。负斜率意味着"手里钱多 ⇒ 网络认为未来改善更少"，
   配合 `AZAI_REL2ABS` 部署后，绝对值的金币导数会被 `hp_delta/20` 主导、这一项只是小修正。
   **这是"过筛子但可能部署反而更爱花钱"的风险**，必须靠实战 A/B 判，不能只看筛子。

### 2.2 结论（筛子层）

- **进实战的臂**：**`relk50`**（唯一双过线）。
- 备选（若还想要一个"不改部署协议"的臂）：`kgeo25`（比值 1.12，`abs` 家族里最好，无需 `REL2ABS`）。
- `kgeo50` 虽是计划里的主力，但筛子上只到 5.8% / 1.09 —— 按用户口径**不算失败**，只是"方向没动够"，
  在"只筛 1 个进实战"的名额下让给 `relk50`。
