- `--label-scale` 的定标：让每个标签的 std ≈ terminal 的 0.531（例外：`rel+geo τ50` 用计划里写死的 4.0）。
  ⚠️ **val MSE 不能跨臂横比**（标签不同、量纲不同）；它只用来挑"这一臂自己的最好 epoch"。
- 训练耗时：每臂 3 epoch ≈ **1.7 min**（GPU），9 臂合计 ≈ 16 min。

### 1.1 `aux2` 臂的实现要点（用户 2026-11-01 定义）

- 结构：`state_emb(128) → value_head[0]:Linear(128,64) → ReLU → h(64)`，在 `h` 上分叉
  `V = value_head[2](h)` / `aux_self = Linear(64,1)(h)` / `aux_enemy = Linear(64,1)(h)`。
  **辅助头只在训练时存在，保存时丢弃** ⇒ 产出的三网 ckpt 与现役**同构**，可被探针/部署直接消费。
- 目标（与主标签**同核同 tau**，只是不取差）：
  `label = wf(HP_self − HP_enemy)`、`aux_self = wf(HP_self)`、`aux_enemy = wf(HP_enemy)`，`wf(·)=Σ k γ^k (·)_{t+k}/Σ k γ^k`。
  恒有 `label = 2.5·(aux_self − aux_enemy)`（`/20` 与 `/50` 的换算）。
- **血值取整数精确值**：`stats[24]=hp/50` 是 float16（~5e-3 量化），所以
  `HP_self = round(50·stats[24])`、`HP_enemy = HP_self − stats[1]`（`hp_delta` 精确）⇒ 主标签与
  `az_train.add_weighted_labels(abs+kgeo)` **逐位一致**（脚本自检：`max|diff| = 0.00e+00`）。
- 辅助头量纲取 **HP/50**（与 `stats[24]` 同尺度）：否则 HP∈[0,50] 的 MSE ~O(100)，λ=0.5 会直接压过主项。
- 实测：主头 val MSE 0.0375（常数基线 0.2116，r=+0.907）；`aux_self` MSE 0.0411（var 0.0684）、
  `aux_enemy` MSE 0.0344（var 0.0685）⇒ 两个辅助头都学到了东西（R²≈0.4–0.5）。

## 2. 筛子：P0-2 / P0-3（探针 = `probe_value_coin_curve.py`，样本 = 3 局真实日志的 103 个有塔局面）

> ⚠️ **2026-11-01 口径修正（用户定）**：P0-3 **不再用 `|∂V/∂coins|cd=0| / |cd≥0.6|`** —— 取绝对值会让

### 2.1 读法（新口径下的诚实结论）

1. **没有任何一臂同时过 P0-2（≥20%）与 P0-3（带符号）**。
   - **过 P0-3 的**：`kgeo50 / kgeo25 / kgeo10 / abs50` —— 但"方向差"只有 **+0.001 ~ +0.004**
     （相对量 3%–13%），且 **P0-2 折点仍在 4.4–5.8%** ⇒ 只能算"方向对了、量级可忽略"。
   - **过 P0-2 的**：`rel50`(23.0%) / `relk50`(26.1%) —— 但 P0-3 都不过：`rel50` 斜率量级仅 ~0.002
     且方向反；`relk50` 的 cd=0 斜率是**负的**（−0.0060），**符号 ✗、方向 ✗**
     ⇒ **"形状变了但方向反"，不算过线**。此前那句"relk50 双过线"是**旧绝对值口径的假通过，已作废**。
2. **`abs` 家族几乎不动**（折点 4.4–5.8%）：与"`abs` 标签 87% 方差能靠 `stats[1]` 抄到"一致 ——
   网络学的是"血差 → 金币"的旁路，没学到 90 币的门槛价值。**只把 terminal 换成逐帧 abs+kgeo 不足以撬动定价**。
3. **`aux2` 没帮上忙**（折点 3.9%、方向 ✗）：辅助头确实学会了分别预测双方未来血量
   （aux MSE 0.041/0.034 vs var 0.068，R²≈0.45），但没转成"金币×冷却"的条件定价；
   它的绝对金币斜率反而最大（+0.050 vs 现役 +0.037），只是不分层。
4. **结论**：9 臂 × 3 epoch × 112 局，**都没长出"90 币折点 + 冷却条件敏感"**。
   按用户口径这**不等于失败**（假说本身可能不成立），但说明**"改标签/加辅助损失"这条路在现数据量下推不动金币定价**：
   要么数据上一个量级，要么改机制（显式给"金币×冷却"特征 / 分段价值头 / 把攒钱当独立决策变量）。
