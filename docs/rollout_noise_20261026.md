# Rollout 噪声与先验容量：两组定量结论（2026-10-26）

> **结论一（噪声）**：随机化 rollout 在 **N=1** 时，分数噪声跨越 **7.7 个名次**；N=16 时降到 **1.9 名**；
> 按 √N 推算 N=64 约 **1.0 名**。⇒ **"降 k + 大采样"（k=48/N=64 = 64.1%）的收益机制是把噪声压到 1 名以内**，
> 而不是"候选更少所以更准"。
>
> **结论二（容量）**：位置网从 555k 加到 **2.6M（4.7 倍）**，留出 @24 峰值只从 85.1% → 85.3%（+0.2pp），
> 且最佳 epoch 提前（过拟合更快）⇒ **容量不是先验的瓶颈**。

---

## 一、Rollout 噪声诊断

**脚本**：`code/test_match/diag_rollout_noise.py`（需要 `AZAI_ROLLOUT_SAMPLES=1`，已在
`flat_rollout_greedy.py` 中加了 `last_samples` 记录开关）

**方法**：从 6 局亚军对局重放出 208 个（局面, 玩家）点，每点跑 `k=48, N=16` 的随机化 rollout
（decay C=.3/k=1、只对手随机、前缀树），记录**每候选 × 每分支**的分数矩阵，然后：

- 把候选按平均分降序排名，回归 `mean_score ~ rank` 得斜率 β（每个名次差多少分）；
- σ_within = 同一候选不同分支的 SD；
- 噪声跨越名次数 = (σ_within/√n) / |β|。

**结果**（208 个点，中位/均值）：

| 量 | 数值 |
|---|---|
| \|β\|（每名掉分）| **0.003**（值网 tanh 输出尺度）|
| R²（名次-分数线性度）| **0.916** |
| σ_within（同一动作不同分支 SD）| **0.020** |

| 采样次数 n | 噪声跨越名次（中位）| 均值 |
|---|---|---|
| **1** | **7.70** | 9.71 |
| 2 | 5.44 | 6.87 |
| 4 | 3.85 | 4.86 |
| 8 | 2.72 | 3.43 |
| **16** | **1.92** | 2.43 |
| 64（按 √N 推算）| **≈0.96** | ≈1.2 |

### 解读

1. **部署配置 `k=160, N=1`**：噪声跨 7.7 名 ⇒ 排在前 8 名的候选**统计上无法区分**，
   "取第一名"在这 8 个里等于随机 ⇒ **广度 160 里有大量是浪费**；
2. **`k=48, N=64`**（我们实测 64.1% 的那组）：噪声跨约 **1 名** ⇒ 名次首次变得可信；
3. **再加大 N 收益很小**（1.9 → 1.0 只提升不到 1 个名次）⇒ 想继续提升，**必须提高单次评估的质量**
   （更长的 rollout、更强的值网），而不是继续堆采样；
4. R²=0.916 说明分数沿名次近似线性下降，所以"每名 0.003"是**均匀的间隔**，不是"头部特别密"。

### 局限

- 只测了 6 局（208 点）、单一值网（posnet_A）、单一 horizon（16）；
- σ_within 混合了"对手随机"与"值网估值误差"两部分，未拆分；
- 尺度是值网输出（tanh 后），换算成血量需要值网标定（未做，但结论只用比值，不受影响）。

## 二、位置网容量对照（加宽/加深/正则）

**脚本**：`code/my_ai/train_prior_wide.py`（复用 z-score/Pearson 损失与 80 局数据管线）

| 组 | 配置 | 参数 | 峰值 @24 | 最佳 epoch |
|---|---|---|---|---|
| 基线 | width=64, blocks=6 | 555k | 85.1% | ep4 |
| **A** | width=128, blocks=6, wd=1e-4 | **2.02M** | **85.3%** | ep2 |
| **B** | width=128, blocks=8, wd=1e-4 | **2.61M** | **85.1%** | ep4 |
| C | width=64 + wd=1e-4 | 553k | 84.8% | ep2 |

（数据：80 局 / 32,000 局面 / 留出 4 局；训练脚本 `_train_wide_3arms.sh`）

### 解读

1. **容量从 555k 增到 2.6M（4.7×），峰值 +0.2pp** ⇒ 容量不是瓶颈；
2. **最佳 epoch 更早**（ep2 vs ep4）⇒ 加宽让过拟合更快，印证"参数/数据比已经过高"
   （555k/32k ≈ 17，加宽后 ≈ 80）；
3. weight decay（1e-4）也没有帮助（C 组 84.8%，略低）；
4. 结合早前的数据曲线（40 → 80 局峰值 84.8 → 85.1%，只 +0.3pp）
   ⇒ **瓶颈在标签的信息量**（单次、双方 idle、16 回合的 rollout 值），不在网络容量或数据量。

## 三、这两条结论合起来的意义

```
先验质量天花板 ≈ 85% @24（受标签限制）
  +  rollout 噪声：N=1 跨 7.7 名、N=64 跨 1 名
  ⇒ 整个系统的瓶颈是"单次评估分辨率"（σ_within=0.020 vs 名次间隔 0.003）
```

**可执行的三条**（按性价比）：

| 优先级 | 动作 | 依据 |
|---|---|---|
| P0 | 评估阶段至少用 **N≥32-64**（我们现在部署是 N=1） | 这是唯一能把噪声从 7.7 名压到 1 名的杠杆 |
| P1 | 提高单次评估质量（horizon 16 → 24/32、或换更强的值网） | 噪声 σ=0.020 是根本限制，采样开方衰减已到边际 |
| P2 | 先验不再投入（容量/数据都已验证无效） | 本文件第二节 |
