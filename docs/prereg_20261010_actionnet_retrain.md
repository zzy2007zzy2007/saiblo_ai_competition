## 1. 判据（先写死；**唯一改动 = 动作网参数**）

**冻结的对照（incumbent = `MC1`）**：`checkpoints/grafted_sdk_A.pt`（其 `value_state` 也冻结不变）+ 部署配置
`MODE=pos-only POSPIN=mc_quiet MC_EVERY=1 MC_ROOTONLY=1 MC_MARGIN=0 MC_UPG=1 MC_TOPK=3 ITERS=256 DEPTH=4 K=24 SAMPLE_MULT=15 TEMP=1e-6 TCLASS=0.5 TPOS=1.0 SKIP1=1 POSPRIOR=off VERIFY=1`
＋ 我方掩码层禁类 `AZAI_BAN_CLASSES=17`、执行层禁 `AZAI_BAN_OPS=21`、对手 launcher 同样禁闪电（`base_pkg` / `ex_pkg` / `rv4_pkg` 都是我们自己的复制件）。

**主判据**：候选 ckpt（只换 `class_state` 与/或 `pos_state`，其余逐位相同）对 **冻结基线**（`base_pkg`）在
**固定段 seed `7..70`（128 局 = 64 对）** 上：
- ✅ 达标 = 配对胜率 **`p̂ ≥ 0.78`**（= incumbent `0.6797` + **10pp**），且 **McNemar 配对 p < 0.05**、差值的 95% CI **不含 0**、无效+缺失 ≤10%、判词全来自引擎；
- **次级门槛（不许破）**：**冻结随机段（64 个 seed，128 局）** `p̂ ≥ 0.7512`（= incumbent `0.7812` − 3pp，即"在噪声内不倒退"），并报方向；
- 若主判据落在 **+5 ~ +10pp**：追加 **256 局（固定段两轮 seed 全量）** 复测后再定性（**不**用"看着更好"下结论）；
- 报告必须含：CI、执先/执后拆分、机制列（建/降/升/闪/有操作回合/回合数/min 每局）、以及**两侧配置指纹不同的核对**。
- 额外只作"背景尺度"（**不设门槛**）：vs 官方 example、vs `rule_v4` 各 128 局。

**为什么这样定**：① 与历史唯一被验证过两次的"actor 侧提升"（+14.1pp / +16.8pp）同形（**单变量、只动一个头**）；② 冻结基线尺度的 incumbent 只有 0.6797/0.7812 ⇒ **离天花板远、+10pp 有物理空间**；③ 若把门槛定在 example 尺度（我们已 ~0.80+）或要求两段都 +10pp（随机段已达 0.7812 ⇒ 需 0.88），**都不现实** —— 这一点必须先说清。

**噪声纪律（历史教训直接换算）**：本项目实测"同配置只换 seed"在 336 局上给出 50.0/25.0/29.7/28.1/26.6 的极端散布 ⇒ **非配对比较一律无效**；本项目另有 3 次"小样本乐观"事故（最典型 `Vk50`：16 局 0.6250 → 128 局 **0.4609**）。⇒ **本 goal 不做"筛查→晋级"，除冒烟外直接上 128 局配对**。

## 2. 路线（按"证据强度 × 成本"排序；每条都先冒烟）

### 路线 A（首选，= 用户新思路）：**用当前配置自己当教师，把高质量位置决策蒸馏进 `pos_state`**
1. **教学数据的来源**：在 incumbent 配置下自对弈采集（**只动 seed、不动配置**），逐决策落盘：
   - `AZAI_AZ_DUMP`：候选 (类,x,y) 标签、**访问分布/rollout 分数**、最终 `chosen`、`root_value`；
   - `AZAI_DUMP_RAW_DIR`：原始观测（便于事后重算位置头输出的 argmax，做一致性审计）。
2. **学生**：`pos_state` 单头（class/value 冻结），逐行**软 CE**到"教师选中的格子分布"（可先用搜索访问平均；若无访问则用 MC 的 rollout 分数）；
   - **按 pos-only 初衷**：只保留"**真有位置选择**"的决策点（候选 ≥2 且非 HOLD）——**约每局 11 点** ⇒ 要 ~3.3 万点需 **~3000 局**（用户已授权数小时级）；**类/HOLD 与价值头的样本不参与本路线**（不清洗训练集，只筛位置样本）。
3. **闸门**：① 冒烟（建塔 ≤0.5/局 ⇒ 退化跳过）；② **目标质量判据**（与教师的一致率 ↑、软 CE ↓，参数无关、便宜）；③ 只有②过了才跑 128 局主判据。
4. **预期副产物（效率）**：若学生真能模仿教师，则可在**等强度**下压 `K`/`ITERS`（历史 §6 判据 4）——这是"同样时间更高产出"的正面答案。

### 路线 B（最便宜，先跑）：**把已有的 SDK 蒸馏训到收敛**
- 事实：incumbent 的动作网来自一次**17.9 分钟 / 30 epoch** 的蒸馏，而日志显示 `cls 1.0039→0.6715`、`map 1.0137→0.1491` **到最后一轮仍在下降**（`training_history/distill_sdk_A.log` 末 8 行）⇒ **很可能欠训**。
- 做法：同数据（`distill_data/` 400 局/106,694 决策）、同损失、同 `--lambda-soft 0`，**只把 epoch 拉长**（先 90，必要时 200）；产物 `distill_sdk_A_e90.pt` → `graft_policy.py`（`--base checkpoints/posnet_A_k5_m32.pt` 保 value 不变）⇒ **与 incumbent 逐位单变量**。
- 成本：~36 s/epoch ⇒ 90 epoch ≈ 55 min；无新代码、无新数据。
- ⚠️ 口径：**只用最终 ckpt 作候选**（不"挑最好 epoch"，避免 winner's curse）；中间 epoch 只作监视。

### 路线 C（更强教师）：**把 MC/搜索的决策蒸进类网 + 位置网**
- 用路线 A 的同一批数据，同时对 `class_state` 做软目标（教师的类分布）+ `pos_state` 软目标。
- ⚠️ 与历史 `C156` 的关键区别：那次是 `pos_pin=argmax` 时代（类头**只在 argmax 路径**被读，故 0/32 对翻转）；**现在类头还被 `decode_head` 的合法性闸门与 MC 菜单的"可解码性"读**⇒ 值得在新配置下重测。
- **前置机制审计（便宜、必做）**：确认类头在现配置下到底影响什么（菜单可解码性 / 兜底 pin / 类内塔型），若审计显示影响为零 ⇒ **直接放弃 C 的类头部分**。

### 路线 D（历史 #3 的直接复刻）：**换更好的 critic ⇒ 重新打标 ⇒ 重训位置头**
- 仅在路线 A 的教师信号被证明"不够"时启用；注意本项目对价值网轴的**五次否证**（换 critic 只值固定段 +3.9pp、随机段 −7.8pp，不可靠）⇒ 预期最低。

**执行顺序**：B（分钟级热身）→ A 的**审计**（不训练）→ A（数小时采集 + 数分钟训练 + 128 局判据）→ C（含审计）→ D（备用）。

## 3. 数据与卫生（历史教训换来的硬规则）

1. **训练/采集只用专用 seed 段**（`≥10000`，且与判据段/随机段/未见段 `501..564` 不重叠）。历史违规先例：候选 R 用判据段 seed 7..14 ⇒ ckpt 作废、当日作废。
2. **判据段/随机段永不入训**；同一 seed 段不重复用于"采集 + 判据"。
3. 每个候选都记：训练命令、数据规模、**子网哈希**（class/pos/value 各自）、产物路径 + sha256、评估 run 名。
4. **只改一个头**的候选优先；任何"多头一起换"的候选必须额外给"逐头单变量"拆解（历史头消融已证明两头近似可加，52%/47%）。

## 4. 成本、机时与资源纪律

- 采集：路线 A 需 ~3000 局才到 3.3 万位置点 ⇒ **按用户授权，允许单批数小时**；并发遵守"总进程 ≤16 / 同时开局 ≤8"。
- 训练：位置头软 CE ~5 s/epoch（历史 `train_value_prior.py` 实测）；SDK 蒸馏 ~36 s/epoch。

- **总预算**：先按 **1–2 天机时**规划；**不做**架构级改动（那是上一个 goal 判 blocked 的结论，超出本目标范围）。

## 7. 修订（2026-10-10，路线 A 的教师信号：**审计先行，结论=不能用 dump 的 visit 分布**）

**已做（只读，不训练）**：写 `code/test_match/audit_pos_head_vs_teacher.py`，在**现成的 60 局 dump**
（`data/s2_policy/COLLECT_S2`，实跑配置 = `pos-only + MC_EVERY=5 + POSPIN=mc_quiet + ckpt=grafted_sdk_A.pt`）上做了两件事。

### 7.1 两处必须记下的口径教训（都已踩到并修正）
1. **dump 语义**（一手：`code/test_match/az_bridge_ai.py:183-213`）：`cands`=候选束（每束 ≤3 个 op）、
   **`visits`=与 cands 同序的访问分布**、`chosen`=**cands 的下标**、`labels`=每个 op 的 (类,x,y)、
   **`intent`=采样期 intent 计数（不是搜索的偏好）**。第一版审计误把 `intent` 当教师 ⇒ 自检
   "chosen 命中教师 argmax" 得 **0/2000** ⇒ 由此定位；改用 `visits` 后自检 **838/838 = 100%** ✓。
2. **obs 与 jsonl 的配对**：jsonl 前缀 `az_`、obs 前缀 `obs_` ⇒ 必须按 `seedNNNNN_pK` 后缀配对；
   被硬杀的局还会留**半条 JSONL**（`Extra data`）⇒ 逐行容错且**用 None 占位保持行对齐**。

### 7.2 审计读数（用对标签后）
| 指标 | 值 |
|---|---|
| 位置头 top-1 一致率（教师 argmax == 我方 argmax）| **49.5%** |
| 教师 argmax 在我方分布中的排名 | 中位 **2**（p25=1，p75=2，≤3 占 **100%**）|
| KL(教师‖我方) | 中位 **0.434** |
| **教师分布归一化熵** | 中位 **1.000**（**100% 的决策 >0.9**）|

⇒ 表面看"有明显距离"，**但距离是在一个几乎完全平坦的目标上**：教师把质量 50/50 摊在两个候选格上。

### 7.3 决定性的补测：**教师到底有没有信息**
对全部 29,303 个有 `visits` 标签的决策统计（不需要网络前向）：
- 真有位置选择（≥2 个落点）的只有 **838 个 = 2.9%**（与历史那个 2.7% 吻合）；
- 落点数分布：**2 个 696、3 个 142**；
- **"决定性"（top1 ≥ 2×top2）= 0.0%；"近平局"（top1 ≤ 1.2×top2）= 100.0%**。

**结论**：**这批 dump 的搜索 visit 分布在位置维上基本是硬币**（树太薄 ⇒ visit 计数 1:1）⇒
**拿它当教师只能教噪声** ⇒ 这正是历史把 `train_pos_distill` 关闭的原因（"两种都不算错的选点"）。
⇒ **原计划的"直接采几小时 dump 再蒸"取消**（省下这几小时）。

### 7.4 修订后的路线 A（= 用户 2026-10-10 的原思路）：**用"安静 rollout"当位置教师**
用户原话：先廉价定"哪个类/要不要 HOLD"，**再对位置候选做 rollout**，拿到高质量决策去训位置网。
⇒ 实现改成**确定性、有区分度的 rollout 打分**，而不是搜索的 visit 计数：
1. **教师信号**：对"钉类有 ≥2 个合法格"的决策，取**位置图得分最高的 2–3 个格**（或全部合法格，视预算），
   每格用 `mc_quiet.quiet_value`（**引擎安静 rollout**：打这一手后双方冻结推到终局，取终局 HP 差）打分 ⇒
   软目标 = 这些分数的 z-score 后 softmax（与 MC 对"类"的打分同一套口径）；
2. **成本**：每候选 ~0.3–0.5 s、每位置决策 2–3 候选、每局 ~50 个位置决策 ⇒ **~1 min/局**
   ⇒ 300 局在 8 线程下 **~40–50 min**（用户已授权数小时级）；
3. **先做 50 局试点 + 信号闸门（~10–20 min）**：量 rollout 分数**是否真有区分度**
   （top1 与 top2 的差 > 该口径的粒度/噪声；若也像 visit 一样全平 ⇒ **路线 A 当场判死**，不浪费机时）；
4. 试点过关才做完整采集 → 只训 `pos_state` → **目标质量闸门** → 128 局主判据（+ 效率读数）。
