# 预注册：**诊断臂「闪电储备门槛」**（`AZAI_LIGHT_MIN_COINS=180`）——"省着放闪电，把钱留给建塔"

> 2026-10-07 第 6 轮写（**在跑这批之前**）。章程：`docs/task_ruleV4_90_charter.md`。
> 性质：**手写干预的诊断臂**（章程②：只能当诊断、判法 = 消融）——**不是交付物**。

## 0. 由来（为什么回到"省钱纪律"这条族）

1. **历史事实**：项目史上**最大的一次配对准入增益**来自手写储备规则 —— `pos_pin=reserve, reserve_coins=180`
   （"金币 <180 不放闪电"）⇒ 验收 **+13.3pp**，且**建塔从 0 → ~10.7/局**。
   ⇒ 它的机理不是"放闪电的技巧"，而是**金币分配**：**省下的钱变成了塔**。
2. **现在的配置可能丢掉了这条纪律**：`mc_quiet` 的菜单里，**只要金币 ≥90（闪电成本）就把闪电放进去**，
   由安静 rollout 决定放不放 ⇒ 没有任何"储备"约束。
3. **但注意**：本族已经被 MC 吸收过一次（MC 主动选经济类），所以**收益可能已经被吃掉**——这正是本臂要回答的。
4. 相关读数：**我方闪电次数是胜负的最强相关量（+0.358）**（256 局败局签名），说明闪电的多寡确实是分水岭；
   但**相关性 ≠ 因果**（第 4 轮的教训）⇒ 必须做**消融**。

## 1. 干预与判据

| 项 | 内容 |
|---|---|
| 干预 | `AZAI_LIGHT_MIN_COINS=180`：AI 返回的 op 里，**若金币 < 180 且该 op 是闪电(21)，则剔除**（该回合等于 HOLD）。**不动搜索、不动候选、不动网络** |
| 对照 | `M6cROOT_128` 同前缀 `7..38` = **0.6562** |
| 样本 | **64 局**（32 对），`jobs=8` |
| 机制读数（必报）| 我方 **闪电次数**（应从 10.5 明显下降）、**建塔**（应上升）、降级、出招回合、`dec_max` |

**判定（诊断臂，方向）**：
- `p̂ ≥ 0.7362` ⇒ **"省钱纪律"仍有未被吃掉的余量** ⇒ 下一步做**方法侧**版本（让机制自己学"何时放闪电"，
  例如把"金币/闪电冷却"进状态、或用训练而**不是**这条手写阈值）；
- `0.6062 < p̂ < 0.7362` ⇒ 方向不明，记档不结论；
- `p̂ ≤ 0.6062` ⇒ **储备纪律已被 MC 吃掉**（甚至有害）⇒ 该族**关闭**。

⚠️ 64 局只分辨 >~12pp；单段不作结论；看数据前判据已写死；**即使大涨也不能当交付物**。

## 2. 预测

- **P1（机制，必然）**：闪电 10.5 → 明显下降；建塔上升（省下的钱被 MC 花掉）。
- **P2**：我估**偏向"≈0 或负"**——理由：① 本族已被 MC 吸收；② 闪电多寡与胜负的相关可能仍是"赢的局打得更久 ⇒ 放得更多"
  的同向伪相关（第 4 轮"降级"就是这样翻车的）；③ 若"能放就放"真是错的，MC 的 rollout 早该学会不放。
- **P3**：若**显著为正** ⇒ 说明 MC 的 save/spend 判断**系统性偏保守不足**，那是一个**可训练**的目标
  （比"选哪个类"有信号得多，因为金币是可直接观测的状态量）。
