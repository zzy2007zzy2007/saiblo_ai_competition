# 基于价值网络的代理评估（Surrogate Evaluation）

## 问题

当前 GA 管线每代消耗大量时间在完整对局评估上：
- 每局 512 回合，每代 2000 局，每局 ~1 秒
- 其中大部分回合的胜负区分度很低（双方焦灼）
- 评估耗时是训练速度的主要瓶颈

如果用价值网络替代完整对局，可以大幅加速。但核心难点在于：**价值网络需要学到一个"好局面"的标准，而这个标准本身又依赖于对局结果。**

## 核心思路：从中间局面开局，用价值差替代完整胜负

不从头到尾跑完整局，而是：

```
局面池 → 随机抽样 → 推进50回合 → V(s_after) - V(s_before) = fitness
```

### 相比"从头跑半局"的好处

如果每次都从回合 0 开始跑半局，只会暴露前 50 回合的局面，后面 400+ 回合的策略永远得不到评估。从局面池中均匀抽样可以覆盖所有游戏阶段——前期发育、中期攻防、后期决战都能训到。

## 整体流程

### 第一阶段：收集局面池

用当前 AI 自对弈收集 `(board, stats, 最终胜负)` 数据，和现有 BC 数据收集并行。

每局不存整局的 npz，而是存成一个局面序列：
- 每帧记录：`board(28,19,19)` + `stats(42,)` + `hp_us, hp_opp` + `turn`
- 每帧附带最终胜负标签（game_over 时的基地血量差）
- 局面池大小控制在 ~10 万帧，轮流淘汰旧帧

### 第二阶段：训练价值网络 V(s)

价值网络结构：
- 共享现有 backbone（Conv7×7 + ResBlock×6 + GAP）
- backbone 输出 → 一个线性头 → 标量 V(s) ∈ [0, 1]（胜率）

训练目标：在当前局面下，预期最终胜率

损失函数：MSE(V(s), final_outcome)

训练数据来源于局面池中的帧 + 最终胜负标签。

**注意**：初始价值网络不需要很准——只需要能区分"明显优势"和"明显劣势"即可。随着 GA 推进，价值网络持续更新。

### 第三阶段：代理评估（核心循环）

每代中，对每个待评估的个体：

1. **从局面池抽样** k 个起始局面（k = games/2 左右，如 12 个）
2. **从第 t 回合开始**，用该个体的策略推进 x 回合（x = 50 左右）
3. **计算 fitness**：
   ```
   fitness = mean(V(s_after) - V(s_before))  # 平均价值变化
   ```
4. 若一个个体的平均 fitness 在 top-K 中，用其 50 回合内的行为数据做 BC

**关键**：推进 x 回合时需要固定对手（或使用简单对手策略），否则价值变化无法归因于被评估个体。推荐用 "当前 mean 策略" 作为固定对手。

### 第四阶段：价值网络持续校准

随着 GA 推进，策略变强，旧局面的价值标签（最终胜负）需要更新：

- 每 N 代，用当前 mean 策略跑若干完整对局（作为校准集）
- 用新对局的胜负重新标注旧局面池中的帧
- 或者定期用新策略重跑部分局面池中的局面（重新推进到结束）

## 关键挑战

### 1. 价值网络偏差放大

如果价值网络 V(s) 本身不准，用它选出来的 top-K 可能不是真正强的个体。这有两个对策：

a) **初始价值网络就足够靠谱**：用大量 BC 数据训练（几十万帧），至少达到"能区分优势劣势"的水平
b) **混合评估**：每代随机抽 10-20% 的个体跑完整局，用真实胜率校准价值网络的预测偏差

### 2. 从中间局面开局的对手行为

从随机中间局面开局，对手也需要一个策略。两种方案：
- **固定为当前 mean 策略**：fitness 反映的是"在 mean 对手面前的价值变化"，归因干净
- **固定为随机/ExampleAI 策略**：fitness 反映 vs 固定对手的表现，但局面是从当前 AI 对局中收集的，分布可能不匹配

推荐先用当前 mean 策略作为对手，因为局面池也是从 mean 策略的自对弈中收集的，分布一致。

### 3. 局面池分布偏移

GA 训练过程中策略变化，早期收集的局面可能和当前策略能遇到的局面分布不同。对策：
- 滚动更新局面池：每代新对局数据加入，淘汰最旧的数据
- 局面池容量不宜太小（~10 万帧），保证多样性

### 4. x=50 步是否足够

需要实验确定。可能的选择：
- 50 步（~10% 的完整局） → 10x 加速，但可能区分度不够
- 100 步（~20%） → 5x 加速，信号更可靠
- 自适应：如果 V(s_after) - V(s_before) 绝对值很小（无法判断），则继续推进

## 和现有管线的集成

```
当前管线（每代循环）：
  变异 → 完整512局评估 → 选top-K → BC训练 → 下一轮

目标管线（每代循环）：
  变异 → 代理评估（50局/50步） → 选top-K → BC训练 → 下一轮
                                                      ↓
                                              每N代校准：少量完整局 → 更新局面池 → 更新V(s)
```

### 不修改的部分
- bc_train：不变
- SSDataset：不变（但数据来源变为 50 步内的帧，不是完整局）
- Leaderboard：不变
- decoder/agent/network：不变

### 新增/修改的部分

| 文件 | 改动 |
|------|------|
| `value_net.py` | 新增。价值网络定义（共享 backbone + value head） |
| `value_train.py` | 新增。从局面池训练/更新价值网络 |
| `position_pool.py` | 新增。局面池管理（存储、抽样、淘汰） |

## 代价与收益估算

### 当前成本
- 完整评估：2000 局 × 512 回合 = 1,024,000 回合/代
- 耗时：40 分钟/代（~425 回合/秒）

### 代理评估成本
- 局面池抽样评估：2000 局 × 50 回合 = 100,000 回合/代
- 耗时：40 × (100,000/1,024,000) ≈ **4 分钟/代**
- 价值网络前向：2000 × 50 × 2 ≈ 200,000 次推理
  - 单次推理 ~2ms（CPU）→ 400 秒 ≈ 7 分钟
  - GPU 推理 ~0.2ms → 40 秒
- **总耗时：~10 分钟以内**（GPU 推理），相比 40 分钟 **4x 加速**

### 可靠性
代理评估可靠性取决于价值网络的准确率。如果价值网络的排序准确率（top-K 选择 vs 完整局）达到 80%+，则 4x 加速是净收益。即使只有 60%，配合混合评估（偶尔跑完整局校准）也足够加速。

## 与其他方法的关系

- **和 MCTS 价值网络的关系**：共用一个价值网络结构（backbone + value head），但用途不同。MCTS 的价值网络用来指导搜索树剪枝；这里的价值网络用来替代完整对局评估。两个价值网络可以用同一套数据训练。
- **和 PPO critic 的关系**：功能类似（都是 V(s)），但用途不同。PPO 的 critic 用来降低策略梯度方差；这里的价值网络用来缩短评估时间。如果用 PPO 做训练，这个价值网络可以直接复用为 PPO 的 critic。
