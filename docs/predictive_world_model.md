# 预测式 World Model 预训练方案

## 动机

当前评分蒸馏（ActionCatalog score regression）的问题：
- 评分函数只用了压力、距离、优先级等部分特征
- 信息素追踪、武器效果范围、蚂蚁行为模式等通道被忽略
- 预训练 backbone 无法利用完整 28 通道信息

评分蒸馏背后的本质矛盾：**用人工定义的启发式规则来教模型看棋盘**——规则只关注了设计师认为重要的特征。

## 核心思想

不学评分，学**预测**：

```
encoder(局面_t) → latent
→ decoder(latent + 双方动作) → 预测 局面_{t+1}
```

模型必须理解"建塔后地图变化"、"蚂蚁移动后压力分布变化"等动态，才能准确预测下一帧。这种理解天然需要提取所有 28 个通道的特征——不是设计师认为重要的，而是**预测未来需要的**。

这与 predictive coding / world model 的思路一致，类似于在 NLP 中 predict next token。

## 与现有方法的对比

| 方法 | 监督信号 | 利用的通道 | backbone 学到 |
|---|---|---|---|
| 硬标签 BC | 哪个动作对（1 bit） | 极少 | 几乎不 |
| 蒸馏 soft logits | 模型输出分布（24 维） | 少量 | 够区分动作类 |
| ActionCatalog 评分 | 启发式打分（24 维 + 位置分） | 部分（压力/距离/成本） | 有限特征 |
| **预测下一帧（本方案）** | **未来局面（28 通道 + 42 维 stats）** | **全部** | **完整棋盘感知** |

## 三阶段流程

```
Phase 1: 预测预训练（本方案）
  收集 棋盘_t + 双方动作_t + 棋盘_{t+1} 数据
  → 训练 encoder + decoder 预测下一帧
  → 产出 frozen_backbone.pt

Phase 2: 评分适配（可选）
  在 frozen backbone 上加小头适配 ActionCatalog 评分
  或直接从预测 latent 接策略头输出

Phase 3: GA 进化
  加载 frozen backbone（冻结前几层或全冻结）
  仅训练策略头 + 微调 backbone 后几层
```

## 实现要点

### 数据收集

score_distill 已有的数据（棋盘序列）可以直接用，额外保存的只是每步的双方动作。

每帧数据：
```
board_t:     (28, 19, 19)      — 当前局面
stats_t:     (42,)             — 当前统计数据
action_us:   (动作编码)        — 己方采取的动作
action_opp:  (动作编码)        — 对方采取的动作
board_{t+1}: (28, 19, 19)     — 下一帧局面
stats_{t+1}: (42,)            — 下一帧统计数据
```

### 训练目标

不精确重建整张棋盘（太难），改预测关键变量的变化：

```
可预测的目标：
  - stats 的变化（金币 +/-, HP 变化, 出兵周期变化等）→ MSE
  - 塔的变化（增/减/升级）→ 每个位置 4 类 logits  
  - 蚂蚁密度变化（粗略分布）→ 下采样密度图 CE
  - 超武 CD 变化 → BCE
  - 信息素变化 → MSE

不可预测的目标（跳过）：
  - 蚂蚁精确位置（逐像素太细，且对手行动有随机性）
  - 兵力具体数字
```

### 网络结构

```
board_t → frozen_encoder → latent(128,) → decoder → 预测变化量
stats_t ──────────┘              ↑
action_us ───────────────────────┘
action_opp ──────────────────────┘
```

decoder 可以很轻量（2-3 层 MLP 即可）。

### 冻结方案

预训练后，encoder 提取的 latent 已经包含了完整的棋盘动态信息。可以：

1. **完全冻结 encoder** — 只在 GA 中训练策略头，encoder 永不更新
2. **冻结前几层** — conv1 + resblock 0-3 冻结，后两层可微调
3. **不冻结** — encoder 在 GA 中持续进化（但有了预测预训练的基础）

推荐方案 2：大部分冻结，后两层在 GA 中自适应。

## 和 ActionCatalog 评分方案的关系

两个方案可以共存，不是替代：

```
路径 A: 预测预训练 → frozen backbone → 策略头 → GA 进化
路径 B: 评分蒸馏 → GA 进化（当前方案）
路径 C: 预测预训练 → 策略头 → GA 进化 + 评分辅助 loss（最佳？）
```

路径 C 用预测预训练提供完整的棋盘感知能力，用评分辅助 loss 提供动作优先级指导，两者互补。

## 待解决的问题

1. 双人博弈的预测不确定性——对方动作本身是模型输出，训练数据中只能记录实际发生的动作
2. 预测范围——单帧 vs N 帧滚动预测
3. 损失函数的权重配比
4. frozen encoder 在 GA 中是否足够稳定（不冻结不训练也不行，wild mutation 会破坏它）

## 参考

- Dreamer (DeepMind): 学习 latent dynamics model，在 latent 空间做规划
- SimPLe (OpenAI): 学 world model，在模拟中训练策略
- 本质上就是 "predict representation"——用未来监督当前特征的提取
