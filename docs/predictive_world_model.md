# 预测式 World Model 预训练方案

## 动机

当前评分蒸馏（ActionCatalog score regression）的问题：
- 评分函数只用了压力、距离、优先级等部分特征
- 信息素追踪、武器效果范围、蚂蚁行为模式等通道被忽略
- 预训练 backbone 无法利用完整 28 通道信息

评分蒸馏背后的本质矛盾：**用人工定义的启发式规则来教模型看棋盘**——规则只关注了设计师认为重要的特征。

## 核心思想

不学评分，学**预测（跳过 N 帧）**：

```
encoder(棋盘_t) → latent → decoder(latent) → 预测 棋盘_{t+N}
```

**不需要动作编码**。不编码对手动作意味着预测必然不准——但这不是 bug，是 feature。模型被迫学会编码不随对手随机性变化的结构性特征：地形、塔的布局、资源趋势、压力分布等。那些随机波动的部分（精确蚂蚁位置）模型会自动学会忽略。

这本质上是一种**自监督预训练**——不需要任何标签，只需要帧序列。

## 为什么跳过 N 帧

直接预测 t+1 帧的问题：相邻帧几乎一样，复制输入就能拿到极低 loss，模型不学任何动态。

跳过 N 帧（N=5~10）后复制不再有效——塔位置变了、蚂蚁位置移动了、资源变化了。模型必须理解动态才能预测。

## 与现有方法的对比

| 方法 | 监督信号 | 利用的通道 | backbone 学到 |
|---|---|---|---|
| 硬标签 BC | 哪个动作对（1 bit） | 极少 | 几乎不 |
| 蒸馏 soft logits | 模型输出分布（24 维） | 少量 | 够区分动作类 |
| ActionCatalog 评分 | 启发式打分（24 维 + 位置分） | 部分（压力/距离/成本） | 有限特征 |
| **预测 N 帧后（本方案）** | **未来棋盘（28 通道）** | **全部（无动作编码）** | **完整棋盘感知** |

## 三阶段流程

```
Phase 1: 预测预训练（本方案）
  现有帧序列 → 采样 (t, t+N) 对
  → 训练 encoder + decoder 预测 N 帧后
  → 产出 frozen_backbone.pt

Phase 2: 策略适配
  在 frozen backbone 上接策略头
  用 BC / 评分蒸馏训策略头（backbone 冻住或浅层微调）

Phase 3: GA 进化
  加载 frozen backbone（冻结前几层）
  仅训练策略头 + 微调 backbone 后几层
```

## 实现细节

### 数据

直接从现有数据拿帧序列，不需要额外收集。`score_data/chunk_*.npz` 已经是帧序列，每 chunk 包含连续帧。

采样方法：从 chunk 中随机取一个起点 t，取 t 和 t+N 两帧构成一个训练样本对。

### 网络结构

```
board_t → encoder(现有 backbone) → latent(128,) → MLP decoder → 预测变化:
  - 塔布局变化：每个位置分类（无/新建/升级/降级/摧毁）
  - 资源变化：△金币, △HP（MSE）
  - 压力变化：△敌人密度（下采样 MSE）
```

decoder 可以很轻量（2-3 层 MLP）。

### 冻结方案

预训练后，encoder 提取的 latent 已包含棋盘结构信息。GA 中可以：

1. **完全冻结**——encoder 永不更新，只训策略头
2. **冻结前几层**——conv1 + resblock 0-3 冻结，后两层微调
3. **不冻结**——在 GA 中持续进化（但有退化风险）

推荐方案 2。

## 和 ActionCatalog 评分方案的关系

两个方案互补：

```
预测预训练 → 提供完整棋盘感知能力（全局特征）
评分蒸馏   → 提供动作优先级指导（策略信号）

两者结合 → 最佳效果
```

## 优势

1. **不需要动作编码**——数据收集零成本
2. **自监督**——不需要任何标签
3. **全部通道被利用**——模型必须提取所有特征才能预测未来
4. **天然兼容现有数据**——现有帧序列直接可用
5. **预测不准是预期行为**——模型学会关注结构，忽略噪声
