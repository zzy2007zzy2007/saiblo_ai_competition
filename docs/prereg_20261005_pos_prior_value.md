# 预注册：**候选 P —— 根节点"位置先验"改用我们自己的价值网（1-ply）**

> 2026-10-05 10:3x 写（**在跑这批数据之前**）。动机链：
> * A1（`pos-only` + `k24/sm15/skip1`）的强度来自"**用价值网给候选位置排序**"；
> * 而候选位置的**采样分布**来自**位置网**的 `action_map`（`t_pos=1.0`）；位置网当初是**被训练去模仿
>   "价值网 1-ply 先验"**的（`docs/az_value_prior_plan.md`）⇒ **模仿是损失过的**；
> * 代码里本来就有"**直接用价值网当根节点位置先验**"的实现：`eval.py:_make_value_pos_prior`
>   （`mode=value`），以及它的**对照** `mode=uniform`（同一条枚举/可执行过滤，**权重全 0**）。
>
> ⚠️ **性质**：这是"**把我们自己的价值网用得更直接**"（不是模仿对手、不是人工先验）。
> 但它**打开了新的计算路径** ⇒ 属**配置/协议变更**，必须记档；默认 `AZAI_POSPRIOR=off`
> 保证已钉死的 A0/A1 读数**逐字节可复现**（本轮新加的开关，见 commit `ac2f569`）。

## 1. 臂（都只改一个环境变量；ckpt 一律 `posnet_A_k5_m32.pt`）

| | 配置 | 说明 |
|---|---|---|
| **对照 P0 = A1** | `k24/sm15/pos-only/skip1`，`AZAI_POSPRIOR=off` | 读数直接取 `C1_a1_hist32`（seed `7..22`，**`p̂ = 0.5000`**）|
| **臂 P1** | 同左 + `AZAI_POSPRIOR=value` | 根节点 action_map = **价值网 1-ply z-score**（在"钉住的类的合法格"上）|
| **臂 P2** | 同左 + `AZAI_POSPRIOR=uniform` | **机制对照**：同枚举、同可执行过滤，但权重全 0 ⇒ 分离"价值信息"与"过滤掉不可执行格"|

## 2. 样本量与判据（**先写死**）

- **快读数** = seed `7..22`（16 对 = **32 局**），`--jobs=8`，预期 ~8–12 min/臂（A1 速度）；
- **验收** = seed `7..70`（128 局）；**只在快读数达标时跑**；
- 主读数 = `analyze_paired.py` 的配对分；
- **晋级**：`p̂ ≥ 0.55`（对照 `0.5000` + 5pp）或 `p̂ ≥ 0.70`；
- 有效性门槛同前；**没有**延长规则；**禁止**看数据后改样本量。

## 3. 预注册的预测

- **P-P1（机制，可复核）**：`value` 臂的**闪电落点分布**应当与 A1 不同
  —— 用 `code/test_match/diag_lightning_aim.py` 量"到敌方基地距离"的分布；
  若分布**几乎不动**，说明该先验没有真正进入候选菜单（那数值读数也不可解释）。
- **P-P2（数值）**：`value` 臂的 `p̂ ∈ [0.45, 0.65]`。理由：位置网的模仿若有损，补上真先验应当**有增益但不巨大**
  （候选菜单只影响"采样到哪些格"，最终仍由 MCTS 的价值排序决定）。
- **P-P3（对照的解释力）**：若 `uniform` 与 `value` 都明显 ≠ 0.5 且**彼此接近**，
  说明起作用的是"**过滤掉不可执行格**"，不是价值信息本身 —— 那也是有用的机制结论。

## 4. 判定与后续

- 任一臂 `p̂ ≥ 0.55` ⇒ 跑 128 局验收；≥0.70 ⇒ 走机械门（独立验证 + 记档 + 用户确认）。
- 都不达标 ⇒ 记"**把价值网直接当位置先验，在本判据下测不到增益**"，转"**换数据/重训**"路线
  （V2：新策略采的数据；以及位置头在新数据上的重训 —— 见 `docs/loop_iteration_recipe_20261005.md`）。
- 无论结果，都要报 §3 的机制读数（落点分布），否则读数不可解释。

## 5. 成本

每臂 ~8–12 min（根节点先验只在根算一次，额外成本 ≈ 每回合 1 次批量价值前向）。
