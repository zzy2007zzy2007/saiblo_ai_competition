# 预注册：**方法侧 M6 —— 用「真跑到底的蒙特卡洛」做类决策**（换掉看不到动作的叶评价）

> 2026-10-06 03:2x 写（**在跑这批数据之前**）。**性质：方法层**（换**评价/决策程序**），无手写规则。
> 依据（全部为本项目已证的读数）：
> * **搜索的类决策受制于叶评价**：价值网**看不到动作**（类级 adv ~80% 并列）；
> * **M5**（3 候选菜单，叶评价 = terminal 价值网）⇒ 建塔 **68/局**、分数 **0.5000**（n=8 局）；
> * 换**视野**（`rel`/`kgeo`）能改行为（建塔 68→38.8）但 **128 局验收 −7.0pp** ⇒ 学出来的叶评价这条路走不通；
> * **手写**储备规则（诊断）值 **+13…20pp** ⇒ "该不该花"确实有空间，但按章程第②条不能当交付物。
>
> ⇒ **本实验直接绕过叶评价**：对每个候选类，**克隆局面 → 打这一手 → 双方贪心打到终局**，
> 用**终局 HP 差**选类。比较完全由**模拟结果**决定，**不依赖价值网、也不含任何手写规则**。

## 1. 臂（写死）

| 臂 | 类决策 | 说明 |
|---|---|---|
| **对照 A1** | `pos_pin=argmax`（全 24 类 argmax ⇒ 闪电，否则 HOLD）| 验收 `0.5312` |
| **M6（`pos_pin=mc_light`）** | **只在闪电可执行的回合**做 MC 比较：候选 = {闪电, HOLD, 最优经济类}，每个候选"先打下去再贪心打到底"，取**终局 HP 差**最大者；其余回合 = A1 | 见 `code/my_ai/az_intent/mc_class.py` |

- ⚠️ **成本**：每回合 MC 比较要 3 次"打到底"（每次 ~400 回合的贪心 rollout）。**先跑 1 局测用时**；
  > 6 min/局 ⇒ 只跑 **8 局**（seed 7..10）并在记档标注。

## 2. 判据（**按本轮新增纪律：直接 128 局**）

- **主判据 = 128 局验收（seed `7..70`）**，对照 **A1 的 0.5312**；
  ⚠️ 本轮刚定稿的纪律：**16/32 局快读数对 ±10pp 无判别力**（VK50b 事故）⇒ **不再用快读数做依据**；
- 若成本闸门触发（>6 min/局）⇒ 先跑 **64 局（seed `7..38`）**并记档说明（**明确标注样本不同**）；
- **机制判据（必报）**：我方**建塔数**与**闪电数**（对照：A1 = 0 / 11.28；M5+terminal 头 = 68 / 12.2）、
  以及 MC 比较的**分数差**（闪电 vs HOLD vs 经济）——若三者分数差几乎为 0 ⇒ 模拟本身分辨不出候选（也是结论）。
- **晋级**：`p̂ ≥ 0.70` ⇒ 机械门（独立验证 + 记档 + 用户确认）；`0.55 ≤ p̂ < 0.70` ⇒ 记为**方法侧进展**并换操作配置；
  `< 0.55` ⇒ 记"真模拟也救不了"。

## 3. 预注册的预测

- **P-M6a（机制）**：建塔数应**显著 > 0**（因为经济类进了候选且由模拟裁决）且**闪电仍 ≥ 10**；
- **P-M6b（数值）**：`p̂ ∈ [0.45, 0.70]`。**我基于已有证据偏谨慎**：贪心 rollout 的策略比部署策略弱，
  可能把类排序带偏；但它是**第一次**用"真实结果"而不是"学出来的评价"来做这个决策。
- **P-M6c**：若 MC 的候选分数差普遍 < 0.01（HP_SCALE 归一后）⇒ 说明**贪心 rollout 分辨不出候选**，
  那么 M6 失败的原因就不是"评价看不到动作"，而是"**贪心模拟的噪声太大**"——这本身是有价值的区分。

## 4. 判定与后续

1. `≥0.70` ⇒ 机械门；`≥0.55` ⇒ 方法侧进展，把 M6 当新操作配置，并继续把 MC 用到更多决策点（更多候选/更早的回合）；
2. `<0.55` 且 **P-M6c 成立** ⇒ 转"更低方差的评价"（例如：同局面多分支配对、固定深度 rollout 平均值）；
3. `<0.55` 且 P-M6c 不成立（分数差明显但选错）⇒ 说明**模拟的贪心策略与部署策略不匹配**（off-policy 评价问题）。

## 5. 成本

实现 ≈ 1 h（已完成）；**128 局验收 ≈ 1.5–3 h**（取决于 MC 的开销；先测 1 局）。
