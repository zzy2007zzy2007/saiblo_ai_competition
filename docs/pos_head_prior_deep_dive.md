### 1.2 损失（训练）
`code/my_ai/az_intent/train_value_prior.py` —— **逐行位置 CE**（不是回归）：
```
目标  p = softmax( z(adv)        / target_tau )
预测  q = softmax( z(action_map[cls]) / t_pos )
L = -Σ p·log q        # 两侧 z-score 都在"合法格"上用同一套尺度
```
```bash
python -u code/my_ai/az_intent/train_value_prior.py \
  --ckpt <三网 ckpt> --data <npz> --epochs 60 --batch-size 256 --lr 1e-3 \
  --target-tau 1.0 --t-pos 1.0 --out training_history/vprior/posnet_r1.pt
```
- **只训 `pos_model`**：`class_model`/`value_model` 都 `requires_grad=False` + `.eval()`，loss 只前向 pos_model，保存时**原样写回** ⇒ **天然单变量**；
- 60 epoch / bs 256 = **325 s（≈5 s/epoch）**；
- ⚠️ **`--target-tau`（旧名 `--tau`）近似是重参数化、不是锐度旋钮**；**部署侧唯一锐度旋钮是 `t_pos`**（作者预测"τ 是空操作"后来**被自己的实测推翻**：τ=0.25 的图本征更尖，地图 std 1.454 vs 0.532、有效候选 176.3 vs 44.3）⇒ **实用结论：别单独调 τ**；
- 这个 τ 与价值标签的时间衰减 τ（`az_train.add_weighted_labels`）**无关**；
- ⚠️ 可选 `--anchor-lambda`（对初始 `pos_state` 的参数空间 L2）。

## 3. 为什么它能涨分 / 为什么一轮就到顶（作者原话）

**能涨分**：位置网原来学的是**搜索的 visit 分布**，而 visit 在可负担设置下**不是局面的函数**——同一局面换 rng 重抽，目标余弦只有 **0.350**、bundle 相同 42.5%；一致率 0–42% ⇒ **目标本身是噪声**。
换成 `adv`（**冻结价值网**在钉类全部合法格上的 1-ply 优势）后，目标是**确定性的、可复现的、便宜的（一次前向）** ⇒ 网络**真的能拟合它**（learned ≈ oracle）⇒ +14.1pp。
旁证：搜索的强度**恰恰来自价值网的排序**——同一候选集、同一出招率（2.8%），按 visit 选 **90.6%**，随机选 **0/32**、按先验选 **0/32** ⇒ "别蒸馏搜索的噪声输出，直接蒸馏让它变强的那个原因"。

**到顶**（作者原文）："这套配方**一次就把增益吃完了**…目标 = **价值网的偏好**，而**价值网全程冻结不变** ⇒ 先验只能逼近它，逼近之后**循环没有新的信息源**。⇒ **下一个天花板是价值网本身**（或'让目标比 1-ply 更深'）。"
且"learned ≈ oracle"是 **±5pp 尺度**上的结论（各 128 局、SE≈4pp）⇒ 准确说法是"再挖不超过 ~5pp"。

## 5. 对我们现在（禁闪电子博弈、打冻结基线）的参考价值

### 5.1 直接可用的结论
1. **"重训那一头"这条方法论**在历史上**只对位置头成立**（类头 11 次全废，因为它不在部署路径上）⇒ **如果还要动动作网，动位置头，别动类头**；
2. **目标必须是确定性的、可复现的、便宜的**——历史先例：visit 目标（一致率 0–42%）失败、1-ply 价值目标成功；
3. **"更好的 critic ⇒ 重新打标 ⇒ 重训头"被独立验证过两次**（critic 自己 +14.1pp p=0.0003；重训头 +16.8pp p=0.00024）⇒ **这是我在本 goal 里没走完的一步**（我只把 critic 换进搜索叶，没有用它重新打标重训位置头）；
4. **作者自己留下的、从未实施的那一步**：把目标从 **1-ply 价值**换成**更深的搜索量**（根节点子值/Q 值/访问平均）——因为实测 **搜索 ≫ 一次选点**（0.3359 vs 0.1719/0.1953/0.1797）。**我们现在每次决策都有 MC/搜索的仲裁 ⇒ 那个"更深的目标"就在手上。**

### 5.2 必须一并说的限制（别抱太高期望）
1. **现在的位置先验很可能已经不是瓶颈**：10-07 三臂在**当前 MC 仲裁体系**下只有 **3.1pp 极差、53–56% 逐对翻转**；
2. **regime 不可传递**：同一单变量在另一台子上是 **−6.25pp（n.s.）**；
3. **1-ply 价值目标已到顶**，而我们现在的价值网（搜索值网 / 我做的那几次）**本身的棋力可信度已被否证**（换 critic 只有固定段 +3.9pp、随机段 −7.8pp）⇒ **"重新打标"的信源质量存疑**；
4. **分辨力**：256 局 ±6pp ⇒ **≤+3pp 的效应在本协议下不可验证** ⇒ 不要用 32 对/16 局去宣称任何进展（本项目已有 3 次"快读数乐观"事故）；
5. **本 subgame 的约束在"类"**（固定段长局失分、覆盖率杠杆 +18pp 打的就是类），所以**位置头的收益可能根本传不到判据上**。

### 5.3 我建议的实验（预注册草案，成本 ~2–4 h，全程可否定）
**第 1 步：审计（~1 h，不训练）——先问"有没有头寸"**
- 用**已有 dump**（本 goal 的观测 + 逐决策候选/访问/被选动作）量三件事：
  (a) 我们位置头的选格与 **MC/搜索的选择**的一致率；
  (b) 位置头选格在 **quiet rollout / 搜索值** 口径下的**后悔值**（regret）；
  (c) 作者那个"目标质量"指标（峰价值分位）的现状。
- **闸门（先写死）**：若一致率已 ≥ **85–90%**、或 regret 落在噪声内 ⇒ **直接停**，不训练（结论：位置头已无头寸）。

**第 2 步（仅当第 1 步过关）：采集"更深的目标"（~15–30 min）**
- 在**当前最好配置**（`pos-only + MC_EVERY=1` + 搜索值网叶评估）下采 200–400 局，逐决策记录**教师标签**：
  **MC 的仲裁选点 + 各候选的 rollout 分数**（或搜索的访问平均分布）——即作者点名"证据最强"的那个目标；
- 训练专用 seed 段；**判据/随机/未见段一律不入训**（历史教训：候选 R 用判据 seed ⇒ ckpt 作废）。

**第 3 步：只重训 `pos_state`（~5 min）**
- 照 `train_value_prior.py` 的形（逐行软 CE、两侧同尺度 z-score、class/value 冻结）；**先预注册目标质量判据**（与教师一致率↑、CE↓），再谈棋力。

**第 4 步：两段判据 + 效率读数**
- 判据：部署配置 vs 冻结基线、固定段 + 随机段各 128 局；**任何 ≤3pp 都写"不可分辨"**；
- **效率**：用新头把 `K`/`ITERS` 往下压，看**等强度下能否更便宜**（这是我认为更可能赚到的地方，也是当初"削上限"那条路缺的东西）。

**先写死的预测（事后对照）**：① 目标质量指标会改善（按构造，可能性高）；② **固定段强度收益 0 ~ +3pp，约一半概率 ≤0**；③ **效率收益的把握大于强度收益**；④ 若第 1 步闸门不过或第 4 步两段均 ≤0 ⇒ **"重训动作网"这条路在本管线上也判到底**，进一步支持"瓶颈在'类从哪来'（架构）"的结论。

## 6. 不确定 / 矛盾（含本次新发现）

1. ✅ **新发现：`_tmp_vprior_verify.sh` 今天跑不通**——它仍用 `--tau 1.0`，而 `train_value_prior.py` 自 `c547bac` 起只认 `--target-tau` ⇒ 复现 B 臂前必须先修。
2. ✅ **新发现：三臂的采集 ckpt 与第一轮不同**（`inject_ex02/valnet_A2.pt` vs `three_mix_r10p_vw_pol_frozen.pt`；两者 `value_state` 哈希不同、策略侧逐位相同）⇒ **B 的 49.2% 不能直接与历史 r1 的 42.2% 比**；作者用 R2 做了同起点对照是对的，但**文档从未点明采集 ckpt 不同**。
3. **R2 的 ckpt 文件名从未落盘**（run 的 `cmd.txt` 只有变量 `O=$OLD; N=$NEW`）⇒ "B 与 R2 只差 `pos_state`"有一个**小未验证前提**（推测 = r1 的 class/pos + valnet_A2 的 value）。
4. "复现 oracle **86%**"是 **14.1/16.4 的比值**，不是独立测量；作者自限 ±5pp。
5. "**提升幅度随 seed 集单调上升（+12.5→+40.6pp）而基线本身在下降**"⇒ 效应**依赖 seed 集**（但每批同向、后两批高度显著）。
6. 三臂的判据 1/2 **按构造读不到那 19 个新通道**（判据 1 只改闪电落点；判据 2 类钉在类网 argmax，诊断行显示 453 回合类一次未变）⇒ 只能算**共享骨干的间接效应**。
7. 作者**自己撤回**过一条机制解释（"学出来比 oracle 更平 ⇒ 更好"，被"若平更好则均匀最好"的反例推翻；真因是**内容对齐**：峰价值分位 8.8% vs 30.3%）。
8. **验证集按行切**（npz 无 game id）⇒ val CE 偏乐观；"加数据"的降级结论部分依赖它。
9. `--skip-single-candidate` 让对局不可复现 ⇒ 所有"逐位相同"论断只在同一 flag 下成立。
10. 第二阶段"**用 visit/更深目标蒸馏**"计划**从未实施**有文档明文，但**为什么没做没有明文**（推测：第一阶段判据方向相反、注意力被类轴/价值阶梯吸走、K48 廉价替身被判量级不足）。
11. 顺带记一条与本主题无关但影响复现的：本主题所有 `pos_state` 哈希已由 subagent 核对（`class_state` 全部 `5b13580b5c05`；`value_state` 旧 `b288f15cc4ed` / 新 `a6ac11c24cd7`）。
