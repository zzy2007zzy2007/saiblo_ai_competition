## 4. 为什么"类头"重训反复失败：结构性根因（一手证据）

```
pos_pin = argmax  ⇒  bundle_mcts.py:304-311 取的是【未掩码】的全 24 类 argmax
                     ⇒ 实测（cmp_class_head_argmax.py）：新旧类头在 9,663 / 9,663 个 (决策, head) 上恒为类 17（LIGHTNING）
                     ⇒ 买不起闪电时整回合退化成 HOLD（"出招仅 11.2/403 回合、建塔恒 0"）
⇒ 只要这条路径不变，任何"在被评估的 5 个合法类之间重排序"的训练都不可能改变行为
   （C2 的日志与对照 sha256 完全相同；M1 建塔 0/闪电 11.2 与 A1 逐字一致；C156 0/32 对翻转）
```
另外三层独立的失败原因（都在 §2.4 有读数）：
1. **识别性**：花钱只出现在富状态 ⇒ Q 头把"状态好"记到类头上（M2/M3/M3b）；
2. **信用分配**：一局一个标量、权重与动作无关（≈1/1000），随机钉的类与状态无关 ⇒ AWR 只能学到"买得起就闪电否则 HOLD"；
3. **教师退化**：在 pos-only+钉类模式下，"按类边缘化的搜索访问分布"**就是那个 pin 本身**（类访问蒸馏 P1 不过）。

## 5. 可复用的配方与教训（历史给出的）

1. ✅ **唯一的大收益来自"外部强教师 + 每决策 (类,位置) 硬标签"的监督蒸馏**；自产信号（我们自己的搜索/我们自己的 MC 判断/结果加权/Q 头）**从未**产出被采纳的动作网提升。
2. ✅ **位置头：换更好的监督目标 >>> 训得更久/更多数据**（r1 +14.1pp；r2 与 r1 逐点相同；CE 早已收敛）。
3. ✅ **先量 oracle 上限再决定训练**（21.1% vs oracle 37.5% ⇒ 才敢投 141 分钟采集 + 训练）。
4. ⚠️ **"训练指标 ≠ 部署行为"**（本线最贵的教训，重复 ≥3 次）：logit std 0.023→**0.285** 而 **0/32 对翻转**；val MSE −3.8% 而棋力 **−1.6pp**。
5. ⚠️ **小样本读数没有判别力，且"多臂里挑最好"会造成系统性乐观**：`VK50` 16 局 **0.6250 可复现**，128 局 **0.4609（−7.0pp）**。
6. ⚠️ **改动必须落在"部署路径真的会读的地方"**：C2 改了 42/94 张量、49.75% 的类内 argmax 变了，而部署**逐字节没变**。
7. ⚠️ **自指/无用的标签**：`head_logits` 其实是 `class_` 的 one-hot（文档写成"旧模型输出"⇒ 理由错、结论不受影响）；`class_scores` 代码会采、数据集会加载，但**损失从不使用**、磁盘 npz 里也没有这个键。
8. ⚠️ **数据卫生**：候选 R 用了判据段 seed 7..14（作者自曝、ckpt 作废）——**训练只用专用 seed 段**这条规矩是被这次违规换来的。
9. ⚠️ **自举迭代会退化**：位置轴 r2 无增益；价值环（09-14 `value_loop`）"堆量反而削弱价值头"；我这次 goal 的价值网第二轮 **−5.1pp**。

## 6. 与"方法提升"的关系（回答上一个问题）

- 历史告诉我们：**这个项目里动作网"方法类"改动（BC/AWR/Q头/自蒸馏/PPO/GA/ES）的全部战绩 = 0 次被采纳的提升**；唯一两次真涨分，一次是**外部教师蒸馏**（我们不可能再找到更强的外部教师：SDK 派生的教师对 example 只有 0.5547），一次是**位置头的目标替换**（已经把 oracle 收益吃到 86%，且第二阶段"visit 目标"从未实施）。
- 而**真正解锁"类"这一维的，不是重训类头，而是改部署机制**：把 `pos_pin=argmax` 换成 **MC 仲裁 + 覆盖率拉满**（我这次 goal 的 `MC_EVERY=1`，+18pp 固定 / +28pp 随机）。
  ⇒ 这也解释了历史：类头在 10-05→10-07 被重训 11 次全废，因为**它根本不在部署路径上**；一旦让它（及其候选集）真的参与决策，收益立刻出现。
- 所以"再上台阶"的两条真路，与历史一致：**(a) 换外部的、更强的监督源**（现在没有）；**(b) 改架构/机制**（让类不再由 argmax 决定 + 学出来的"停止/成本"概念，即路 C 的方向）——后者正是我在本 goal 里试过但被机制闸门（刷屏/僵持）与刷屏重训证伪挡住的那条。
