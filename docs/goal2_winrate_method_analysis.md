# 胜率提升的方法分析（goal-2600a56a：双方禁闪电子博弈、对手 = 冻结基线）

> 真实日期 **2026-10-09**。本文回答一个问题：**在这个 goal 里，究竟是"什么方法"把对冻结基线的配对胜率提上去了？**
> 所有数字都来自本 goal 的实测（`docs/goal_register.md` / `docs/experiment_log.md`），并经**两轮无上下文独立验证**复核。
> 口径：双方禁闪电（`AZAI_BAN_CLASSES=17` + `AZAI_BAN_OPS=21`）；对手 = **冻结基线**（`checkpoints/grafted_sdk_A.pt`，sha256 `8c21f44d…36ba` + `MODE=pos-only POSPIN=mc_quiet MC_EVERY=5 MC_ROOTONLY=1 MC_MARGIN=0 MC_UPG=1 MC_TOPK=3 ITERS=256 DEPTH=4 K=24 SAMPLE_MULT=15 TEMP=1e-6 TCLASS=0.5 TPOS=1.0 SKIP1=1 POSPRIOR=off VERIFY=1`）；
> 判分只看引擎判词、按"边"计胜负（`winner_side`），**"基线自比"的定义值是 0.50**（镜像对决）。

---

## 0. 一句话结论

**真正把胜率提上去的只有一件事：把 MC 仲裁的覆盖率从 20% 提到 100%（`AZAI_MC_EVERY` 5 → 1，其余配置一律不动）。**
它把"类的决定"从**策略网的一次 argmax**换成**用引擎 rollout 比出来的选择**，实测 **固定段 0.50 → 0.6797（+18pp）、随机段 0.50 → 0.7812（+28pp）**。
另外还有一个 +3.9pp 的小效应（换掉价值网 `value_state`），但**它经不起"两段 + 分侧"检验，我在结论里不把它算作提升**（详见 §3）。

## 2. 方法 A：把 MC 仲裁覆盖率 20% → 100%（唯一强效应）

### 2.1 改动本身（真的只有一行）

```diff
- AZAI_MC_EVERY=5      # 冻结基线
+ AZAI_MC_EVERY=1      # 我们的候选
# 其余全部保持不变：MODE=pos-only POSPIN=mc_quiet MC_ROOTONLY=1 MC_MARGIN=0 MC_UPG=1 MC_TOPK=3
# ITERS=256 DEPTH=4 K=24 SAMPLE_MULT=15 TEMP=1e-6 TCLASS=0.5 TPOS=1.0 SKIP1=1 POSPRIOR=off VERIFY=1
# ckpt 也不变（仍是 checkpoints/grafted_sdk_A.pt）
```

也就是说：**这张"提升"完全不来自新权重、新数据或更大算力，而来自"决策权交给谁"**。这也是它可信的原因——A/B 两侧共享同一个 ckpt、同一套超参，唯一差异就是那一个环境变量。

### 2.2 为什么有效：从"决策结构"出发的机制链

本管线每一步要决定 **(出哪个类, 落在哪个格)**。类的来源只有两个：

- **(a) 策略网的 argmax**：一次前向的类选择，**不做任何比较**；
- **(b) MC 仲裁**：把"候选类 × 位置"当菜单（HOLD + 闪电 + 类头 top-k 经济类 + 显式升级），**每个候选做一次"安静 rollout"**（从该手之后的局面出发、**谁都不出招**、推到终局或到 `MC_HORIZON`），比终局 HP 差，分高者被钉住。

而**闸门就是 `MC_EVERY`**（代码：`bundle_mcts.py` 的 `if self.mc_every > 0 and (_rnd % int(self.mc_every) == 0) and (not self.mc_root_only or _is_root)`）：

- 冻结基线 `MC_EVERY=5` ⇒ **只有 1/5 的回合**走 (b)，**其余 4/5 走 (a)**；
- 我们的候选 `MC_EVERY=1` ⇒ **全部回合**走 (b)。

**所以这一行改动的语义是：把那 80% 的"一次前向 argmax"，换成"用真实 rollout 比出来的类"。**

### 2.3 证据（我据以判断"这里有大收益"的五条实测）

| # | 观测 | 数值 | 说明 |
|---|---|---|---|
| 1 | **候选数分布**（抽样 880 个真实决策）| `{1: 802, 2: 2, 4: 8, 8: 2, 12: 4, 14: 2, 22: 6, 24: 54}` ⇒ **单候选占 91.6%** | 配合 `SKIP1=1`（根节点 ≤1 个 bundle 就短路，`bundle_mcts.py` 的 `if self.skip_single_candidate and len(root.bundles) <= 1`）⇒ 绝大多数回合**既不搜索也不比较**，类就是 argmax |
| 2 | **按"决策序号 mod 5"分组的候选数** | mod=0 ⇒ **30.1% 多候选**；mod=1..4 ⇒ 8.0 / 1.1 / 3.4 / 1.7% | 多候选**恰好集中在 MC 回合** ⇒ 闸门确实决定了"哪些回合有真正的选择" |
| 3 | **两段判据读数** | 固定 **0.6797**、随机 **0.7812**（vs 基线自比 0.50）| 提升同时出现在两个独立 seed 段上 |
| 4 | **机制列**（我方/局）| `MC1` 建塔 29.0 / 降级 19.9 / 升级 7.8 / **有操作回合 46.2**；与"做得更多"无关 | 行动量几乎不变（46.2 回合）⇒ 是**选得更好**，不是"更忙" |
| 5 | **对 example 的筛查** | 冻结基线 0.8125 ▸ `MC1` **0.9375**（32 对）| 换一个对手也同向 |

⇒ 机制结论：**"类"这一维的决策质量是本管线的瓶颈，而基线配置在 80% 的决策上根本没在做决策。** 把覆盖率拉满，等于把那条最弱的一环补上。

### 2.4 成本

- 覆盖率拉满后，MC 仲裁（每个候选一次安静 rollout）在**每一次决策**都要付出：判据臂实测 **~2.0–4.9 min/局**（8 线程下，随价值网/开关不同），而"单候选短路 + 无 MC"的极简配置只要 **~0.6 min/局** ⇒ **量级上贵 5–8 倍**；
- 附带一个反直觉的实测：**削短 rollout 上限并不能省时间**（上限 256→64 时，耗时 2.03→2.11 min/局，几乎不变）——因为**中局**的安静 rollout 本来就很早到终局（开局 245 回合是均衡局面的最坏情形）⇒ **安静 rollout 不是成本瓶颈**，`MC_EVERY` 那个"每 N 回合才仲裁一次"的注释里写的成本担忧（"每回合 ×3 heads ×512 回合 rollout ⇒ ~20 min/局"）是**最坏情形**的估算。

### 2.5 边界：为什么这个杠杆到 100% 就用尽

覆盖率是 [0,1] 的比例，**没有"超过 100%"**。拉满之后，同一维度的剩余空间只剩两块，而这两块我都测过并且**都不行**：
- **菜单质量**（手搭的 5 类候选）：加宽（`MC_TOPK 3→5`）筛查 +1.6pp、**判据 +0.0pp**；加"类×格"（`MC_CELLS=8`）**有害**（0.6250 + churn 风暴）；
- **裁判质量**（安静 rollout）：换学习价值网当裁判**五次否证**（见 §4）。

## 3. 方法 B：换掉 `value_state`（固定段 +3.9pp）——**但我不把它算作提升**

### 3.1 做法（如果只看固定段，它确实涨了）

1. 双方禁闪电、用**训练专用 seed 段**（≥10000）自对弈 **60 局**，每决策记录观测 + **搜索回传的根节点价值 `root_value`**；
2. **以"搜索自己的判断"当目标**（而不是终局胜负）：实测它更稠密、更平滑、校准更好（目标 std 0.246、1322 个不同取值、开局 ≈ −0.085 中性；而用终局胜负当目标的网**开局就给 +0.44**，过度自信）；
3. 训练**同架构** `AntWarNetwork`（94 张量、`create_model(**model_kwargs_from_ckpt(base))`），损失 `MSE(tanh(v), target)`（与部署口径 `value = tanh(裸输出)` 一致），**按局切分**（按帧切分曾给出 0.0338，比按局的 0.3453 好 10 倍 ⇒ 明显泄漏）；
4. 训完**只替换 `value_state`**，产出 `checkpoints/grafted_sdk_A_vsearch.pt`（独立验证确认：`class_state` 94/94、`pos_state` 94/94 **逐位相同**，`value_state` 94/94 全不同）。

它在**固定段**给出 **0.6797 → 0.7188（+3.9pp）**，机制上说得通：`value_state` **每次决策都进搜索的叶评估**（`make_three_net_fn(class, pos, value)`；同局面换网：叶值 −0.168 → +0.439），而离线对"搜索自己的值"的 MAE 从 **0.2368（旧网）** 降到 **0.0718（新网，3.3 倍）**。

### 3.2 为什么我最终不认它：两段反向 + 固定段的增益本身是"分侧混合"

| 段 | `MC1`（旧网）| `MC1` + 新价值网 | 差 | 分侧拆解 |
|---|---|---|---|---|
| 固定段 7..70 | 0.6797 | **0.7188** | **+3.9pp** | 执先 **0.719 → 0.672（−4.7pp）**、执后 **0.641 → 0.766（+12.5pp）** |
| **冻结随机段** | **0.7812** | 0.7031 | **−7.8pp** | 执先 0.828 → 0.734、执后 0.734 → 0.672（**两侧都更差**）|

⇒ **同一改动在两段上方向相反，而且固定段那点"收益"本身就是两个方向相反的侧向变化拼出来的** ⇒ 这是**噪声/段依赖**，不是可复制的提升。（这与项目前史里"svs 60.9% 却拆出执后手 +28pp / 执先手 −3pp"完全同型，见 `docs/goal2_value_label_prior_art.md`。）

### 3.3 机制解释：**"预测搜索" ≠ "给候选打分"**

同一张网在三条通道上的表现**互相矛盾**（这本身是一条有价值的机制发现）：

| 通道 | 表现 |
|---|---|
| 预测"搜索自己的值"（离线 MAE）| **最好**（0.0718，是旧网的 1/3.3）|
| **搜索叶评估**（部署时主要通道）| 固定段 +3.9pp，**随机段 −7.8pp**（不可靠）|
| **当 MC 裁判**（`MC_SCORE=value_only`）| **最差**：搜索值网 0.2031 < 旧网 0.3438 < 终局网 0.4531 ≪ **安静 rollout 0.9375** |

直觉解释：**"贴合搜索自身的（含偏置的）估计"与"判断'下这一手会怎样'（因果效应）是两件事**——一张网越贴合搜索，就越继承搜索的偏置，当裁判反而更差。

### 3.4 顺带被否掉的"价值迭代"

- 用第一轮的网**再采一轮**搜索值、再训（第二轮）：离线按局 `val_mae` 从 0.0718 **劣化**到 0.0973（同目标对照：0.0923 vs 0.0718）⇒ 预注册的**发散护栏触发、中止**；
- 随后做的"规则外诊断"判据臂证实护栏是对的：第二轮网 **0.6797**（比第一轮 −5.1pp，等于陈旧旧网的水平）⇒ **价值网"一次性有用、不可迭代"**；
- 项目前史（2026-09-09）也早已记录过同一现象："**链式自对弈会被退化价值头污染**" ⇒ 我这是复现，不算新发现。

## 5. 我是怎么确认"提升是真的"（方法论，比结论更重要）

### 5.1 五级证据阶梯（每条候选都要过）

1. **冒烟/机制闸门**（2 局）：我方建塔 ≤0.5/局 判退化 ⇒ 直接跳过，不浪费机时（本 goal 它**两次**拦下了空跑产物）；
2. **筛查**：32 对（vs example 或 vs 基线）；
3. **判据**：64 对、**两段都要**、报 CI 与**执先/执后拆分**、无效+缺失 ≤10%、判词必须全 engine；
4. **未见 seed 确认**（章程要求）：501..564（当前最好结论在此 0.7109 vs 固定段 0.7188 ⇒ 复现）；
5. **机械门 + 无上下文独立验证**：门要核对"两侧配置指纹确实不同"；验证者**自写解析器**、不调用我的脚本（本 goal 两轮：13/13 逐位吻合；第二轮 1–8、10 逐位复现 + 约 220 个 tag 反作弊全扫）。

### 5.2 三个"假提升"实例（都是本 goal 亲自踩到的）

| 陷阱 | 实例 |
|---|---|
| **筛查高估** | `MC_TOPK=5` 筛查 0.9531 ⇒ 判据 **0.6797（+0.0pp）**；`MC1` 筛查 0.9375 ⇒ 判据 0.6797 ⇒ **筛查比判据高约 26pp**，绝不能拿筛查当真 |
| **分侧/分段混合** | 换价值网：固定段 +3.9pp、随机段 **−7.8pp**；且固定段内部"执先 −4.7 / 执后 +12.5" ⇒ 若只跑固定段就会采纳一个假结论 |
| **噪声主导** | 前史 `kgeo_gap` 32 局 46.9% 而**姊妹臂只有 12.5%**；64 局 svs 60.9% 却拆出"执后手 +28pp / 执先手 −3pp" |

### 5.3 反作弊（本 goal 全程守）

不模仿 rule_v4/冠军/亚军；手写启发式只作**诊断臂**；**判据/随机/未见段的 seed 一律不入训**（训练只用 ≥10000 专用段）；镜像复制/重复 token/判词矛盾做了全表扫描（无）。

## 7. 如果还想再往上走：已知的结构性障碍

- **判据的约束在固定段**（最好 0.7188，差 8.1pp），而随机段已被 `MC1` 推到 **0.7812**（差 1.9pp）；
- **固定段的失分集中在长局**：短局 0.790 / **长局 0.576**（胜局均值 238 回合、负局 253 回合）；而且**不是"钱没花出去"**（长局败局终局金币 96 vs 胜局 107，几乎相同）；
- **真瓶颈是"类从哪来"**：91.6% 的决策只有 1 个候选、80% 不进搜索；要突破必须换这一步（真正的 RL/新决策架构：学出来的**停止/成本**模型 + 每次决策都搜索），或做更大规模自对弈/更大的网 —— 量级**数天–数周**，且要先解决"训练信号能否被吸收"。
