# 价值头空间池化实验（2026-09-11）

## 动机

`network.py` 的价值头输入是：
```python
board_emb = spatial_feat.mean(dim=[2, 3])        # 全局平均池化 → 64 维
state_emb = cat([board_emb, stats_emb])          # 128 维
value = value_head(state_emb)
```
**位置信息被全局平均严重压缩**。实测：同一局面在不同位置建同样的塔，价值输出差异
只有 max 0.062 / std 0.024（价值量级 ±0.25）——**不是完全失明，但区分度偏小**。
而这个游戏塔的位置是核心（策略头有空间 action_map、搜索在位置上比较）。

对照：§21 记录的"rel 价值对大部分建塔位置输出相同值（-0.0303 平齐）"正是这类症状。

## 假设

**价值头的天花板部分来自"输入表达太粗"**。给它更细的空间信息应该能提升。

## 实验设计

只改 `value_head` 的**输入构造**（策略路径完全不动），骨干冻结 + no_bn + 新数据 336 局
（与擂主 A 完全同配方），标签 terminal。

| arm | 池化方式 | 价值头输入维度 | 说明 |
|-----|---------|--------------|------|
| A（擂主）| GAP | 128 | 现状，31.2% |
| **M** | **两区域**（沿 x 轴切两半）| 192 | 语义直接（基地在 x=2/x=16）|
| **N** | **粗网格 4×4** | 1088 | 保留"塔在哪个象限"|
| **O** | **注意力池化** | 192 | 1×1 卷积打分 → softmax 加权求和（网络自学该看哪）|
| **P** | GAP+GMP 拼接 | 192 | 对照：只加"存在性"不加位置 |

评价：az_r10 策略 + 各价值头 vs rule_v4 32 局（seed 0-31，配对可比）。

## 改动清单

1. `network.py`：`AntWarNetwork` / `create_model` 增加 `value_pool: str = "gap"`
   （`gap`/`region`/`grid`/`attn`/`gapmax`）；`forward` 里按类型构造 `value_emb`
2. 各保存点写 `value_pool` 字段；加载路径读它（复用 `value_*` 覆盖机制）
3. `value_warmup.py` 增加 `--value-pool`

## 判读

- 任一个明显 >31.2% → **"输入表达太粗"是瓶颈之一**，继续往空间方向做（注意力池化/更细网格）
- 全部 ≈31.2% → 瓶颈确实在标签/数据 → 转**对手池**方向

## 风险

- 价值头输入维度变了 → checkpoint 结构变，必须重新训练；加载路径要读新字段
- 策略网不受影响（`board_emb` 保持 GAP 用于策略头）
