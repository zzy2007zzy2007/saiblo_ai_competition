# 预注册：**闭环重训 —— 把 MC 的判断蒸馏进类头**（`posnet_R4_clshead`）

> 2026-10-07 第 4 轮写（**在训练/评估之前**）。章程：`docs/task_ruleV4_90_charter.md`。
> ⚠️ **换 ckpt = 机械门**（章程 §4）⇒ 本预注册 + 若晋级则独立验证 + 记档。

## 0. 为什么是这条（第 4 轮的理由）

前三轮把**决策层**（评价器深度 R1/R2、位置网 A/A1/B、菜单宽度 TOPK/CELLS、平局门控 MARGIN）与
**两个动作级干预**（强制升级 0/64、抑制降级 −20.3pp）全部排除 ⇒ **唯一没动过的是"训练分布/目标"**。

**关键机制动机**：我们的类头是**常数函数**（一直闪电/HOLD）⇒ **80% 的非仲裁回合**（`MC_EVERY=5`）里
它只会"能放闪电就放、否则 HOLD"，**完全不考虑经济类**；而我们**全部建塔**都来自那 1/5 的 MC 仲裁回合。
⇒ 若把 **MC 自己的判断**蒸馏进类头，**每一回合**都能享受 MC 的判断（这是"决策分布"的改变，
不是前三轮那种"换评价器"）。

**合规**：数据 = **我们自己的**自对弈（`mc_quiet` 部署配置），**不涉及模仿 `rule_v4`/冠亚军**（章程①）；
种子 = `50,010,000+`（`--seed 5001`），**与判据 seed（7..70 / 1000..9927）完全不重叠**（章程③）。

## 3. 判据（**先写死**）

| 读数 | 判定 |

- **机制读数（必报）**：新类头在留出状态集上的 **argmax 类分布**（是否混合，预测 P1）；
  部署后我方 **建塔/降级/闪电/出招回合**（是否在**非仲裁回合**也出现经济动作，预测 P2）；
  `dec_max`；无效/超时。
- ⚠️ 64 局只分辨 >~12pp；单段不作结论；看数据前判据已写死。

## 4. 预测

- **P1**：新类头的 argmax 分布**混合**（≥3 个类各占 >5%）——若仍单一 ⇒ 蒸馏失败（数据里 81% 是闪电，很可能就学成"几乎总是闪电"）。
- **P2**：部署行为出现"**非仲裁回合也有经济动作**"（建塔数上升、或降级数变化），出招回合数上升。
- **P3（分数）**：不确定；**若 P1 失败 ⇒ 我预期分数不变**（这类"换组件"在前三轮全部无效）。
  真正值得看的是：**若 P1 成功而分数不动** ⇒ 那就把"决策分布"这条也记为阴性，
  后面只剩"换搜索/换目标/换规模"这类大改。
