- 日期：2026-10-12

- 动因：本会话所有重训都只用**一套配方**（Adam / lr 1e-3 / 10 epoch / best-val / 软或硬 CE / 只训 `pos_state`）✗
  ⇒ **配方本身是一个从未被控住的混淆** ✗ —— 例如硬标签版 `p̂ = 0.5000`（−18pp）既可能是"数据饥饿/结构"，也可能是"配方没调" ✗。

## 1. ⚠️ 纪律（最重要，先写死）

1. **判据段（seed 7..70）已被本会话反复使用 ~10 次** ✗ ⇒ **禁止用它选配方** ✓；
2. **选择集** = dump 数据的**离线指标**（零对局 ✓；dump 种子与判据段隔离 ✓ 23000–23199 ✓）；
3. 只给**最终 1–2 个入围配方**各跑**一次**判据臂（128 局 ✓），并在本文档预注册"本次只跑这几个" ✓；
4. 所有变体**同一份数据、同一个随机切、同一套评估代码**（否则比较无效 ✓）。

## 2. 候选变体（按机制优先级；全部零对局可评）

| 优先级 | 变体 | 机制依据 |
|---|---|---|
| P0 | **硬标签 one-hot**（现状 ✓）| 名次曲线（86ad）：只有 rank-1 有分辨率 ✓ |
| **P1** | **rank-1 vs 其余**（0.5 给 rank-1，其余均分 0.5/（n−1））| rank 2/3/5 **实测不可分辨**（0.5469/0.5469/0.4922 ✓）⇒ "rank-1 vs 其余"才是被测量的结构 ✓ |
| **P2** | **全合法格 softmax**（目标在**该类全部合法格**上归一化，非候选格给 0）| 修当前实现的缺陷 ✗（现在只在候选格上归一化 ⇒ 其余合法格未约束 ✓）|
| **P3** | **剔除类 16（降级）行** | 目标是 churn 的主要来源（机制列显示降级 22.2 vs 19.9 ✗）|
| P4 | 硬标签 + 标签平滑（ε ∈ {0.05, 0.1, 0.2}）| 过拟合缓解（train 69% vs val 38% ✗）|
| P5 | **pairwise/margin 排序损失**（直接优化"图上 argmax == 目标 rank-1 格"）| 部署只看 argmax ⇒ 目标函数应与之一致 ✓ |
| P6 | 结果加权（AWR：按对局 HP 差/胜负加权行）| 引入**结局**这一新信息 ✓（启发式教师从没见过 ✓）|
| P7 | lr 扫描 {3e-4, 1e-3, 3e-3} + early stop | 过拟合与收敛速度未调 ✗ |
| **P8** | **只训 `action_map` 头、冻结位置网骨干**（`--head-only`）| 三网**各自独立**（无共享骨干 ✓）⇒ 位置网**整网本来就在训** ✓；3.2k 行过拟合明显（train 69% vs val 38%）⇒ **减少可训参数应更稳** ✓ |
| — | ~~训练 `class_state` / `value_state`~~ | **不做** ✗：**这才是**会破坏单变量、且本目标禁止的两件事 ✓ （三网互相独立 ⇒ 训位置网**不可能**改到 `class_state` ✓，代码见 `az_selfplay.py:112-117` ✓）|

## 3. 选择指标（离线，全部零对局）

1. **部署相关**：`图上 argmax（钉住的类内）== 目标 rank-1 格` 的**比例**（val ✓）—— 部署最终取的就是图的 argmax/候选 ✓；
2. **目标质量（§9 口径）**：val CE 相对 incumbent 头的下降（≥0.10 ✓）与"与目标 argmax 一致率"是否超过 incumbent ✓；
3. **图健全性**：`action_map` 有限、无退化（避免上一轮"0 建塔"那类事故 ✗）+ **往返加载 + 一次前向自检** ✓（新纪律 ✓）；
4. 记录**参数变化范数**（现在动辄 5,000+ ⚠️ 偏大 ⇒ 作为诊断列 ✓）。

## 1.1 ⚠️ 更正（2026-10-12，用户追问）：不存在"共享骨干"，位置网整网本来就在训

- 我原先在本表里写了"~~解冻共享骨干 ⇒ 会改 `class_state`~~ **不做**" ✗ —— **错**：
  `load_three_models`（`code/my_ai/az_intent/az_selfplay.py:112-117`）会**分别**创建三个 `AntWarNetwork`
  （`class_model` / `pos_model` / `value_model`）并各自载入 `class_state` / `pos_state` / `value_state` ✓
  ⇒ **三网之间没有任何共享张量** ✓ ⇒ **训位置网在架构上不可能改到类网** ✓
  （实证：本会话每个候选的 `class_state` 都是 **94/94 逐位不变** ✓ —— 结构保证 ✓）。
- 而我们现有的训练器（`train_visit_marginal.py` 等）**已经把整个 `pos_model`（骨干 + `action_map` 头）开了梯度** ✓
  ⇒ 所以"解冻骨干"是**空操作** ✓（这正是 `pos_state` 里 80/94 张量改变、参数范数 5,000+ 的原因 ✓）。
- "共享骨干漏梯度"是**单网时代**的问题 ✗（三个头共用一条骨干 ⇒ 价值梯度漏进策略 ✓，见历史记录 ✓）；
  **三网拆分之后不再适用** ✓。
- ⇒ 被拆分**真正解锁**的合法变体是**反方向**的：**只训 `action_map` 头、冻结位置网骨干**（P8 ✓，实现 `--head-only` ✓）。
- ⇒ 会破坏单变量的只有两件：**训 `class_state`（类网）** 与 **训 `value_state`（本目标冻结 ✓）** —— 我们都不做 ✓。
