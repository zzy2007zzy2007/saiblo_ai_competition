# 决定：把搜索/采集的位置温度默认值从 0.3 改为 1.0

> 日期：2026-09-18。依据 `docs/experiment_log.md` 的五条：`tpos_prior_quality`、
> `tpos_strength`、`tpos_similarity`、`tpos_rule_v4`、`tpos_rule_v4_mild`。

## 1. 背景：`0.3` 这个数字的语义在 2026-09-17 悄悄变了

`decoder._sample_position` 原来用固定尺度 `channel_map / 100`，2026-09-17 改成**合法格上的
z-score**（`z = (map - mean) / std`）。两者对"温度"的含义差一个因子：

| | logit 的宽度 |
|---|---|
| 改前 | `std(map) / (100 · t_pos)` |
| 改后 | `1 / t_pos` |

实测 `std(map) = 0.26`（`_tmp_pos_scale_probe.py`，n=120 头槽位）⇒ 改前在 `t_pos=0.3` 时
logit 宽度只有 **0.0087**，softmax 基本是平的 ⇒ **改前 `t_pos` 是个完全失效的旋钮**
（等效新值 = 旧值 × 381 ≈ 无穷大）。旁证：`map_quality_effect`（修复前那轮）里
`tp0.3` 与 `tp1.0` 两档结果**逐位相同**。

⇒ **修复后的 `t_pos=0.3` 是一个从未真正用过的档位，而且极尖。**

## 2. 实测：强度随温度的曲线（各 64 局打 rule_v4，同 seed 逐局配对）

| t_pos | 地图 top1 | 有效候选（共 ~270 合法格） | vs rule_v4 |
|---|---|---|---|
| 0.3 | 0.47 | 10 | **1.6%**（1W/63L）|
| 0.5 | 0.21 | 48 | **7.8%**（5W/59L）|
| 0.7 | 0.10 | 107 | **18.8%**（12W/52L）|
| 1.0 | 0.04 | 173 | **20.3%**（13W/51L）|
| 2.0 | 0.01 | 242 | **20.3%**（13W/51L）|

配对 McNemar（`_tmp_paired_rule_v4.py`）：**0.3 vs 1.0 → p=0.0005，12 个翻转全部朝向 1.0**；
0.7 vs 1.0 → p=1.00；1.0 vs 2.0 → p=1.00。平台从 `t_pos≈0.7` 开始，**0.3 比平台低 18.7pp**。

**机制（不是"探索少一点"，是"多样性塌缩"）**：`k=24` 在两种温度下都只给 24 个候选，
差别不是数量而是**这 24 个铺在哪**。高温时它们散布全图（= 24 次不同区域的探测），
低温时挤在先验的那一小片（= 对同一个区域采样 24 次）——那个区域一旦不好就逃不出去。
对空间相关的价值场这是结构性的损害，**不需要假设先验是"反向"的**；而 `峰对齐价值 = 0/22`
说明先验也没有补偿性的好处。（顺带：这也解释了为什么"低温目标可复现性高、余弦 0.966"
没有价值——那个位置的搜索本身只有 1.6% 强度。）

## 3. 决定

把下列路径的默认值/硬编码值从 `0.3` 改为 **`1.0`**（= 平台起点，也是 `eval.py` 原有的默认值）：

| 文件 | 位置 |
|---|---|
| `code/my_ai/az_intent/az_selfplay.py` | `--t-pos` 默认 |
| `code/my_ai/az_intent/az_train.py` | `--t-pos` 默认 + 两处函数签名默认 |
| `code/my_ai/az_intent/az_search_vs_search.py` | `--t-pos` 默认 |
| `code/my_ai/az_intent/_bench_depth_cost.py` | `--t-pos` 默认 |
| `code/my_ai/az_intent/run_az_batches.sh` | `T_POS` 默认 |
| `code/run_az_bn_kgeo.sh`、`run_policy_only.sh`、`run_posnet_loop.sh`、`run_value_loop.sh` | 硬编码 `0.3` → `1.0` |

**影响**：改完之后采集/评估走的是 ~20% 强度的策略，而不是 1.6% 的。**历史数据不必重跑**——
那时候尺度是坏的、等价于"温度无限大"，所以那些数据反而是安全的。

**故意没改的地方**（保持可复现性）：
- `_tmp_*.sh` 里的一次性评测脚本仍写 `--t-pos 0.3`。那些是**历史实验的快照**，
  `experiment_log.md` 里记的命令跟它们逐字对应；改掉会让"日志里的命令 ↔ 脚本内容"对不上。
  它们已经跑过、结论已入档，不需要再跑。
- `code/my_ai/az_intent/diag_native_crash*.py` 同理（它测的是崩溃路径，不是棋力）。

## 4. 未决 / 待验证

- `az_train.py` 的 `t_pos` 是**损失侧的 CE 温度**（`pos_logits = am_c / t_pos`），语义与采样器
  不同，但按道理应当匹配（目标是搜索采样出来的那个分布）。本次一并改为 1.0，
  **但没有单独消融过**，属于待验证项。
- `pos_greedy_vs_raw` = 1.3125（对**全部**合法格做 1-ply 价值 argmax，确定性）反而低于
  "24 个采样候选里按 visit 选" 的 2.0000。可能是 visit-argmax 比"对 270 个噪声估计取 max"
  更稳健（winner's curse），**未验证**。
- 本次扫的是"温度轴"，扫完的结论是**温度不能解决先验内容差的问题**：平台强度 20.3%
  与历史 18.8%~29.7% 区间一致 ⇒ **绝对强度没有提升**，卡点不在这里。
