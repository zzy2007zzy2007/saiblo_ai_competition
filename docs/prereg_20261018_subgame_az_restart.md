## 0. 三处必须先修正的前提（避免照搬）

| 用户前提 | 实测事实 | 影响 |
|---|---|---|
| "MCTS 内部的引擎要改成禁闪电" | **不存在这一步**：搜索用的就是真引擎（`GameStateFacade`），禁闪电是**决策层掩码**（`decoder.make_class_mask`），已实测传播进 rollout（836 次决策 0 次闪光） | 省掉该步 |
| "动作网/价值网都训过了" | 训的是**真实对局**的网；子博弈没有专门的网。质量是弱环：价值头重训 val MSE 0.1015→0.0976 但**筛选 −1.6pp**；**无搜索纯策略在真实对局仅 0.0938** | 重训必须 |
| "蒸馏 example 得动作网" | 章程允许；但**升级在本管线结构上不可达**（解码器遇"格子已有塔"给**降级**；升级只从 MC 显式 op 候选进来） | **必须先修动作编码**，否则 AZ 学不会升级 |

## 1. 四步与闸门（每步先过机制闸门，再看胜率）

| 步 | 做什么 | 成本 | 闸门（先写死）|
|---|---|---|---|
| **S0** | **把升级接进搜索的动作集**（`candidate_fn` 钩子 / 显式 `('op',12,tower_id,tgt)` 候选），子博弈下 | ~1 h 代码 + 128 局 | 我方**升级 > 0/局**且**建塔 ≥15/局**（不塌）|
| **S1** | 给 `ex_pkg` 加"裸 dump"：每回合记录（状态特征、example 选的束）⇒ 采 200–400 局 ⇒ **蒸馏进类头/位置头** | ~半天 | 蒸馏后对 example 动作的**离线一致率**显著高于现网；且 建/降/升 分布接近 example |
| **S2** | **双方禁闪电**自对弈采数据（我方 = 当前最好配置），**只重训价值头**（子博弈结果）| 数天 | 在同 128 局上，价值头当评价器**棋力 ≥ 安静 rollout 评价器**（不是比 MSE）|
| **S3** | 仅当 S2 过线（例如对 example ≥0.6）才做：**回传真实对局** | —— | 真实对局固定段 **≥0.7344**（不倒退）|

## 2. 读数协议（两个参照，避免自指）

- 参照 A：**官方 `example`**（可比历史：A3 = 0.0156 → E2 = 0.4375 → **S0 = 0.3828**）。
- 参照 B（**不自指**）：**与当前最强子博弈 agent（S0 配置）正面交手** ⇒ 新流水线要能赢过旧的最好（≥50%）。
- 样本：固定段全段 `7..70`（128 局 = 64 对，分半报）；"候选"类结论要在**未见 seed**（`501..564`）确认。
- ⚠️ 硬约束（如实记录）：本机 ~8–9k 局/天 ⇒ **AZ 量级自对弈差 2–4 个数量级** ⇒ 本计划只在"子博弈更简单、小网+中等搜索够用"这个**赌注**成立时才有戏。

## 3. 预测（事后对照）

- **S0**：升级 0 → ~2–3/局；胜率变化我估 **±5pp 内**（中性）。
- **S1**：动作分布会第一次像"会打经济的人"；对 example 胜率我给 **0.45–0.60**（有机会首次超过"打补丁"最好值 0.3828，但未必过 0.5）。
- **S2**：若价值头不能在棋力上赢过安静 rollout ⇒ **这条 AZ 线在 S2 就关门**（即用读数再次证明"评价器是本管线瓶颈"）。
