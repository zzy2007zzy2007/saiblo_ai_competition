## 0. TL;DR（先给结论，三句话）

1. **Q1 —— 第二阶段参数没有不同。** unified 和 pin 的 flat rollout 评估器是**同一个类**（`FlatRolloutGreedy.search()` 原样继承），构造函数参数逐字相同（见 §1 对照表 + 双方日志的 `AI0 env` 逐字段比对：唯一差异就是多一个 `AZAI_CAND_MODE=unified`）。阶段 2 的 rollout / 叶值网 / 选择规则**一字不动**。不存在"参数设不同"的候选 bug。
2. **Q2 —— bandit 砸降级预算不是"值网把降级打高分"，而是「贫困陷阱」+「16→1 通道别名」。** 实测 73.6% 的决策里合法类集合坍缩成 **{降级(16), HOLD(23)} 两个**（因为建塔要金币、降级不要金币），bandit 的预算**被逼**压在这两个臂上（此时 `N[16]≈72`）；而值网阶段 1 对降级的打分 `Q[16]=−0.017` **低于**建塔 `Q[build]=+0.008` —— 所以不是 Q 驱动，是"穷时只剩降级可选"。`N[16]` 在 round 0→400 全程稳定在 ~58~72，**没有单调上升、没有"越选越喂"的发散**（Pearson(Q,N)≈−0.01）。
3. **Q3 —— 降级是"果"不是"因"；最根本病因是「值网只读得懂金币、读不懂塔的长期价值」。** 值网金币斜率弱为正（+0.037/币），于是"降级退款"(+0.047) 和"空过攒钱"(+0.101) 都判成正分、而"建塔花钱"判成≈0/负分（阶段 1 `−0.011`）。pin+flat 把这条病**藏**起来（MC 仲裁 78% 钉 HOLD、`n_cand=1`、根本不摆降级候选）；统一搜索每回合把"降级退款"摆上台，值网一逮到就选，叠上"建塔→变穷→只剩降级合法"的贫困陷阱，把病放大成建塔↔降级的烧钱循环。16→1 别名是**次级放大器**，不是主因。

## 1. Q1：第二阶段（flat rollout）参数对照 —— 逐项、结论

### 1.1 结论先行

**没有任何一项设得不同。** 阶段 2 评估器是 `FlatRolloutGreedy.search()`，unified 的 `UnifiedCandFlatSearch` **不重写** `search()`，只在外面包一层日志（`unified_cand.py:799-835`）；`__init__` 直接 `super().__init__(*args, **kwargs)` 把参数原样传给 `FlatRolloutGreedy`（`unified_cand.py:652-653`）。两条路径的构造函数调用**共用同一行代码**（`az_bridge_ai.py:1362-1384`），区别只有 `_searcher_cls` 是 `FlatRolloutGreedy`（pin）还是 `make_unified_searcher_class()`（unified）。

### 1.2 实测证据（不是看默认值，是看真正传进构造器的值）

对战日志把 AI0 的完整 env 原样打印出来，直接比对 `AB_RV4_OLDCFG_PINFLAT_VOID/incumbent/100.log`（pin）与 `AB_RV4_FULL/incumbent/100.log`（unified）——两串 env **唯一差异**是后者多了 `AZAI_CAND_MODE: 'unified'`：

### 1.4 三个容易误判的"看起来不同"，实际都一致

1. **k=48 的语义**：pin 的 `_expand` 里 `n_samples = k*sample_mult = 48×15 = 720`，取 top-48 去重候选；unified 的 `generate` 里 `pool_target = k*1.5 = 72`，再按阶段 1 分取 top-48。**两边的"k"都是 48**，只是"候选从哪来"不同。pin 常产出 `n_cand=1`（78% 钉 HOLD），unified 常产出 `n_cand≈4~48` —— 这是候选来源的**设计差异**，不是参数不同。
2. **每候选采样数**：预算公式 `n_rollouts = min(64, 49152 // (n_cand×16))`。pin 的 `n_cand=1` → `n_rollouts=64`；unified 的 `n_cand≤48` → `n_rollouts=64`（因为 `49152 = 48×16×64` 刚好卡满）。**两边都是 64 次 rollout/候选**，unified 并没有被"多候选摊薄采样"。
3. **阶段 1 → 阶段 2 的样本复用**：`_phase2_cache` 只在"阶段 1 估计器 == 阶段 2 估计器"时非空。实测阶段 1 是 `idle`、阶段 2 是 `random`，签名不等 ⇒ `_phase2_cache=None` ⇒ **不复用**。即 unified 的阶段 2 也是纯 fresh random rollout，和 pin 完全同源。

**§1 最终结论：第二阶段参数逐项一致，没有候选 bug。unified 比 pin 差的全部差异都发生在"候选从哪来"（阶段 1 的 bandit 生成），不在阶段 2 评估器。**

## 2. Q2：bandit 为什么砸降级预算 —— 机制 + cand.jsonl 证据

### 2.1 先把代码机制讲清楚（回答"Q[c] 到底怎么算"）

`unified_cand.py` 的 bandit 是**决策内**的（每决策 `_reset_state` 重建 Q/N，跨决策零记忆）：

- **Q[c]（`_q_util`，:327）** = **玻尔兹曼加权平均** `Σᵢ wᵢ·xᵢ`，`wᵢ = softmax(β·xᵢ)`（β=3）。**x 是"阶段 1 的确定性 idle rollout 分数"**：把该候选 bundle 打进克隆局面 → 双方谁都不出招地 `advance_round()` horizon=16 次 → 叶状态送**值网**打分（`idle_rollout_values` → `_leaf_values`，即 `posnet_A_k5_m32.pt` 的输出，tanh 到 [−1,1]）。**x 不是"idle 分"这个词能概括的——它就是值网对"打完这手 + 静置 16 回合"之后局面的评分**。β=3 使 Q[c] ≈ 观测到的**最大值**（对重复同值不敏感）。
- **UCB（`_ucb`，:349）** = `Q[c] + c·√(log N_total / n)`（c=1.0）；`n==0` 时返回 `+∞`（未试过的臂优先）。
- **选类（`_pick_group`，:401）**：3 个头，**头 0 = UCB argmax（利用主导）**，**头 1、2 = `softmax(UCB/τ)` 采样（τ=1.0）**。形状 = 去掉 HOLD、排序、**保留重复**的规范多重集 ⇒ 同一束里允许 `[16,16]`、`[16,16,16]`。
- **回写（`_credit`，:356）**：把**阶段 1 分数完整**写给束内**每一个**类（不打 1/|束长| 折扣）。**关键事实：`_credit` 只在阶段 1 生成时被调用，阶段 2 的选中结果根本不会回写 Q**（阶段 2 在 `FlatRolloutGreedy.search()` 里，发生在 `generate()` 返回之后，且 bandit 每决策重置）。

### 2.2 证据 ①：预算砸降级，但**不是**因为 Q[16] 高

| 指标（cand.jsonl，165,012 决策） | 值 |
|---|---|
| 含降级通道 16 的决策占比 | 97.8% |
| **Q[16]（降级）** | **−0.0166** |
| **Q[build 通道 0..15 均值]** | **+0.0082** |
| Q[16] > Q[build] 的决策占比 | **42.6%**（不足一半） |
| Q[16] 是 argmax-Q 的占比 | **14.8%** |
| **N[16]（降级访问数）** | **58.7 / 决策** |
| N[build 单通道均值] | 4.5 / 决策 |
| N[16] / N[build 单通道] | **13.1×** |

**这组数直接推翻了前序文档的隐含机制**："bandit 把预算花在降级上" ≠ "值网给降级打高分"。值网阶段 1 对降级的打分**反而低于建塔**（Q[16]=−0.017 < Q[build]=+0.008），而 N[16] 仍是建塔单通道的 13 倍。**所以"砸预算"不是 Q 驱动的。**

### 2.3 证据 ②：真机制 = 「贫困陷阱」—— 穷时合法动作坍缩成 {降级, HOLD}

按"每决策合法类集合"（= `Q` 的 key 集）分组：

| 合法类构成 | 决策数 | 占比 | 此时 N[16] 均值 |
|---|---|---|---|
| **{16(降级), 23(HOLD)} 只有两个** | **121,969** | **73.6%** | **72.3** |
| build 通道 0..15 合法（≥1 个） | 43,587 | 26.3% | 15.9 |

机制（`_reset_decision` 用 `intent_decoding=False`，即**连金币一起查**）：

- **建塔（通道 0–15）合法 ⇔ 买得起**（`make_position_masks` 的代价门槛）；建塔费随塔数翻倍（`coin.cpp:11-19`：15→30→45→90→135→270…）。
- **降级（通道 16）合法 ⇔ 有塔**（**不要金币**，它本身是退款）。
- **HOLD（23）恒合法**。

⇒ 每当 AI 建了一座塔、金币跌破下一座塔的造价（这正是"刚建完"的常态），合法类集合就**坍缩成 {降级, HOLD} 两个**。bandit 的 3 个头在这个 2 元素集合上 `softmax(UCB/τ)` 近似 50/50 采样 ⇒ **预算被逼压在这两个臂上**，于是 `N[16]≈72`（和 `N[23]≈72` 平分）。

### 2.4 证据 ③：多重集 [16,16] / [16,16,16] 是"穷时 3 个头都只能选降级"的产物

进 top-k 候选里，**纯降级候选的多重集分布**：

| 多重集 | 候选条数 | 占纯降级候选比例 |
|---|---|---|
| 降级 ×1 | 340,550 | 53.5% |
| **降级 ×2** | **261,212** | **41.0%** |
| **降级 ×3** | **46,686** | **7.3%** |

对照建塔：`build×1 = 507,511`、`build×2 = 73,481`、`build×3 = 209`（多重占比仅 13%）。

**为什么降级多重集这么高**：穷态合法集只有 {16, 23} 两个，3 个头各 50/50 落在 16/23 ⇒ 期望产生 0/1/2/3 个"降级头"的比 ≈ 1:3:3:1，于是 `[16,16]`、`[16,16,16]` 大量出现。而建塔有 16 个通道，"同建塔通道重复"要 2 个头撞上**同一个**通道（1/16 概率），所以 `[build,build]` 罕见。**降级多重集不是 bandit "结构性偏袒降级"，而是"穷时除了降级没别的非 HOLD 类可挑"。**

### 2.5 证据 ④：没有"越选越喂"的正反馈发散

| 观测 | 结果 |
|---|---|
| N[16] 随 round 分桶（0→400+） | 58.7 → 57.9 → 59.3 → 59.0 → 58.6 → 58.4 → 58.1 → 57.0 → 57.6（**全程稳定，无单调上升**） |
| Q[16] 随 round 分桶 | −0.004 → −0.028 → −0.024 → −0.013 → −0.007 → −0.014 → −0.026 → −0.026 → −0.020（**无趋势**） |
| Pearson(Q,N) | 通道 16 = **−0.011**（几乎无关）；通道 0–15 = +0.168 |

**结论**：`_credit` 的"回写"只在**阶段 1 内部**、只写阶段 1 分、且**每决策重置**；阶段 2 的选中**不回写** bandit。所谓"越选越喂"的正反馈**在 bandit 的 Q/N 里不存在**（Q 是玻尔兹曼≈max，天然有界；N 是每决策独立快照、稳定）。真正的正反馈发生在**游戏经济层**（见 §3 的贫困陷阱循环），不是 bandit 参数层。

### 2.6 证据 ⑤：阶段 2 才是"退款被判正分"的地方，且它分不清降级/建塔

阶段 1（idle）/ 阶段 2（random）平均分（cand.jsonl 全量）：

| 类 | s1（idle） | s2（random） |
|---|---|---|
| HOLD | +0.048 | **+0.101** |
| build（建塔） | −0.0115 | +0.0377 |
| **downgrade（降级）** | **−0.0095** | **+0.0467** |
| upgrade（升级） | +0.050 | +0.108 |

阶段 2 转化率（该候选被选中的比例）：HOLD 66.5%、**降级×1 5.33%**、建塔×1 3.72%、降级×2 1.12%、建塔+降级 1.31%。

**要点**：值网在阶段 2 里给"降级退款"和"建塔"都打**弱正分**（+0.047 vs +0.038，只差 0.009），给"空过攒钱"打 +0.101。**它不是"独爱降级"，而是"攒钱/退款略好于花钱建塔"**——这正是弱正金币斜率的表现。当候选池被贫困陷阱灌满降级时，值网没有信号去拒绝它，于是降级被选中 38%（非 HOLD 里）与建塔 37% 几乎持平。

## 3. Q3：降级是"果"还是"因"？

### 3.1 判断：降级是「果」（暴露点），值网读不懂「塔 vs 退款」才是「因」

**因果链（证据支撑，不是空谈）：**

```
值网金币斜率弱为正（+0.037/币，见 value_net_retrain_v1_20261101.md）
  → 值网把"退款/攒钱"判成正分、把"花钱建塔"判成≈0/负分（§2.6）
  → 统一搜索每回合把"降级退款"摆进候选池（pin 不摆，见 §3.2）
  → AI 一建塔就变穷（建塔费翻倍，coin.cpp:11-19）
  → 穷态合法动作坍缩成 {降级, HOLD}（§2.3，73.6% 决策）
  → 值网周期性选"降级退款"（阶段 2 降级 +0.047 > 建塔 +0.038）
  → 建塔 ↔ 降级 churn（前序文档：55% 的建塔 3 回合内被自己拆掉）
  → 更穷 → 更只剩降级 → …… 贫困陷阱正反馈
```

**为什么说"降级是果不是因"**：把降级从候选池拿掉（`AZAI_NO_DOWNGRADE=1` 或砍通道 16），穷态的合法集就坍缩成 **{HOLD} 一个**——churn 的燃料（退款）没了，循环断掉，AI 只能攒钱→建塔→攒钱，金币会从 56 回到 pin 量级、血差会大幅回收。**降级是值网弱点的"暴露点"，不是独立病因。**

**为什么说"值网读不懂塔"才是因**：值网真正的问题不是"读不懂降级"（它给降级 +0.047 和建塔 +0.038，几乎无差别），而是**horizon-16 的 rollout 里看不到"一座塔未来能打掉多少蚂蚁/守住多少血"，只看得到"现在金币 +/−"**。于是它对"花钱建塔"和"退款拆塔"都只按金币瞬时差来判，攒钱(HOLD)永远最优、退款(降级)次之、花钱(建塔)最差。这条病 pin 和 unified **共享**（同一个 ckpt），差别只在"有没有被暴露"。

### 3.2 pin+flat 为什么没这病：不是值网更好，是候选生成把病藏起来了

- pin 的候选来源 `bundle_mcts._expand`：MC 安静仲裁（`mc_quiet_choose`）先钉**一个类**（78% 钉 HOLD），再 `pinned=[_ccls]*3` 采样 ⇒ `n_cand=1` 占 82.3%。**它根本不给降级这个选项**（前序文档 §2.4 已测）。
- unified 的候选来源：bandit **每回合枚举**"当前买得起/合法的所有类"，穷态下必然包含降级。

所以：**同一个弱值网，pin 把它"锁在 HOLD"上（忍得住、攒 235 币），unified 把它"摆在降级面前"（折腾、烧到 56 币）。** 这是"候选生成"与"值网质量"的交互，不是值网质量本身在两条路径上不同（§1 已证同 ckpt 同评估器）。

### 3.3 16→1 别名是次级放大器，不是主因

前序文档 H4 把"16→1 建塔别名"列为放大器，本文件数据确认它的量级：

- 富态（build 合法，26.3% 决策）里，N[16] 降到 15.9，但建塔预算仍被 16 个通道摊薄（通道 0 拿到 ~16、通道 1–15 各 ~3.5）。
- 后果：建塔候选在富态被低估（16 个别名臂互相 cache 命中、升级只能靠游标碰巧落到己方塔格）。

**但它不是 churn 的主因**：churn 的燃料是"穷态只剩降级合法"（73.6% 决策），与 16→1 无关；即便 `decode=split` 修掉别名，穷态依旧 {降级, HOLD}，值网依旧会选降级。别名影响的是"富态建塔/升级搜得全不全"，是**效率**问题，不是 churn 的**开关**。

## 4. 结论：最根本病因 + 最小验证实验

### 4.1 最根本病因（一句话）

> **统一搜索比 pin+flat 差的最根本病因：值网的弱正金币斜率（+0.037/币）让它读不懂"塔的长期价值"，把"降级退款/空过攒钱"判得比"建塔"更值；统一搜索每回合把这个弱点摆成候选、再叠上"建塔→变穷→合法动作坍缩成{降级,HOLD}"的贫困陷阱，把值网的病放大成建塔↔降级的烧钱循环——降级 churn 只是这条因果链的"果"。**

### 4.2 最小验证实验（一个 env 变量，零改代码，预注册判据）

> 复用 `_value_ab_vs_rv4.sh` 同一批设施，对手 rule_v4，镜像配对。

| 臂 | 配置 | 判据 |
|---|---|---|
| A（主验证） | unified + `AZAI_NO_DOWNGRADE=1`（把降级从候选池里删掉，切断贫困陷阱燃料） | 血差应从 +0.25 回收 **≥ 一半缺口（≥ +10）**，且金币从 56 回到 pin 量级 |
| B（对照） | 现役 unified（不动） | 复现 +0.25 |
| C（对照） | 现役 pin+flat | 复现 +21.5 |

- **若 A 回收 ≥ 一半缺口**：确认"降级暴露 + 贫困陷阱"是 churn 的开关，值网弱金币斜率是主因（本文件判断）。
- **若 A 几乎不动**：说明 churn 不是主因，回看 16→1 别名 / 值网更底层的塔价值盲区（需值网侧重训，属下一步）。

> 次要诊断（可选，验证"16→1 是放大器"）：`AZAI_CAND_DECODE=split` + unified vs legacy。判据：split 应提高富态建塔/升级候选占比，但**血差回升幅度应远小于 A**（因为它不断 churn 的燃料）。
